## How Strassen's algorithm works

Split each n x n matrix into four n/2 x n/2 blocks. The schoolbook rule for blocks needs eight block products (`A11*B11`, `A12*B21`, and so on), and the recurrence `T(n) = 8 T(n/2) + O(n^2)` solves to <BigO of="n^3" />, no gain at all. Strassen found seven products whose sums and differences still give every block of the result. Block additions cost only <BigO of="n^2" />, so trading one product for extra additions pays off.

<Steps>
  <Step title="Split">
    Cut `A` and `B` into the quadrants `A11, A12, A21, A22` and `B11, B12, B21, B22`. This needs an even size; an odd size is padded first.
  </Step>
  <Step title="Form seven products">
    Each `P1` ... `P7` multiplies one sum or difference of blocks of `A` by one of `B`, and each one is computed by a recursive call.
  </Step>
  <Step title="Recombine with additions only">
    The four result blocks `C11, C12, C21, C22` are sums and differences of the seven products. No more multiplications are needed.
  </Step>
  <Step title="Stop at the cutoff">
    A 1 x 1 matrix is a single multiplication. Below the cutoff (`n <= 64` in this repository) the recursion hands over to the naive triple loop, because the extra additions and allocations cost more than they save on small blocks.
  </Step>
</Steps>

<Callout title="The identity behind it">
Every result block is a bilinear expression in the blocks of `A` and `B`, and the seven products are chosen so that all cross terms cancel exactly. For example `C12 = P1 + P2 = A11(B12 - B22) + (A11 + A12) B22 = A11 B12 + A12 B22`, which is the schoolbook value. The proof is plain algebra, so the result is exact on integers.
</Callout>

Recombining them:

- `C11 = P5 + P4 - P2 + P6 = 65 + 8 - 24 - 30 = 19`
- `C12 = P1 + P2 = -2 + 24 = 22`
- `C21 = P3 + P4 = 35 + 8 = 43`

That is the matrix `[[19, 22], [43, 50]]`, the same as the schoolbook product, from 7 multiplications instead of 8.

## Pseudocode

```text
strassen(A, B):                       # n x n
    n = size of A
    if n == 1: return [[A[0][0] * B[0][0]]]
    if n <= 64: return naive(A, B)
    if n is odd:                      # pad by one zero row and column
        C = strassen(pad(A, n + 1), pad(B, n + 1))
        return top-left n x n part of C
    split A and B into A11 A12 A21 A22 and B11 B12 B21 B22
    P1 = strassen(A11, B12 - B22)
    P2 = strassen(A11 + A12, B22)
    P3 = strassen(A21 + A22, B11)
    P4 = strassen(A22, B21 - B11)
    P5 = strassen(A11 + A22, B11 + B22)
    P6 = strassen(A12 - A22, B21 + B22)
    P7 = strassen(A11 - A21, B11 + B12)
    C11 = P5 + P4 - P2 + P6
    C12 = P1 + P2
    C21 = P3 + P4
    C22 = P5 + P1 - P3 - P7
    return combine(C11, C12, C21, C22)
```

## Implementation

All three languages follow this pseudocode, including the cutoff of 64 and the odd-size padding. Python also offers `strassen_multiply_general` for rectangular inputs: it pads to the next power of two, multiplies and cuts the result back to `m x p`. The C++ and Go versions work on `int` matrices only, so large products can overflow `int`. Each language comes with tests, including sizes 65, 128 and 130 that reach the seven-product recursion.

## Complexity analysis

One level does seven recursive products on half-size blocks plus a constant number of block additions, each <BigO of="n^2" />.

<Equation label="Schoolbook blocks" expr="T(n) = 8 T(n/2) + O(n^2)" result="O(n^3)" />
<Equation label="Strassen" expr="T(n) = 7 T(n/2) + O(n^2)" result="O(n^{log2(7)}) = O(n^2.81)" />

By the master theorem, the leaves dominate: there are `7^(log2 n) = n^log2(7)` of them, and `log2(7)` is about 2.807. The additions are a lower-order term.

<Callout title="The cutoff matters more than the exponent">
For n = 128 with the cutoff of 64, there is one level: 7 naive products of size 64 cost 7 * 64<sup>3</sup> = 1,835,008 multiplications, against 128<sup>3</sup> = 2,097,152 for the naive method (about 12 percent fewer), but with extra allocation and 18 block additions. Real implementations tune the cutoff by measurement.
</Callout>

## Applications

- **Large dense matrix products** where the size is in the hundreds or thousands and the entries are exact (integers, or elements of a finite field).
- **Reductions.** Anything that reduces to matrix multiplication, such as counting paths of length k with an adjacency matrix power, inherits the speed-up.
- **Teaching.** It shows that the exponent of a problem can be lower than the obvious algorithm suggests.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Odd sizes.** Splitting at `n / 2` drops the last row and column when n is odd. The C++ and Go versions used to return a truncated matrix for an odd n above 64; they now pad by one zero row and column.
- **No cutoff.** Recursing down to 1 x 1 makes the algorithm slower than the schoolbook method.
- **Wrong sign in a block.** One flipped sign in a `C` block gives a plausible but wrong matrix. Always test against the naive product on random input larger than the cutoff.
- **Integer overflow.** The C++ and Go versions use fixed-width `int`, and the intermediate sums can be larger than the inputs.
- **Assuming it is faster everywhere.** Below a few hundred rows, a tuned naive kernel usually wins.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does saving one multiplication change the exponent?">
    Because the saving repeats at every level. The number of leaf products is `7^(log2 n)` instead of `8^(log2 n)`, and `7^(log2 n) = n^log2(7)`, about n<sup>2.81</sup>, while `8^(log2 n) = n^3`.
  </FaqItem>
  <FaqItem question="Is Strassen's algorithm used in practice?">
    Sometimes, for large matrices and with a high cutoff. Many numerical libraries rely on highly tuned schoolbook kernels instead, because of cache behavior and floating-point stability.
  </FaqItem>
  <FaqItem question="Does it work for non-square or non-power-of-two matrices?">
    Yes, by padding. In this repository `strassen_multiply_general` (Python) pads rectangular input to a power-of-two square and crops the result. `strassen_multiply` and the C++ and Go functions take square matrices and pad any odd size they meet.
  </FaqItem>
  <FaqItem question="Can matrix multiplication go below n^2.81?">
    Yes, asymptotically: researchers have found methods with exponents near 2.37. They are not used in practice because their constant factors are enormous.
  </FaqItem>
</Faq>
