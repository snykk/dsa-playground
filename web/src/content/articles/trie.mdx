## What a trie is

A trie is a rooted tree where each edge carries one character and each node stands for the prefix spelled by the path from the root. A node also carries a flag, `is_end_of_word`, that says whether that prefix is a stored word. Two words that start the same way share the nodes of their common prefix.

The trie holding `app`, `apple`, `apt`, `bat` and `bath`:

<TreeDiagram
  root={{
    children: [
      { edge: 'a', children: [
        { edge: 'p', children: [
          { edge: 'p', tone: 'f', children: [
            { edge: 'l', children: [
              { edge: 'e', tone: 'f' },
            ] },
          ] },
          { edge: 't', tone: 'f' },
        ] },
      ] },
      { edge: 'b', children: [
        { edge: 'a', children: [
          { edge: 't', tone: 'f', children: [
            { edge: 'h', tone: 'f' },
          ] },
        ] },
      ] },
    ],
  }}
  legend={{ f: 'end of a stored word' }}
  caption="Eleven nodes (the root plus ten characters) hold five words. The path a-p-p ends a word and also continues, so app is stored inside apple."
/>

The word marker is essential. `app` is a prefix of `apple`, and only the flag tells `search('app')` (true) apart from `search('ap')` (false).

<Callout title="The path is the key">
There is no key stored in a node. The key is the sequence of edges leading to it, so equal prefixes cost nothing extra and a prefix lookup is just a walk down the tree.
</Callout>

Names differ by language: C++ uses `startsWith`, `deleteWord`, `getAllWords`, `countWords` and `isEmpty`, and Go uses `Insert`, `Search`, `StartsWith`, `Delete`, `GetAllWords`, `CountWords` and `IsEmpty`. The empty string is a valid word: after `insert("")` the trie is not empty and `count_words()` is 1.

### Insert

Follow the word from the root. When the next character has no child, create one. After the last character, set the end flag. Inserting `apple` into a trie that holds `app` creates only two nodes, `l` and `e`:

  rows={[
    ['1', 'a', 'child exists, move down'],
    ['2', 'p', 'child exists, move down'],
    ['3', 'p', 'child exists, move down (this node already ends `app`)'],
    ['4', 'l', 'no child: create it'],
    ['5', 'e', 'no child: create it, then set the end flag'],
  ]}
/>

### Search and prefix search

Both walk the same path. They differ only at the end: `search` also needs the end flag. In the example trie:

<DataTable
  columns={['Query', 'Path exists', 'End flag', 'search', 'starts_with']}
  rows={[
    ['`app`', 'yes', 'yes', 'true', 'true'],
    ['`ap`', 'yes', 'no', 'false', 'true'],
    ['`apple`', 'yes', 'yes', 'true', 'true'],
    ['`bax`', 'no (x missing)', '-', 'false', 'false'],
  ]}
/>

To list every word with a prefix (autocomplete), walk to the prefix node and run a depth-first traversal from there. For `ap` that gives `app`, `apple`, `apt`.

### Delete

Deleting is two steps. First clear the end flag of the last node. Then walk back up and remove every node that now has no children and is not a word itself, stopping at the first node that is a word or still has another child. The return value is true exactly when the word was stored. Deleting from the trie above, one word at a time:

<DataTable
  columns={['Delete', 'Flag cleared at', 'Nodes pruned', 'Why it stops', 'Nodes left']}
  rows={[
    ['`apple`', 'e', '`e`, `l`', 'the node `app` is itself a word', '9'],
    ['`bath`', 'h', '`h`', 'the node `bat` is itself a word', '8'],
    ['`app`', 'second p', 'second `p`', 'the node `ap` still has the child `t`', '7'],
  ]}
/>

Each row counts the nodes including the root. Deleting `appl`, a prefix that is not a word, or a word that was never stored, changes nothing and returns false.

## Complexity

<DataTable
  columns={['Operation', { label: 'Time', kind: 'mono' }, 'Why']}
  rows={[
    ['insert, search, starts with, delete', 'O(L)', 'one hash-map step per character, independent of the number of words'],
    ['list all words', 'O(total characters)', 'every node is visited once'],
    ['space', 'O(total characters)', 'at most one node per inserted character, fewer when prefixes are shared'],
  ]}
/>

The cost is a function of the word length, not of n, the number of words: a binary search tree of strings would pay O(L log n) because every comparison reads up to L characters.

The repository tries store children in hash maps keyed by character, so a node costs memory in proportion to its actual children. Textbook tries often use an array of 26 pointers per node; that gives O(1) child access without hashing but uses O(26 &times; nodes) space, which is wasteful for sparse tries.

## Applications

- **Autocomplete and spell suggestions:** all words under a prefix node.
- **Dictionary lookups and word games:** Boggle-style searches prune a branch as soon as a prefix has no child.
- **IP routing:** longest-prefix match on a bitwise trie.
- **Word frequency and prefix counts:** store a counter per node.
- **Multi-pattern search:** the trie is the skeleton of the Aho-Corasick automaton.
- **Maximum XOR of two numbers:** a bitwise trie of the numbers.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Confusing prefix and word.** `search('ap')` is false when only `app` is stored. Always check the end flag.
- **Deleting without pruning**, or pruning too far. Stop at a node that is itself a word or has another child, or you remove words you meant to keep.
- **Returning the wrong value from delete.** The result must say whether the word was stored, not whether the parent may remove the node.
- **Mixing bytes and characters.** Python walks code points, Go walks runes, and C++ walks bytes, so a multi-byte UTF-8 character is several nodes in C++. Use one view for insert, search and delete (Go once indexed bytes in delete and broke on non-ASCII words).
- **Forgetting the empty word.** `insert("")` flags the root, so `is_empty` must look at the root flag too.
- **Recursing per character** on very long words. The implementations here use loops and explicit stacks.
- **Sharing a trie by copying it in C++.** Nodes are owned through raw pointers, so the class deletes copying.
</Callout>

## Implementation

All three versions have a node with a map of children and an end flag. Python and Go walk code points and runes, while C++ walks bytes. `delete` is iterative in all three: it records the path on the way down, clears the flag, then prunes back up. In C++ the destructor frees every node with an explicit stack. `get_all_words` returns insertion order in Python and map order (unspecified) in C++ and Go.

## Frequently asked questions

<Faq>
  <FaqItem question="What is the difference between search and starts_with?">
    `search(word)` returns true only if the path exists and its last node is marked as the end of a stored word. `starts_with(prefix)` returns true if the path exists at all. After inserting `apple`, `starts_with('app')` is true but `search('app')` is false.
  </FaqItem>
  <FaqItem question="Why is a trie O(L) and not O(L log n)?">
    Each step follows one edge chosen directly by the next character, so the number of steps equals the word length and does not grow with the number of stored words. A comparison-based structure must compare whole strings at each of its log n levels.
  </FaqItem>
  <FaqItem question="Array or hash map for the children?">
    An array of 26 slots is fastest for lowercase letters but costs 26 pointers per node even for leaves. A hash map costs memory in proportion to the children that exist and handles any alphabet, which is what these implementations do.
  </FaqItem>
  <FaqItem question="How do I get words in sorted order?">
    Keep the children sorted (an ordered map, or sort the characters while traversing) and do a depth-first traversal that emits a word when it meets a flagged node, before descending into its children.
  </FaqItem>
</Faq>
