## Definition

A prime is an integer greater than 1 whose only positive divisors are 1 and itself. The sieve computes the set of primes up to a limit `n` without testing divisibility of any single number.

<Equation label="Why sqrt(n) is enough" expr="composite m <= n  =>  m has a prime factor p <= sqrt(m) <= sqrt(n)" />

## Intuition

Start with all numbers from 2 to `n` unmarked. The smallest unmarked number is prime. Cross out its multiples, then move to the next unmarked number, which is again prime, and repeat. Crossing out the multiples of `p` can start at `p * p`, because a smaller multiple `p * k` with `k < p` has a smaller prime factor and was already crossed out. And once `p * p > n`, no new composite can appear, so the loop can stop.

## How it works

<Steps>
  <Step title="Mark everything prime">
    Create `n + 1` flags, all true, and set the flags of 0 and 1 to false.
  </Step>
  <Step title="Walk i up to the square root">
    For `i = 2, 3, ...` while `i * i <= n`, look at the flag of `i`.
  </Step>
  <Step title="Cross out the multiples">
    If `i` is still marked prime, set the flags of `i*i, i*i + i, i*i + 2i, ...` up to `n` to false.
  </Step>
  <Step title="Read off the primes">
    Every index whose flag is still true is prime.
  </Step>
</Steps>

<Callout title="Invariant">
When the outer loop reaches `i`, every composite with a prime factor smaller than `i` is already crossed out. So `i` is prime exactly when its flag is still true, and no divisibility test is needed.
</Callout>

## Pseudocode

```text
sieve(n):
    if n < 2: return []
    isPrime = array of n + 1 trues
    isPrime[0] = isPrime[1] = false
    for i = 2 while i * i <= n:
        if isPrime[i]:
            for j = i * i; j <= n; j = j + i:
                isPrime[j] = false
    return [i for i in 2..n if isPrime[i]]

isPrimeSieve(k, sieve):
    if 0 <= k < length(sieve): return sieve[k]
    return false                      # negative, or never sieved
```

## Implementation

All three languages have the same three functions: the list of primes, the flag array and a lookup. The lookup returns false for a negative number, which would otherwise wrap around to the end of a Python list or read out of bounds in C++, and false beyond the end of the sieve. A negative limit gives an empty result instead of an exception or a panic. The C++ version uses `long long` loop counters because `i * i` and `j += i` overflow an `int` for `n` near 2^31 - 1.

## Complexity

A prime `p` causes about `n / p` crossings. Summing over the primes up to `sqrt(n)` gives `n` times the sum of `1 / p`, and that sum grows like `log log n`.

<Equation label="Total work" expr="sum over primes p <= sqrt(n) of (n / p)  ~  n * log(log(n))" result="O(n log log n)" />

Memory differs by language: a Python list holds a pointer (8 bytes) per number, a Go slice of bool 1 byte, and a C++ `vector<bool>` 1 bit, so a sieve up to `2^31 - 1` fits in 256 MB in C++.

## Applications

- **Prime counting and listing.** Number of primes up to `n`, the `k`-th prime, prime gaps.
- **Factorization.** With a smallest-prime-factor table, any number up to `n` factors in `O(log n)`.
- **Number-theoretic tables.** Euler's totient and divisor sums for all numbers up to a limit.
- **Building blocks.** Choosing prime moduli or checking the small primes before Miller-Rabin.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Negative indexes.** In Python `sieve[-1]` wraps around to the last element; in C++ it reads out of bounds. Check `k >= 0` before the lookup.
- **Overflowing `i * i`.** With 32-bit `int`, `i * i` and `j += i` overflow when `n` is near 2^31 - 1. Use 64-bit counters or the test `i <= n / i`.
- **Wrong start or stop.** Starting at `2 * i` still works but doubles the work; running the outer loop to `n` wastes time.
- **Forgetting 0 and 1.** Neither is prime, so set their flags to false before sieving.
- **Looking beyond the sieve.** A number larger than the limit was never sieved; the lookup returns false for it, which is not a statement about primality.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does the inner loop start at i * i?">
    Every smaller multiple `i * k` with `k < i` has a prime factor below `i`, so an earlier iteration already crossed it out. Starting at `i * i` skips that repeated work.
  </FaqItem>
  <FaqItem question="Why can the outer loop stop at the square root of n?">
    If a composite `m <= n` had all its prime factors above `sqrt(n)`, then `m` would be larger than `n`. So every composite has a prime factor at most `sqrt(n)`, and all of them have been crossed out by then.
  </FaqItem>
  <FaqItem question="Is the sieve really faster than checking each number?">
    Yes. Trial division costs about `sqrt(k)` per number `k`, so `O(n sqrt n)` overall, against `O(n log log n)` for the sieve.
  </FaqItem>
  <FaqItem question="What if I only need one large number?">
    Use Miller-Rabin instead. The sieve builds a table for every number up to `n`, which is wasteful and impossible beyond a few billion.
  </FaqItem>
</Faq>
