## When to use it

Look for these signals in a problem statement:

- **A small number of items** (n up to about 20 to 25) and the answer depends on which subset was chosen, visited or used.
- **A DP state is a set:** "visited cities", "used items", "which people already got a task".
- **Set operations in a hot loop:** membership, union, intersection, difference, counting elements.
- **Subsets of subsets,** such as splitting a set into two parts, or summing a value over all subsets of each mask.

If n is 40 or more, enumerating 2<sup>n</sup> subsets is out of reach; consider meet in the middle instead.

## How it works

Number the items 0 to n-1. A set is the integer whose bit i is 1 exactly when item i is in the set.

<Steps>
  <Step title="Encode the set">
    `mask = (1 << i) | (1 << j)` is the set `{i, j}`. The empty set is 0 and the full set is `(1 << n) - 1`.
  </Step>
  <Step title="Use bit operations as set operations">
    Test `(mask >> i) & 1`, add `mask | (1 << i)`, remove `mask & ~(1 << i)`, toggle `mask ^ (1 << i)`. Union is `a | b`, intersection `a & b`, size is a popcount.
  </Step>
  <Step title="Enumerate">
    Loop `mask` from 0 to 2<sup>n</sup> - 1 for all subsets, `sub = (sub - 1) & mask` for the submasks of one mask, and Gosper's hack for the masks with exactly k bits.
  </Step>
  <Step title="Use the mask as a DP index">
    A table `dp[mask]` or `dp[mask][last]` holds the best value for that set. Process masks in increasing numeric order: every submask is smaller than its mask, so transitions that add an element always go to a larger mask.
  </Step>
</Steps>

<Callout title="Why the submask loop visits every submask once">
`(sub - 1) & mask` subtracts one, which flips the lowest set bit and sets all the bits below it, then removes every bit that is not in `mask`. The result is the next smaller submask. Starting from `mask` it reaches 0 after 2<sup>popcount(mask)</sup> steps. Summed over all masks this is 3<sup>n</sup>, because each element is either outside the mask, inside the mask but outside the submask, or inside both.
</Callout>

## Template

```text
# basic operations
get(mask, i)      = (mask >> i) & 1
set(mask, i)      = mask | (1 << i)
clear(mask, i)    = mask & ~(1 << i)
toggle(mask, i)   = mask ^ (1 << i)
lowest(mask)      = mask & -mask
dropLowest(mask)  = mask & (mask - 1)

# all submasks of mask, including 0
sub = mask
loop:
    use(sub)
    if sub == 0: break
    sub = (sub - 1) & mask

# all masks with exactly k bits among n (k >= 1), Gosper's hack
mask = (1 << k) - 1
while mask < (1 << n):
    use(mask)
    c = mask & -mask
    r = mask + c
    mask = (((r ^ mask) >> 2) / c) | r

# TSP: dp[mask][last] = shortest path from city 0 through the cities in mask, ending at last
dp[1][0] = 0
for mask in 1 .. 2^n - 1:
    for last in mask: for next not in mask:
        dp[mask | (1 << next)][next] = min(that, dp[mask][last] + dist[last][next])
answer = min over last >= 1 of dp[full][last] + dist[last][0]
```

## Implementation

The Python, C++ and Go files share the basic operations, subset enumeration, a TSP DP, subset-sum counting, power-of-two helpers and SOS DP (sum over subsets); the exact function sets differ.

- Python also has `log2_floor`, `log2_ceil` and a meet-in-the-middle subset-sum check; C++ also has `trailingZeros`, `leadingZeros`, an `absNoBranch` trick and a `BitSet` class for more than 64 items; Go has `SOSDP` and `NextPowerOf2`.
- `next_power_of_2` uses `bit_length` in Python and `bits.Len` in Go, so it is correct beyond 32 bits. The C++ version uses the shift-or ladder on a 32-bit `int`, so it is valid up to 2<sup>30</sup>.
- `tsp` returns 0 for zero or one city in all three languages.
- `subsets_of_size_k(n, 0)` yields only the empty mask: Gosper's hack divides by the lowest set bit, which does not exist for 0.
- `sos_dp` accepts any length: missing entries count as absent.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Shift by the width or more.** In C++, `1 << 31` overflows a 32-bit `int` (Go's `int` is 64 bits on common platforms), and shifting by 32 or more is undefined in C++. Use `1LL << i` or `uint64_t`.
- **Precedence.** In C and C++, `mask & bit == 0` parses as `mask & (bit == 0)`. Write `(mask & bit) == 0`; Python and Go bind the other way, but the parentheses are always safe.
- **Loop condition `sub > 0`.** It skips the empty submask. Use the explicit break shown in the template if the empty set matters.
- **Wrong range.** All subsets are `0` to `(1 << n) - 1`, not `1 << n`.
- **Counting trailing or leading zeros of 0.** `__builtin_ctz(0)` and `__builtin_clz(0)` are undefined; the C++ helpers here return 32.
- **Signed right shift.** `n >> 31` on a negative `int` is implementation-defined before C++20; the `absNoBranch` trick relies on it and fails for the minimum `int`.
- **Too many items.** 2<sup>25</sup> states of 4 bytes each is 128 MB; check the memory limit before choosing a DP over masks.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is enumerating submasks of all masks O(3^n) and not 4^n?">
    For each element there are three cases: not in the mask, in the mask but not in the submask, in both. That gives 3<sup>n</sup> pairs of (mask, submask), while 4<sup>n</sup> would count the impossible case of being in the submask but not the mask.
  </FaqItem>
  <FaqItem question="Why does Gosper's hack work?">
    It finds the next larger number with the same popcount. `c` is the lowest set bit; adding it to `mask` carries through the lowest block of ones and gives `r`. The ones that the carry cleared are then moved back to the bottom with `((r ^ mask) >> 2) / c`, and OR-ing them into `r` restores the popcount.
  </FaqItem>
  <FaqItem question="How large can n be?">
    A DP over masks needs 2<sup>n</sup> entries times the number of other state dimensions. Around n = 20 is comfortable, 25 is tight, and beyond that you need a different idea.
  </FaqItem>
  <FaqItem question="What is the difference between this topic and Bit Manipulation?">
    Bit Manipulation is about tricks on single numbers (parity, XOR pairing, single-bit counting). Bitmasking is about representing a set as a number and using it for enumeration and DP.
  </FaqItem>
</Faq>
