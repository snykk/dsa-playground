## What a deque is

A queue adds at one end and removes at the other. A stack adds and removes at the same end. A deque allows all four moves: push or pop at the front, push or pop at the back. Using only the back gives a stack, and using the back to push and the front to pop gives a queue.

The repository stores the items in a growable array: a Python `list`, a C++ `std::vector<int>` and a Go `[]int` slice. The front of the deque is index 0 and the back is the last index.

<Callout title="The array makes one end expensive">
Growable arrays are built for changes at the end. Anything at index 0 forces the other items to move, so the front operations cost O(n) in Python and C++, and `push_front` costs O(n) in Go as well.
</Callout>

Python and C++ use snake_case names; Go uses `PushFront`, `PopBack` and so on. Popping or peeking an empty deque raises `IndexError` in Python, throws `std::runtime_error` in C++ and returns an error in Go. Python also has `display()`, which returns a copy of the items as a list.

### Push at the front

Pushing `3` to the front of `[1, 2]` must open slot 0, so every existing item moves one place to the right:

In Go, `append([]int{item}, dq.deque...)` builds a brand new slice, which also copies all n items.

### Pop at the front

Python's `list.pop(0)` and C++ `vector::erase(begin())` shift every remaining item left by one. Go's `PopFront` just reslices with `dq.deque[1:]`, which moves nothing, so it is O(1). The skipped slot stays in the backing array until a later `append` reallocates it.

## Design choices

The repository's array version is the simplest design. Two others give O(1) at both ends:

<DataTable
  columns={['Design', 'Both ends', 'Trade-off']}
  highlight={0}
  rows={[
    ['Array (this repository)', 'back O(1), front O(n)', 'simplest and cache-friendly, but the front is slow'],
    ['Ring buffer that grows', 'O(1) amortized', 'indices wrap around, and the array doubles when full (see Circular Queue)'],
    ['Doubly linked list', 'O(1)', 'a node and two pointers per item, poor cache behaviour'],
  ]}
/>

A growable ring buffer keeps `front` and `size`, pushes at the front by moving `front` back one slot with wrap-around, and copies the items in order into a bigger array when it is full. Java's `ArrayDeque` is built this way. Python's `collections.deque` and C++ `std::deque` store items in blocks instead, and both give O(1) at both ends.

## Implementation

All three versions share the same API. Because they wrap a plain array, they are honest about the cost: the front operations really do shift items.

## Applications

- **Sliding window maximum or minimum:** a deque of candidate indices drops stale items from the front and dominated ones from the back (see the Monotonic Queue article).
- **Palindrome check:** compare the front and back item, pop both, repeat.
- **Undo history with a limit:** push new actions at the back and drop the oldest at the front.
- **0-1 BFS:** push zero-cost edges at the front and unit-cost edges at the back of the frontier.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Assuming both ends are O(1).** In this repository's array versions the front is O(n). Loops that call `push_front` or `pop_front` n times cost O(n<sup>2</sup>).
- **Popping from an empty deque.** Check `is_empty()` first, or handle the exception or error.
- **Mixing up which end is which.** Here the front is index 0 and the back is the last index.
- **Using a deque where a stack suffices.** If only one end is used, the simpler structure is clearer.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is a deque a queue or a stack?">
    Both. Pushing and popping at the back behaves as a stack. Pushing at the back and popping at the front behaves as a queue.
  </FaqItem>
  <FaqItem question="Why is the front slow in this implementation?">
    The items live in an array with the front at index 0. Opening or closing slot 0 moves all other items. A ring buffer avoids this by moving a `front` index instead of the items.
  </FaqItem>
  <FaqItem question="Should I use my own deque in real code?">
    Rarely. Python has `collections.deque`, C++ has `std::deque`, and Go programs usually use a slice or a ring buffer. The implementations here are for learning.
  </FaqItem>
  <FaqItem question="Why is Go's pop_front O(1) but push_front O(n)?">
    Dropping the first element is just `slice[1:]`, a new view of the same array. Inserting before the first element needs space that does not exist, so Go allocates a new slice and copies.
  </FaqItem>
</Faq>
