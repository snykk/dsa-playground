## What a priority queue is

A priority queue is an abstract data type: a collection where each item carries a priority and `dequeue` always returns the item with the best one. A simple queue answers "who came first?". A priority queue answers "who matters most?".

This repository's priority queue treats a **lower number as a higher priority**, so `dequeue` returns the smallest priority value. To get the largest first, negate the priority when you enqueue.

The structure behind the interface is a binary min heap stored in an array. The Min Heap article explains the heap itself (sift up, sift down, the index formulas). Here the focus is the interface and the tie rule.

Every entry stores three things: the priority, an insertion counter and the item. The heap orders entries by `(priority, counter)`. Since the counter is unique and always grows, no two entries compare equal.

Dequeue and peek on an empty queue raise `IndexError` in Python, throw `std::runtime_error` in C++ and return an error in Go. In C++ and Go the item and the priority are `int`. Python stores any object as the item, and the priorities only need to be comparable with each other.

### Enqueue: sift up

The new entry goes at the end of the array and swaps with its parent while it is smaller. The comparison is on `(priority, counter)`. Enqueueing `review` (priority 1, counter 4) into a heap of four entries:

### Dequeue: sift down

The root is the answer. The last entry replaces it and sinks, swapping with the smaller child. Dequeuing from the five-entry heap above returns `fix bug`:

This is what the C++ `heapify_down` does. Python's `heapq` reaches the same array by another route: it moves the smaller child up at every level without comparing the sinking entry, so `3 #0` moves up too and `2 #3` lands in the leaf at index 3. Only then is `2 #3` compared with its parents: it swaps back up to index 1 and stops under `1 #4`. The animation above shows this route.

Dequeuing everything from this queue gives `fix bug`, `review`, `deploy`, `write report`, `email`.

## Pseudocode

```text
enqueue(item, priority):
    entry = (priority, counter, item)
    counter = counter + 1
    heap.append(entry)
    siftUp(last index)            # swap with parent while entry < parent

dequeue():
    if heap is empty: error
    top = heap[0]
    heap[0] = heap.last
    remove heap.last
    siftDown(0)                   # swap with the smaller child while larger
    return top.item
```

Python uses `heapq` for the sift steps, with the tuple `(priority, counter, item)`. C++ implements `heapify_up` and `heapify_down` by hand over a `std::vector`. Go uses `container/heap` with a `Less` that compares priority and then counter.

## Implementation

The three versions expose the same `enqueue`, `dequeue`, `peek`, `is_empty`, `size` and `clear`. In Go, the exported `PriorityQueue` type is the raw heap slice and `PriorityQueueWrapper` is the API to use. The C++ tie-break counter is a 64-bit unsigned integer.

Space is O(n) for the entries. The tie-break counter adds one integer per entry.

## Applications

- **Task and event scheduling:** run the most urgent job next.
- **Dijkstra's algorithm and Prim's algorithm:** repeatedly take the closest or cheapest vertex.
- **Heap Sort** and **top-k** selection, which are built on the same heap.
- **Merging k sorted lists:** keep the current head of every list in the queue.
- **Simulations:** process events in time order, with ties handled in arrival order.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Assuming a bigger number means higher priority.** Here the smallest priority value leaves first. Negate priorities for a max priority queue: after enqueueing priorities -10, -5 and -1, the first `dequeue` returns the item with priority -10.
- **Expecting `dequeue` to return the priority.** It returns the item only.
- **Expecting sorted iteration.** Only the root is guaranteed to be the best entry.
- **Relying on tie order from a plain heap.** A bare heap is not stable. The counter is what keeps equal priorities in insertion order.
- **Dequeuing from an empty queue.** Check `is_empty()` first.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="How is a priority queue different from a heap?">
    A priority queue is the interface: enqueue with a priority, dequeue the best. A heap is one way to implement it. This repository uses a binary min heap.
  </FaqItem>
  <FaqItem question="What happens to items with the same priority?">
    They leave in the order they were enqueued. Each entry gets an increasing counter and the heap compares `(priority, counter)`.
  </FaqItem>
  <FaqItem question="How do I get a max priority queue?">
    Negate the priority on the way in, so a larger priority becomes a smaller number. The item you get back is unchanged.
  </FaqItem>
  <FaqItem question="Does clear() reset the tie-break counter?">
    Yes. All three versions reset it to 0, which is safe because the queue is empty.
  </FaqItem>
</Faq>
