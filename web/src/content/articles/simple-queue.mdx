## What a queue is

A queue is a line. New items join at the **back** (`enqueue`) and the item at the **front** leaves first (`dequeue`). Nothing in the middle can be touched. This first-in, first-out (FIFO) rule is what makes queues the natural tool for anything that must be handled in arrival order.

The repository stores the items in a growable array: a Python `list`, a C++ `std::vector<int>` and a Go `[]int` slice. The front is index 0 and the back is the last index.

<Callout title="The invariant">
Items leave in exactly the order they arrived. `enqueue` only ever touches the back and `dequeue` and `peek` only ever touch the front, so no operation can reorder the line.
</Callout>

### Why dequeue costs O(n)

Python's `list.pop(0)` and C++ `vector::erase(begin())` close the gap at index 0 by moving every remaining item one slot to the left. With n items that is n - 1 moves.

<ArrayDiagram
  legend={{ m: 'removed item', l: 'item that has to move' }}
  rows={[
    { label: 'before', values: [10, 20, 30, 40], tones: 'mlll' },
    { label: 'after', values: [20, 30, 40], tones: 'lll', note: 'Three moves to remove one item. A queue of 100000 items would need 99999.' },
  ]}
/>

Go's `Dequeue` instead reslices: `q.queue = q.queue[1:]`. That only moves the start of the slice view, so nothing is copied and the cost is O(1). The dropped slot stays in the backing array until a later `append` has to reallocate, and the new array then holds only the live items. The three versions behave the same, and only the cost differs.

## Pseudocode

```text
enqueue(x):
    items.append(x)

dequeue():
    if items is empty: error
    x = items[0]
    remove items[0]          # shifts the rest in Python and C++, reslices in Go
    return x

peek():
    if items is empty: error
    return items[0]
```

## Implementation

All three versions are a thin wrapper around the built-in growable array. The Go version is the odd one out because of the reslice.

Enqueue is amortized O(1) because an append occasionally reallocates the array and copies it, and growing the capacity geometrically makes the average cost per append constant. Draining a queue of n items one by one costs O(n<sup>2</sup>) in Python and C++ but O(n) in Go.

## Applications

- **Breadth-first search:** the frontier is a queue, so vertices are explored level by level.
- **Task and request handling** in arrival order, such as a print queue.
- **Buffers** between a producer and a consumer.
- **Simulations** that process events in the order they were created.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Assuming dequeue is O(1).** In Python and C++ here it shifts every item. Draining a large queue is quadratic. For real work use `collections.deque` or `std::queue`, or the Circular Queue.
- **Dequeueing or peeking an empty queue.** Check `is_empty()` first, or handle the exception or error.
- **Using a stack by accident.** Removing from the back (`pop()`) gives LIFO, not FIFO.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What does FIFO mean?">
    First in, first out. The item that has been in the queue the longest is the next one removed.
  </FaqItem>
  <FaqItem question="Why is Go's dequeue faster than Python's here?">
    Go reslices (`queue[1:]`) and moves no data, while Python's `pop(0)` and C++ `erase(begin())` shift every remaining item. The results are identical, only the cost differs.
  </FaqItem>
  <FaqItem question="How do I get an O(1) dequeue?">
    Keep a head index instead of shifting, use a circular array, or use a linked list with head and tail pointers. In practice use `collections.deque` in Python or `std::queue` in C++.
  </FaqItem>
  <FaqItem question="What is the difference between peek and dequeue?">
    Peek returns the front item and leaves it in the queue. Dequeue returns it and removes it.
  </FaqItem>
</Faq>
