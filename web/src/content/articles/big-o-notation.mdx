## Definition

Big-O is a relation between two functions of `n`. Here `f(n)` is usually a running time (steps as a function of input size) and `g(n)` is a simple comparison function such as `n` or `n log n`.

<Equation label="Big-O" expr="f(n) = O(g(n))  if there are constants c > 0 and n0 such that  0 <= f(n) <= c * g(n)  for all n >= n0" />

In words: from some point `n0` on, `f` stays below a constant multiple of `g`. The constants `c` and `n0` only need to exist; you choose them.

<Callout title="The equals sign is misleading">
`f(n) = O(g(n))` really means "f is in the set O(g)", the set of all functions bounded above by a multiple of `g`. That is why `n = O(n^2)` is true and `O(n^2) = n` is nonsense. Every function in that set is a valid upper bound, so many different `g` work for the same `f`.
</Callout>

## Intuition

Big-O keeps only the part of a formula that dominates when `n` is large.

- **Drop constants.** `5n` and `n` grow the same way: `O(5n) = O(n)`. Constants depend on the machine and the language, not on the algorithm.
- **Drop lower-order terms.** `n^2 + 100n` is `O(n^2)`: for large `n` the `n^2` term wins.
- **It is an upper bound only.** `3n + 1` is `O(n)`, and also `O(n^2)` and `O(2^n)`, because those functions all stay above it. The statement is true but not informative. To say that the bound is tight you use Big-Theta.

## Worked examples

### Proving a bound with c and n0

Claim: `f(n) = 3n^2 + 5n + 2` is `O(n^2)`. For `n >= 1`, `5n <= 5n^2` and `2 <= 2n^2`, so

<Equation label="Proof" expr="3n^2 + 5n + 2 <= 3n^2 + 5n^2 + 2n^2 = 10 n^2  for n >= 1" result="c = 10, n0 = 1" />

### Disproving a bound

Is `n^2 = O(n)`? That would need `n^2 <= c * n`, which means `n <= c` for all `n >= n0`. No constant `c` works, because `n` grows without limit. So `n^2` is not `O(n)`.

## Using it in practice

Big-O is a statement about **a function**. To use it on an algorithm you first choose which function you are bounding, and that choice is the case:

- the running time on the **best** input of size `n`,
- on the **worst** input of size `n`, or
- the **average** over a distribution of inputs.

Each of those is a different function of `n`, and any of the three can be bounded with O, Omega or Theta. For linear search:

<DataTable
  columns={['Function being bounded', 'Big-O statement', 'Also true']}
  rows={[
    ['best case (target is first)', 'O(1)', 'Theta(1)'],
    ['worst case (target absent)', 'O(n)', 'Theta(n)'],
    ['average case (target equally likely anywhere)', 'O(n)', 'Theta(n)'],
    ['"the running time on any input"', 'O(n)', 'Omega(1)'],
  ]}
/>

So "the worst case of Quick Sort is O(n^2)" is a statement about the worst-case function. "Quick Sort's average case is also O(n log n)" bounds a different function with the same notation. Writing "O(n) = best case" or "O(n^2) = worst case" confuses the notation with the case.

Practical rules:

- **Sequential steps add:** `O(f) + O(g) = O(max(f, g))`.
- **Nested steps multiply:** a loop of `n` with `O(m)` work inside is `O(n * m)`.
- **Several inputs need several variables:** graph search is `O(V + E)`, not `O(n)`.
- **Be honest about size:** for numbers, `n` may be the value, not the bit length.
- **Pick the tightest bound you can prove.** Saying `O(n!)` for a linear algorithm is true but useless.

## Implementation

All three languages implement the same ladder of examples: constant, logarithmic, linear, linearithmic, quadratic, cubic and exponential. Python also has the factorial example. Honest labels for the code:

- **Linearithmic.** Python implements a real merge sort. C++ and Go call the library sort (`std::sort`, `sort.Ints`), which is O(n log n) in the worst case, and for Go about O(n) on already sorted input.
- **Exponential.** The Fibonacci example is O(2<sup>n</sup>), which is valid but loose: its exact growth is about 1.618<sup>n</sup>.
- **Factorial** (Python only). It builds all n! permutations by slicing, which costs n times n! steps. That is O(n * n!), not O(n!).

## Common misconceptions

<Callout tone="warning" title="Watch out for these">
- **"O means worst case."** O is an upper bound on a function. The best, average and worst case are different functions, and each can be bounded with O, Omega or Theta.
- **"O(n) is always faster than O(n^2)."** Only for large `n`. For small `n` constants dominate: `100n` is bigger than `n^2` until `n = 100`.
- **"O(g) is a precise statement."** `n = O(n^2)` is true. Use Theta when you mean a tight bound.
- **"The log base matters."** It does not: `log2 n = (1 / log10 2) * log10 n`, a constant factor. Write `O(log n)`.
- **"Constants never matter."** They are hidden by the notation, not absent. Two `O(n)` algorithms can differ by a factor of 100.
- **Wrong variable.** Graph algorithms depend on both `V` and `E`; writing a single `n` hides that.
- **Mislabeled examples.** Building all permutations is `O(n * n!)`, because each permutation costs `O(n)` to write down.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is Big-O the worst case?">
    No. Big-O bounds a function from above. Worst case is a choice of which function to analyse (the slowest input of each size). You can state the worst case with O, with Omega or with Theta, and you can bound the best or average case with O too.
  </FaqItem>
  <FaqItem question="How do I pick c and n0?">
    Any pair that makes the inequality hold for all `n >= n0` is enough. Bound each term by a multiple of the dominant term (`5n <= 5n^2` for `n >= 1`), add the multiples to get `c`, and take `n0` where the inequalities start to hold.
  </FaqItem>
  <FaqItem question="Why is log n the same for any base?">
    Changing the base multiplies by a constant: `log_a n = log_b n / log_b a`. Constants are absorbed by `c`.
  </FaqItem>
  <FaqItem question="What is the difference between O(n) and Theta(n)?">
    `f = O(n)` says `f` is at most linear. `f = Theta(n)` says `f` is both at most and at least linear, so linear is its exact growth rate. See the Big-Theta article.
  </FaqItem>
</Faq>
