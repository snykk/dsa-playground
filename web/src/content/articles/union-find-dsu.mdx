## How Union-Find works on graphs

Each set of connected vertices is stored as a tree. `parent[x]` points towards the root, and the root, which points to itself, names the whole set. Two vertices are connected exactly when `find` returns the same root for both.

<Steps>
  <Step title="Start with singletons">
    `parent[i] = i` and `rank[i] = 0` for every vertex. The count of sets is `n`.
  </Step>
  <Step title="find with path compression">
    Follow parent pointers up to the root, then point every vertex on the way directly at the root. The next search from any of them is one step.
  </Step>
  <Step title="union by rank">
    Find both roots. If they are equal, the vertices are already connected: return false. Otherwise hang the root of lower rank under the other. Only when the ranks tie does the surviving root's rank grow by one.
  </Step>
  <Step title="Feed it the edges">
    Process the edges one by one. A `union` that returns true merged two components; one that returns false is an edge between vertices that were already connected.
  </Step>
</Steps>

<Callout title="Rank is a height bound, not a size">
The rank of a root is an upper bound on the height of its tree. A tree of rank `r` always contains at least 2<sup>r</sup> vertices, so with union by rank no tree is taller than log<sub>2</sub>(n). Path compression flattens trees but never lowers the stored rank, so it stays an upper bound. Attaching the smaller tree by vertex count is a different rule, union by size, which gives the same bounds.
</Callout>

Now `find(7)` climbs 7, 6, 4, 0 and then points 7 and 6 straight at the root (vertex 4 already pointed there). The parent array becomes `[0, 0, 0, 2, 0, 4, 0, 0]`. Calling `find(7)` again takes one step. A final `union(3, 7)` returns false because both already share the root 0.

## Pseudocode

```text
find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])           # path compression
    return parent[x]

union(x, y):
    rx = find(x); ry = find(y)
    if rx == ry: return false                  # same set: this edge closes a cycle
    if rank[rx] < rank[ry]: parent[rx] = ry
    elif rank[rx] > rank[ry]: parent[ry] = rx
    else: parent[ry] = rx; rank[rx] += 1       # only a tie raises the rank
    count -= 1
    return true
```

## Implementation

The core structure has the same operations everywhere, but the union method has a different name in each language: `union` in Python, `unite` in C++ (because `union` is a keyword) and `Union` in Go. Python and Go also expose the set count as `get_count()` and `GetCount()`, C++ as `getCount()`.

Python adds graph helpers on top: `union_find_connected_components(edges, n)`, `union_find_cycle_detection(edges, n)`, `union_find_largest_component(edges, n)` and `union_find_kruskal_mst(edges, n)`, plus `get_components()`. C++ and Go have only the cycle-detection helper (`unionFindCycleDetection`, `UnionFindCycleDetection`). A self-loop or a repeated edge counts as a cycle in all of them.

`find` is recursive in all three languages. That is safe here: union by rank keeps every tree at most log<sub>2</sub>(n) high, and the tests merge a chain of 10<sup>5</sup> (Python) or 10<sup>6</sup> (C++, Go) vertices without trouble. Nothing checks that an element is in `0 .. n-1`: in Python a negative id silently wraps around (so `union(-1, 0)` merges the last element), an id of `n` or more raises `IndexError`, C++ has undefined behaviour and Go panics.

Without union by rank, compression alone gives O(log n) amortized. With neither, a chain makes `find` linear.

## Applications

- **Connected components and their sizes.** Union every edge, then group by root (`get_components`) or keep the largest.
- **Cycle detection in undirected graphs.** Adding an edge between two vertices that share a root closes a cycle. LeetCode 684, Redundant Connection, asks exactly this.
- **Kruskal's minimum spanning tree.** Sort edges by weight and keep each edge whose union succeeds (see the Kruskal article).
- **Merging accounts or friends.** LeetCode 547 (Number of Provinces) and LeetCode 721 (Accounts Merge) are union-find problems.
- **Offline connectivity as roads are built.** CSES Road Construction asks for the number of components and the largest size after each new road.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Linking non-roots.** Always call `find` on both vertices first. Setting `parent[x] = y` directly can detach whole subtrees.
- **Comparing `parent` values.** Two vertices are connected when `find` agrees, not when `parent` agrees; the parent can be stale until the next find.
- **Calling "union by rank" a size rule.** Rank bounds height. Attaching by vertex count is union by size.
- **Skipping union by rank in a recursive find.** A long chain would make the recursion deep.
- **Unchecked ids.** A negative id in Python wraps silently, and an id `>= n` crashes or misbehaves in the other languages. Validate input if it is not trusted.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What is alpha(n)?">
    The inverse of the Ackermann function. It grows so slowly that it stays below 5 for every input that fits in memory, so each operation is constant for all practical purposes. The exact bound needs both path compression and union by rank.
  </FaqItem>
  <FaqItem question="Does path compression change the rank?">
    No. After compression the stored rank can overestimate the true height, but it remains an upper bound, which is all the analysis needs.
  </FaqItem>
  <FaqItem question="Can Union-Find undo a union?">
    Not with path compression. A rollback variant exists that skips compression and records each change, at the cost of O(log n) per operation.
  </FaqItem>
  <FaqItem question="How is this different from the data structure article?">
    The data structure article explains the structure itself. This page looks at it as a graph tool: components, cycle detection and Kruskal, using the helpers in this folder.
  </FaqItem>
