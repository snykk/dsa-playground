## How LCS works

A **subsequence** keeps the order of the characters but may skip some: `ace` is a subsequence of `abcde`, but a **substring** must be contiguous. A string of length `m` has 2<sup>m</sup> subsequences, so comparing them all is hopeless. Instead, let `dp[i][j]` be the LCS length of the first `i` characters of `s1` and the first `j` characters of `s2`.

<Steps>
  <Step title="Start with empty prefixes">
    `dp[0][j] = 0` and `dp[i][0] = 0`: an empty string shares nothing with anything.
  </Step>
  <Step title="If the last characters match, extend">
    When `s1[i-1] == s2[j-1]`, that character can end a common subsequence of the two prefixes: `dp[i][j] = dp[i-1][j-1] + 1`.
  </Step>
  <Step title="Otherwise skip one character">
    The last characters cannot both be used, so drop one of them and keep the better result: `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`.
  </Step>
  <Step title="Read the corner">
    The LCS length is `dp[m][n]`. To get one LCS, walk back from the corner.
  </Step>
</Steps>

<Callout title="Why a match can be taken greedily">
If the last characters of both prefixes are equal, some longest common subsequence ends with that character. Take it and look at the remaining prefixes. Using the match is never worse than skipping both characters, so the recurrence never has to branch on a match.
</Callout>

## Worked example

Find an LCS of `ABCBDAB` and `BDCAB`. The numbers below come from running `lcs_length` and `lcs_sequence` on this pair.

The length is `dp[7][5] = 4`. The traceback starts at the corner and repeats:

- if the characters match, record the character and move diagonally;
- else if the cell above is strictly larger than the cell on the left, move up;
- else move left (this is the tie rule of `lcs_sequence`).

It meets matches at `B` (row 7), `A` (row 6), `D` (row 5) and `B` (row 4), and returns `BDAB` after reversing. `BCAB` is another LCS of the same length, so the answer is not unique: a different tie rule would return a different one.

## Pseudocode

```text
lcsLength(s1, s2):
    dp = (m + 1) x (n + 1) table of zeros
    for i = 1 to m:
        for j = 1 to n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]

lcsSequence(s1, s2):                  # Python only
    fill dp as above
    i = m; j = n; result = []
    while i > 0 and j > 0:
        if s1[i-1] == s2[j-1]:
            append s1[i-1]; i = i - 1; j = j - 1
        elif dp[i-1][j] > dp[i][j-1]:
            i = i - 1
        else:
            j = j - 1
    return reverse(result)

lcsOptimized(s1, s2):                 # Python only: two rows
    make s2 the shorter string
    keep prev and curr rows of n + 1 zeros, fill them row by row, swap them
    return prev[n]
```

## Implementation

Python has three functions: `lcs_length`, `lcs_sequence` (with traceback) and `lcs_optimized` (two rows, length only). C++ and Go have only the length (`lcsLength`, `LCSLength`). Python compares Unicode code points; C++ and Go compare bytes, so an accented letter that takes two bytes in UTF-8 is two characters there.

## Complexity analysis

<ComplexityTable
  rows={[
    { case: 'Time', time: 'O(m n)', when: 'Each of the (m + 1)(n + 1) cells is computed once from one or two neighbors. The traceback adds O(m + n).' },
    { case: 'Space (table)', time: 'O(m n)', space: 'O(m n)', when: 'Needed to recover the sequence in this code.' },
    { case: 'Space (two rows)', time: 'O(m n)', space: 'O(min(m, n))', when: 'Row i depends only on row i-1; lcs_optimized keeps two rows of the shorter length. It gives the length only.' },
  ]}
/>

Without the table, the recursion on a mismatch branches twice:

<Equation label="Plain recursion, worst case" expr="T(m, n) = T(m-1, n) + T(m, n-1) + O(1)" result="O(2^(m+n))" />

The same prefix pairs repeat, but there are only (m + 1)(n + 1) distinct ones, which is where the table bound comes from. Hirschberg's algorithm recovers the sequence in O(min(m, n)) space at about twice the time, but it is not in this repository.

LCS is the edit distance with only inserts and deletes: that distance equals `m + n - 2 * LCS`.

## Applications

- **File comparison.** Diff tools show the lines that are not in the common subsequence of two files.
- **Sequence similarity.** In bioinformatics, the LCS of two DNA strings is a simple similarity score.
- **Version control and merging.** Finding what two revisions share is an LCS-style problem.
- **Related problems.** Uncrossed Lines is the LCS in disguise, and the shortest common supersequence is built from the LCS.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Confusing subsequence and substring.** For a substring, a mismatch sets the cell to 0 and the answer is the largest cell.
- **Off-by-one on indices.** The table is one larger than the strings: compare `s1[i-1]` with `s2[j-1]` for `dp[i][j]`.
- **Using the two-row version for the sequence.** It forgets the earlier rows, so there is nothing to trace back.
- **Expecting a unique answer.** `BCAB` and `BDAB` are both correct for the worked example.
- **Bytes versus characters.** In C++ and Go a multi-byte character is compared byte by byte.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What is the difference between a subsequence and a substring?">
    A substring is a contiguous block (`ell` in `hello`). A subsequence only keeps the order (`hlo` in `hello`). Every substring is a subsequence, so the LCS is at least as long as the longest common substring.
  </FaqItem>
  <FaqItem question="How do I get the sequence, not just the length?">
    Keep the whole table and walk back from `dp[m][n]`: on a match, take the character and go diagonally; otherwise move toward the larger neighbor. `lcs_sequence` in Python does exactly this.
  </FaqItem>
  <FaqItem question="Why does the LCS code return different strings for different tie rules?">
    When the cell above and the cell on the left are equal, both directions lead to a common subsequence of the same length. Which one you follow only changes which LCS you get.
  </FaqItem>
  <FaqItem question="Can I do better than O(m n)?">
    For general strings, no strongly subquadratic algorithm is known. Bit-parallel versions pack the table into machine words and run about a word-size factor faster, and special cases (few matches, small alphabet) have faster algorithms.
  </FaqItem>
</Faq>
