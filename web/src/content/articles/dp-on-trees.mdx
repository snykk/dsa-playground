## When to use DP on trees

A tree has no cycles and exactly one path between two nodes, so the answer for a subtree depends only on the subtrees of its children. Use the pattern when:

- you must choose nodes or edges with a constraint between neighbours (no two adjacent, at most k per node);
- you want the best path, diameter or total of some quantity over a tree;
- the same question is asked for every subtree.

If the same structure were a general graph, the constraint would make the problem hard. On a tree, each subtree is independent of its siblings, which is what makes the DP exact.

## How it works

Root the tree and process it in post-order (children before their parent). For each node compute a small state from the children's states.

<Steps>
  <Step title="Define the state of a subtree">
    Write down what a subtree must report to its parent. For independent set it is a pair: the best sum if the node is taken (`include`) and if it is not (`exclude`). For a maximum path it is one number: the best sum of a chain going **down** from the node.
  </Step>
  <Step title="Solve the children first">
    A recursive DFS calls itself on each child and gets their states. Leaves are the base case.
  </Step>
  <Step title="Combine into the node's state">
    Apply the rule for the problem. This is the only problem-specific step.
  </Step>
  <Step title="Read the answer at the root">
    Often the answer is the root's state. For path problems the answer can be a node in the middle of the tree, so it is tracked in a variable that the DFS updates on the way.
  </Step>
</Steps>

<Callout title="Each child is visited exactly once">
The cost is linear only if the DFS loops over the children once and reuses what it got. Calling the recursion a second time for every child doubles the work at each level and makes the algorithm exponential. An earlier version of this repository's path function did exactly that.
</Callout>

## Example 1: maximum independent set

Choose nodes of maximum total value so that no two chosen nodes are connected by an edge. For each node `v` with children `c`:

<Equation label="Independent set" expr="include(v) = val(v) + sum of exclude(c);  exclude(v) = sum of max(include(c), exclude(c))" result="answer = max(include(root), exclude(root))" />

If `v` is taken, its children must be skipped. If `v` is skipped, each child is free to do whichever is better. Here is the tree with root 1, children 2 and 3, and node 2 having leaves 4 and 5. Each badge shows `(include, exclude)`.

The best set is `{3, 4, 5}` with sum 12: the root is skipped, node 2 is skipped (its children are better) and node 3 is taken. The repository returns 12 for this tree.

## Example 2: maximum path sum

Find the path with the largest value sum. A path may start and end at any node and uses each node once. Values may be negative, and a path has at least one node.

Let `chain(v)` be the best sum of a path that starts at `v` and goes **down**. A path whose highest node is `v` goes down through at most **two** children, so the best path through `v` is `val(v) + best1 + best2`, where those are the two largest positive child chains (0 if fewer or negative). The parent can only continue one of them, so `chain(v) = val(v) + best1`.

### Why two children, not all of them

A path is a line, so at a node it can use one chain coming in and one going out. In a star with center 1 and leaves 2, 3 and 4, the best path is 3, 1, 4 with sum 8, not 1 + 2 + 3 + 4 = 10. Summing every positive child, as an earlier version here did, counts nodes that cannot be on one path.

## Pseudocode

```text
maxIndependentSet(node):                     # returns (include, exclude)
    if node is null: return (0, 0)
    include = node.val
    exclude = 0
    for child in node.children:
        (ci, ce) = maxIndependentSet(child)
        include += ce
        exclude += max(ci, ce)
    return (include, exclude)
answer = max(maxIndependentSet(root))

maxPathSum(root):
    best = -infinity
    chain(node):                              # best downward chain from node
        if node is null: return 0
        best1 = 0; best2 = 0                  # two largest positive child chains
        for child in node.children:
            g = chain(child)
            if g > best1: best2 = best1; best1 = g
            else if g > best2: best2 = g
        best = max(best, node.val + best1 + best2)
        return node.val + best1
    chain(root)
    return best
```

## Applications

- Choosing non-adjacent items in a hierarchy, such as selecting employees with no direct manager pairs (independent set).
- Network design: maximum-value paths and diameters in tree-shaped networks.
- File-system or organisation trees: aggregates over every subtree such as sizes and counts.
- A building block for harder problems: heavy-light decomposition and centroid decomposition rely on the same bottom-up merging.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Taking every positive child in a path.** A path uses at most two child chains at a node: keep the two largest.
- **Recursing twice per child.** Store the result of the first call. A second call per child makes the time exponential.
- **Returning the through-node sum to the parent.** The parent can extend only a downward chain: return `val + best1`, and use `val + best1 + best2` only to update the answer.
- **Forgetting that a path needs one node.** If all values are negative the answer is the largest single value, not 0.
- **Ignoring recursion depth.** A chain of 5,000 nodes overflows Python's default recursion limit.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does the independent set need two values per node?">
    The best choice for a node depends on whether its parent is taken. A taken parent forces the child to be skipped, while a skipped parent leaves the child free. Keeping both answers lets the parent pick the compatible one.
  </FaqItem>
  <FaqItem question="Is the answer always at the root?">
    For independent set, yes. For path problems the best path may have its highest node anywhere, so the answer is the maximum over all nodes, tracked in a variable updated at each node.
  </FaqItem>
  <FaqItem question="What if the tree is given as an undirected edge list?">
    Pick any node as the root and pass the parent along the DFS, skipping it when you look at neighbours. The repository functions expect an already rooted `TreeNode` structure.
  </FaqItem>
  <FaqItem question="How do I avoid the recursion limit?">
    Compute a DFS order with an explicit stack, then process the nodes in reverse order, so every child is handled before its parent. The combine step does not change.
  </FaqItem>
</Faq>
