## How Linear Search works

Start at the first element and compare each one with the target in order. Return the index of the first match. If the end is reached with no match, return -1.

<Steps>
  <Step title="Start at index 0">
    The search looks at one element at a time and needs nothing else: no ordering, no random access.
  </Step>
  <Step title="Compare with the target">
    If `arr[i] == target`, return `i` immediately. The first match wins, so duplicates are not an issue.
  </Step>
  <Step title="Advance">
    Move to `i + 1` and repeat.
  </Step>
  <Step title="Report a miss">
    After the last element, return -1. All `n` elements were compared.
  </Step>
</Steps>

<Callout title="The invariant">
Before checking index `i`, the target is known to differ from `arr[0 .. i - 1]`. When the loop finishes, the target differs from every element, so -1 is correct.
</Callout>

## Pseudocode

```text
linearSearch(arr, target):
    for i = 0 to len(arr) - 1:
        if arr[i] == target:
            return i
    return -1

allOccurrences(arr, target):
    indices = []
    for i = 0 to len(arr) - 1:
        if arr[i] == target:
            indices.append(i)
    return indices
```

## Implementation

Each language has `linear_search`-style functions for the first match, a recursive form and all occurrences. There is no last-occurrence function: scan from the end, or take the last element of the all-occurrences result.

- **Python:** `linear_search`, `linear_search_recursive(arr, target, index=0)` and `linear_search_all_occurrences`. The recursive form raises `RecursionError` once it has to scan more than about a thousand elements (Python's default recursion limit), so treat it as a teaching example.
- **C++:** templates with instances for `int`, `double` and `std::string`. They return `int` indexes.
- **Go:** `LinearSearch` and `LinearSearchAllOccurrences` for `[]int`, `LinearSearchRecursive(arr, target, index)`, and the generic `LinearSearchGeneric[T comparable]`.

An empty input returns -1 (or an empty list of indexes) everywhere.

## Complexity analysis

<ComplexityTable
  rows={[
    { case: 'Best case', time: 'O(1)', when: 'The target is the first element: one comparison.' },
    { case: 'Average case', time: 'O(n)', when: 'If the target is present and every position is equally likely, (n + 1) / 2 comparisons.' },
    { case: 'Worst case', time: 'O(n)', when: 'The target is last or absent: n comparisons.' },
    { case: 'Space', time: 'O(1)', when: 'Iterative. The recursive version uses O(n) stack; the all-occurrences version stores the k matches.' },
  ]}
/>

For a present target at position `i` (1-indexed), the search makes `i` comparisons, so the average over `n` positions is `(1 + 2 + ... + n) / n = (n + 1) / 2`. Missing targets always cost `n`, so a workload with many misses is closer to the worst case.

Sorting first only pays off if you search often: `n` linear searches cost `O(n^2)`, while one sort plus `n` binary searches costs `O(n log n)`.

## Applications

- **Small collections**, where the constant factor beats any smarter method.
- **Unsorted or one-off data**, where sorting or building an index would cost more than one scan.
- **Linked lists and other sequential structures** with no random access.
- **Finding the first element that satisfies a predicate**, not only an equal value.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using it on large sorted data.** Binary Search does the same job in O(log n).
- **Recursing on long inputs.** The Python recursive version fails with `RecursionError` once it scans about a thousand elements.
- **Forgetting that it returns the first match only.** Use the all-occurrences function if you need every position.
- **Returning a valid index for a miss.** Return -1 (or another value that cannot be an index) and check it.
- **Comparing floating-point numbers with `==`.** Rounding can make equal values compare unequal; use a tolerance.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is Linear Search ever faster than Binary Search?">
    Yes, on small arrays and when the data is not sorted. Binary Search needs sorted data (an O(n log n) sort if it is not), and for tiny `n` the simple loop is as fast or faster.
  </FaqItem>
  <FaqItem question="What does the sentinel trick do?">
    You temporarily store the target in a slot after the last element. The loop can then drop its `i < n` test, since a match is guaranteed, and afterwards checks whether the match was the sentinel. It saves one comparison per step but needs a spare slot.
  </FaqItem>
  <FaqItem question="How many comparisons does it make on average?">
    If the target is present and every position is equally likely, `(n + 1) / 2`. If the target is absent, exactly `n`.
  </FaqItem>
  <FaqItem question="How do I find the last occurrence?">
    Scan from the end, or take the last element of the result of the all-occurrences function. This repository has no dedicated last-occurrence function.
  </FaqItem>
</Faq>
