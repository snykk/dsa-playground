## How it works

**Euler's totient** `phi(n)` is the number of integers `k` with `1 <= k <= n` and `gcd(k, n) = 1`. Of the numbers 1 to 12, only 1, 5, 7 and 11 share no factor with 12, so `phi(12) = 4`. Counting them one by one costs n gcds. The prime factorization gives the same number at once:

<Equation label="Product formula" expr="n = p1^k1 * ... * pr^kr  =>  phi(n) = n * (1 - 1/p1) * ... * (1 - 1/pr)" />

A fraction `1/p` of the numbers up to n are multiples of a prime `p` that divides n, and the primes act independently, so the fraction `(1 - 1/p)` survives each one. For 12 that is `12 * 1/2 * 2/3 = 4`. It is inclusion-exclusion over the primes of n.

<Steps>
  <Step title="Factor n by trial division">
    Try `p = 2, 3, 4, ...` while `p * p` is at most what is left of n, and divide each `p` out as often as it goes. A composite candidate never divides what is left, because its prime factors are already gone.
  </Step>
  <Step title="Keep the last prime">
    When the loop stops, what is left is 1 or a single prime above the square root. It counts as a factor too.
  </Step>
  <Step title="Apply the formula">
    Start with `result = n` and, for each distinct prime `p`, do `result -= result // p`. The division is exact, because `p` divides n and no earlier step removed it.
  </Step>
</Steps>

<Callout title="Every n, in O(n): the linear sieve">
Every composite m is `p * i` for exactly one pair in which p is its smallest prime factor, and then `p <= spf(i)`. So the sieve visits each `i` from 2 to n once, and crosses out `i * p` only for the primes `p` up to `spf(i)`. Each composite is crossed out exactly once, and `phi(i * p)` comes from `phi(i)` in O(1). The Sieve of Eratosthenes crosses 12 out twice, by 2 and by 3; the linear sieve crosses it out once, as 6 x 2. The same loop gives the smallest prime factor of every number, which the Precomputation topic uses to factorize any x up to n in O(log x).
</Callout>

## Pseudocode

```text
prime_factors(n):                         # ValueError for n < 1: phi(0) is undefined
    factors = []; p = 2
    while p <= n // p:                    # p * p <= n, without forming p * p
        k = 0
        while n % p == 0: n //= p; k += 1
        if k: factors.append((p, k))
        p += 1
    if n > 1: factors.append((n, 1))      # the one prime left above the root
    return factors

phi(n):
    result = n
    for p, _ in prime_factors(n): result -= result // p
    return result

linear_sieve(n):                          # ValueError for n < 0
    phi = [0] * (n + 1); spf = [0] * (n + 1); primes = []; crossings = 0
    if n >= 1: phi[1] = 1
    for i in 2 .. n:
        if spf[i] == 0: spf[i] = i; phi[i] = i - 1; primes.append(i)
        for p in primes:
            if p > spf[i] or p > n // i: break        # i * p > n
            spf[i * p] = p
            phi[i * p] = phi[i] * p if p == spf[i] else phi[i] * (p - 1)
            crossings += 1
    return phi, spf, primes, crossings

mod_inverse_euler(a, n):                  # ValueError if n < 1 or gcd(a, n) != 1
    r = a % n
    return pow(r, phi(n) - 1, n)          # 0 for n = 1
```

## Implementation

Every language provides the same operations with the same results:

- **`prime_factors`** (`primeFactors`, `PrimeFactors`) and **`phi`** (`phi`, `Phi`): trial division, primes in increasing order.
- **`linear_sieve`** (`linearSieve`, `LinearSieve`): the tables `phi` and `spf` for 0 to n, the primes, and the number of crossings, which equals the number of composites.
- **`mod_inverse_euler`** (`modInverseEuler`, `ModInverseEuler`): `a^(phi(n) - 1) mod n`. C++ and Go also export the modular product and power they need (`mulMod` and `powMod`, `MulMod` and `PowMod`); Python uses its built-in `pow`.

**64-bit limits.** C++ and Go take n as an unsigned 64-bit integer, so the largest n is 2<sup>64</sup> - 1. The loop test is written `p <= n / p`: `p * p` would wrap around to 0 once p reaches 2<sup>32</sup>. `phi(n)` is at most n and `result -= result / p` never grows, so the result cannot overflow either. The inverse multiplies two residues below n, which needs 128 bits: `unsigned __int128` in C++, `bits.Mul64` with `bits.Rem64` in Go. Python's integers have no limit. In the sieve, `i * p` reaches 2n, so the bound is written `p > n // i` there too, which keeps a C++ `int` from overflowing when n is above about 2<sup>30</sup>.

**Time at the limit.** A prime near 2<sup>64</sup> makes trial division try about 2<sup>32</sup> candidates: 8 seconds in C++ and in Go on the machine the numbers were measured on, and an estimated 15 to 25 minutes in Python. `phi(2^64 - 1) = 9,208,981,628,670,443,520` needs only 65,536 candidates, because 2<sup>64</sup> - 1 = 3 x 5 x 17 x 257 x 641 x 65537 x 6700417 has small factors.

**Errors.** `phi(0)` is undefined: n = 0 raises `ValueError` in Python (as does a negative n), throws `std::invalid_argument` in C++, and returns an error wrapping `ErrZero` in Go. A negative sieve limit raises `ValueError`, throws `std::invalid_argument`, or wraps `ErrNegativeLimit`; an `a` with `gcd(a, n) != 1` raises `ValueError`, throws `std::invalid_argument`, or wraps `ErrNotCoprime`.

**The same answers.** The C++ and Go tests pin 31 values of phi up to 2<sup>64</sup> - 1, 8 factorizations, 11 inverses and the tables of `linear_sieve(30)`, all computed by the Python code. Every language checks phi against a count of gcds up to 3000, the sieve against phi up to 5000, the divisor sum, Euler's theorem, and the inverse against an extended Euclid.

Counted with the Python code: trial division never tried more than `isqrt(n) - 1` candidates for any n up to 20,000, and `2^k` always tried one, because the bound shrinks with what is left. The linear sieve crossed out every composite exactly once for every limit tested up to 65,536. Up to 10<sup>6</sup> it made 921,501 crossings, one per composite, where the Sieve of Eratosthenes makes 2,122,048 writes. Python's `linear_sieve(10^7)` took 3.9 seconds.

## Applications

- **Counting coprime numbers and reduced fractions.** The fractions `k / d` in lowest terms with `0 < k <= d` are `phi(d)` of them.
- **Sums of gcds.** `gcd(a, b)` is the sum of `phi(d)` over the divisors d of the gcd, so a sum of gcds becomes a sum over d of `phi(d)` times a count of multiples.
- **Huge exponents.** `a^e mod n` with `e` itself huge: reduce `e` modulo `phi(n)` when `gcd(a, n) = 1`, modulo `p - 1` for a prime p.
- **RSA.** The private exponent is the inverse of the public one modulo `phi(pq) = (p - 1)(q - 1)`.
- **Cyclic structures.** The number of generators of a cyclic group of order n, and of primitive n-th roots of unity, is `phi(n)`.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **`p * p <= n` at 64 bits.** It wraps around for n near 2<sup>64</sup>; write `p <= n / p`.
- **`result * (p - 1) / p`.** The product overflows; take `result / p` first.
- **Forgetting the prime left over.** Without it, `phi(202)` comes out as 101 instead of 100.
- **The wrong factor in the sieve.** When p already divides i, `phi(i * p) = phi(i) * p`, not `phi(i) * (p - 1)`.
- **Dropping the `p > spf[i]` break.** The tables can still come out right, but composites are crossed out several times and the sieve is no longer linear.
- **Euler's theorem without the gcd.** `2^phi(4) = 4 = 0 (mod 4)`, not 1. Check `gcd(a, n) = 1` first.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What is phi(1), and what is phi(0)?">
    phi(1) is 1: the number 1 shares no factor with itself. phi(0) is undefined, so the code raises an error for it in every language; the sieve's table keeps 0 at index 0 only so that index i holds phi(i).
  </FaqItem>
  <FaqItem question="Why does the linear sieve stop at p = spf(i)?">
    For a larger prime p, the smaller prime spf(i) divides `i * p`, so p is not the smallest prime factor of `i * p`. That number is crossed out later, by `(i * p) / spf(i)` with the prime spf(i). Stopping there is what makes every composite come up exactly once.
  </FaqItem>
  <FaqItem question="Should I use the Euler inverse or the extended Euclid?">
    For one inverse modulo a composite n, the extended Euclid: O(log n), no factoring. The Euler form pays off when phi(n) is known anyway. For a prime p it is `a^(p - 2)`, the usual way to divide modulo 10<sup>9</sup> + 7.
  </FaqItem>
  <FaqItem question="How large an n can trial division handle?">
    Any n up to 2<sup>64</sup> - 1 in C++ and Go, and any n in Python, but the time depends on the factors. A 64-bit prime needs about 2<sup>32</sup> candidates, 8 seconds in C++ or Go; Python takes about as long, 6.7 seconds, for the prime 999,999,999,999,989, just below 10<sup>15</sup>.
  </FaqItem>
</Faq>
