## Definition

`f(n) = Theta(g(n))` means that `f` is squeezed between two constant multiples of `g` from some point on.

<Equation label="Big-Theta" expr="f(n) = Theta(g(n))  if there are constants c1, c2 > 0 and n0 such that  0 <= c1 * g(n) <= f(n) <= c2 * g(n)  for all n >= n0" />

Equivalently, `f` is both `O(g)` and `Omega(g)`:

<Equation label="Characterisation" expr="f(n) = Theta(g(n))  if and only if  f(n) = O(g(n)) and f(n) = Omega(g(n))" />

Unlike Big-O and Big-Omega, which are loose by default (`n` is `O(n^2)`), Theta pins the growth rate down: `n` is not `Theta(n^2)`. Like them, it describes a **function**, and the `=` means "is in the set".

## Intuition

Picture `f(n)` between two copies of `g(n)`, one scaled down by `c1` and one scaled up by `c2`. Past `n0` the curve never leaves that band, so `f` grows exactly like `g`.

Theta is where the "cases" misconception does the most damage. The popular rule "use Theta only when best = average = worst" is wrong. Theta is just a tight bound, and an algorithm has several functions you can bound:

- the best-case running time `B(n)`,
- the average-case running time `A(n)`,
- the worst-case running time `W(n)`.

Each of them may have its own Theta. When the cases differ, you state one Theta per case. When they all have the same Theta, the running time on every input is `Theta(g)` and you can say it of the whole algorithm.

## Worked examples

### Proving a Theta bound

Claim: `f(n) = 3n^2 + 5n + 2` is `Theta(n^2)`.

- Lower: `3n^2 <= 3n^2 + 5n + 2` for all `n >= 1`, so `c1 = 3`.
- Upper: for `n >= 1`, `5n <= 5n^2` and `2 <= 2n^2`, so `f(n) <= 10 n^2`, giving `c2 = 10`.

### Common closed forms

- `n(n + 1)/2 = Theta(n^2)`: the sum 1 + 2 + &hellip; + n.
- `a_k n^k + ... + a_0 = Theta(n^k)` for a positive leading coefficient: every polynomial has the Theta of its leading term.
- `log2(n!) = Theta(n log n)`.
- `log_a n = Theta(log n)` for every base `a > 1`.

## Using it in practice

1. Bound the function from above (O) and from below (Omega). If you can make them meet, you have a Theta.
2. State the case: "worst-case time is Theta(n^2)". Without a case, a single Theta is only valid if every input costs the same order.
3. Prefer Theta when you mean "exactly this order". Saying `O(n)` for a loop that always does `n^2` steps is true and misleading; `Theta(n^2)` is informative.
4. Use Theta to say two algorithms have the same growth rate: `f = Theta(g)` is an equivalence relation (reflexive, symmetric and transitive).

## Implementation

Python has four examples: sum, binary search, a real merge sort and naive matrix multiplication. C++ and Go have three (no matrix multiplication). Two honest caveats about the code:

- In C++ and Go, `mergeSortExample` / `MergeSortExample` call the library sort (`std::sort`, `sort.Ints`), not a merge sort. They are `O(n log n)` in the worst case, but not `Theta(n log n)` in every case: Go's `sort.Ints` is a pattern-defeating quicksort that is close to linear on sorted input.
- The binary search examples return early, so their best case is `Theta(1)`.

## Common misconceptions

<Callout tone="warning" title="Watch out for these">
- **"Theta only applies when best = average = worst."** False. Theta bounds one function tightly. The worst case of Quick Sort is `Theta(n^2)` and its average case is `Theta(n log n)`; both are correct Theta statements.
- **"We cannot say Quick Sort is Theta(n log n)."** The statement without a case is unclear. For the average case it is correct.
- **"Theta is always the best bound to use."** It needs a matching lower bound, which is sometimes unknown. Then you state O and Omega separately.
- **"Binary search is Theta(log n)."** Only its worst and average cases are. Its best case is `Theta(1)` because it returns early.
- **"Library sort is a Theta(n log n) merge sort."** In C++ and Go here it is not: it is `O(n log n)`, and Go's version can be close to linear on sorted input.
- **Theta is not exactness of the constant.** `Theta(n)` hides constants: `3n` and `300n` are both `Theta(n)`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Does Theta mean best case equals worst case?">
    No. Theta is a tight bound on a function. If you bound the worst case and the best case separately, they may have different Thetas. A single Theta for the whole algorithm exists only when they agree.
  </FaqItem>
  <FaqItem question="How do O, Omega and Theta relate?">
    `f = Theta(g)` exactly when `f = O(g)` and `f = Omega(g)`. Big-O gives the ceiling, Big-Omega the floor, and Theta says the two meet.
  </FaqItem>
  <FaqItem question="Why is Quick Sort's worst case Theta(n^2) and its average Theta(n log n)?">
    The worst case follows the recurrence `T(n) = T(n - 1) + Theta(n)`, which gives `Theta(n^2)`. On random input the split is balanced on average, giving `T(n) = 2T(n/2) + Theta(n)` and `Theta(n log n)`.
  </FaqItem>
  <FaqItem question="Can a function be both O(n) and Theta(n^2)?">
    No. `Theta(n^2)` implies `Omega(n^2)`, which is larger than every `O(n)` function for large `n`.
  </FaqItem>
</Faq>
