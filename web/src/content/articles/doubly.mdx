## What a doubly linked list is

Each node holds a value, a `next` reference and a `prev` reference. The first node has `prev = None`, the last has `next = None`, and the list object stores the `head`. Every link has a mirror image: if `a.next` is `b` then `b.prev` is `a`. Keeping both halves of that pair in sync is the whole difficulty of the structure.

The extra `prev` link costs one reference per node. In return, a node can be removed without searching for its predecessor, and the list can be read backward.

## See it in action

Every pointer write is its own step, so you can watch `next` and `prev` stay mirror images; try **Delete keeps prev links**, which ends by printing the list backward through the `prev` links.

Python names are shown; C++ uses `insertAtHead`, `insertAtTail`, `deleteValue`, `traverseForward`, `traverseBackward`, and Go the same in capitalised form. The traversals print rather than return a sequence. Python's `delete_value` returns `True` if it removed a node and `False` otherwise; the C++ and Go versions return nothing.

### Insert at head: two pointer writes

Inserting `5` into `[10, 20]`: the new node's `next` is the old head, the old head's `prev` is the new node, and `head` moves.

### Insert at tail: a walk, then two writes

The code follows `next` until it reaches a node with no successor, then sets `last.next = new` and `new.prev = last`. The walk is the O(n). With a stored tail pointer the same insertion would be O(1), but this implementation has none.

In C++ the matched node is then freed with `delete`. In Python and Go the garbage collector reclaims it once nothing refers to it.

### Backward traversal

The list stores only `head`, so `traverse_backward` first walks to the last node and then follows `prev` links to the front. It prints the same values in reverse. Reading backward costs O(n) here, not O(1) per step, only because of that initial walk.

This repository implements the plain version: head only, no sentinel, no tail pointer.

"Delete a known node" is the real strength of the doubly linked list. This code takes a value, not a node, so it cannot offer that O(1) form. Space is O(n), with two references per node.

## Applications

- **LRU cache:** a hash map points into a doubly linked list so that moving an entry to the front and evicting from the back are O(1). See the LRU Cache topic.
- **Deques:** push and pop at both ends.
- **Undo/redo and browser history:** step back and forward along a sequence.
- **Text editor buffers and playlists** where the cursor moves in both directions.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Updating only one direction.** After a delete, both `prev.next` and `next.prev` must change, or a backward walk still sees the removed node.
- **Null dereference at the ends.** The head has no `prev` and the tail has no `next`. Guard both writes, or use sentinel nodes.
- **Forgetting to move `head`** when the head is deleted.
- **Order of writes on insert.** Set the new node's own links before overwriting a neighbour's, so you do not lose the reference you still need.
- **Assuming insert at tail is O(1).** Without a stored tail it walks the list.
- **Leaking or double-freeing in C++.** Free every node in the destructor and never copy a list that owns raw nodes.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does a doubly linked list delete in O(1) if this code needs O(n)?">
    The O(1) figure assumes you already hold the node. This implementation deletes by value, so it must search first. A design that hands out node handles (as an LRU cache does) gets the O(1) removal.
  </FaqItem>
  <FaqItem question="Is insert at tail O(1) in a doubly linked list?">
    Only if the list stores a tail pointer. Here it does not, so the code walks from the head.
  </FaqItem>
  <FaqItem question="What do sentinel nodes buy me?">
    A dummy head and a dummy tail make every real node have both neighbours, so insert and delete need no special cases for the first, last and only node.
  </FaqItem>
  <FaqItem question="How is this different from a deque?">
    A deque is an interface (push and pop at both ends). A doubly linked list with head and tail pointers is one way to implement it; a ring buffer or a chunked array is another.
  </FaqItem>
</Faq>
