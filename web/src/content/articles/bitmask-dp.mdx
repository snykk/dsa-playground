## When bitmask DP applies

Use it when a problem asks for the best way to pick, order or assign a **small set of items** (n &le; 20 or so) and the future depends only on *which items are already used*, not on the order in which they were used.

- The statement has a small bound such as `n <= 16` or `n <= 20` next to something factorial, like orderings or matchings.
- You must visit, assign or cover every item exactly once.
- Brute force would try every permutation, but many permutations lead to the same situation.

The last point is the key. Two different paths that visited the same cities and now stand in the same city have the same future, so they can share one DP value.

## How it works

An integer with n bits represents a subset: bit `i` is 1 when item `i` is in the set. A 4-city subset such as `{A, C}` is `0b0101`, which is the number 5. Because the integer is also an array index, the whole set of subsets becomes one table of size 2<sup>n</sup>.

<Steps>
  <Step title="Define the state">
    `dp[mask][last]` is the cheapest cost of a path that starts at city 0, visits exactly the cities in `mask` and currently stands at `last`. Bit `last` must be set in `mask`.
  </Step>
  <Step title="Set the base case">
    `dp[1][0] = 0`: the mask with only city 0 set, standing at city 0, has cost 0. Every other cell starts at infinity.
  </Step>
  <Step title="Transition by adding one city">
    From `dp[mask][last]` try every city `j` not in `mask`: `dp[mask | (1 << j)][j] = min(itself, dp[mask][last] + dist[last][j])`.
  </Step>
  <Step title="Close the tour">
    Once `mask` is full, add the edge back to city 0 and take the minimum over `last`: `min(dp[full][last] + dist[last][0])`.
  </Step>
</Steps>

<Callout title="Why increasing mask order is a valid order">
A transition always turns one 0 bit into a 1 bit, so `new_mask` is strictly larger than `mask` as a number. Looping `mask` from 1 upward therefore finalizes every state before anything reads it, with no recursion and no memo dictionary.
</Callout>

## Pseudocode

```text
tsp(dist):
    n = number of cities
    if n == 0: return 0
    dp = table (1 << n) x n, filled with infinity
    dp[1][0] = 0
    for mask = 1 to (1 << n) - 1:
        if bit 0 not in mask: continue        # every tour starts at city 0
        for last in 0 .. n-1 with last in mask:
            for j in 0 .. n-1 with j not in mask:
                nm = mask | (1 << j)
                dp[nm][j] = min(dp[nm][j], dp[mask][last] + dist[last][j])
    full = (1 << n) - 1
    return min over last of dp[full][last] + dist[last][0]    # infinity if no tour
```

## Implementation

The Python version returns `float('inf')` when no tour exists, for example when a city has no usable edge. The C++ (`travelingSalesmanDp`) and Go (`TravelingSalesmanDP`) ports take a matrix of doubles, mark a missing edge with infinity (`kInfinity` in C++, `math.Inf(1)` in Go) and return infinity in the same case. All three give the same cost.

## Complexity analysis

There are 2<sup>n</sup> masks and n values of `last`, so the table has n &middot; 2<sup>n</sup> cells. Each cell tries up to n next cities.

A problem that only needs *which subset*, with no last item, uses a one-dimensional `dp[mask]` and costs O(2<sup>n</sup> &middot; n) time and O(2<sup>n</sup>) space. In pure Python the practical limit is lower than in C++ or Go because of per-cell object overhead.

## Applications

- Shortest route that visits every stop of a small delivery round.
- Assigning a small number of jobs to workers at minimum total cost.
- Counting tilings or placements on boards with a small width.
- The inner step of larger solvers that handle a few special items exactly.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Mistaking infeasible for free.** Initializing with infinity is right, but returning 0 when the final minimum is still infinity hides the case where no tour exists. This implementation returns `float('inf')` and the tests cover it.
- **Reading a state that was never reached.** `dp[mask][last]` is meaningful only when bit `last` is set in `mask`. Skip the rest.
- **Wrong operator precedence.** In C-like languages write `mask & (1 << i)` with parentheses.
- **Using 32-bit shifts.** `1 << j` overflows an `int` once j reaches 31; use `1LL << j` for larger masks.
- **Forgetting the return edge.** TSP is a cycle: add `dist[last][0]` at the end, or the answer is a Hamiltonian path instead.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does the state need the last city and not only the mask?">
    The cost of the next edge depends on where you stand. Two paths covering the same cities but ending in different cities have different futures, so they cannot share a value.
  </FaqItem>
  <FaqItem question="Why does the table only use masks that contain city 0?">
    A tour is a cycle, so any city can be the start. Fixing city 0 as the start removes a factor of n from the number of equivalent tours, and the code skips masks without bit 0 because they are never reached.
  </FaqItem>
  <FaqItem question="Can I recover the tour itself?">
    Yes: store, next to each `dp[mask][last]`, the previous city that produced the minimum, then walk back from the best final state. The repository code returns only the cost.
  </FaqItem>
  <FaqItem question="Can I save memory?">
    For subset-only DP, yes, when transitions read a limited set of masks. For TSP the full table is needed, which is why it stops around n = 20 to 25 in practice.
  </FaqItem>
</Faq>
