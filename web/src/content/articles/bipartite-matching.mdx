## How bipartite matching works

A bipartite graph has two sides, left vertices `L0, L1, ...` and right vertices `R0, R1, ...`, and every edge joins a left vertex to a right one. A **matching** is a set of edges with no vertex in common. The task is a **maximum matching**: as many pairs as the edges allow, such as workers to jobs or students to projects.

Both algorithms here grow the matching one pair at a time along an **augmenting path**: a path from a free left vertex to a free right vertex whose edges alternate between outside and inside the matching. It has one more edge outside than inside, so flipping it (the outside edges enter the matching, the inside edges leave) adds one pair and keeps every matched vertex matched.

<Callout title="Berge's theorem">
A matching is maximum exactly when no augmenting path exists. So an algorithm that keeps finding and flipping augmenting paths, and stops when there is none, ends with a maximum matching.
</Callout>

<Steps>
  <Step title="Kuhn: one search per left vertex">
    For each left vertex in order, run a DFS. Standing on `u`, try its next neighbour `v` that this search has not tried. If `v` is free, the path found is augmenting: flip it. If `v` is matched to `w`, go on from `w`, which must move to another right vertex for `u` to take `v`.
  </Step>
  <Step title="Kuhn: one pass is enough">
    If a left vertex finds no augmenting path, it stays free for good: a vertex with no augmenting path keeps having none as the matching grows. So every left vertex is searched from once.
  </Step>
  <Step title="Hopcroft-Karp: BFS layers">
    Each phase starts with one BFS from every free left vertex at once (layer 0). An edge from layer `d` to a matched right vertex puts its partner in layer `d + 1`. The BFS stops at the first free right vertex: shortest augmenting paths end in that layer, called `last`, and later layers are cleared.
  </Step>
  <Step title="Hopcroft-Karp: disjoint shortest paths">
    From each free left vertex, a DFS steps only from layer `d` to layer `d + 1`, so every path it finds is a shortest one. A vertex whose search fails is marked dead for the rest of the phase, so the paths of a phase share no vertex. Repeat until the BFS finds no free right vertex.
  </Step>
</Steps>

<Callout title="Konig's theorem and the reduction to flow">
In a bipartite graph, a minimum vertex cover (fewest vertices touching every edge) has as many vertices as a maximum matching has edges. And matching is a special case of maximum flow: an edge of capacity 1 from a source to each left vertex, from left to right along each edge, and from each right vertex to a sink. The maximum flow is the size of the matching.
</Callout>

Both end with 3 pairs, but not the same ones: Kuhn returns `match_left = [2, 1, 0, -1]` and Hopcroft-Karp `[2, 0, -1, 1]`. For the cover, start from the free left vertex L2 of the Hopcroft-Karp matching and follow alternating paths: they reach R0, L1, R1 and L3, the set `Z`. The cover is the left vertices outside `Z` and the right vertices inside it, `L0`, `R0` and `R1`.

## Pseudocode

```text
kuhn(n_left, n_right, edges):
    adj[u] = right neighbours of u, in edge order
    match_left = [-1] * n_left; match_right = [-1] * n_right
    for root in 0 .. n_left - 1:
        if augment(root): size += 1          # one DFS, seen marks cleared per root
    return size, match_left

augment(u):                                  # recursive form; the code keeps a stack
    for v in adj[u] not seen in this search:
        mark v seen
        if match_right[v] == -1 or augment(match_right[v]):
            match_left[u] = v; match_right[v] = u
            return True
    return False

hopcroft_karp(n_left, n_right, edges):
    while (last := bfs_layers()) != -1:      # layer 0 = free left vertices
        for root in free left vertices, in order:
            if dfs(root): size += 1          # only from layer d to a partner in layer d + 1
    return size, match_left                  # dfs sets dist[u] = -1 on a dead end
```

## Implementation

Each language takes the two side sizes and a list of edges `(u, v)`, left vertex first, both sides numbered from 0, and returns the size of the matching and `match_left`, the partner of each left vertex or -1. A third function returns Konig's minimum vertex cover, built from the Hopcroft-Karp matching, as two increasing lists. The names are `kuhn`, `hopcroft_karp` and `min_vertex_cover` in Python, `kuhn`, `hopcroftKarp` and `minVertexCover` in C++ (a `Matching` and a `VertexCover` struct), and `Kuhn`, `HopcroftKarp` and `MinVertexCover` in Go.

**Which matching comes back.** `adj[u]` keeps the edges in the order given, a repeated edge included, and every search tries them in that order; the roots go from 0 up. So the result is fixed by the input, and Python, C++ and Go return the same matching and the same cover: the C++ and Go tests check 40 graphs against outputs of the Python code. The two algorithms often return different maximum matchings: on the edges `(0, 0), (0, 1), (1, 0), (1, 1)` Kuhn gives `[1, 0]` and Hopcroft-Karp `[0, 1]`.

**Bad input and long paths.** A negative side size or an edge endpoint out of range raises `ValueError` in Python, throws `std::invalid_argument` in C++ and returns an error wrapping `ErrInvalidGraph` in Go. No edges, or an empty side, gives a matching of size 0. Both searches keep their path in an explicit stack in all three languages, since an augmenting path can pass every left vertex: a recursive Python version fails at about 1000.

## Complexity analysis

Let `V` be the number of vertices and `E` the number of edges. In one search of either algorithm each left vertex is entered at most once (Kuhn tries each right vertex once per search; Hopcroft-Karp marks failed vertices dead and never reaches a flipped path again), so each adjacency list is scanned at most once: one search costs <BigO of="E" />.

    { case: 'Hopcroft-Karp, one phase', time: 'O(V + E)', space: 'O(V + E)', when: 'One BFS, then DFSs that enter each vertex at most once.' },
    { case: 'Hopcroft-Karp, total', time: 'O(E sqrt(V))', space: 'O(V + E)', when: 'At most about 2 sqrt(V) phases.' },
    { case: 'Konig cover', time: 'O(V + E)', space: 'O(V + E)', when: 'One walk over alternating paths after the matching.' },
  ]}
/>

<Equation label="Hopcroft-Karp" expr="O(sqrt(V)) phases x O(V + E) per phase" result="O(E sqrt(V))" />

Why so few phases: every phase makes the shortest augmenting path longer. After sqrt(V) phases each remaining augmenting path has more than sqrt(V) left vertices, and the paths that separate the current matching from a maximum one are vertex-disjoint, so fewer than sqrt(V) of them are left; each later phase flips at least one.

The phases count every BFS, including the last one, which finds no path: on the complete graph Hopcroft-Karp's first phase matches every vertex and the second only confirms it. Kuhn's new roots there each ask for R0 first and push every earlier vertex one place along, n(n + 1)(n + 2)/6 looks in all. The last family is close to Hopcroft-Karp's worst case, about sqrt(V) phases, while Kuhn finds each long path in a single search. Hopcroft-Karp has the better bound, not a win on every graph.

Kuhn is the reduction's Ford-Fulkerson in disguise: each search looks for an augmenting path in the residual graph from one free left vertex, and the backward residual edges are the matching edges, walked from right to left. Hopcroft-Karp is what Dinic's blocking flows become on the same unit-capacity network.

## Applications

- **Assignment.** Workers to jobs, students to projects, gophers to holes: each allowed pair is an edge.
- **Tiling a grid.** Colour the cells like a checkerboard; a domino covers one cell of each colour, so the most dominoes is a maximum matching.
- **Vertex cover and independent set.** By Konig's theorem the minimum vertex cover of a bipartite graph has the size of the matching, and the maximum independent set is the other vertices: V minus the matching.
- **Path cover of a DAG.** Give each vertex a left and a right copy and an edge `u -> v` the pair `(u, v)`. The fewest vertex-disjoint paths covering every vertex is V minus the maximum matching.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Two numberings for one vertex.** Both sides start at 0 here, so `(1, 1)` joins L1 and R1. Code that numbers the right side after the left must do so everywhere.
- **Not resetting `seen` between Kuhn's roots.** A later search would skip right vertices it never tried. The code here stamps each mark with the root instead of clearing.
- **Recursion depth.** An augmenting path can pass every left vertex; a recursive DFS in Python fails at about 1000 of them.
- **Expecting one particular matching.** Only the size is unique; another algorithm or another edge order can give other pairs.
- **Dropping the layer rule in Hopcroft-Karp.** A DFS that takes any augmenting path is still correct, but it loses the O(E sqrt(V)) bound.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does Kuhn search from each left vertex only once?">
    A left vertex that finds no augmenting path never finds one later: flipping other augmenting paths cannot create one from it. So once its search fails, it can stay free, and one pass over the left vertices gives a maximum matching.
  </FaqItem>
  <FaqItem question="Why do Kuhn and Hopcroft-Karp return different pairs?">
    A graph can have many maximum matchings, and the two algorithms look for augmenting paths in a different order. Hopcroft-Karp's first phase gives every left vertex its first free neighbour, while Kuhn may move earlier vertices to make room. The size is always the same.
  </FaqItem>
  <FaqItem question="How do I get a maximum independent set?">
    Take the complement of a minimum vertex cover: every vertex not in the cover. No edge has both ends outside the cover, and its size is V minus the matching. The code returns the cover, so the independent set is one set difference away.
  </FaqItem>
  <FaqItem question="Should I use max flow instead?">
    Flow code handles more (capacities other than 1, extra constraints), but for plain matching it is longer and no faster: Ford-Fulkerson on the reduction is Kuhn's algorithm with more bookkeeping.
  </FaqItem>
</Faq>
