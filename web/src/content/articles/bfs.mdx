## How BFS works

BFS explores a graph the way a ripple spreads on water. It first visits the start vertex, then everything one edge away, then everything two edges away, and so on. A FIFO queue produces exactly this order: vertices discovered earlier are expanded earlier.

<Steps>
  <Step title="Seed the queue">
    Put the start vertex in the queue and mark it visited. The implementations return an empty result when the start is not a key of the graph.
  </Step>
  <Step title="Dequeue a vertex">
    Take the vertex at the front of the queue and report it. This is the moment it is processed.
  </Step>
  <Step title="Discover its neighbors">
    For every neighbor that is not yet visited, mark it visited **now** and append it to the queue. Neighbors already seen are skipped.
  </Step>
  <Step title="Repeat">
    Go back to step 2 until the queue is empty. Every vertex reachable from the start has been visited exactly once.
  </Step>
</Steps>

<Callout title="The invariant: the queue is sorted by distance">
At every moment the queue holds vertices of distance d followed by vertices of distance d + 1, never anything else. A vertex of distance d + 1 can only be discovered while a distance-d vertex is dequeued, and all distance-d vertices leave the queue before any distance-(d + 1) vertex does. So the first time a vertex is discovered, it is discovered by a shortest path.
</Callout>

## Pseudocode

```text
bfs(graph, start):
    if start not in graph: return []
    visited = {start}
    queue = [start]
    order = []
    while queue is not empty:
        v = queue.popFront()
        order.append(v)
        for each neighbor w of v:          # graph.get(v, []) for sink vertices
            if w not in visited:
                visited.add(w)             # mark on enqueue, not on dequeue
                queue.pushBack(w)
    return order

bfsWithPath(graph, start, target):
    if start == target: return [start]
    if start not in graph: return none
    parent = {start: none}
    queue = [start]
    while queue is not empty:
        v = queue.popFront()
        for each neighbor w of v:
            if w == target:
                return walk parents back from v to start, then append w
            if w not in parent:
                parent[w] = v
                queue.pushBack(w)
    return none
```

The path version stores one `parent` entry per vertex and rebuilds the path once at the end. Copying the whole path into every queue entry would cost O(V<sup>2</sup>) on a long path.

## Implementation

The Python, C++ and Go versions offer the same four functions: traversal order, shortest path, level order and shortest distance to every vertex. They all use an adjacency list (a dictionary or map from vertex to its neighbor list) and treat a vertex that appears only inside neighbor lists as a vertex without outgoing edges. Python also has `bfs_connected_components`. Each language comes with its tests.

<TopicCode topic="Algorithms/Graph_Algorithms/Traversal/BFS" />

Language notes:

- Python uses `collections.deque`, so `popleft` is O(1). A plain list with `pop(0)` would make every dequeue O(V).
- C++ uses `std::queue` with `unordered_map` and `unordered_set`.
- Go uses a slice as the queue (`queue = queue[1:]`). That is fine here, but the slice keeps the dequeued prefix of its backing array alive until it is reallocated.

The two terms are separate because a graph with many isolated vertices costs O(V) even though E is small, and a dense graph costs O(E), up to O(V<sup>2</sup>).

<Equation label="Work" expr="sum over v of (1 + deg(v)) = V + E" result="O(V + E)" />

<Callout title="Space is O(V), the answer is part of it">
The visited set holds at most V vertices, and the queue never holds more than V vertices because a vertex is queued only once. On an adjacency matrix the same algorithm costs O(V<sup>2</sup>) time, because finding the neighbors of a vertex scans a whole row.
</Callout>

## Applications

- **Fewest steps.** Shortest route in a maze or grid, minimum moves in a puzzle, word-ladder style problems.
- **Layers.** Level-order traversal of a tree, which is BFS on a tree.
- **Reachability and components.** Which vertices can be reached from a start, and the connected components of an undirected graph.
- **Multi-source distances.** Distance from each cell to the nearest source, by starting with all sources in the queue.
- **Bipartite check.** Color the layers alternately; an edge inside one layer means the graph is not bipartite.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Marking on dequeue instead of on enqueue.** A vertex can then be queued many times before it is first dequeued. The result is still correct for plain traversal, but the queue can grow to O(E) and the work multiplies. Mark when you enqueue.
- **Using BFS on weighted graphs.** BFS counts edges, not weights. For weights use Dijkstra, or 0-1 BFS when weights are only 0 or 1.
- **A list as the queue.** `list.pop(0)` in Python and slicing in other languages can turn the dequeue into O(V). Use `deque`.
- **Requiring the target to be a key.** A vertex that only appears in neighbor lists has no outgoing edges but is still reachable. Look neighbors up with a default empty list.
- **Directed input to the components function.** `bfs_connected_components` is meant for symmetric (undirected) adjacency lists. On a directed graph it returns the vertices first reached from each unvisited key, not strongly connected components.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does BFS find the shortest path?">
    It expands vertices in order of distance. Everything at distance d is dequeued before anything at distance d + 1, so a vertex is first discovered from a vertex that is as close to the start as possible. That discovery sets its distance, and nothing can improve it later.
  </FaqItem>
  <FaqItem question="Is BFS or DFS faster?">
    Both are O(V + E). Choose by what you need: BFS for fewest edges and layers, DFS for structure such as cycles, finishing order and components.
  </FaqItem>
  <FaqItem question="Does BFS work on directed graphs?">
    Yes. It follows edges in their direction and reaches exactly the vertices reachable from the start. Only the components function assumes an undirected graph.
  </FaqItem>
  <FaqItem question="How do I get the path and not only the distance?">
    Record `parent[w] = v` when you discover `w`, then walk the parents back from the target and reverse the result. `bfs_with_path` does this and returns `None` (Python) or an empty list or vector (C++ and Go) when there is no path.
  </FaqItem>
</Faq>
