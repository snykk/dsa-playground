## How Bucket Sort works

Bucket Sort uses the value of an element, not comparisons with other elements, to decide roughly where it goes. The implementations in this repository sort numbers in the closed interval `[0.0, 1.0]` with `n` buckets: a value `x` goes to bucket `floor(x * n)`, and `1.0` goes to the last bucket.

<Steps>
  <Step title="Validate the range">
    Every value must satisfy `0.0 <= x <= 1.0`. Anything else (a negative number, a value above 1, NaN) has no bucket, so Python raises `ValueError`, C++ throws `std::invalid_argument` and Go panics.
  </Step>
  <Step title="Distribute">
    Create `n` empty buckets and append each value to bucket `floor(x * n)`. Bucket `b` collects the values in `[b/n, (b+1)/n)`, and the last one also takes `1.0`.
  </Step>
  <Step title="Sort each bucket">
    Sort every bucket on its own. Python uses a small insertion sort; C++ and Go call the library sort (`std::sort`, `sort.Float64s`).
  </Step>
  <Step title="Concatenate">
    Read the buckets from first to last. Every value in bucket `b` is smaller than every value in bucket `b + 1`, so the result is sorted.
  </Step>
</Steps>

<Callout title="Why the output is sorted">
The bucket index `floor(x * n)` never decreases as `x` grows, so a smaller value can never end up in a later bucket than a larger one. Buckets therefore hold disjoint, increasing ranges, and sorting inside each bucket finishes the job.
</Callout>

## Pseudocode

```text
bucketSort(arr):                     # values in [0, 1]
    n = length(arr)
    for x in arr:
        if not (0 <= x <= 1): error
    buckets = n empty lists
    for x in arr:
        b = floor(x * n)
        if b == n: b = n - 1         # x == 1.0
        append x to buckets[b]
    for each bucket: sort it
    return buckets joined in order
```

## Implementation

The three versions follow the pseudocode. Differences worth knowing:

- Python takes an optional `num_buckets` (default `len(arr)`), sorts each bucket with insertion sort and returns a new list (for an empty list it returns the same object). C++ and Go always use `n` buckets and sort in place.
- Python also has `bucket_sort_integers`, which uses one bucket per integer value, from the minimum to the maximum. That is Counting Sort written with lists: it accepts negatives, but needs memory proportional to `max - min + 1`.

## Complexity analysis

Distributing and concatenating cost <BigO of="n + k" /> for `k` buckets. The sorting step depends on how many values share a bucket. If bucket `i` holds `n_i` values and is insertion-sorted:

<Equation label="Total time" expr="T(n) = O(n + k) + sum of O(n_i^2)" result="O(n) when every n_i is about n/k" />

<ComplexityTable
  rows={[
    { case: 'Best case', time: 'O(n + k)', space: 'O(n + k)', when: 'Every bucket has at most a few values, so sorting the buckets is linear in total.' },
    { case: 'Average case', time: 'O(n + k)', space: 'O(n + k)', when: 'Uniformly distributed input with k about n: the expected size of each bucket is a constant.' },
    { case: 'Worst case', time: 'O(n^2)', space: 'O(n + k)', when: 'All values fall into one bucket (clustered input), so the whole sort is one insertion sort. C++ and Go sort buckets with a library sort, so there it is O(n log n).' },
  ]}
/>

The extra space is the `n` buckets plus the `n` stored values.

<Callout title="The uniformity assumption is the whole point">
The linear bound is a statement about the input distribution, not about the algorithm. Values such as `[0.11, 0.12, 0.13, 0.14, 0.15, 0.16, 0.9]` all land in the first two of seven buckets except one, and the sort degenerates to the inner sort. Choose bucket boundaries from the data (for example from the minimum and maximum) or a better inner sort if the data is skewed.
</Callout>

## Applications

- **Uniform real numbers.** Random samples in a known range, such as the textbook case of values in `[0, 1)`.
- **External or parallel sorting.** Distributing data into value ranges and sorting each range separately (on separate machines or threads) is the same idea.
- **Frequency grouping.** Placing items into buckets by count is the idea behind many "top k frequent" solutions.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Forgetting the `1.0` case.** `floor(1.0 * n)` is `n`, one past the last bucket. Clamp it to `n - 1`.
- **Values outside the range.** Negative values give a negative (wrapping) index and values above 1 give an index past the end. Validate, or normalise by the minimum and maximum.
- **Assuming it is always linear.** Without an even spread, a single bucket holds most of the data.
- **Calling it stable without checking the inner sort.** Only the insertion-sort version here is stable, and for bare numbers that rarely matters.
- **Huge integer ranges.** `bucket_sort_integers` allocates `max - min + 1` lists.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is Bucket Sort really O(n)?">
    Only in expectation and only when the input is spread evenly over the buckets. In the worst case every value falls into one bucket and the cost is that of the inner sort (O(n^2) for insertion sort).
  </FaqItem>
  <FaqItem question="How many buckets should I use?">
    About `n` is the usual choice: each bucket then holds a constant number of values on average, and the distribute and concatenate steps stay linear. This repository uses exactly `n` buckets, except for Python, where you can pass `num_buckets`.
  </FaqItem>
  <FaqItem question="How is Bucket Sort different from Counting Sort?">
    Counting Sort keeps one counter per distinct value, so it works for a small integer range and never sorts inside a bucket. Bucket Sort keeps one bucket per value range, so it handles real numbers, but the buckets still need sorting.
  </FaqItem>
  <FaqItem question="Can it sort negative numbers or values above 1?">
    Not directly here: the functions reject them. Scale the data to `[0, 1]` first with `(x - min) / (max - min)`, or use `bucket_sort_integers` in Python for integers.
  </FaqItem>
</Faq>
