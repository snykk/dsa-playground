## What the two kinds are

A graph is a set of vertices plus a set of edges. In an **undirected** graph an edge is an unordered pair `{u, v}`: friendship, a two-way road. In a **directed** graph (digraph) it is an ordered pair `(u, v)`: a hyperlink, a one-way street, "task u must finish before task v".

The class `Graph(directed)` in this folder holds both kinds. It stores an adjacency list, a map from each vertex to the list of vertices it points to. The only difference between the modes is that an undirected `add_edge(u, v)` also records `u` in `v`'s list.

<Callout title="Undirected is directed with both arrows">
Any undirected graph is a directed graph in which every edge appears in both directions. Many algorithms (BFS, DFS, Dijkstra) are written once for digraphs and work unchanged on undirected graphs stored this way.
</Callout>

The three languages share these operations (Go uses `AddEdge`, `GetNeighbors` and so on; C++ has no recursive DFS). Adding an edge that already exists changes nothing, so there are no parallel edges.

### Degree

In an undirected graph `deg(v)` counts incident edges. Summing every degree counts each edge twice, so the sum is 2E (the handshake lemma). In a digraph, the in-degrees sum to E and so do the out-degrees. For the directed graph above:

<DataTable
  columns={['Vertex', { label: 'In', kind: 'mono' }, { label: 'Out', kind: 'mono' }, { label: 'get_degree', kind: 'mono' }]}
  rows={[
    ['1', '0', '2', '2'],
    ['2', '1', '1', '2'],
    ['3', '2', '1', '3'],
    ['4', '1', '1', '2'],
    ['5', '1', '0', '1'],
  ]}
/>

For a directed graph the code's `get_degree` returns in plus out. Computing the in-degree scans every list, so it costs O(V + E).

### Traversal and reachability

On the undirected graph, BFS from 1 visits `[1, 2, 4, 3, 5]`, and every other start also reaches all five vertices (from 3 the order is `[3, 2, 4, 5, 1]`): the graph is connected. On the directed graph the answer depends on where you start:

<DataTable
  columns={['Start', 'Directed BFS result']}
  rows={[
    ['1', '[1, 2, 4, 3, 5]'],
    ['3', '[3, 5]'],
    ['5', '[5]'],
  ]}
/>

That is why `is_connected()` refuses a directed graph (`ValueError` in Python, `std::invalid_argument` in C++, a panic in Go): "connected" needs a definition (weak or strong), and the code does not guess.

## Applications

- **Undirected:** social networks, road and cable networks, connected components, spanning trees.
- **Directed:** web links, build and course dependencies (topological sort), state machines, flow networks.
- **Directed reachability:** strongly connected components, cycle detection.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Mirroring a directed edge** or forgetting to mirror an undirected one. A traversal then silently misses vertices.
- **Calling `is_connected()` on a directed graph.** It raises, throws or panics; decide between weak and strong connectivity first.
- **Mixing up degree and out-degree.** `get_degree` on a digraph is in plus out, not the number of neighbors.
- **Cycle detection with the undirected rule on a digraph.** Seeing a visited vertex is not enough; it must be on the current path.
- **Assuming BFS from any vertex reaches everything** in a directed graph.
- **Self-loops and degree.** An undirected self-loop is stored once, so its degree contribution is 1, not 2.
</Callout>

## Implementation

All three versions are an adjacency list in a map. Python and Go return a copy from `get_neighbors`, so editing the result never corrupts the graph. `get_edges` skips the mirrored copy of an undirected edge.

## Frequently asked questions

<Faq>
  <FaqItem question="Is an undirected graph just a directed graph with two edges per pair?">
    Yes for storage and algorithms: replacing each undirected edge by two opposite arrows gives an equivalent digraph. The two representations count edges differently (E versus 2E), so be careful with formulas.
  </FaqItem>
  <FaqItem question="What is the difference between in-degree and out-degree?">
    The out-degree of v counts edges leaving v, and the in-degree counts edges entering v. Both sums over all vertices equal E.
  </FaqItem>
  <FaqItem question="When is a directed graph connected?">
    Weakly connected means the graph is connected when directions are ignored. Strongly connected means every vertex can reach every other along the arrows. Algorithms such as Kosaraju or Tarjan find strongly connected components.
  </FaqItem>
  <FaqItem question="Does BFS work on directed graphs?">
    Yes. It follows only outgoing edges, so it visits exactly the vertices reachable from the start, which may be fewer than all vertices.
  </FaqItem>
</Faq>
