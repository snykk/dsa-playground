## How Floyd-Warshall works

Instead of growing a tree from a source, Floyd-Warshall asks one question about every pair (i, j): **is it shorter to go through vertex k?** It lets the vertices 0, 1, 2, ... become allowed intermediate stops one at a time.

<Steps>
  <Step title="Start with the direct edges">
    `dist[i][i] = 0`, `dist[i][j]` is the cheapest edge from i to j (the cheapest, if there are parallel edges), and infinity where there is no edge.
  </Step>
  <Step title="Allow vertex k as a stop">
    For k = 0, 1, ..., V - 1, and for every pair (i, j): if `dist[i][k] + dist[k][j] < dist[i][j]`, replace `dist[i][j]`.
  </Step>
  <Step title="Check the diagonal">
    If any `dist[i][i]` is negative, vertex i lies on a negative cycle and shortest distances do not exist.
  </Step>
  <Step title="Read the answer">
    Otherwise `dist[i][j]` is the shortest distance from i to j, or infinity if j is unreachable from i.
  </Step>
</Steps>

<Callout title="The state: paths that stop only at vertices 0..k">
After the round for k, `dist[i][j]` is the length of the shortest path from i to j whose intermediate vertices all lie in `0..k`. The new path through k has two halves, i to k and k to j, and neither half needs k as a stop, so both come from the previous round. The outer loop must therefore be **k**, not i or j.
</Callout>

## Pseudocode

```text
floydWarshall(graph, n):
    dist[i][j] = infinity;  dist[i][i] = 0
    for each edge (u, v, w):
        dist[u][v] = min(dist[u][v], w)        # parallel edges, self-loops
    for k in 0 .. n-1:
        for i in 0 .. n-1:
            for j in 0 .. n-1:
                if dist[i][k] and dist[k][j] are finite:
                    dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
    if any dist[i][i] < 0: return negative cycle
    return dist
```

For paths, Python's `floyd_warshall_path` keeps a `next` matrix: `next[i][j]` is the first vertex after i on a shortest path to j. It is set to `next[i][k]` whenever the route through k wins, and `reconstruct_path(next, i, j)` follows it. On the example, the path from B to D is B, C, D and from D to C is D, A, B, C.

## Implementation

Input is an adjacency list (`graph[u]` is a list of `(v, weight)` pairs) and the number of vertices. The edge initialization takes the minimum, so parallel edges keep the cheapest and a positive self-loop never raises the diagonal above 0.

C++ and Go check the diagonal after every round, so distances in a negative cycle cannot keep shrinking toward an overflow. Python integers do not overflow, so one check at the end is enough there. The C++ version accepts fewer adjacency rows than `numVertices`; the missing rows have no edges. In Python, `floyd_warshall_path` also returns `None` on a negative cycle, and `reconstruct_path` gives up after V vertices instead of looping.

The in-place update is safe because during round k the entries `dist[i][k]` and `dist[k][j]` do not change: `dist[k][k]` is 0 unless there is a negative cycle, which is detected anyway.

## Negative cycles

If a vertex i lies on a cycle of negative total weight, some round produces `dist[i][i] < 0`. The result is then not a set of shortest distances, because every pair whose path can reach the cycle has no shortest path. The implementations return the negative-cycle signal for the whole matrix; they do not mark individual pairs.

## Applications

- **All-pairs shortest paths** on small or dense graphs, such as distance tables between cities or stations.
- **Transitive closure.** Replace min and + by or and and to learn which vertices can reach which (Warshall's algorithm).
- **Negative cycle detection** from the diagonal.
- **Graph diameter or centrality** on small graphs, from the distance matrix.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **The wrong loop order.** `k` must be the outermost loop. With i or j outside, paths through later intermediates are missed.
- **Overwriting instead of taking the minimum.** With parallel edges the last one would win, and a self-loop would overwrite the diagonal 0. Always use min.
- **Adding to infinity.** Skip the update when `dist[i][k]` or `dist[k][j]` is the infinity sentinel, or the sum overflows.
- **Ignoring the diagonal.** A negative `dist[i][i]` means the other entries cannot be trusted.
- **Following next pointers after a negative cycle.** They can loop forever. `floyd_warshall_path` returns `None` in that case, and `reconstruct_path` stops after V vertices.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does the k loop have to be the outermost one?">
    Round k assumes that all shorter paths using only vertices below k are already complete. With k outermost, each round finishes the whole matrix for one more allowed stop. With k inside, a cell can be finished before its two halves are.
  </FaqItem>
  <FaqItem question="Can Floyd-Warshall handle negative weights?">
    Yes, as long as there is no negative cycle. If there is one, the diagonal shows it and no finite answer exists for the affected pairs.
  </FaqItem>
  <FaqItem question="When is it better to run Dijkstra V times?">
    On sparse graphs with non-negative weights: V runs cost O(V (V + E) log V), which is far below V<sup>3</sup> when E is much smaller than V<sup>2</sup>.
  </FaqItem>
  <FaqItem question="How do I get the actual path, not just the distance?">
    Keep a next matrix as `floyd_warshall_path` does, and follow it with `reconstruct_path`. It returns `None` if there is no path. C++ and Go in this repository return distances only.
  </FaqItem>
</Faq>
