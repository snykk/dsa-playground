## What a circular linked list is

Each node stores a value and a `next` reference, exactly as in a singly linked list. The difference is the end of the chain: the last node's `next` is the head, not null. Starting anywhere you can reach every node by following `next`, and you know you have gone all the way round when you see the head again.

An empty list has `head = None`. A list with one node has `head.next == head`: the node is both head and tail and points at itself. That single-node case is the one to watch in every operation.

<Callout title="Empty, one node, many">
Most circular-list bugs live in the one-node case. There the head and the tail are the same node, so code that says "move head to head.next" leaves head unchanged. The delete operation here handles it first and sets `head` to `None`.
</Callout>

Names differ by language: `insertAtHead`, `deleteValue`, `traverse` in C++ and `InsertAtHead`, `DeleteValue`, `Traverse` in Go. Python returns the values as a list, while C++ and Go print them. All three accept a limit on how many nodes to visit: optional in Python (default: no limit) and C++ (default 10, so longer lists are cut short), required in Go.

### Traverse

A walk cannot test for null. It records the head's value, steps forward, and stops when it arrives back at the head (or when the optional limit is reached). Without that stop condition it would loop forever, which is the defining danger of a ring.

## Variant: keep a tail pointer

The code in this repository stores only `head`, so both inserts must walk to the tail. The more common representation stores only `tail`, because `tail.next` is the head:

<DataTable
  columns={['Representation', { label: 'Insert head', kind: 'mono' }, { label: 'Insert tail', kind: 'mono' }, { label: 'Delete head', kind: 'mono' }]}
  rows={[
    ['head only (this repo)', 'O(n)', 'O(n)', 'O(n)'],
    ['tail only (`tail.next` is head)', 'O(1)', 'O(1)', 'O(1)'],
  ]}
/>

Inserting at the head is `new.next = tail.next; tail.next = new`, and inserting at the tail does the same and then moves `tail = new`. Both are O(1).

## Implementation

The three versions follow the same logic. In Python and Go the tests walk the ring through `head` and `next`. The C++ class owns its nodes: it has a destructor that opens the ring and frees every node, and its copy constructor and assignment are deleted, because two lists would free the same nodes.

## Applications

- **Round-robin scheduling:** serve each task for a time slice, then move on; the list never needs resetting.
- **Turn-based games and the Josephus problem:** repeatedly skip k nodes and remove one, as in LeetCode 1823.
- **Playlists and carousels** that loop.
- **The base of other structures:** circular buffers and some queue implementations.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Looping until null.** There is no null: stop when the pointer returns to the head.
- **Deleting the only node like any other.** The tail is the node itself, so `head = head.next` changes nothing. Set `head` to null (and free the node in C++ before clearing the pointer).
- **Forgetting to repoint the tail** when the head is inserted or deleted. The ring would still reference the old head.
- **Walking without a guard** while the ring may be broken. A `limit` argument keeps a debugging traversal finite.
- **Leaking in C++.** Freeing nodes one by one with a `while(head)` loop never ends on a ring: open the ring first, as the destructor does.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="How do I know I have been all the way round?">
    You are back at the head node. Compare node identity (the pointer or reference), not the stored value, because values may repeat.
  </FaqItem>
  <FaqItem question="Why does inserting at the head cost O(n) here?">
    The tail's `next` must point at the new head, and the list stores no tail pointer, so the code walks the whole ring to find it. Storing a tail pointer (and recovering the head as `tail.next`) makes it O(1).
  </FaqItem>
  <FaqItem question="Is a circular linked list the same as a circular queue?">
    No. A circular queue is usually an array with head and tail indexes that wrap around with modulo. A circular linked list is a ring of separately allocated nodes.
  </FaqItem>
  <FaqItem question="Can a circular list be doubly linked?">
    Yes: make the last node's `next` the head and the head's `prev` the last node. That gives O(1) access to the tail from the head and lets you walk in both directions. This repository's circular list is singly linked.
  </FaqItem>
</Faq>
