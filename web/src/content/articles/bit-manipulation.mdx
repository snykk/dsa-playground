## When to use it

Signals in a problem statement:

- "every element appears twice except one": XOR cancels pairs;
- "is it a power of two", "count the 1 bits", "Hamming distance";
- a set of at most about 20-30 items where you must try **all subsets**: one integer per subset;
- flags, permissions or visited sets that should fit in one word;
- "lowest set bit" appears inside Fenwick trees, where `x & -x` is the step size.

## How it works

Integers are stored in two's complement. Six operators do all the work: `&`, `|`, `^`, `~`, `<<`, `>>`.

    ['Lowest set bit', '`n & (-n)`', '-n inverts every bit above the lowest 1 and keeps that bit'],
    ['Clear lowest set bit', '`n & (n - 1)`', 'n - 1 flips the lowest 1 and the zeros below it'],
    ['Power of two', '`n > 0 and (n & (n - 1)) == 0`', 'exactly one bit set; n > 0 excludes 0'],
    ['Even', '`(n & 1) == 0`', 'bit 0 is the parity'],
  ]}
/>

<Steps>
  <Step title="Think in positions">
    Bit i has value 2<sup>i</sup>, counted from the least significant bit at position 0.
  </Step>
  <Step title="Build a mask for what you want to touch">
    `1 << i` is a mask with only bit i set. `~mask` is its complement.
  </Step>
  <Step title="Combine with the right operator">
    AND keeps or clears, OR sets, XOR flips or cancels.
  </Step>
</Steps>

<Callout title="The key identity">
`n & (n - 1)` removes the lowest set bit. Subtracting 1 turns the lowest 1 into 0 and every 0 below it into 1, so AND-ing with `n` wipes exactly that bit. Counting how many times you can repeat it before reaching 0 gives the number of set bits (Brian Kernighan's algorithm).
</Callout>

## Template

```text
popcount(n):                      # Brian Kernighan; negatives count as 64-bit values
    if n < 0: n = n mod 2^64      # Python only: ints have unlimited sign bits
    count = 0
    while n != 0:
        n = n & (n - 1)           # drop the lowest set bit
        count = count + 1
    return count

all_subsets(n):                   # element i is in the subset when bit i of mask is 1
    for mask in 0 .. 2^n - 1:
        subset = [i for i in 0 .. n - 1 if mask & (1 << i)]
```

## Worked example: counting bits of 13

`count_set_bits(13)` clears one bit per round: 13 = `1101`.

The same idea yields Hamming distance: `count_differing_bits(7, 10)` XORs the numbers (`0111 ^ 1010 = 1101`) and counts the 3 set bits. And `lowest_set_bit(12)` returns `12 & -12 = 4`.

## Implementation

Each language provides `is_power_of_two`, `count_set_bits`, `get_bit`, `set_bit`, `clear_bit`, `toggle_bit`, `lowest_set_bit`, `highest_set_bit`, `count_differing_bits`, `swap_without_temp`, `is_even`, `next_power_of_two` and `subset_generation` (named in camelCase in C++ and exported names in Go). C++ and Go use 64-bit `int64` values.

Negative inputs to the bit counters are treated as 64-bit two's complement values in all three languages, so `count_set_bits(-1)` is 64. The Python version masks to 64 bits first, because without it the loop would run forever: a Python `int` has infinitely many sign bits.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Precedence in C and C++.** `n & (n - 1) == 0` parses as `n & ((n - 1) == 0)`, because `==` binds tighter than `&`. Always parenthesize: `(n & (n - 1)) == 0`.
- **Forgetting `n > 0`.** `0 & -1 == 0`, so 0 passes the power-of-two test unless you exclude it.
- **Shifting by the width or more.** `1 << 32` on a 32-bit `int` is undefined behaviour in C++. Use `1LL << i` or `uint64_t` for bit positions above 30.
- **Right shift of negatives.** `>>` on a signed value is an arithmetic shift in practice: it copies the sign bit. Use unsigned types for pure bit work.
- **Negative numbers in loops.** Python integers never run out of sign bits, so `while n: n &= n - 1` never ends for negatives unless masked.
- **Too clever.** XOR swap does nothing useful on modern compilers and fails when both names refer to the same variable.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does n & (n - 1) clear the lowest set bit?">
    Write n as a prefix, a lowest 1, then zeros. Subtracting 1 turns that 1 into 0 and the zeros into 1s, leaving the prefix unchanged. AND-ing with n keeps the prefix and clears the rest.
  </FaqItem>
  <FaqItem question="Why does x & -x give the lowest set bit?">
    In two's complement, -x is ~x + 1. Inverting flips every bit, and adding 1 carries up through the trailing ones, restoring the lowest 1 and the zeros below it. Only that lowest bit is set in both x and -x.
  </FaqItem>
  <FaqItem question="How many items can a bitmask hold?">
    One machine word: 64 bits for `int64`. But enumerating subsets costs 2<sup>n</sup>, so exhaustive search is practical for n up to about 20-25.
  </FaqItem>
  <FaqItem question="Is bit manipulation always faster?">
    Not by much on its own: the compiler already turns `x * 2` into a shift. The real gains come from the algorithms, such as O(k) popcount, XOR cancellation in O(n) time and O(1) space, and subset DP.
  </FaqItem>
</Faq>
