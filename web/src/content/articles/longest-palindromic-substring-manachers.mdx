## How Manacher's algorithm works

A palindrome is centered either on a character (`aba`) or between two (`abba`). Manacher's algorithm first removes that difference: it puts a `#` between every pair of characters and at both ends, so `abc` becomes `#a#b#c#`. Now every palindrome has a single center character, and its length in the original string equals its radius in the new one.

Let `p[i]` be the radius of the longest palindrome centered at `i` in the new string. Keep the center `c` and right edge `r` of the palindrome that reaches furthest right so far.

<Steps>
  <Step title="Transform the string">
    Build `t = "#" + "#".join(s) + "#"`. A character `s[k]` sits at index `2k + 1`. There are no sentinel characters: the expansion checks both ends against the string bounds, so every character is allowed in the input, including `^` and `$`.
  </Step>
  <Step title="Start from the mirror">
    For index `i`, if `i < r`, the mirror of `i` around `c` is `2c - i`. Whatever palindrome the mirror has is also around `i`, but only as far as the edge `r`. Start with `p[i] = min(r - i, p[mirror])`.
  </Step>
  <Step title="Expand">
    Compare `t[i + p[i] + 1]` with `t[i - p[i] - 1]` and grow `p[i]` while they are equal and inside the string.
  </Step>
  <Step title="Move the boundary">
    If `i + p[i] > r`, this palindrome reaches further right: set `c = i` and `r = i + p[i]`.
  </Step>
  <Step title="Read the answer">
    The largest `p[i]` is the length of the longest palindrome, and it starts at `(i - p[i]) / 2` in the original string. The first index with the largest radius wins ties.
  </Step>
</Steps>

<Callout title="Why the mirror is safe">
Inside a palindrome centered at `c`, the string reads the same in both directions, so the neighbourhood of `i` is a copy of the neighbourhood of its mirror, as far as the edge `r`. If the mirror's palindrome fits strictly inside `[c - (r - c), r]`, it is exactly the palindrome at `i` and no comparisons are needed. If it reaches the edge, only the part beyond `r` is unknown and must be compared.
</Callout>

## Pseudocode

```text
manacher(s):
    if s is empty: return ("", 0, 0)
    t = "#" + "#".join(s) + "#"
    n = len(t); p = [0] * n
    center = 0; right = 0
    for i = 0 to n - 1:
        if i < right:
            p[i] = min(right - i, p[2 * center - i])
        while i - p[i] - 1 >= 0 and i + p[i] + 1 < n
              and t[i + p[i] + 1] == t[i - p[i] - 1]:
            p[i] += 1
        if i + p[i] > right:
            center = i; right = i + p[i]
    i = first index with the largest p[i]
    start = (i - p[i]) / 2
    return (s[start .. start + p[i] - 1], start, p[i])
```

## Implementation

Python returns `(substring, start, length)`, with code-point indices. C++ and Go return the substring only. C++ works on bytes, so a multi-byte UTF-8 palindrome is found only if its bytes are a palindrome. Go works on runes and slices the original string at rune boundaries, so multi-byte characters are never split.

## Complexity analysis

<ComplexityTable
  rows={[
    { case: 'Every case', time: 'O(n)', space: 'O(n)', when: 'The transformed string has 2n + 1 characters. Each successful comparison in the while loop moves the right edge forward, and the edge never moves back.' },
  ]}
/>

Why the expansion is cheap: when `i < r`, the start value either already equals the true radius (the mirror's palindrome ends strictly inside `r`, so the loop fails on its first comparison) or equals `r - i`, in which case the loop can only succeed by passing `r`. So every successful comparison raises `r` by one, and `r` is at most `2n`. Failed comparisons happen at most once per index.

<Equation label="Total work" expr="comparisons <= (successful, each raises r) + (failed, one per index) <= 2n + (2n + 1)" result="O(n)" />

## Applications

- **Longest palindromic substring** as a direct answer.
- **Counting palindromic substrings**, from the radii.
- **Palindrome partitioning and shortest-palindrome style problems**, where the radii say which prefixes are palindromes.
- **Bioinformatics.** Finding palindromic stretches in a sequence.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using characters from the input as sentinels.** An older version used `^` and `$` at the ends, so an input like `b^a^b^a` expanded past the sentinel. Check the bounds instead.
- **Mapping the result back wrongly.** The start in the original string is `(i - p[i]) / 2`, and the length is `p[i]`. Both come from the same transformed index.
- **Forgetting the mirror limit.** `p[i] = p[mirror]` without the `min` with `r - i` over-counts when the mirror's palindrome crosses the edge.
- **Mixing bytes and characters.** In Go the string was once transformed per rune but indexed per byte, which broke every multi-byte character. Transform and index the same units.
- **Updating the boundary too eagerly.** Move `center` and `right` only when `i + p[i] > right`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why insert # between characters?">
    It makes every palindrome odd-length in the new string, so each has one center character. Even palindromes such as `abba` get a `#` center, and no separate even case is needed.
  </FaqItem>
  <FaqItem question="Why is Manacher's algorithm linear when it has a nested loop?">
    The right boundary `r` only moves forward, and every successful comparison in the inner loop moves it. Copying from the mirror does not use comparisons. So the total number of successful comparisons is at most the length of the transformed string.
  </FaqItem>
  <FaqItem question="Which palindrome is returned when several tie?">
    The one with the earliest center, which is also the earliest start. For `babad` that is `bab`; for `cbbd` it is `bb`.
  </FaqItem>
  <FaqItem question="Is it related to the Z-algorithm?">
    Yes, in spirit. Both keep the furthest-reaching window found so far and reuse a mirrored value inside it, which is what makes them linear.
  </FaqItem>
</Faq>
