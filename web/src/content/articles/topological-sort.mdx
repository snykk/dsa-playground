## How topological sort works

An edge `u -> v` means "u must come before v". An ordering that respects every edge exists exactly when the graph has no directed cycle. Two classic algorithms build it.

**Kahn's algorithm** works from the front. A vertex with in-degree 0 has no unmet prerequisite, so it can be placed now.

<Steps>
  <Step title="Count in-degrees">
    For every vertex count the edges pointing at it. A vertex that only appears as a neighbour is counted too.
  </Step>
  <Step title="Queue the free vertices">
    Put every vertex with in-degree 0 into a queue.
  </Step>
  <Step title="Place, then release">
    Take a vertex off the queue and append it to the order. For each outgoing edge, reduce the neighbour's in-degree. A neighbour that reaches 0 joins the queue.
  </Step>
  <Step title="Compare the counts">
    If the order contains every vertex, it is valid. If vertices are left over, each of them still has an unplaced predecessor, so there is a cycle.
  </Step>
</Steps>

**The DFS version** works from the back. Run a DFS and append each vertex when it finishes. For an edge `u -> v` the vertex `v` always finishes before `u`, unless the edge closes a cycle. The reversed finish order is therefore a valid topological order.

<Callout title="Why leftover vertices prove a cycle">
Suppose Kahn's algorithm stops with vertices left. Every leftover vertex has in-degree at least 1 among the leftovers (otherwise it would have been queued). Start anywhere and keep stepping to a leftover predecessor: with finitely many vertices you must revisit one, and that walk traced backwards is a directed cycle.
</Callout>

Python's Kahn returns `[0, 5, 1, 2, 3, 4]` and its DFS version returns `[5, 0, 2, 1, 3, 4]`. Both are valid. There are 10 valid orders in all (`topological_sort_all_orders` returns them).

## Pseudocode

```text
kahn(graph):
    inDegree[v] = 0 for every vertex (keys and neighbours)
    for each edge u -> v: inDegree[v] += 1
    queue = every vertex with inDegree 0
    order = []
    while queue is not empty:
        u = queue.pop_front(); order.append(u)
        for each edge u -> v:
            inDegree[v] -= 1
            if inDegree[v] == 0: queue.push_back(v)
    if len(order) < number of vertices: report a cycle
    return order

dfsOrder(graph):
    for each unvisited vertex s: visit(s)       # a back edge to the current path is a cycle
    visit(u): mark u; visit unvisited neighbours; append u to finish list
    return reverse(finish list)
```

## Implementation

All three languages provide Kahn's algorithm and a DAG check: `topological_sort_kahn` and `is_dag` (Python), `topologicalSortKahn` and `isDAG` (C++), `TopologicalSortKahn` and `IsDAG` (Go). On a cycle, Python returns `None`; C++ and Go return an empty vector or slice. For an empty graph Kahn also returns an empty result, so use the `isDAG` function, which returns true for an empty graph and false for a cycle.

Python offers more: `topological_sort_dfs` (iterative, `None` on a cycle), `topological_sort_all_orders` (backtracking, `[[]]` for an empty graph and `[]` for a cycle), and `longest_path_dag(graph, weights, source=None)`, which returns the longest distance to every vertex, with `-inf` for vertices unreachable from `source` and an empty dictionary on a cycle. Without a `source`, every vertex with no incoming edge starts a path at distance 0.

All of them accept vertices that appear only as neighbours.

## Applications

- **Dependency resolution.** Build systems, task scheduling and course prerequisites (LeetCode 207 and 210, CSES Course Schedule).
- **Dynamic programming on DAGs.** Longest or shortest path, and counting paths (CSES Game Routes), by relaxing edges in topological order.
- **Ordering derived from comparisons.** Alien Dictionary (LeetCode 269) builds a graph of letter order and sorts it.
- **After SCC contraction.** The condensation of any directed graph is a DAG, so it can be ordered.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Counting only dictionary keys.** A vertex that is only a neighbour still needs an in-degree and a place in the order. Comparing with the number of keys makes a DAG look cyclic.
- **Confusing an empty result.** In C++ and Go, an empty list means either an empty graph or a cycle; call `isDAG` to tell them apart.
- **Reversing the wrong way.** A DFS finish order must be reversed. The order in which vertices are first visited is not topological.
- **Assuming a unique answer.** Tests should check that every edge points forward, not compare with one fixed list.
- **Self-loops.** An edge `v -> v` is a cycle: the in-degree of `v` can never reach 0.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Can a graph with a cycle be sorted?">
    No. In a cycle every vertex must come before the next one around the loop, which is impossible. Kahn's algorithm stops early, and the DFS version meets a back edge.
  </FaqItem>
  <FaqItem question="How many topological orders are there?">
    It depends on the graph: one for a simple chain, up to V! for a graph with no edges. The example above has 10. Counting them in general is hard, so `topological_sort_all_orders` is meant for small inputs.
  </FaqItem>
  <FaqItem question="Which algorithm should I use?">
    Kahn's algorithm, usually: it is iterative, it shows layers of independent tasks, and its cycle check is a simple count. Use the DFS version when you are already running a DFS.
  </FaqItem>
  <FaqItem question="How do I get the longest path in a DAG?">
    Sort topologically, then process vertices in that order: for each edge `u -> v`, set `dist[v] = max(dist[v], dist[u] + weight)`. `longest_path_dag` does this in Python.
  </FaqItem>
</Faq>
