## How the key operations work

### Cross product: left, right or straight

With `u = a - o` and `v = b - o`, the cross product is `u.x * v.y - u.y * v.x`. Its absolute value is the area of the parallelogram spanned by `u` and `v`, and its sign tells the turn from `u` to `v`: positive for a counterclockwise (left) turn, negative for a clockwise (right) turn, zero if the vectors are collinear. `orientation` just returns the sign as a code.

<Steps>
  <Step title="Subtract the origin">
    Form `a - o` and `b - o`.
  </Step>
  <Step title="Take the cross product">
    Compute `(a.x - o.x)(b.y - o.y) - (a.y - o.y)(b.x - o.x)`.
  </Step>
  <Step title="Read the sign">
    Greater than 0 gives 2 (counterclockwise), less than 0 gives 1 (clockwise), exactly 0 gives 0 (collinear).
  </Step>
</Steps>

<Callout title="Exact signs, no epsilon">
The sign is read directly, with no 1e-9 threshold. A fixed threshold is wrong at both ends of the scale: the cross product has units of length<sup>2</sup>, so at a scale of 1e-5 every triple would look collinear, and the same code would work at a scale of 1. For integer coordinates the sign is exact.
</Callout>

### Dot product and angle

The dot product `u.x * v.x + u.y * v.y` equals `|u||v|cos(theta)`. The angle is computed as `atan2(|cross|, dot)`, because `cross = |u||v|sin(theta)`. Unlike `acos(dot / (|u||v|))`, this stays accurate near 0 and pi. Using `acos`, the angle between `(1, 0)` and `(1, 1e-8)` comes out as exactly 0 instead of 1e-8.

### Point in triangle

Take the three cross products of the point against the triangle's edges, `d1 = cross(p, a, b)`, `d2 = cross(p, b, c)` and `d3 = cross(p, c, a)`. The point is inside or on the boundary if the three values never have both a negative and a positive sign. A triangle with zero area contains nothing, so a collinear or repeated vertex list returns false.

### Point in circle

Compare squared distances, so no square root is needed: `contains_point` tests `dist^2 <= r^2`, and `point_on_circle` tests `dist^2 == r^2` exactly.

Orientation of `(0,0) -> (4,4) -> (1,2)` is `4 * 2 - 4 * 1 = 4 > 0`, so the turn is counterclockwise (code 2). For `(2,1)` it is `4 * 1 - 4 * 2 = -4`, clockwise (code 1), and for `(2,2)` it is 0.

For the angle between `A = (3,4)` and `B = (2,1)` seen from the origin, `cross = -5` and `dot = 10`, so the angle is `atan2(5, 10)`, about 26.57 degrees. The cross product is negative, so B is clockwise from A.

## Pseudocode

```text
cross(o, a, b) = (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x)
dot(o, a, b)   = (a.x - o.x) * (b.x - o.x) + (a.y - o.y) * (b.y - o.y)

orientation(p, q, r):
    v = cross(p, q, r)
    if v == 0: return 0                  # collinear
    return 2 if v > 0 else 1             # counterclockwise : clockwise

angleBetweenPoints(o, a, b):
    if a == o or b == o: return 0
    return atan2(abs(cross(o, a, b)), dot(o, a, b))

pointInTriangle(p, a, b, c):
    if cross(a, b, c) == 0: return false  # degenerate triangle
    d1 = cross(p, a, b); d2 = cross(p, b, c); d3 = cross(p, c, a)
    hasNeg = any of d1, d2, d3 is < 0
    hasPos = any of d1, d2, d3 is > 0
    return not (hasNeg and hasPos)

circle.contains(p):   dist2(center, p) <= r * r
circle.onBoundary(p): dist2(center, p) == r * r
```

## Implementation

All three languages expose the same operations. Python and C++ use methods on `Point`, `Line` and `Circle` (`distance_to`, `distanceTo`) and free functions for the cross product, dot product, orientation, angle and triangle test; Go capitalizes the names (`CrossProduct`, `Orientation`, `PointInTriangle`).

Behaviors worth knowing:

- Point equality is exact: `Point(0, 0) == Point(5e-10, 0)` is false.
- A zero-length line has no direction: `slope` returns NaN and both `is_vertical` and `is_horizontal` are false. A vertical line has an infinite slope.
- A negative radius is rejected: `ValueError` in Python, `std::invalid_argument` in C++, a panic in Go (`NewCircle`).
- `angle_between_points` returns 0 when A or B coincides with O, where the angle is undefined.

## Applications

- **Convex hulls and polygon algorithms.** Orientation is the core test of Graham's scan and similar algorithms.
- **Line and segment intersection.** Built on four orientation values.
- **Collision and hit testing.** Point in triangle, point in circle.
- **Games and graphics.** Angles between directions, facing tests.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **A fixed epsilon on the cross product.** It depends on the scale, because the cross product is a length<sup>2</sup>. Compare the sign instead.
- **Computing the angle with `acos`.** It loses all precision near 0 and pi and returns 0 for small angles. Use `atan2(|cross|, dot)`.
- **Swapped orientation codes.** The codes are 1 for clockwise and 2 for counterclockwise in all three languages. Test them with exact values, never with a check that accepts either code.
- **Degenerate triangles.** With a zero-area triangle all three signs are zero and a naive test says every point is inside. Reject the triangle first.
- **Assuming collinear decimals are exact.** Convert to integers if possible.
- **Comparing computed points with `==`.** Use your own tolerance for results of arithmetic.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is there no epsilon in orientation?">
    The cross product has units of length squared, so no single absolute epsilon works at every scale. For integer input the exact sign is correct. For decimals, scale to integers when borderline cases matter.
  </FaqItem>
  <FaqItem question="What do the orientation codes mean?">
    0 means the three points are collinear, 1 means that walking p, q, r turns clockwise (right), and 2 means counterclockwise (left).
  </FaqItem>
  <FaqItem question="Does point_in_triangle include the edges?">
    Yes. A point on an edge or at a vertex counts as inside. A triangle with zero area contains no point.
  </FaqItem>
  <FaqItem question="Why compare squared distances for circles?">
    Squaring both sides keeps the test in multiplications, with no square root and no extra rounding. It is valid because both sides are non-negative.
  </FaqItem>
</Faq>
