## What pattern matching is

Given a text of length `n` and a pattern of length `m`, report every index `i` such that `T[i..i+m-1] == P`. Matches may overlap: searching `aa` in `aaaa` gives `[0, 1, 2]`.

All four algorithms here return the same thing, a list of start indices in increasing order. They differ only in how much work they do to find them, and that comes down to one question: after a mismatch, how much of what you already learned can you reuse?

<DataTable
  columns={['Algorithm', 'Preprocessing', 'Idea', 'Matching time']}
  rows={[
    ['Naive', 'none', 'compare the pattern at every alignment, forget everything on a mismatch', 'O(n*m)'],
    ['KMP', 'O(m): the LPS table', 'never move the text pointer back; shift the pattern by a border of what matched', 'O(n)'],
    ['Rabin-Karp', 'O(m): the pattern hash', 'compare a hash of each window first, characters only when the hashes agree', 'O(n) expected, O(n*m) worst'],
    ['Boyer-Moore (bad character)', 'O(m): last-occurrence table', 'compare right to left and jump by the mismatching character', 'O(n/m) best, O(n*m) worst'],
  ]}
/>

This topic is the overview and the code of all four side by side. Each algorithm has its own article with the full analysis; see the links at the end.

    ['`bad_char_table(pattern)`', 'the last index of each character of the pattern', 'O(m)'],
    ['`boyer_moore_search(text, pattern)`', 'all start indices, right-to-left with bad-character shifts', 'O(n/m) best, O(n*m) worst'],
  ]}
/>

An **empty pattern** occurs at every position `0..n` in all four, so `search("abc", "")` returns `[0, 1, 2, 3]`. A pattern **longer than the text** returns `[]`. Offsets are code points in Python and bytes in C++ and Go.

## The key idea: reuse what matched

Take the pattern `ababaca` and the text `abababaca`. After five matching characters the pattern meets a mismatch (`c` against `b`). The naive scan would throw the five characters away and restart one position to the right. KMP notices that the matched part `ababa` ends with `aba`, which is also a prefix of the pattern, so those three characters are already matched at the next alignment.

The LPS table stores exactly that, one number per prefix:

The loop runs 9 times (one per text character examined). Naive search on the same input compares up to `m` characters at each of 3 alignments.

<Callout title="Why KMP is linear">
`i` only ever increases, and each time `j` falls back through the LPS table it strictly decreases. `j` can fall back at most as many times as it has grown, and it grows at most `n` times in total. So the matching loop does at most 2n steps.
</Callout>

## Pseudocode

```text
naive(T, P):
    for i = 0 to n - m:
        if T[i .. i+m-1] == P: report i

lps(P):
    lps[0] = 0; len = 0; i = 1
    while i < m:
        if P[i] == P[len]:   len += 1; lps[i] = len; i += 1
        elif len != 0:       len = lps[len - 1]
        else:                lps[i] = 0; i += 1

kmp(T, P):
    if m == 0: report 0..n; return
    i = 0; j = 0
    while i < n:
        if P[j] == T[i]: i += 1; j += 1
        if j == m: report i - j; j = lps[j - 1]
        elif i < n and P[j] != T[i]:
            if j != 0: j = lps[j - 1]
            else:      i += 1

rabin_karp(T, P):                       # d = 256, q = 101
    hp = hash(P); ht = hash(T[0 .. m-1]); h = d^(m-1) mod q
    for i = 0 to n - m:
        if hp == ht and T[i .. i+m-1] == P: report i
        ht = (d * (ht - T[i] * h) + T[i+m]) mod q

boyer_moore(T, P):                      # bad character only
    last = last index of each character in P
    s = 0
    while s <= n - m:
        j = m - 1
        while j >= 0 and P[j] == T[s + j]: j -= 1
        if j < 0: report s; s += 1
        else:     s += max(1, j - last.get(T[s + j], -1))
```

## Complexity

<DataTable
  columns={['Algorithm', { label: 'Best', kind: 'mono' }, { label: 'Worst', kind: 'mono' }, { label: 'Extra space', kind: 'mono' }, 'Worst input']}
  rows={[
    ['Naive', 'O(n)', 'O(n*m)', 'O(1)', '`aaaa...a` against `aaa...ab`'],
    ['KMP', 'O(n + m)', 'O(n + m)', 'O(m)', 'none: the bound always holds'],
    ['Rabin-Karp', 'O(n + m)', 'O(n*m)', 'O(1)', 'many windows whose hash equals the pattern hash'],
    ['Boyer-Moore (bad char)', 'O(n/m)', 'O(n*m)', 'O(sigma + m)', 'periodic text such as `aaaa...a` with a pattern like `baa`'],
  ]}
/>

The Python and C++ naive searches copy a window (`text[i:i+m]`, `text.substr(i, m)`) at each alignment, so their constant factor is worse than a character loop, but the O(n*m) bound is the same. Go compares a string slice, which does not copy. The Python Rabin-Karp computes each power with `pow(d, m-i-1, q)`, so building the first two hashes is O(m log m) rather than the O(m) of a Horner loop.

<Callout tone="warning" title="Rabin-Karp with q = 101 collides often">
With a modulus of 101, about one window in 101 shares the pattern hash by chance. Such a spurious hit is rejected by the character comparison, so the result is always correct, but the running time moves toward O(n*m) on adversarial text. Use a large prime in real code.
</Callout>

## Applications

- **Text editors and search tools.** Find and replace, `grep`-like scans of a file.
- **Bioinformatics.** Locating a short DNA motif in a long genome.
- **Plagiarism and duplicate detection.** Rabin-Karp style hashing of windows.
- **Network filters.** Scanning packets for known signatures, usually many patterns at once.

For everyday code, use the standard library (`str.find`, `std::string::find`, `strings.Index`): it is tuned and tested. The code in this topic is for learning how the algorithms work.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Empty pattern.** It must not crash: it occurs at every position `0..n`. All four functions here return `[0..n]`.
- **Pattern longer than the text.** Return `[]`. Rabin-Karp must check `m > n` before it hashes the first window.
- **Moving `i` back in KMP.** On a mismatch only `j` falls back (`j = lps[j-1]`). Resetting `i` makes it quadratic again.
- **Stopping after the first match.** After a full match KMP continues with `j = lps[j-1]`, which finds overlapping matches; Boyer-Moore here moves by 1.
- **Bytes versus characters.** C++ and Go index bytes, Python indexes code points, so offsets in non-ASCII text differ between languages.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What does lps[i] mean?">
    It is the length of the longest proper prefix of `pattern[0..i]` that is also a suffix of it. For `ababaca` the table is `[0, 0, 1, 2, 3, 0, 1]`. After matching `j` characters and hitting a mismatch, the next candidate is `lps[j-1]` characters long.
  </FaqItem>
  <FaqItem question="Why not always use Boyer-Moore?">
    Its good case, O(n/m), needs a long pattern and a large alphabet. On a binary alphabet or a short pattern the shifts are small, and the bad-character rule alone can degrade to O(n*m). KMP is predictable in every case.
  </FaqItem>
  <FaqItem question="How do I search for several patterns at once?">
    Hash all patterns with Rabin-Karp when they share a length, or build an Aho-Corasick automaton, which generalises the KMP table to a set of patterns and scans the text once.
  </FaqItem>
  <FaqItem question="Which topic should I read next?">
    The KMP article for the full proof and trace, then Rabin-Karp for rolling hashes and Boyer-Moore for the skip idea. The Z-algorithm is another route to the same linear bound.
  </FaqItem>
</Faq>
