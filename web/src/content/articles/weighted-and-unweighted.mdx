## What the two kinds are

In an **unweighted** graph an edge either exists or it does not. The length of a path is its number of edges. In a **weighted** graph each edge carries a number, its weight, and the length of a path is the sum of its weights.

The `WeightedGraph` class here stores an adjacency list of `(neighbor, weight)` pairs and serves both kinds: an edge added without a weight gets weight 1.0, so an "unweighted" graph is just one where every weight is 1.0.

<Callout title="Weight changes the meaning of shortest">
In an unweighted graph the shortest path has the fewest edges. In a weighted graph it has the smallest total weight, and those two paths can be different.
</Callout>

Python also has `get_edges`, `get_vertices`, `dfs`, `dfs_recursive` and `is_connected` (undirected only). C++ and Go have the operations above plus `bfs`. Adding an existing edge again **updates its weight**: `add_edge(0, 3, 1)` after `add_edge(0, 3, 10)` leaves one edge of weight 1 and lowers the total from 22 to 13 in the graph above.

### Total weight

For the graph above, the undirected edges once each weigh 4 + 1 + 2 + 5 + 10 = 22, and `get_total_weight()` returns it as the float `22.0`, because the sum starts at `0.0`. The method deduplicates the mirror entries; on a directed graph it just sums all entries.

### Zero and negative weights

Weights are plain numbers, so 0 and negative values are stored and returned as given (`get_weight` returns them; `has_edge` reports the edge). Storing a negative weight is easy. Using it is the hard part, because many algorithms assume weights are non-negative (see below). In C++ and Go an absent edge also returns -1.0 from `get_weight`, so use `has_edge` first when negative weights are possible.

### Weights change the answer: BFS versus Dijkstra

BFS ignores weights. From vertex 0 it reaches vertices 1 and 3 in one hop each, so it reports the direct edges as the "shortest" paths. Dijkstra's algorithm, which sums weights, finds cheaper routes through vertex 2:

## Applications

- **Routing and navigation:** distances or travel times on road networks.
- **Network design:** latency or bandwidth costs, minimum spanning trees for cabling.
- **Scheduling and planning:** costs of moving between states.
- **Game pathfinding:** terrain costs, with A* on top.
- **Unweighted special cases:** social graphs, mazes and grids, where BFS is enough.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Running BFS on a weighted graph** and calling the result the shortest path. It minimizes edges, not cost.
- **Running Dijkstra with negative weights.** It can return wrong answers; use Bellman-Ford.
- **Treating a weight of 0 as "no edge".** Here an edge with weight 0 exists; check with `has_edge`.
- **Using -1.0 as a missing-edge marker** (C++ and Go `get_weight`) when -1 can be a real weight.
- **Comparing float sums with `==`.** Use a tolerance, or integer weights.
- **Updating only one direction** of an undirected edge. `add_edge` and `remove_edge` handle both for you.
- **Summing all list entries** to get the total weight of an undirected graph: that counts every edge twice.
</Callout>

## Implementation

All three versions store an adjacency list of `(neighbor, weight)` pairs. Python and C++ keep tuples or pairs in a map. Go stores `Edge{To, Weight}` structs and requires the weight argument, so pass 1.0 for an unweighted edge.

## Frequently asked questions

<Faq>
  <FaqItem question="Is an unweighted graph the same as a weighted graph with all weights 1?">
    For shortest-path purposes, yes: with every weight equal to 1 the cheapest path is the one with the fewest edges, which BFS finds faster than Dijkstra. This class stores the weight 1.0 for you when none is given.
  </FaqItem>
  <FaqItem question="Why can BFS not find shortest paths in a weighted graph?">
    BFS expands vertices in order of the number of edges, not the total weight. A path with more edges can be cheaper, as 0 - 2 - 3 (cost 6) beats the direct edge 0 - 3 (cost 10).
  </FaqItem>
  <FaqItem question="Which algorithm handles negative edge weights?">
    Bellman-Ford handles them and detects negative cycles. Dijkstra requires non-negative weights.
  </FaqItem>
  <FaqItem question="What happens when I add an edge that already exists?">
    The old edge is replaced, so its weight is updated and the graph still has one edge between the two vertices.
  </FaqItem>
</Faq>
