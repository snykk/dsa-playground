## How Dinic's algorithm works

A flow network is a directed graph with a capacity on every edge, a source `s` and a sink `t`. Like Ford-Fulkerson and Edmonds-Karp, Dinic keeps a **residual graph**: an edge `u -> v` with capacity `c` and flow `f` leaves an entry `u -> v` with `c - f` of room, and a reverse entry `v -> u` with `f`, through which later flow can cancel it.

Edmonds-Karp runs a whole BFS for every augmenting path. Dinic runs one BFS per **phase** and then pushes flow along as many shortest paths as it can before the next one.

<Steps>
  <Step title="Build the residual graph">
    Copy every capacity and add a reverse entry of 0 for each edge, as Edmonds-Karp does. Sort the entries of every vertex by neighbour: every search tries them in that order.
  </Step>
  <Step title="BFS: the levels">
    A BFS from `s` over the entries with room gives every vertex it reaches a **level**, its distance in residual edges. If `t` has no level, stop.
  </Step>
  <Step title="The level graph">
    Keep only the entries with room that go exactly one level deeper. Every path from `s` to `t` in this level graph is a shortest augmenting path.
  </Step>
  <Step title="DFS with current arcs: a blocking flow">
    Search from `s`, stepping only one level deeper. Each vertex keeps a pointer, its **current arc**, to the first entry not yet found useless; a vertex with no entry left is a dead end, and the vertex before it moves its pointer on. When a search reaches `t`, push the bottleneck along the path and search again from `s`, with every pointer where it was.
  </Step>
  <Step title="Repeat">
    When the search backs out of `s`, every path of the level graph has a full entry: the flow of the phase is **blocking**. Run the next BFS, which finds `t` at a deeper level or not at all.
  </Step>
</Steps>

<Callout title="Why a pointer never has to move back">
Inside a phase the levels are fixed. Pushing flow along a level-graph entry only empties it, and the reverse entry it fills points one level back, which the searches never take. So an entry that is full, goes to the wrong level or leads to a dead end stays useless until the phase ends, and the pointers only move forward. When the last BFS misses the sink, the vertices it reached form the source side of a minimum cut.
</Callout>

The maximum flow is 12 + 4 + 7 = 23, after 3 phases (the last BFS included) and 40 entry visits. In search 2 of phase 1, vertex 1 does not look at its entries to 0 and 2 again: search 1 already moved its pointer past them. Edmonds-Karp takes the same three paths on this network, with one BFS for each and a fourth to stop; Dinic runs three BFS in all.

## Pseudocode

```text
dinic(graph, s, t):
    if s == t: return 0
    residual = copy of graph, plus a reverse entry of 0 for every edge
    adj[u] = residual entries of u, sorted by neighbour
    maxFlow = 0
    loop:                                        # one phase
        level = BFS from s over entries with residual > 0
        if t has no level: return maxFlow        # the vertices with a level: a minimum cut
        current[u] = 0 for every u
        while (path = findPath()) is not None:
            maxFlow += push the bottleneck along path

findPath():                                      # recursive form; the code keeps a list
    dfs(u):
        if u == t: return [t]
        while current[u] < len(adj[u]):
            v = adj[u][current[u]]
            if residual[u][v] > 0 and level[v] == level[u] + 1:
                rest = dfs(v)
                if rest is not None: return [u] + rest    # the pointer stays on v
            current[u] += 1                              # useless for the rest of the phase
        return None                                      # u is a dead end
    return dfs(s)
```

## Implementation

Each language takes the same input as Edmonds-Karp, a map `u -> {v: capacity}`, and has two functions. `dinic` returns the flow value. `dinic_flow` in Python, `dinicFlow` in C++ and Go, returns the value, the flow on every edge of the input, `source_side` (the vertices the last BFS reached, increasing), the number of phases (every BFS, the last one included) and the number of entries the searches looked at. The C++ and Go results are a `DinicResult` struct.

**Which flow comes back.** A network can have many maximum flows. Every search tries the entries of a vertex in increasing order of the neighbour, so Python, C++ and Go return the same flow on every edge and the same counts: the C++ and Go tests check 40 networks against outputs of the Python code. Only the value and the source side of the cut are the same for every order.

**Edge cases, as in Edmonds-Karp.** `source == sink` returns 0, with every flow 0, no phase and the source alone on its side. An unreachable sink returns 0 after one BFS. A map holds one capacity per edge, so parallel edges are given as one edge with their summed capacity. Anti-parallel edges share their residual entries, and only their net flow is defined: it goes to the edge it runs along, and the other edge reports 0. Zero capacities and self-loops never carry flow. Nothing raises an error.

**Numbers and depth.** Python integers never overflow and Go's `int` is 64-bit; in C++ the capacities are `int`, but the residual graph, the flows and the total are `long long`, so two paths of `INT_MAX` give 4294967294. The search keeps its path in a list in all three languages, so a chain of 5000 vertices works in Python, where a recursive search fails at about 1000.

## Complexity analysis

Let `V` be the number of vertices and `E` the number of edges. A blocking flow leaves no augmenting path of the current length, so the sink's level grows by at least one every phase. It is at most V - 1, so at most V - 1 phases push flow.

  ]}

<Equation label="Dinic" expr="O(V) phases x O(V E) per blocking flow" result="O(V^2 E)" />

A **unit network** has capacity 1 everywhere, and every vertex other than the source and the sink has a single entering or a single leaving edge, like the network built for bipartite matching. After sqrt(V) phases every augmenting path is longer than sqrt(V). The flow still missing splits into paths that share no vertex, so at most sqrt(V) units are missing, and every later phase adds at least one.

A search that started every vertex at its first entry again would walk past them in every search, about 2.5 k^2 visits: 257,441 for k = 320. The 80-component network is close to the worst case for unit networks, one phase per path length.

## Applications

- **Maximum flow and minimum cut** on networks too large for one BFS per path: traffic, pipelines, data transfer.
- **Matching and disjoint paths.** Bipartite matching and vertex-disjoint paths, with every vertex split in two, are unit networks, where Dinic runs in O(E sqrt(V)). Edge-disjoint paths have capacity 1 everywhere, so each phase costs O(E).
- **Minimum vertex cuts.** Split every vertex into an in copy and an out copy joined by an edge of the vertex's cost; the cut then picks vertices.
- **Project selection.** Profits from the source, costs to the sink; the minimum cut separates the chosen projects from the rest.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **No current arc.** Every search walks past the same full entries and dead ends again; the comb above goes from 7k + 1 to about 2.5 k^2 visits. The value stays right, the bound is lost.
- **Not resetting the pointers each phase.** The levels change, so the BFS keeps finding the sink while every search fails at once, and the loop never ends; on the classic network it stalls at a flow of 16.
- **Moving the pointers after a push.** An entry on the path may still have room; the phase then ends before its flow is blocking, and the next BFS can find the sink at the same level again.
- **Recursion depth.** A path can be as long as the graph; keep it in a list, or raise the recursion limit.
- **Overflow in C++.** Keep the residual graph, the flows and the total in `long long`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What does the current arc save?">
    Within a phase, an entry that is full, goes to the wrong level or leads to a dead end stays useless. Without a pointer, every search would look at it again; with it, each vertex starts where its last search stopped, so a phase passes each entry at most once.
  </FaqItem>
  <FaqItem question="Why does the sink's level grow every phase?">
    At the BFS, every entry with room climbs at most one level, and the reverse entries the pushes open point one level back. A path to the sink as short as before would have to climb one level at every step, so it would use only level-graph entries, and the blocking flow left a full entry on every such path. So the next BFS finds the sink deeper, and since its level is at most V - 1, at most V - 1 phases push flow.
  </FaqItem>
  <FaqItem question="How is it related to Hopcroft-Karp?">
    On the flow network of a bipartite matching, a Dinic phase is a BFS for the levels and then shortest augmenting paths that share no vertex, since every left vertex has one entering edge and every right vertex one leaving edge, each of capacity 1. A Hopcroft-Karp phase does the same on the bipartite graph itself. The two codes do not always pick the same paths, so their numbers of phases can differ, but both stay within O(sqrt(V)).
  </FaqItem>
  <FaqItem question="Is the returned flow the only maximum flow?">
    Usually not. Only the value is unique, and so is the set of vertices the source still reaches at the end. The flow on each edge depends on the order the searches try the edges, which is why the code fixes it.
  </FaqItem>
</Faq>
