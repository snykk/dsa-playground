## What a Cartesian tree is

Given a sequence, its Cartesian tree is the one binary tree with two properties at once:

- **Order by position:** the in-order traversal returns the sequence unchanged. Everything left of a node in the array is in its left subtree, and everything right of it is in its right subtree.
- **Heap order by value:** every node is `<=` its children, so the root is the minimum of the array.

The two properties fix the tree. The root must be the minimum (leftmost if there are ties); the part of the array to its left becomes the left subtree and the part to its right becomes the right subtree, recursively. Equal values: the later one becomes a descendant of the earlier one, so the leftmost minimum is always the ancestor.

## Building in O(n)

Process the array left to right and keep a stack that holds the **right spine** of the tree built so far (values increasing from the bottom). For each new value `v`:

<Steps>
  <Step title="Pop larger values">
    While the top of the stack is strictly greater than `v`, pop it. The last popped node is the root of the subtree that now belongs below `v`.
  </Step>
  <Step title="Hang the popped subtree on the left">
    The last popped node becomes the left child of the new node.
  </Step>
  <Step title="Attach to the spine">
    If the stack is not empty, the new node becomes the right child of the top. Push the new node. The root is the bottom of the stack at the end.
  </Step>
</Steps>

Each value is pushed once and popped at most once, so the whole build is O(n). Because only strictly greater values are popped, an equal value stays on the stack and the new one hangs to its right.

## Range minimum query

The minimum of `array[l..r]` is the **lowest common ancestor** of the nodes at positions `l` and `r`. By heap order the LCA is smaller than everything below it, and by position order it lies between `l` and `r`. So the code just walks down from the root:

<Steps>
  <Step title="Start at the root">
    Look at the index `i` of the current node.
  </Step>
  <Step title="Move toward the range">
    If `i < l`, the node is left of the range, so every candidate is in its right subtree: go right. If `i > r`, go left.
  </Step>
  <Step title="Stop inside the range">
    The first node with `l <= i <= r` is the answer.
  </Step>
</Steps>

Query `[4, 8]` on the array above (values 8, 12, 10, 20, 15):

Other queries (checked against the code): `[0, 2]` gives index 1 (value 3), `[5, 9]` gives index 6 (value 10), `[6, 10]` gives index 10 (value 5).

The cost is the depth of the LCA, at most the tree height h. The answer for ties is the leftmost minimum. To answer queries in O(1), compute the LCA with an Euler tour and a sparse table; this repository walks the tree, so a query is O(h), not O(1).

## Implementation

The three languages build the tree the same way and keep the original array for range checks.

- `get_min_index` walks from the root (an earlier version searched the whole tree, O(n) per query).
- Traversals, height, size and destruction are iterative in Python and C++, so a chain from sorted input (n = 10<sup>6</sup> in the C++ tests) does not overflow the stack. Go uses recursion, which is safe because goroutine stacks grow.
- C++ `buildFromArray` frees the previous tree, and the class is not copyable.
- C++ has `getRootValue` (`INT_MIN` when empty) and Go `GetRootValue` (`-1` when empty); Python has no such method, use `tree.root.value`.
- The Go package has a small `main`, so `go run .` works.

The height h depends on the data. Random data gives O(log n) in expectation. A sorted array gives a chain with h = n - 1, so every query can cost O(n). Space is O(n) for the nodes plus a copy of the array.

## Applications

- **Range minimum queries** through LCA.
- **Treaps:** the shape of a treap is the Cartesian tree of its (key, priority) pairs.
- **Largest rectangle in a histogram** and similar "nearest smaller element" problems: the stack in the build is the same stack. Related problems are LeetCode 84 (Largest Rectangle in Histogram) and LeetCode 654 (Maximum Binary Tree), which builds the max version of this tree.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Searching the whole tree for a range.** Once a node lies inside the range it is already the minimum of its subtree, so there is nothing to explore below it.
- **Popping on `>=`.** This code pops only strictly greater values, so ties keep the leftmost element as the ancestor. Popping on `>=` changes which of the equal minima a query returns.
- **Recursing on sorted input.** The tree is a chain; recursive traversal or destruction overflows the stack.
- **Forgetting that the range is inclusive and validated.** `get_min_index(l, r)` returns -1 for `l < 0`, `r >= n`, `l > r` or an empty tree.
- **Calling it a balanced tree.** Its shape is dictated by the data.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is the Cartesian tree unique?">
    Yes, once ties are broken by a fixed rule. The root is the minimum (here the leftmost one), and the left and right parts of the array recurse independently, so there is exactly one tree.
  </FaqItem>
  <FaqItem question="Why is the build O(n) even though it has a nested loop?">
    Each element is pushed once and popped at most once, so the total number of pops over the whole run is at most n.
  </FaqItem>
  <FaqItem question="Why is the range minimum the LCA?">
    The LCA of the nodes at positions l and r lies between them in the array (in-order is the array) and is an ancestor of both, so it is no larger than either end and, by heap order, no larger than anything in the range below it.
  </FaqItem>
  <FaqItem question="How is a treap related?">
    A treap is the Cartesian tree whose positions are the sorted keys and whose values are random priorities. Random priorities make a random shape with expected height O(log n).
  </FaqItem>
</Faq>
