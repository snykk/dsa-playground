## How Prim's algorithm works

Prim's algorithm looks like Dijkstra's algorithm, with one difference in the priority: Dijkstra ranks a vertex by its total distance from the source, Prim ranks it by the weight of **one edge** that connects it to the tree.

<Steps>
  <Step title="Start the tree">
    Put the start vertex in the tree. Push all its edges into a min-heap, ordered by weight.
  </Step>
  <Step title="Take the cheapest crossing edge">
    Pop the lightest edge from the heap. If its far end is already in the tree, it is a stale entry: ignore it.
  </Step>
  <Step title="Add the new vertex">
    Otherwise the edge joins a new vertex to the tree. Keep the edge, mark the vertex, and push every edge from it to a vertex that is still outside.
  </Step>
  <Step title="Repeat">
    Continue until the heap is empty or the tree has V - 1 edges. Vertices that cannot be reached from the start are never added.
  </Step>
</Steps>

<Callout title="Why the cheapest crossing edge is safe: the cut property">
At any moment the tree and the remaining vertices form a cut. Every edge in the heap that still crosses the cut leaves the tree. The lightest edge across any cut belongs to some minimum spanning tree, so adding it can never rule out an optimal answer. Repeating this V - 1 times produces a minimum spanning tree.
</Callout>

## Pseudocode

```text
primHeap(graph, start):                         # adjacency list
    heap = [(0, start, start)]                  # (weight, from, to)
    visited = {}; mst = []; total = 0
    while heap is not empty:
        w, from, to = heap.popMin()
        if to in visited: continue              # stale entry
        visited.add(to)
        if from != to: mst.append((from, to, w)); total += w
        for (nb, w2) in graph.get(to, []):
            if nb not in visited: heap.push((w2, to, nb))
    return mst, total

primMatrix(matrix, start):                      # O(V^2), no heap
    key[v] = infinity; key[start] = 0; parent[v] = none
    repeat V times:
        u = unvisited vertex with the smallest key
        if none: break
        visit u; if parent[u] exists: add edge (parent[u], u, key[u])
        for v with matrix[u][v] != 0 and v unvisited and matrix[u][v] < key[v]:
            key[v] = matrix[u][v]; parent[v] = u
```

Notes:

- Every version is the lazy variant: stale entries are skipped when popped, so the heap can hold up to E entries.
- The matrix version uses `0` for "no edge", so it cannot represent an edge of weight 0. Negative weights are supported.
- A vertex that appears only in neighbor lists (not as a key) is handled in the Python and Go dictionary versions. In C++ the graph is a vector, so every vertex has a row.
- On a graph with no vertices, or a single vertex, every version returns no edges.

On a dense graph E is about V<sup>2</sup>, so the heap version costs O(V<sup>2</sup> log V) and the array version, at O(V<sup>2</sup>), wins. On a sparse graph the heap version is better.

## Disconnected graphs

Prim's algorithm grows one tree, so it covers only the component of the start vertex. For edges `(0,1,1), (2,3,1)` on 4 vertices, `prim_mst_edge_list` returns just `[(0, 1, 1)]` with total 1, while Kruskal returns both edges (total 2). To get a spanning forest with Prim, restart from every vertex that is still unvisited. Check that the result has V - 1 edges before treating it as a spanning tree.

## Prim vs Dijkstra

The loops are almost identical: a priority queue, a visited set and relaxation of the edges of the vertex just taken. Dijkstra pushes `dist[v] + w`, the length of a whole path; Prim pushes `w`, a single edge. Because of that, a spanning tree from Prim is not a shortest-path tree, and Dijkstra's tree is not a minimum spanning tree.

## Applications

- **Network design:** the cheapest set of links that connects every site, for cables, pipes or roads.
- **Clustering:** cutting the heaviest tree edges leaves clusters.
- **Approximation:** a minimum spanning tree is the first step of the metric travelling-salesman 2-approximation.
- **Image segmentation and maze generation:** a randomized Prim (random weights) builds mazes.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using the total distance as the priority.** That is Dijkstra, and it builds a shortest-path tree, not a minimum spanning tree.
- **Stopping at `len(graph)` vertices.** If a vertex appears only as a neighbor, `len(graph)` undercounts and the loop ends early. The code here runs until the heap is empty.
- **No stale check.** Without the `visited` test, an edge to a vertex already in the tree would be added again and create a cycle.
- **Zero-weight edges in a matrix.** The matrix version treats 0 as "no edge".
- **Assuming a connected graph.** A disconnected input returns a smaller tree without any error.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Does the start vertex change the result?">
    Not the total weight. The tree is the same unless edge weights tie, in which case a different tree of equal weight can come out.
  </FaqItem>
  <FaqItem question="Heap or matrix version?">
    Use the heap on sparse graphs (E much smaller than V<sup>2</sup>). Use the array and matrix version on dense graphs, where O(V<sup>2</sup>) beats O(E log V).
  </FaqItem>
  <FaqItem question="Does Prim's algorithm work with negative weights?">
    Yes. It only compares weights. The matrix version treats every non-zero entry as an edge, negative ones included.
  </FaqItem>
  <FaqItem question="How is Prim different from Dijkstra?">
    Dijkstra's priority is the distance from the source through a path; Prim's is the weight of one connecting edge. The answers differ: a minimum spanning tree minimizes total edge weight, not distances from a vertex.
  </FaqItem>
</Faq>
