## How line intersection works

Everything is built from the **cross product**, `cross(o, a, b) = (a.x - o.x)(b.y - o.y) - (a.y - o.y)(b.x - o.x)`. Its sign says on which side of the line through `o` and `a` the point `b` lies: positive on the left, negative on the right, zero on the line.

### Infinite lines

Write the first line as `P = p1 + t(p2 - p1)` and the second as `P = p3 + u(p4 - p3)`. Setting them equal gives two equations in `t` and `u`. With `d1 = p2 - p1` and `d2 = p4 - p3` the solution is `t = cross(p3 - p1, d2) / cross(d1, d2)`. The denominator `cross(d1, d2)` is the code's `denom`. If it is exactly 0 the lines are parallel (or coincide), and there is no single intersection point.

### Segments

Segments need a yes or no decision first. Four orientation values decide it:

<Steps>
  <Step title="Compute four orientations">
    `o1 = cross(p1, p2, p3)`, `o2 = cross(p1, p2, p4)`, `o3 = cross(p3, p4, p1)` and `o4 = cross(p3, p4, p2)`.
  </Step>
  <Step title="Proper crossing">
    If `o1` and `o2` have strictly opposite signs, and `o3` and `o4` have strictly opposite signs, each segment straddles the line of the other, so they cross.
  </Step>
  <Step title="Endpoint on the other segment">
    If an orientation is 0, that endpoint is on the other segment's line. It then counts only if it also lies in the bounding box of that segment. This covers T-junctions, shared endpoints, collinear overlap and zero-length segments.
  </Step>
  <Step title="Otherwise they miss">
    No rule applies, so the segments do not meet.
  </Step>
</Steps>

<Callout title="Why exact comparisons are safe here">
The tests only ask whether a number is exactly zero or which sign it has. For integer coordinates these cross products are exact in Python (any size), and in C++ and Go as long as they stay below 2<sup>53</sup>. A tolerance such as 1e-9 would fail: it is an absolute threshold on a quantity measured in length<sup>2</sup>, so at a scale of 1e-5 it calls every pair parallel.
</Callout>

## Pseudocode

```text
cross(o, a, b) = (a.x - o.x) * (b.y - o.y) - (a.y - o.y) * (b.x - o.x)

lineIntersection(l1, l2):
    denom = (x1 - x2) * (y3 - y4) - (y1 - y2) * (x3 - x4)
    if denom == 0: return none                  # parallel, coincident, or a zero-length line
    t = ((x1 - x3) * (y3 - y4) - (y1 - y3) * (x3 - x4)) / denom
    return (x1 + t * (x2 - x1), y1 + t * (y2 - y1))

segmentsIntersect(l1, l2):
    o1 = cross(p1, p2, p3);  o2 = cross(p1, p2, p4)
    o3 = cross(p3, p4, p1);  o4 = cross(p3, p4, p2)
    if sign(o1) * sign(o2) < 0 and sign(o3) * sign(o4) < 0: return true
    if o1 == 0 and inBox(p1, p2, p3): return true     # p3 lies on segment 1
    if o2 == 0 and inBox(p1, p2, p4): return true
    if o3 == 0 and inBox(p3, p4, p1): return true
    if o4 == 0 and inBox(p3, p4, p2): return true
    return false

segmentIntersection(l1, l2):
    if not segmentsIntersect(l1, l2): return none
    if denom == 0:                                   # collinear overlap, touching, or a point segment
        return the larger of the two lower ends, ordering points by (x, y)
    if o1 == 0: return p3   (and o2 -> p4, o3 -> p1, o4 -> p2)   # an endpoint, returned exactly
    return lineIntersection(l1, l2)

pointOnSegment(p, line):
    return cross(p1, p2, p) == 0 and inBox(p1, p2, p)
```

## Implementation

The four functions are `line_intersection` (infinite lines, a point or nothing), `segment_intersection` (one common point or nothing), `segments_intersect` (a yes or no) and `point_on_segment`. A `Line` holds two points and is used as a segment or as the infinite line through them.

When segments overlap along a line there are infinitely many common points. `segment_intersection` then returns the first one in (x, y) order, and returns an endpoint exactly in the touching cases. `line_intersection` returns nothing for coincident lines, because they have no single intersection point, and for a `Line` whose two endpoints are equal.

## Applications

- **Polygon tests.** Segment intersection tests are the building block for checking whether a polygon is simple and for polygon clipping.
- **Geometry in games and graphics.** Ray and wall collisions, line of sight.
- **GIS and CAD.** Overlaying roads, boundaries and plans.
- **Map and routing checks.** Detecting crossing roads or paths.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Dividing first.** Computing `t` and `u` and testing `0 <= t <= 1` rejects every parallel case, including collinear overlap, and loses endpoints to rounding. Decide with orientations, then compute the point.
- **An absolute epsilon.** Writing `abs(denom) < 1e-9` is a threshold on length<sup>2</sup>; at a scale of 1e-5 every pair counts as parallel.
- **Forgetting the bounding box in the collinear case.** Zero orientations only say that the point is on the line; you still need to check that it lies between the endpoints.
- **Forgetting zero-length segments.** A segment whose endpoints are equal is a point. The orientation tests handle it, a parametric formula does not.
- **Treating `line_intersection` as a segment test.** It works on infinite lines; the point it returns may be outside both segments.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What does segment_intersection return for collinear overlapping segments?">
    The first shared point in (x, y) order, for example `(1, 0)` for `(0,0)-(2,0)` and `(1,0)-(3,0)`. Use `segments_intersect` if you only need to know whether they meet.
  </FaqItem>
  <FaqItem question="Why does line_intersection return nothing for coincident lines?">
    Two identical lines share infinitely many points, so there is no single point to return. The code treats them like parallel lines.
  </FaqItem>
  <FaqItem question="Can I use decimal coordinates?">
    Yes. Shared endpoints are still detected exactly, because the cross product with a repeated point is exactly zero. For other near-degenerate cases the result is only as exact as floating point, so scale decimals to integers if borderline cases matter.
  </FaqItem>
  <FaqItem question="How do I find all intersections among many segments?">
    Checking all pairs costs O(n<sup>2</sup>). Sweep-line algorithms such as Bentley-Ottmann do better when there are few intersections; they are not implemented in this repository.
  </FaqItem>
</Faq>
