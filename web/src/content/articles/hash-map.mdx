## What a hash map is

A map (also called dictionary or associative array) is an abstract data type: a collection of `key -> value` pairs with unique keys. A **hash map** implements it with hashing: the key is hashed to a bucket, and the pair is found by looking only in that bucket. "Hash table" is the name usually given to the underlying structure, and "hash map" to the interface, but the two terms are used interchangeably.

In this repository the Hash Map code is the Hash Table with extra methods:

- **Python:** `HashMap` subclasses `HashTable`.
- **C++:** the `HashMap` class template inherits from the `HashTable` class template.
- **Go:** `HashMap` embeds a private copy of `HashTable` (it does not reuse the Hash Table folder, and the copy has only `Put`, `Get` and `Contains`).

For how buckets, chains and resizing work, read the Hash Table topic. This page covers what the extra operations do and how to use a map well.

<Callout title="The invariant">
Each key appears at most once. `put` on an existing key replaces its value, and the number of entries is the number of distinct keys.
</Callout>

All lookups are O(1) average, and `update` and `copy` are O(m) for m pairs. Note that Python iteration yields `(key, value)` tuples, unlike `dict`, which yields keys.

### Get with default: counting

The classic use is counting. `get_or_default(word, 0)` replaces an if/else, and writing back `count + 1` updates the entry:

<DataTable
  columns={['Word', 'Lookup', 'Stored']}
  rows={[
    ['`to`', 'absent, default 0', '`to` = 1'],
    ['`be`', 'absent, default 0', '`be` = 1'],
    ['`or`', 'absent, default 0', '`or` = 1'],
    ['`not`', 'absent, default 0', '`not` = 1 (load passes 0.75, capacity 4 doubles to 8)'],
    ['`to`', 'present, 1', '`to` = 2'],
    ['`be`', 'present, 1', '`be` = 2'],
  ]}
/>

Iterating the result with the repository code, starting from capacity 4, yields `to, be, or, not`. That order follows the buckets, which is why it differs from the insertion order of the text, and it can change after any resize.

### Insert if absent

`put_if_absent(key, value)` returns True and stores the pair if the key is new, and returns False without touching the map if it already exists. After the counts above, `put_if_absent('to', 99)` returns False (the count stays 2), and `put_if_absent('that', 1)` returns True.

"Absent" means the key is missing, not that its value is empty: a key stored with the value None counts as present, so `put_if_absent('k', None)` followed by `put_if_absent('k', 5)` leaves `k` as None. This was a real bug here, because the check was written as `get(key) is not None`.

### Update and copy

`update(other)` puts every pair of `other` into the map, overwriting values for keys that already exist. In Python it accepts a `dict` or a `HashMap`; anything else, such as a list of pairs, is silently ignored. In C++ it takes a `std::map`. `copy()` (Python) builds a new map with the same capacity and re-puts every pair, so later changes to one map do not affect the other.

## Applications

- **Frequency counting:** characters, words, events.
- **Grouping:** anagram groups, records by a field.
- **Memoisation and caches** (an LRU cache is a hash map plus a linked list).
- **Indexing:** map an id to its record, or a value to its position for two-sum.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Confusing absent with None.** A stored `None` is a present key. Use `contains`, not `get(key) is not None`.
- **Relying on iteration order.** It follows buckets and changes on resize.
- **Mutating while iterating.** Putting or removing during a loop can resize or reshuffle buckets.
- **Passing the wrong thing to Python `update`.** Only a `dict` or `HashMap` works; other iterables are ignored without an error.
- **Go keys of non-comparable types.** Keys are compared with `==`, so slices and maps panic. Other key types such as int64 or float64 are hashed through their printed form and work.
- **Expecting Go to match the others.** The Go `HashMap` has no `Remove`, `Size`, `Update`, `Copy` or iteration.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is a hash map the same as a hash table?">
    Practically yes. Some texts say "hash table" for the data structure and "map" for the interface. Both store unique keys and use hashing for O(1) average lookup.
  </FaqItem>
  <FaqItem question="Why does iteration order look random?">
    Pairs are visited bucket by bucket, and the bucket of a key depends on its hash and the current capacity. After a resize the order can change.
  </FaqItem>
  <FaqItem question="When should I use a hash set instead?">
    When you only need to know whether a key is present and have no value to store. A set is a map without values.
  </FaqItem>
  <FaqItem question="How do I count things with a map?">
    Use get-with-default and write back the incremented count: `m.put(x, m.get_or_default(x, 0) + 1)`. In Go write `m.Put(x, m.GetOrDefault(x, 0).(int)+1)`.
  </FaqItem>
</Faq>
