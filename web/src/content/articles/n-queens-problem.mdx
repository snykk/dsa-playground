## How the N-Queens search works

A queen attacks along its row, its column and both diagonals. Two queens in the same row are never allowed, so a solution has exactly one queen per row. The solver uses this to shrink the search: instead of choosing n squares out of n<sup>2</sup>, it only decides **which column** each row gets.

<Steps>
  <Step title="Work on one row at a time">
    The recursive call for `row` assumes rows `0..row-1` already hold safe queens. When `row == n`, all n queens are placed and the board is a solution.
  </Step>
  <Step title="Try every column in the row">
    For each `col` from 0 to n-1, `is_safe` looks upward: the column above the square and the two diagonals above it. Rows below are still empty, so they need no check.
  </Step>
  <Step title="Place, recurse, undo">
    On a safe square set `board[row][col] = 1` and solve `row + 1`. When the call returns without stopping the search, set the square back to 0 and try the next column.
  </Step>
  <Step title="Stop or continue">
    With `find_all = False` the first complete board ends the search. With `find_all = True` every board is copied into the result and the search continues until all branches are exhausted.
  </Step>
</Steps>

<Callout title="Pruning is what makes it work">
A partial placement that already contains an attack is never extended. Whole subtrees of the search disappear: for n = 8 the solver makes 15,720 safety checks to list all 92 solutions, while the number of orderings of columns alone is 8! = 40,320.
</Callout>

## Pseudocode

```text
isSafe(board, row, col, n):
    for i = 0 to row - 1:                       # column above
        if board[i][col] == 1: return false
    for (i, j) = (row - 1, col - 1); i >= 0 and j >= 0; i--, j--:    # upper-left
        if board[i][j] == 1: return false
    for (i, j) = (row - 1, col + 1); i >= 0 and j < n; i--, j++:     # upper-right
        if board[i][j] == 1: return false
    return true

solve(board, row, n, solutions, findAll):
    if row == n:
        solutions.append(copy of board)
        return not findAll                      # true means: stop searching
    for col = 0 to n - 1:
        if isSafe(board, row, col, n):
            board[row][col] = 1
            if solve(board, row + 1, n, solutions, findAll):
                return true
            board[row][col] = 0                 # backtrack
    return false
```

## Implementation

Python and C++ return a list of boards (each board is an n x n grid of 0 and 1, where 1 is a queen). With `find_all` false the list holds one board, in column-lexicographic order, so `n = 8` gives the columns `[0, 4, 7, 5, 2, 6, 1, 3]`. Both return an empty list when no solution exists, and one empty board for `n = 0`.

Go has the same search, but `solveNQueens(n, true)` returns only the first board, as a single grid. Use `solveNQueensAll(n)` to get every solution.

## Complexity analysis

At depth k the queens occupy k different columns, so there are at most n!/(n-k)! partial placements. Summing over k gives about e &middot; n! nodes, which is <BigO of="n!" />. Every node tries all n squares of the next row with an <BigO of="n" /> safety check each, so the code costs at most <BigO of="n^2 * n!" /> in the worst case. Pruning keeps real runs far below that bound.

## Variants and design choices

`is_safe` here scans the board in O(n). Practical solvers track the attacked lines instead:

<DataTable
  columns={['Variant', 'Safety check', 'State', 'Note']}
  rows={[
    ['Board scan (this repository)', 'O(n)', 'n x n grid', 'simple, closest to the problem statement'],
    ['Column and diagonal sets', 'O(1)', 'three boolean arrays', 'column `c`, diagonal `r - c` and anti-diagonal `r + c` are all that matters'],
    ['Bitmasks', 'O(1) with bit tricks', 'three integers', 'the fastest simple counter'],
    ['Symmetry reduction', 'unchanged', 'unchanged', 'only search half of the first row and mirror the results'],
    ['Min-conflicts (local search)', 'n/a', 'one queen per column', 'finds one solution for very large n, no completeness guarantee'],
  ]}
/>

The two diagonals are the key to the O(1) variants: all squares on one diagonal share `r - c`, and all squares on one anti-diagonal share `r + c`.

## Applications

- **Teaching backtracking and pruning.** It is the classic example for the pattern.
- **Constraint satisfaction benchmarks.** Solvers and heuristics are often compared on n-queens instances.
- **Parallel search.** The branches under different first-row columns are independent.
- **Testing.** The solution counts form a known sequence, which makes them a convenient correctness test for search code.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Checking the lower half.** Only rows above `row` hold queens during the search; checking below is wasted work, and writing the check over the whole board is a common source of bugs.
- **Appending the live board.** Saving `board` itself instead of a copy leaves every stored solution pointing at the same grid, which ends up empty after backtracking.
- **Forgetting to undo.** Without `board[row][col] = 0` the failed queen stays on the board and blocks later branches.
- **Checking only one diagonal direction.** Both upper-left and upper-right are needed.
- **Mixing up the Go API.** `solveNQueens(n, true)` in Go returns one board, not all of them.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why one queen per row?">
    Two queens in a row attack each other, and a board with n queens and n rows therefore needs exactly one per row. Choosing a row at a time turns a search over subsets of squares into a search over column choices, which is far smaller.
  </FaqItem>
  <FaqItem question="Does a solution exist for every n?">
    No. There are none for n = 2 and n = 3. For n = 1 and every n of 4 or more at least one solution exists. The numbers of solutions for n = 1 to 9 are 1, 0, 0, 2, 10, 4, 40, 92, 352.
  </FaqItem>
  <FaqItem question="How can I make it faster?">
    Replace the board scan by three boolean arrays (columns, diagonals, anti-diagonals) or by bitmasks, so the safety check is O(1), and return a list of column indexes instead of an n x n grid.
  </FaqItem>
  <FaqItem question="Why is the first solution for n = 8 not symmetric looking?">
    The solver always takes the smallest safe column first, so it returns the lexicographically smallest solution, `[0, 4, 7, 5, 2, 6, 1, 3]`, which is the first of 92 in that order.
  </FaqItem>
</Faq>
