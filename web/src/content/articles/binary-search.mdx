## How Binary Search works

Keep a window `[lo, hi]` of positions where the target may still be. Look at the middle, and either you are done or half of the window is ruled out, because the array is sorted.

<Steps>
  <Step title="Start with the whole array">
    Set `lo = 0` and `hi = n - 1`.
  </Step>
  <Step title="Probe the middle">
    Compute `mid = lo + (hi - lo) / 2` and compare `arr[mid]` with the target. If they are equal, return `mid`.
  </Step>
  <Step title="Discard one half">
    If `arr[mid] < target`, everything up to `mid` is too small: set `lo = mid + 1`. Otherwise everything from `mid` on is too large: set `hi = mid - 1`.
  </Step>
  <Step title="Stop when the window is empty">
    When `lo > hi` there is nothing left and the target is absent: return -1.
  </Step>
</Steps>

<Callout title="The loop invariant">
If the target is in the array, it is inside `arr[lo..hi]`. The invariant holds at the start, each step keeps it (the discarded half cannot contain the target in a sorted array), and when the window is empty it means the target is not there.
</Callout>

## Pseudocode

```text
binarySearch(arr, target):
    left = 0; right = len(arr) - 1
    while left <= right:
        mid = left + (right - left) / 2
        if arr[mid] == target:  return mid
        elif arr[mid] < target: left = mid + 1
        else:                   right = mid - 1
    return -1

firstOccurrence(arr, target):             # last occurrence: mirror it
    left = 0; right = len(arr) - 1; result = -1
    while left <= right:
        mid = left + (right - left) / 2
        if arr[mid] == target:  result = mid; right = mid - 1   # keep looking left
        elif arr[mid] < target: left = mid + 1
        else:                   right = mid - 1
    return result
```

## Implementation

The Python, C++ and Go files all contain the iterative search, a recursive search and the first and last occurrence searches. Python also has `binary_search_closest`, which returns the index of the element nearest to the target (the larger one on a tie, `-1` for an empty list). C++ is a template with instances for `int` (and `double` for the basic and recursive forms); Go works on `[]int`. Python's `binary_search_recursive` defaults `right` to the end of the list; the C++ and Go recursive functions take `left` and `right` explicitly.

## Complexity analysis

Each probe halves the window, so after `k` probes at most `n / 2^k` positions remain. The search ends when that reaches zero.

<Equation label="Recurrence" expr="T(n) = T(n/2) + O(1)" result="O(log n)" />

With duplicates, the exact-match version returns an arbitrary one of them: on `[1, 2, 2, 2, 2, 3, 4]` searching for 2 returns index 3, while the first and last occurrence searches return 1 and 4.

## Applications

- **Dictionary-style lookups** in sorted arrays and sorted files.
- **Insertion points and range counts:** the number of values in `[a, b]` is two bound searches.
- **Binary search on the answer:** minimum capacity, smallest feasible speed, and similar optimization questions, as in LeetCode 875 "Koko Eating Bananas".
- **Debugging:** `git bisect` uses the same halving idea to find the commit that introduced a bug.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Searching unsorted data.** The result is meaningless, and no error is raised.
- **Wrong loop condition.** With `hi = n - 1` the loop must be `lo <= hi`. Mixing it with `hi = mid` loops forever.
- **Not shrinking the window.** Writing `lo = mid` instead of `lo = mid + 1` can make the loop run forever on two elements.
- **Overflow in the midpoint.** In C++ and Go, `(lo + hi) / 2` can overflow `int` on huge arrays. Write `lo + (hi - lo) / 2` (Python integers cannot overflow, but the repository uses the same form).
- **Duplicates.** The plain search returns any match. Use the first or last occurrence variant when the position matters.
- **Ties in closest.** The Python `binary_search_closest` prefers the larger value on a tie: for `[1, 3, 5, 7, 9]` and target 4, it returns the index of 5, not 3.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why must the array be sorted?">
    The discard step relies on order: if `arr[mid] < target`, every element at or before `mid` is also smaller, so none of them can match. On unsorted data that argument fails.
  </FaqItem>
  <FaqItem question="Is recursive or iterative better?">
    Iterative. Both are O(log n) in time, but the recursive form uses O(log n) stack, and the depth is tiny (about 30 frames for a billion items) so it is safe, but it adds nothing. The recursive form is useful for teaching.
  </FaqItem>
  <FaqItem question="Can I use binary search on a linked list?">
    Not usefully. Reaching the middle node takes O(n), so the total cost is no better than a linear scan.
  </FaqItem>
  <FaqItem question="What does it return when the target is missing?">
    -1 in every function here. If you need the position where the value would be inserted, use a lower-bound search (such as Python `bisect_left`) instead.
  </FaqItem>
</Faq>
