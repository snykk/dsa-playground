## What a hash set is

A set is a collection with no duplicates and no meaningful order. A hash set implements it with a hash table whose buckets hold the elements themselves (there are no values). To add or look up an element, hash it to a bucket and scan only that bucket.

This implementation uses separate chaining: each bucket is a small list. Here are the elements 10, 14, 18, 3 and 7 in a set that started with 4 buckets and grew to 8 (computed with the repository code):

<Callout title="Membership is one bucket">
`contains(x)` never looks outside bucket `hash(x) mod capacity`. As long as chains stay short (the table resizes when the load passes 0.75), that is a constant amount of work.
</Callout>

## See it in action

Run **Add and resize**: 10, 14 and 18 share bucket 2, adding 3 pushes the load past 0.75, and the set doubles to 8 buckets and adds every element again; then `add(14)` returns False because 14 is already there.

Names: Python `add`, `remove`, `contains`, `clear`, `is_empty`, `to_list`, plus `in`, `len`, iteration and `repr`. C++ has `add`, `remove`, `contains`, `getSize`, `bucketCount`, `isEmpty`, `clear`. Go has `Add`, `Remove`, `Contains`, `Size`, `IsEmpty`, `Clear`. Only Python can iterate. None of them has union, intersection or difference.

### Add and resize

Starting from 4 buckets, `add` 10, 14 and 18 (all `mod 4 = 2`) builds a chain of three. Adding 3 makes the load 4/4 = 1 > 0.75, so the bucket count doubles to 8 and every element is rehashed with `mod 8`:

<DataTable
  columns={['Call', 'Returns', 'Buckets after the call', 'Note']}
  rows={[
    ['`add(10)`', 'True', '2: [10]', '4 buckets'],
    ['`add(14)`', 'True', '2: [10, 14]', '4 buckets'],
    ['`add(18)`', 'True', '2: [10, 14, 18]', '4 buckets, load 3/4 = 0.75, not above the threshold'],
    ['`add(3)`', 'True', '2: [10, 18], 3: [3], 6: [14]', 'load 4/4 > 0.75: resized to 8 buckets'],
    ['`add(7)`', 'True', 'adds 7: [7]', '8 buckets'],
    ['`add(14)`', 'False', 'unchanged', 'already present'],
    ['`remove(18)`', 'True', '2: [10]', 'chain shrinks'],
  ]}
/>

C++ and Go splice or move the existing elements into the new buckets, and Python re-adds each element into the new table. A set that never resized, as the C++ and Go versions once did, keeps 16 buckets forever and degrades to O(n / 16) per operation.

### Remove

`remove(x)` finds `x` in its bucket and unlinks it, so chain order of the others stays the same. Because chaining has no probe sequence, no tombstone is needed (open addressing, in the Collision Handling topic, does need them).

## Complexity

<DataTable
  columns={['Operation', { label: 'Average', kind: 'mono' }, { label: 'Worst', kind: 'mono' }, 'Why']}
  rows={[
    ['add', 'O(1) amortized', 'O(n)', 'a resize rehashes all n elements'],
    ['contains, remove', 'O(1)', 'O(n)', 'worst case: all elements in one bucket'],
    ['iterate', 'O(capacity + n)', 'O(capacity + n)', 'visits every bucket'],

/>

Space is O(n + capacity). Resizing doubles the bucket count, so the cost of all resizes over n adds is below 2n, which makes `add` amortized O(1). The average chain stays at most 0.75 elements, so `contains` compares a constant number of elements.

## Applications

- **Duplicate detection:** `add` returning False means the element was already there (LeetCode 217, Contains Duplicate).
- **Visited sets** in graph search, to avoid revisiting nodes.
- **Membership filters** such as stop words or allowed values.
- **Intersection and difference** of collections by looking up each element of one in a set built from the other.
- **Two-sum style problems** that ask whether a complement was seen.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Expecting an order.** Iteration follows buckets and changes after a resize; use a tree set or sort the result if you need order.
- **Mutating elements.** Changing an element after adding it changes its hash and loses it.
- **Capacity 0.** `hash mod 0` divides by zero. Python raises `ValueError` and C++ throws `std::invalid_argument`; Go uses 16.
- **Assuming O(1) without a resize.** Without the load-factor check, chains grow with n. The C++ and Go versions now resize like Python.
- **Go key types.** Elements are compared with `==`, so slices and maps panic. Negative ints and other comparable types (int64, float64, bool) work.
- **Counting set operations as free.** Union and intersection of two sets cost O(n + m), and this code does not provide them.
</Callout>

## Implementation

All three versions are chaining tables of bare elements with a 0.75 load factor and doubling. Python iterates buckets with `__iter__` and keeps a `_resize` that re-adds elements, C++ is a `HashSet` class template over `std::list` buckets with `std::hash`, and Go uses `[][]interface{}` buckets with its own hash for ints, strings and everything else.

## Frequently asked questions

<Faq>
  <FaqItem question="Is a hash set just a hash map with no values?">
    Yes. It is the same table where only the key is stored. Many libraries build their set on top of their map.
  </FaqItem>
  <FaqItem question="Why does add return a boolean?">
    So you can detect duplicates in one call: True means the element was new, False means it was already present.
  </FaqItem>
  <FaqItem question="When is a tree set better?">
    When you need sorted iteration, the smallest or largest element, or elements in a range. It costs O(log n) per operation instead of O(1) average.
  </FaqItem>
  <FaqItem question="What if I only need to know probably-present?">
    A Bloom filter uses far less memory for a very large set, at the price of occasional false positives and no way to list or delete elements.
  </FaqItem>
</Faq>
