## What it is

A stack adds and removes items at one end only, the **top**, so the last item pushed is the first one popped (LIFO). A static-size stack stores its items in an array whose length, the **capacity**, is chosen when the stack is created. A separate `top` index records the last used slot, with `-1` meaning empty.

Items never move. Push writes to slot `top + 1` and pop reads slot `top`, so both just add or subtract one from `top`.

<Callout title="The invariant">
The stack is the slots `0 .. top`. Everything above `top` is garbage that may be overwritten. The stack is empty when `top == -1` and full when `top == capacity - 1`.
</Callout>

    ['`peek()`', 'return the item at `top`; fails when empty', 'O(1)'],
    ['`is_empty()`, `size()`', '`top == -1` and `top + 1`', 'O(1)'],
  ]}
/>

The capacity is a constructor argument that must be at least 1, with a default of 100: `ArrayStack(capacity=100)` in Python, `ArrayStack(int size = 100)` in C++, and `NewArrayStack(capacity)` or `NewStack()` in Go. Errors by language:

- **Python:** `OverflowError` on a full push, `IndexError` on an empty pop or peek, `ValueError` for a bad capacity.
- **C++:** `std::overflow_error`, `std::underflow_error` and `std::invalid_argument`. The C++ method is `isEmpty()`.
- **Go:** `Push` returns an `error` (overflow), `Pop` and `Peek` return `(int, error)`, and `NewArrayStack` returns an error for a bad capacity.

## Pseudocode

```text
push(x):
    if top == capacity - 1: error "overflow"
    top = top + 1
    arr[top] = x

pop():
    if top == -1: error "underflow"
    x = arr[top]
    top = top - 1
    return x
```

Python keeps the same scheme on a preallocated list `[None] * capacity` and sets a popped slot back to `None`, so the removed object can be garbage collected. C++ uses a raw `new int[capacity]` array freed by the destructor, and the copy operations are deleted because a copy would free the array twice. Go creates the slice with `make([]int, 0, capacity)` and checks `len(data) == capacity` before each `append`, so the backing array is never reallocated.

Space is O(capacity) whether the stack is empty or full. Unlike the dynamic stack, no push ever costs more than constant time.

## Applications

- **Systems with a hard memory limit,** such as embedded code that must not allocate at run time.
- **Bounded recursion depth:** an explicit stack with a known maximum depth.
- **Expression evaluation and parenthesis matching** when the maximum nesting is known.
- **Undo history with a cap,** where overflow is a design decision.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Off-by-one on the full test.** Full is `top == capacity - 1`, not `top == capacity`.
- **Reading above `top`.** Slots past `top` hold old or default values. Use `size()` and `peek()` instead of the raw array.
- **Ignoring the overflow error.** In Go, `Push` returns an `error`, and dropping it loses the item silently.
- **Capacity 0 or negative.** All three constructors reject a capacity below 1.
- **Copying the C++ stack.** The class owns a raw array, so its copy operations are deleted.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why have a fixed capacity at all?">
    It gives constant-time pushes with no copying and a predictable memory footprint. That matters when memory is tight or when latency spikes from a resize are not acceptable.
  </FaqItem>
  <FaqItem question="What happens when I push onto a full stack?">
    The push is rejected: Python raises `OverflowError`, C++ throws `std::overflow_error` and Go returns an error. The stack is left unchanged.
  </FaqItem>
  <FaqItem question="Does pop clear the slot?">
    Only Python resets it (to `None`, so the object can be collected). C++ and Go just move `top` or reslice, and the old value is overwritten by the next push.
  </FaqItem>
  <FaqItem question="How is this different from the dynamic size stack?">
    The dynamic version grows by replacing its array with a bigger one, so a push never fails but occasionally copies. This one never grows and never copies.
  </FaqItem>
</Faq>
