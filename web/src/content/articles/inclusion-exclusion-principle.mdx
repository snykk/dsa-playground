## When to use it

Signals in a problem statement:

- "count numbers up to n divisible by **at least one** of these";
- "count the elements in the union of several sets" where intersections are easy to count;
- "count the objects that avoid **all** of several bad properties" (count everything, subtract the union of the bad ones);
- the number of conditions is small (about 20 or fewer), because the work is 2<sup>k</sup>.

If the conditions are independent and you only need the complement, multiplying probabilities or counts is faster; inclusion-exclusion is for overlapping conditions.

## How it works

For sets <em>A<sub>1</sub></em>, ..., <em>A<sub>k</sub></em>, the size of the union is the sum over every non-empty subset of the sets of the size of their intersection, with a sign that depends on the subset size.

<Equation label="Union" expr="|A1 u A2 u ... u Ak| = sum over non-empty S of (-1)^(|S|+1) * |intersection of the sets in S|" result="odd-sized subsets add, even-sized subsets subtract" />

<Steps>
  <Step title="Enumerate subsets with a bitmask">
    Loop `mask` from 1 to 2<sup>k</sup> - 1. Bit j of `mask` says whether condition j is in the subset.
  </Step>
  <Step title="Count the intersection of the subset">
    For divisibility, "divisible by all of d<sub>1</sub>, d<sub>2</sub>, ..." means divisible by their `lcm`, so the intersection has `n / lcm` elements. For explicit sets, intersect them.
  </Step>
  <Step title="Add or subtract by parity">
    An odd number of sets adds the term, an even number subtracts it.
  </Step>
</Steps>

<Callout title="Why the signs work">
Take an element that lies in exactly m of the sets. It appears in C(m, 1) single terms, C(m, 2) pair terms, and so on. Its total contribution is C(m,1) - C(m,2) + C(m,3) - ... which equals 1 for every m &ge; 1. So each element of the union is counted exactly once and elements outside the union never appear.
</Callout>

## Template

```text
count_divisible(n, divisors):              # numbers in 1..n divisible by some divisor
    result = 0
    for mask in 1 .. 2^k - 1:
        lcm = 1; count = 0
        for j in 0 .. k - 1:
            if mask has bit j:
                count += 1
                lcm = lcm / gcd(lcm, divisors[j]) * divisors[j]
                if lcm > n: skip this mask      # n / lcm = 0, and lcm could overflow
        result += n / lcm if count is odd else -(n / lcm)
    return result

count_union_sets(sets):                    # size of the union
    result = 0
    for mask in 1 .. 2^m - 1:
        inter = intersection of sets[j] for every bit j in mask   # from the FIRST set in the mask
        result += |inter| if popcount(mask) is odd else -|inter|
    return result
```

## Worked example: divisible by 2, 3 or 5

How many numbers in 1..100 are divisible by 2, 3 or 5? `count_divisible(100, [2, 3, 5])` returns 74.

For explicit sets the same recipe applies. With `A = {1, 2, 3}`, `B = {2, 3, 4}`, `C = {3, 4, 5}`: the singles give 3 + 3 + 3 = 9, the pairs give |A&cap;B| + |A&cap;C| + |B&cap;C| = 2 + 1 + 2 = 5, the triple gives |A&cap;B&cap;C| = 1. The union has 9 - 5 + 1 = 5 elements, and `count_union_sets` returns 5.

## Implementation

`count_divisible(n, divisors)` and `count_union_sets(sets)` exist in all three languages, plus a `gcd` helper. Behaviour worth knowing:

- Divisors must be at least 1. In C++ and Go the lcm is built step by step and a subset is skipped as soon as its lcm exceeds `n` (its term would be 0 anyway). That also prevents integer overflow with many divisors.
- Each subset's intersection starts from the first set that is in the subset. (An earlier version started from `sets[0]` every time and returned 3 instead of 5 for the example above.)
- Both functions loop over `1 << k` masks, so they are meant for small k (the C++ and Go versions use 32-bit shifts on `int`, so k must stay below 31).

The 2<sup>k</sup> factor is the whole cost: k = 20 means about a million subsets, k = 40 is out of reach. Pruning masks whose lcm exceeds n makes divisor counting much faster in practice.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Starting every intersection from the first set of the list** instead of the first set in the subset. Every term then includes that set and the answer is wrong.
- **Using the product instead of the lcm.** Divisors that share a factor (4 and 6) overlap in multiples of 12, not 24.
- **Overflow.** The lcm of a dozen numbers passes 32 bits quickly. Use a wider type and skip subsets whose lcm is above `n`.
- **Wrong sign.** For the union, odd subsets add. For the complement (none of the properties), the sign is the opposite and you start from the total.
- **Using it with large k.** 2<sup>k</sup> terms: reformulate, or use a different technique, when k grows beyond about 20-25.
- **Weak tests.** Check against a brute-force count. A test that only asserts the result is positive will not catch wrong signs.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why do the signs alternate?">
    Each element in exactly m sets is counted C(m,1) - C(m,2) + ... + (-1)^(m+1) C(m,m) times, and that alternating sum is exactly 1 for any m &ge; 1. The alternation cancels the overcounting layer by layer.
  </FaqItem>
  <FaqItem question="How do I count numbers divisible by none of the divisors?">
    Subtract the union from n: `n - count_divisible(n, divisors)`.
  </FaqItem>
  <FaqItem question="Can I speed it up?">
    Prune subsets whose lcm exceeds n (they contribute 0), sort divisors so pruning starts early, or use DFS over the divisors with a running lcm instead of recomputing it for each mask.
  </FaqItem>
  <FaqItem question="What if the divisors are not coprime?">
    The method still works because it uses the lcm of each subset. Only the coprime case lets the lcm equal the product.
  </FaqItem>
</Faq>
