## Definition

Big-Omega mirrors Big-O. It says a function `f(n)` stays above a constant multiple of `g(n)` once `n` is large enough.

<Equation label="Big-Omega" expr="f(n) = Omega(g(n))  if there are constants c > 0 and n0 such that  0 <= c * g(n) <= f(n)  for all n >= n0" />

It is the reverse of Big-O:

<Equation label="Duality" expr="f(n) = Omega(g(n))  if and only if  g(n) = O(f(n))" />

As with Big-O, the `=` means "is in the set": `n^2 = Omega(n)` is true, `Omega(n) = n^2` is not.

## Intuition

Big-O answers "at most this much"; Big-Omega answers "at least this much". Together they sandwich a function. Big-Omega bounds are as loose as Big-O bounds: `n^2 + 1` is `Omega(n^2)`, and also `Omega(n)` and `Omega(1)`. The statement `Omega(1)` is true of every algorithm and says nothing. Useful lower bounds are the largest ones you can prove.

Big-Omega is where the "best case" confusion most often comes from. It is easy to read "lower bound" as "best case", but those are different things:

- **A case** picks which function you analyse: the fastest input of each size, the slowest, or the average.
- **A notation** says how you bound that function from one side or both.

You can put an Omega bound on the **worst case** ("some input of size `n` takes at least `n log n` steps") and an O bound on the **best case** ("the fastest input takes at most `n` steps"). Both are valid, and both are common.

## Worked examples

### Proving an Omega bound

Claim: `f(n) = n^2 / 2 - 3n` is `Omega(n^2)`. Pick `c = 1/4`. We need `n^2 / 4 <= n^2 / 2 - 3n`, which rearranges to `n^2 / 4 >= 3n`, that is `n >= 12`.

<Equation label="Proof" expr="n^2/4 <= n^2/2 - 3n  for all n >= 12" result="c = 1/4, n0 = 12" />

The choice of `n0` matters: at `n = 11` the inequality fails (30.25 against 27.5).

### A lower bound for a whole problem: comparison sorting

Any algorithm that sorts only by comparing elements can be drawn as a decision tree. Each internal node is a comparison, and each leaf is one possible output order. Here is the tree for three elements `a, b, c`:

A binary tree with `n!` leaves has height at least `log2(n!)`, and the longest path is the number of comparisons in the worst case.

<Equation label="Counting" expr="log2(n!) >= log2((n/2)^(n/2)) = (n/2) log2(n/2)" result="Omega(n log n) comparisons in the worst case" />

This bound is a statement about the **worst case** (and the average case) of any comparison sort, not about every input. Insertion sort and bubble sort with early exit finish a sorted input in `n - 1` comparisons, which is `O(n)`. The tree has short paths too; it just also has a long one.

## Using it in practice

- **State what you bound.** Say "the worst case of comparison sorting is Omega(n log n)", not "comparison sorting is Omega(n log n)" without the case.
- **Use Omega for impossibility.** To show an algorithm is optimal, match an upper bound with a lower bound: Merge Sort is `O(n log n)` and the problem is `Omega(n log n)`, so both are tight.
- **Searching an unsorted array** must look at every element in the worst case: `Omega(n)`.
- **Output size is a lower bound.** Printing all subsets of `n` items takes `Omega(2^n)` just to write them out.
- **Combine with Big-O** to get Big-Theta when the two bounds meet.

## Implementation

Python has four examples: linear search, bubble sort, a three-way quick sort and matrix traversal. C++ and Go have three (no quick sort). The quick sort example builds new lists and is **not** an `Omega(n log n)` best case: an all-equal input is sorted in linear time, and its extra memory is not `O(log n)`.

## Common misconceptions

<Callout tone="warning" title="Watch out for these">
- **"Omega is the best case."** Omega bounds a function from below. The best case is one function you may bound; the worst case is another. "Comparison sorting is Omega(n log n) in the worst case" is an Omega bound on the worst case.
- **"No comparison sort can beat n log n."** Not on every input. The bound is for the worst and average case. Insertion sort needs `n - 1` comparisons on sorted input.
- **"Omega(1) is a useful bound."** It holds for every algorithm. Prove the largest lower bound you can.
- **"Binary search is Theta(log n)."** Its best case (target at the middle) is `Theta(1)`; its worst case is `Theta(log n)`. The statement needs a case.
- **Mixing up the roles of O and Omega** when comparing: `f = Omega(g)` means `g = O(f)`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is Big-Omega the best case?">
    No. It is a lower bound on a function. The best, average and worst case are three functions, and each can have O, Omega and Theta bounds. A lower bound on the worst case (such as `n log n` for comparison sorting) is a common and important use.
  </FaqItem>
  <FaqItem question="Why does the decision tree give n log n?">
    A correct sort has at least `n!` leaves, one per possible order. A binary tree with `n!` leaves has height at least `log2(n!)`, which grows like `n log n`.
  </FaqItem>
  <FaqItem question="Does Omega(n log n) mean Merge Sort is optimal?">
    For comparison sorting, yes: Merge Sort is `O(n log n)` in the worst case and the problem needs `Omega(n log n)` comparisons, so the bounds match. Non-comparison sorts such as counting sort avoid the bound by using the key values themselves.
  </FaqItem>
  <FaqItem question="What is the relation to Big-O?">
    `f = Omega(g)` exactly when `g = O(f)`. If `f` is both `O(g)` and `Omega(g)`, then `f = Theta(g)`.
  </FaqItem>
</Faq>
