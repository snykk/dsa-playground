## What a max heap is

A max heap is a *complete* binary tree in which every parent is `>=` its children, so the maximum sits at index 0. The array layout, the index formulas (children `2i + 1` and `2i + 2`, parent `(i - 1) / 2`) and the cost analysis are identical to the Min Heap article (linked under related topics), which explains them in detail. Only the comparison flips: sift **up** while the parent is *smaller*, and sift **down** by swapping with the *larger* child.

## See it in action

Run **Insert: sift up** to watch each new value climb while it is larger than its parent, and **Extract: largest first** to see the maximum leave and the last element sink along the larger child. The tree and the array are the same list, so every swap moves in both.

### Heap sort uses a max heap

Heap sort heapifies the array into a max heap and then repeatedly swaps the root with the last unsorted slot and sifts down within the shrinking prefix. The largest values accumulate at the **end**, so the result is **ascending**. (A *descending* result only appears if you extract the maximum into a new list.) From `[10, 5, 8, 4, 1, 3]`:

## Complexity

The costs are exactly those of the min heap: peek O(1), insert and extract O(log n) (one swap per level of a tree of height about log<sub>2</sub>(n)), heapify O(n) (most nodes are near the bottom and sink only a short way), search for an arbitrary value O(n). Extra space is the array, O(n).

## Max heap vs min heap

<DataTable
  columns={['', 'Max heap', 'Min heap']}
  rows={[
    ['Root', 'largest', 'smallest'],
    ['Order rule', 'parent `>=` children', 'parent `<=` children'],
    ['Sift down swaps with', 'the larger child', 'the smaller child'],
    ['Typical use', 'largest-first queue, heap sort, k smallest', 'smallest-first queue, Dijkstra, k largest'],
  ]}
/>

A max heap of numbers behaves like a min heap of their negations, which is how Python's `heapq` (min only) is used as a max heap. C++ `std::priority_queue` is a max heap by default.

## Applications

- **Largest-first priority queues**, such as highest-priority task scheduling.
- **Heap sort:** the max heap pushes the maximum to the end of the array, giving ascending order.
- **K smallest elements:** keep a max heap of size k; when a new value is smaller than the root, replace the root. The root is the k-th smallest, and the cost is O(n log k). For example with k = 3 over `5, 1, 9, 3, 7, 8` the heap ends holding `1, 3, 5`.
- **Running median:** a max heap for the lower half plus a min heap for the upper half.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Swapping with the smaller child** during sift down. Always pick the larger one.
- **Starting heapify at the root** or going upward. Start at `n / 2 - 1` and go down to 0.
- **Mixing 0-based and 1-based index formulas.**
- **Claiming heap sort is descending.** In place with a max heap it is ascending.
- **Reading from an empty heap.** Python raises `IndexError`, C++ throws `std::runtime_error`, Go panics.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is a max heap just a reversed min heap?">
    Structurally yes: same shape, same index formulas, same costs. Only the order rule is flipped.
  </FaqItem>
  <FaqItem question="Why does heap sort use a max heap for ascending order?">
    Each extraction puts the current maximum into the last free slot, so the sorted part grows from the right. A min heap would need an extra array or would yield descending order in place.
  </FaqItem>
  <FaqItem question="How do I find the k smallest values with a heap?">
    Keep a max heap of size k. A new value smaller than the root replaces it. After one pass the heap holds the k smallest.
  </FaqItem>
</Faq>
