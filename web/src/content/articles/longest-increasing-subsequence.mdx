## How LIS works

A subsequence keeps the original order but may skip elements. The LIS asks for the longest one whose values strictly increase. There are 2<sup>n</sup> subsequences, so we need structure.

### The O(n<sup>2</sup>) table

Let `dp[i]` be the length of the longest increasing subsequence that **ends at** index `i`.

<Steps>
  <Step title="Start every entry at 1">
    Each element alone is an increasing subsequence of length 1.
  </Step>
  <Step title="Look at every earlier element">
    For each `j < i` with `arr[j] < arr[i]`, the element `arr[i]` can extend a run that ends at `j`: `dp[i] = max(dp[i], dp[j] + 1)`.
  </Step>
  <Step title="Take the best end">
    The answer is the largest `dp[i]`, because an LIS has to end somewhere.
  </Step>
  <Step title="Recover the sequence">
    Store the predecessor `parent[i] = j` whenever `dp[i]` improves, then follow the parents back from the best end. `lis_with_sequence` does this.
  </Step>
</Steps>

<Callout title="Why the answer is the maximum, not dp[n-1]">
`dp[i]` only counts runs that end exactly at `i`. The last element is not always part of the best run, so the answer is the maximum over all `i`.
</Callout>

### The O(n log n) tails array

Keep an array `tails` where `tails[k]` is the **smallest possible last value** of an increasing subsequence of length `k + 1` among the elements seen so far. It is always sorted, so a new element `x` can be placed by binary search: find the first position with `tails[pos] >= x`. If there is none, `x` extends the longest run (append). Otherwise `x` becomes a smaller tail for that length (replace). The final length of `tails` is the LIS length.

## Worked example

Array `[10, 9, 2, 5, 3, 7, 101, 18]`. The LIS length is 4 (`lis_dp`, `lis_binary_search` and `lis_naive` all agree), and `lis_with_sequence` returns `[2, 5, 7, 101]`.

The final `tails` is `[2, 3, 7, 18]`, which happens to be increasing but is **not** guaranteed to be a real subsequence of the input (3 comes after 5 in the array, but 5 was replaced). Only its length is the answer.

## Pseudocode

```text
lisDP(arr):                              # O(n^2)
    if arr is empty: return 0
    dp = [1] * n
    for i = 1 to n - 1:
        for j = 0 to i - 1:
            if arr[j] < arr[i]: dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

lisBinarySearch(arr):                    # O(n log n), Python
    tails = []
    for x in arr:
        pos = first index with tails[pos] >= x      # bisect_left
        if pos == length(tails): append x to tails
        else: tails[pos] = x
    return length(tails)

lisWithSequence(arr):                    # O(n^2), Python
    like lisDP, plus parent[i] = j when dp[i] improves
    end = first index with the largest dp
    follow parent back from end and reverse
```

## Implementation

Python has four functions: `lis_naive` (exponential recursion), `lis_dp`, `lis_binary_search` and `lis_with_sequence`. C++ and Go have only the O(n<sup>2</sup>) length (`lisDP`, `LISDP`). The binary-search version uses `bisect_left`, which makes the subsequence **strictly** increasing: equal values replace each other instead of extending. Empty input gives 0 everywhere.

The tails array stays sorted, which is why binary search is valid: replacing the first tail that is `>= x` with `x` keeps it increasing.

## Why the tails trick works

The invariant is that `tails[k]` is the smallest last value over all increasing subsequences of length `k + 1` seen so far. A smaller tail is always at least as good: anything that can extend a larger tail can extend a smaller one as well. A new `x` either beats every tail (a longer subsequence exists) or improves the first tail that is `>= x`. The tails are increasing in `k`, because the last value of a run of length `k + 1` is larger than the last value of a run of length `k` inside it. Recovering the actual sequence in O(n log n) is possible by also storing, for each element, the index of the previous tail, but this repository does not do that.

## Applications

- **Patience sorting.** The tails array is the top row of a deck of piles dealt by the patience sorting game; its number of piles is the LIS length.
- **Chains and nesting.** Russian doll envelopes and pair chains reduce to an LIS after sorting.
- **Measuring order.** The LIS length tells how close a sequence is to being sorted: `n - LIS` elements must move out of the way.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Returning dp[n-1].** The answer is the maximum over all `dp[i]`.
- **Strict versus non-strict.** `arr[j] < arr[i]` and `bisect_left` give strictly increasing runs. `[7, 7, 7]` is 1, `[1, 3, 3, 5]` is 3. With `<=` or `bisect_right` it would be 4 for the second.
- **Reading `tails` as the answer.** Only its length is meaningful.
- **Using `bisect_right` with a strict LIS.** It would let equal values extend a run.
- **Starting the table at 0.** Every `dp[i]` starts at 1 (the element alone).
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does the tails array have the right length but the wrong contents?">
    Each replacement lowers a tail to keep future options open, even when the replaced value is no longer part of any single run. The count of lengths stays correct, but the entries may come from different subsequences.
  </FaqItem>
  <FaqItem question="Can O(n log n) also give the sequence?">
    Yes. Store, for every element, which tail was before it when it was placed, and follow those links back from the last tail. This repository returns the sequence only from the O(n<sup>2</sup>) version.
  </FaqItem>
  <FaqItem question="Does the LIS have to be unique?">
    No. `[1, 3, 2, 4]` has two LISs of length 3, `[1, 3, 4]` and `[1, 2, 4]`. The code returns the one found first by its tie rule.
  </FaqItem>
  <FaqItem question="What if equal values are allowed?">
    Then you want the longest non-decreasing subsequence: replace `<` with `<=` in the table, or `bisect_left` with `bisect_right`.
  </FaqItem>
</Faq>
