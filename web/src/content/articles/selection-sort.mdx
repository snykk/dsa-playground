## How Selection Sort works

The array is split into a sorted prefix on the left and an unsorted rest on the right. Each round **selects** the smallest element of the rest and puts it right after the prefix, so the prefix grows by one element that is already in its final position.

<Steps>
  <Step title="Scan the unsorted part">
    Starting at index `i`, look at every element `arr[i..n-1]` and remember the index `min_idx` of the smallest one. Ties keep the first minimum, because the comparison is a strict `<`.
  </Step>
  <Step title="Swap it to the front">
    If `min_idx` is not `i`, swap `arr[i]` and `arr[min_idx]`. When the minimum is already at `i`, nothing is written.
  </Step>
  <Step title="Grow the sorted prefix">
    Move `i` one step to the right and repeat until only one element is left.
  </Step>
</Steps>

<Callout title="The invariant">
Before round `i`, `arr[0..i-1]` holds the `i` smallest elements in sorted order, each in its final position. Everything in `arr[i..n-1]` is at least as large as everything in the prefix, so no later round ever touches the prefix again.
</Callout>

## Pseudocode

```text
selectionSort(arr):
    n = length(arr)
    for i = 0 to n - 1:
        min_idx = i
        for j = i + 1 to n - 1:
            if arr[j] < arr[min_idx]:
                min_idx = j
        if min_idx != i:
            swap(arr[i], arr[min_idx])
    return arr
```

The last round (`i = n - 1`) scans nothing and cannot swap, so running it is harmless.

## Implementation

All three versions sort in place and follow the pseudocode, including the `min_idx != i` guard that skips useless self-swaps. Python's `selection_sort` returns the same list; C++ is a template over the element type of a `std::vector` (instantiated for `int` and `double`) and needs only `operator<`; Go sorts a `[]int`.

## Complexity analysis

Round `i` always compares the minimum candidate with all `n - i - 1` elements after it, whatever their values:

<Equation label="Comparisons" expr="(n - 1) + (n - 2) + ... + 1" result="n(n - 1)/2 = O(n^2)" />

<Callout title="Few writes, many reads">
Bubble Sort and Insertion Sort do one move per inversion, up to `n(n - 1)/2` of them. Selection Sort never makes more than `n - 1` swaps. That is its one real advantage, and it matters only when moving an element is much more expensive than comparing two (for example, a very large record or a slow write medium).
</Callout>

## Applications

- **Expensive writes.** When writing is far costlier than reading, for example flash memory with limited write cycles, the n - 1 swap bound helps.
- **Teaching.** It shows the sorted-prefix invariant and how to count comparisons and swaps.
- **Tiny arrays.** For a handful of elements the simplicity and low overhead are enough.
- **Partial selection.** Stopping after `k` rounds gives the `k` smallest elements in order, in `O(k n)`.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Swapping the wrong index.** Swap `arr[i]` with `arr[min_idx]`, not with `arr[j]` at the end of the scan.
- **Resetting `min_idx` wrongly.** It must start at `i` for every round, not at 0.
- **Expecting stability.** Sorting `[2a, 2b, 1]` gives `[1, 2b, 2a]`: the first 2 is swapped to the far end and passes its twin. Sort `(key, index)` pairs if order of equal keys matters.
- **Assuming it is faster on sorted input.** It is not: the scans always run in full.
- **Using `<=` when searching for the minimum.** It picks the last of several equal minima and causes extra swaps.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is Selection Sort stable?">
    No. The swap moves the minimum across the elements in between, so an equal element can end up behind its twin. For example `[2a, 2b, 1]` becomes `[1, 2b, 2a]`.
  </FaqItem>
  <FaqItem question="Why does it make at most n - 1 swaps?">
    Each round fixes one element and swaps at most once, and the last element is in place once the other n - 1 are. A round where the minimum is already at the front swaps nothing, because the code skips the self-swap.
  </FaqItem>
  <FaqItem question="Why is it O(n^2) even for sorted input?">
    The scan has no way to know that the front element is already the minimum until it has compared it with every other element of the unsorted part, so all n(n - 1)/2 comparisons happen.
  </FaqItem>
  <FaqItem question="Is Heap Sort a kind of Selection Sort?">
    Yes. Both repeatedly pick the extreme element of the unsorted part and place it. Heap Sort keeps the unsorted part in a heap, so each pick costs O(log n) instead of O(n).
  </FaqItem>
</Faq>
