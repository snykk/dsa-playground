## What a singly linked list is

A node is a small record with two fields: `data` and `next`. The list object stores one thing, the `head`, a reference to the first node. The last node's `next` is `None` (null), which marks the end. Nodes live wherever the allocator put them, and the `next` links are the only thing that holds the sequence together.

<ListDiagram
  kind="singly"
  values={[7, 3, 9, 5]}
  pointers={{ 0: 'head', 3: 'last' }}
  tones="f..."
  legend={{ f: 'the head: the only node the list itself knows about' }}
  caption="A list of four nodes. Everything else is reached by following next from the head."
/>

An empty list is `head = None`. Because there is no index arithmetic, you reach a node only by following links from the head.

<Callout title="Losing the head loses the list">
The head is the only handle on the chain. If you overwrite it before saving what it pointed to, every node behind it becomes unreachable. Every operation below is an exercise in updating `next` references in the right order.
</Callout>

## Operations

    ['`delete(key)`', 'unlink the first node holding `key`; nothing happens if absent', 'O(n)'],
    ['`display()`', 'return the values from head to tail', 'O(n)'],
  ]}
/>

Python and Go use `insert_at_head` / `InsertAtHead` and `delete` / `Delete`. C++ uses `insert_at_head`, `insert_at_tail` and `delete_node`. `display` returns a list in Python and a slice in Go, while the C++ version prints; C++ also has a `to_vector()` helper that returns the values. There is no search, size or reverse in the code.

### Insert at head: two writes

Inserting `1` into `[7, 3]`: point the new node at the old head first, then move `head`. The order matters; moving `head` first would lose the old chain.

### Delete by value: keep a prev pointer

Deleting needs the node before the match, so the code walks with two pointers, `prev` and `curr`, until `curr` holds the key, then writes `prev.next = curr.next`. Deleting `3` from `[7, 3, 9]`:

  rows={[

C++ then calls `delete` on the unlinked node. Python and Go rely on garbage collection.

### Reversing a list (not in the code)

A classic exercise reverses the links in place with three pointers: `prev` (initially none), `curr` (the head) and `next`. Each step does `next = curr.next`, `curr.next = prev`, `prev = curr`, `curr = next`. Reversing `[1, 2, 3]`:

<DataTable
  columns={['Step', 'prev', 'curr', 'Links after the step']}
  rows={[
    ['start', 'none', '1', '1 -> 2 -> 3'],
    ['1', '1', '2', '1 -> none, 2 -> 3'],
    ['2', '2', '3', '2 -> 1 -> none, 3 stays'],
    ['3', '3', 'none', '3 -> 2 -> 1 -> none'],
  ]}
/>

The new head is `prev`. It is O(n) time and O(1) extra space.

## Implementation

The C++ class owns its nodes. A destructor frees the chain, and the copy constructor and assignment are deleted so that two lists never free the same nodes. `head` is private there, so the C++ test uses `to_vector()`.

## Complexity

<DataTable
  columns={['Operation', { label: 'Time', kind: 'mono' }, 'Why']}
  rows={[
    ['insert at head', 'O(1)', 'two pointer writes, no traversal'],
    ['insert at tail', 'O(n)', 'follow n - 1 links to the last node (O(1) with a tail pointer)'],
    ['delete by value', 'O(n)', 'search with a prev pointer; the rewrite itself is O(1)'],
    ['search, access by index', 'O(n)', 'only forward walking is possible'],
    ['traverse', 'O(n)', 'one visit per node'],
  ]}
/>

Space is O(n): one node per element, each carrying a link (8 bytes on a typical 64-bit machine, plus allocator overhead and the value). All operations need O(1) extra space.

## Applications

- **Stacks and queues:** a stack is push and pop at the head; with a tail pointer a queue is O(1) too.
- **Hash-table chaining:** each bucket holds a short list.
- **Adjacency lists** in graphs.
- **Interview classics:** reversing, detecting a cycle, merging two sorted lists, finding the middle.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Losing the head.** Always connect the new node to the old chain before you move `head`.
- **Null dereference.** Check `curr` before reading `curr.next`, and handle the empty list.
- **Deleting without `prev`.** To unlink a node you need its predecessor. Track it while you walk.
- **Forgetting the head case.** When the match is the head there is no `prev`; move `head` instead.
- **Assuming tail insertion is O(1).** Without a tail pointer it walks the whole list.
- **Leaks in C++.** Every `new` needs a matching `delete`; the destructor frees the chain, and copying must be forbidden or deep.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is insert at tail O(n) here?">
    The list stores only the head. To append, the code walks to the last node. Storing a `tail` pointer fixes it, at the price of keeping that pointer correct on every delete.
  </FaqItem>
  <FaqItem question="Why do I need a prev pointer to delete?">
    A node has no link back to its predecessor, and the predecessor's `next` is the reference that must change. You carry it along while searching.
  </FaqItem>
  <FaqItem question="When is a linked list better than an array?">
    When you insert and remove near known positions (especially the front) and do not need indexing. For most workloads arrays are faster in practice because of cache locality, so measure before choosing.
  </FaqItem>
  <FaqItem question="How do I find the middle of a list in one pass?">
    Move a slow pointer one step and a fast pointer two steps at a time. When the fast pointer reaches the end, the slow pointer is at the middle.
  </FaqItem>
</Faq>
