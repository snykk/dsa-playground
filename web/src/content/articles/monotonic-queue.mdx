## When to use it

Signals in a problem statement:

- "maximum (or minimum) of every window of size k";
- a window that **slides** over an array: elements enter on the right and leave on the left;
- a DP transition `dp[i] = best(dp[j]) + cost` over a bounded range of j (`i - k <= j < i`);
- "longest subarray whose max minus min is at most k" (two monotonic queues together);
- you only need the extreme of the window, not its median or k-th element.

## How it works

The deque holds **indices**, and the array values at those indices are in decreasing order (for a maximum) from front to back.

<Steps>
  <Step title="Evict from the front">
    If the front index is no longer inside the window (`front <= i - k`), pop it.
  </Step>
  <Step title="Pop from the back while dominated">
    While the value at the back is `<=` the new value, pop it. An older value that is not bigger than a newer one can never be the window maximum again: it leaves the window earlier.
  </Step>
  <Step title="Push the new index">
    The deque is again decreasing from front to back.
  </Step>
  <Step title="Read the answer">
    Once the first window is complete (`i >= k - 1`), the front of the deque is the maximum of the window.
  </Step>
</Steps>

<Callout title="The invariants">
All indices in the deque lie in the current window, their values decrease from front to back, and the front is the window maximum. Every index is pushed once and popped at most once, so the inner `while` loops do O(n) work in total.
</Callout>

## Template

```text
sliding_window_max(arr, k):
    if k <= 0 or arr is empty or k > len(arr): return []
    dq = empty deque of indices
    result = []
    for i in 0 .. n - 1:
        while dq and dq.front <= i - k:        # left the window
            dq.pop_front()
        while dq and arr[dq.back] <= arr[i]:   # dominated by the newcomer
            dq.pop_back()
        dq.push_back(i)
        if i >= k - 1:
            result.append(arr[dq.front])
    return result
```

For the minimum, flip the back comparison to `arr[dq.back] >= arr[i]`.

## Implementation

`sliding_window_max` and `sliding_window_min` exist in Python, C++ (header `monotonic_queue.h`) and Go (`SlidingWindowMax`, `SlidingWindowMin`). All return an empty list for `k <= 0`, an empty array, or `k > len(arr)`.

Python also has `MonotonicDeque(should_pop)`, a reusable class: `push(value)`, `pop_front_if(value)`, `front()`. It stores `(index, value)` pairs and evicts by index, so equal values are handled correctly. With values only, the rule `existing <= new` collapses equal values and evicting the outgoing copy would remove the newer one still inside the window: for `[5, 5, 1]` with `k = 2` the answer must be `[5, 5]`, not `[5, 1]`. The Go deque is a slice; popping the front reslices `dq[1:]`.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Storing values instead of indices.** You cannot tell when the front has left the window, and equal values get evicted wrongly.
- **Evicting after reading the answer.** The expiry check must run before you read the front.
- **Emitting answers too early.** The first k - 1 steps produce no output.
- **Wrong comparison direction.** Max needs a decreasing deque, min an increasing one.
- **Using it for rank queries.** The deque only knows the extreme; for the median or k-th element use a balanced tree or two heaps.
- **Skipping the guards.** `k <= 0` and `k > n` return an empty result here; without the guard the loops misbehave.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is it O(n) when there are nested loops?">
    The inner loops only remove elements that were pushed by the outer loop. Each of the n indices is pushed once and popped at most once, so the total number of pops is at most n.
  </FaqItem>
  <FaqItem question="How is it different from a monotonic stack?">
    A stack only changes at the top. A monotonic queue also removes from the front when an element leaves the window, so it needs a deque.
  </FaqItem>
  <FaqItem question="Should I pop on equal values?">
    Either rule gives correct answers when the deque stores indices. Popping on equality keeps the deque shorter. With value-based eviction only the strict rule is safe.
  </FaqItem>
  <FaqItem question="Can I get the maximum and the minimum at once?">
    Yes: run two deques over the same window, one decreasing and one increasing. That solves problems such as the longest subarray whose range is at most a limit.
  </FaqItem>
</Faq>
