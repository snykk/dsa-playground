## How Dijkstra's algorithm works

Think of BFS on a graph where an edge takes w minutes to cross: you cannot simply process vertices in the order you discover them. Dijkstra keeps a tentative distance for every vertex and always **settles the vertex with the smallest tentative distance**. Settling means its distance is now final.

<Steps>
  <Step title="Initialize">
    Set `dist[start] = 0` and every other distance to infinity. Put `(0, start)` in a min-priority queue.
  </Step>
  <Step title="Pop the closest entry">
    Remove the entry with the smallest distance. If its vertex is already settled, it is a stale entry from an earlier, worse push: ignore it.
  </Step>
  <Step title="Settle it and relax its edges">
    Mark the vertex settled. For each edge (v, u, w) to an unsettled neighbor, if `dist[v] + w < dist[u]`, lower `dist[u]` and push `(dist[u], u)`.
  </Step>
  <Step title="Repeat">
    Continue until the queue is empty. Every reachable vertex is settled; the others stay at infinity.
  </Step>
</Steps>

<Callout title="Why a settled distance is final">
Suppose v has the smallest tentative distance d among unsettled vertices. Any other route to v must leave the settled region through some unsettled vertex x, and dist[x] is already at least d. Adding the rest of the route can only add non-negative weights, so that route costs at least d. Nothing beats d, so v is final. A negative edge breaks exactly this step.
</Callout>

## Pseudocode

```text
dijkstra(graph, start):
    dist[v] = infinity for every vertex       # keys AND neighbor-only vertices
    dist[start] = 0
    pq = [(0, start)]
    settled = {}
    while pq is not empty:
        d, v = pq.popMin()
        if v in settled: continue             # stale entry
        settled.add(v)
        for (u, w) in graph.get(v, []):
            if u in settled: continue
            if d + w < dist[u]:
                dist[u] = d + w
                previous[u] = v               # only in the path version
                pq.push((dist[u], u))
    return dist
```

`dijkstra_with_path` stops as soon as the target is popped and walks `previous` back to the start.

## Implementation

All three languages take an adjacency list of `(neighbor, weight)` pairs and return distances to every reachable vertex, plus a version that returns one path. A vertex that appears only as a neighbor counts as a vertex with no outgoing edges. Python also has `dijkstra_all_pairs`, which runs Dijkstra from every vertex.

## What goes wrong with negative edges

Dijkstra never revisits a settled vertex, so a negative edge into one cannot fix it. Take the directed graph `0->1 (2), 0->2 (5), 2->1 (-4)`. The repository code settles vertex 1 at distance 2 first. The route 0, 2, 1 costs 5 - 4 = 1, but vertex 1 is already settled, so `dijkstra` returns `{0: 0, 1: 2, 2: 5}` with no error. Use Bellman-Ford when weights can be negative.

Zero weights are fine. Parallel edges and self-loops are also fine, since only the cheapest relaxation wins.

## Applications

- **Road and route planning**: least travel time or distance between places.
- **Network routing**: link-state protocols such as OSPF compute shortest paths over weighted links with Dijkstra's algorithm.
- **Weighted grids and games**: movement with different terrain costs, with A* as the usual speed-up.
- **A subroutine**: Johnson's algorithm and many "cheapest path" problems with modified weights.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Negative weights.** The answer is wrong without any warning. Use Bellman-Ford.
- **No stale-entry check.** Without skipping settled vertices, an old queue entry is processed again and the work can blow up.
- **Marking visited on push.** A vertex must be settled when it is popped, not when it is first pushed; the first push is not the cheapest.
- **Ignoring neighbor-only vertices.** A vertex that appears only in neighbor lists needs an initial distance too, or the lookup fails.
- **Overflow.** In a 32-bit integer, two large weights overflow. Use 64-bit distances.
- **Social-network "degrees of separation".** That is an unweighted problem: BFS is simpler and faster.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does Dijkstra fail with negative edges?">
    Its correctness rests on the claim that the smallest tentative distance is final. A negative edge can later offer a cheaper route into a vertex that is already settled, and the algorithm never goes back to update it.
  </FaqItem>
  <FaqItem question="Does a priority queue need decrease-key?">
    Not necessarily. Pushing a new entry and skipping stale ones (lazy deletion) gives the same O((V + E) log V) bound, at the price of a heap with up to E entries.
  </FaqItem>
  <FaqItem question="Can I stop early?">
    Yes, when you only need one target. Settled distances are final, so the moment the target is popped its distance is known. `dijkstra_with_path` does exactly that.
  </FaqItem>
  <FaqItem question="What does it return for unreachable vertices?">
    Infinity: `float('inf')` in Python, `LLONG_MAX` in C++ and `math.MaxInt` in Go. The path functions return `None` in Python and `(-1, {})` or `(-1, nil)` in C++ and Go.
  </FaqItem>
</Faq>
