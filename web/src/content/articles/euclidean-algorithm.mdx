## Definition

The greatest common divisor `gcd(a, b)` is the largest integer that divides both `a` and `b`, with `gcd(0, 0) = 0` by convention. The algorithm rests on one identity, and on the Bezout identity for the extended form.

<Equation label="Euclid's step" expr="gcd(a, b) = gcd(b, a mod b)" result="stop when b = 0: gcd(a, 0) = |a|" />
<Equation label="Bezout's identity" expr="a*x + b*y = gcd(a, b)" result="x and y are integers" />

## Intuition

Any number that divides both `a` and `b` also divides `a - k*b`, and any number that divides `b` and `a - k*b` also divides `a`. So `(a, b)` and `(b, a mod b)` have exactly the same common divisors, and the pair shrinks at every step. Picture a rectangle tiled with the largest squares that fit: the square side you end with is the gcd.

## How it works

<Steps>
  <Step title="Take absolute values">
    The repository functions work on `|a|` and `|b|`, so signs never matter for the gcd.
  </Step>
  <Step title="Reduce">
    While `b` is not zero, replace `(a, b)` by `(b, a mod b)`.
  </Step>
  <Step title="Read the answer">
    When `b` is zero, `a` is the gcd.
  </Step>
</Steps>

<Callout title="Why it always stops">
The remainder `a mod b` is strictly smaller than `b`, so the second number decreases at every step and must reach 0. In fact, after two steps the larger number has at least halved, which gives the logarithmic bound.
</Callout>

## Extended Euclid

The extended algorithm keeps, for every remainder `r`, the coefficients with `r = a*x + b*y`. Starting from `a = 1*a + 0*b` and `b = 0*a + 1*b`, each new remainder is the old one minus `q` times the next, so the coefficients follow the same recurrence. Worked on `240` and `46`:

### Negative inputs

The code runs on `|a|` and `|b|` and then negates `x` if `a` was negative and `y` if `b` was negative. For `-240` and `46` it returns `(2, 9, 47)`, and `-240*9 + 46*47 = 2`. Skipping that last step is a classic bug: the coefficients then satisfy `|a|*x + |b|*y = g`, which is a different identity.

## Pseudocode

```text
gcd(a, b):
    a = |a|; b = |b|
    while b != 0:
        (a, b) = (b, a mod b)
    return a

lcm(a, b):
    if a == 0 or b == 0: return 0
    return |a| / gcd(a, b) * |b|        # divide first

extendedGcd(a, b):                      # returns (g, x, y)
    (g, x, y) = extendedGcdNonNegative(|a|, |b|)
    if a < 0: x = -x
    if b < 0: y = -y
    return (g, x, y)

extendedGcdNonNegative(a, b):
    if b == 0: return (a, 1, 0)
    (g, x1, y1) = extendedGcdNonNegative(b, a mod b)
    return (g, y1, x1 - (a / b) * y1)
```

## Implementation

Each language provides a recursive and an iterative `gcd`, `lcm` and `extended_gcd`. The C++ and Go versions use 64-bit integers: `lcm` divides before it multiplies, and Go takes absolute values in integer arithmetic (an older version went through `float64` and returned wrong answers above 2^53). Python integers have no limit. The minimum 64-bit integer is not supported in C++ and Go, since its absolute value does not fit.

Two steps at least halve the larger number, so there are at most about `2 log2(min)` steps. Lame's theorem tightens this to at most five times the number of decimal digits of the smaller input. The recursive versions use a stack of the same depth: `O(log min(a, b))`. The extended version also needs that much.

## Applications

- **Fractions.** Divide numerator and denominator by their gcd to reduce a fraction.
- **LCM.** `lcm(a, b) = |a| / gcd(a, b) * |b|`, used for synchronizing periodic events.
- **Modular inverses.** If `gcd(a, m) = 1`, the `x` from `a*x + m*y = 1` is the inverse of `a` modulo `m`.
- **Linear Diophantine equations.** `a*x + b*y = c` has integer solutions exactly when `gcd(a, b)` divides `c`.
- **Chinese Remainder Theorem.** The merge step of the topic next door is one extended Euclid per congruence.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Multiplying before dividing in lcm.** `a * b / gcd` overflows when `a * b` does not fit, even if the lcm does: `lcm(4000000000, 4000000000)` is 4000000000, but the product 1.6e19 does not fit in 64 bits. Write `a / gcd * b`.
- **Dropping signs in the extended form.** Apply the sign corrections to `x` and `y`, or `a*x + b*y` is not the gcd for negative `a` or `b`.
- **Using floating point for the absolute value.** `float64` rounds integers above 2^53: `GCD(2^53 + 1, 3)` must be 3, not 1.
- **Forgetting zero.** `gcd(0, 0)` is 0, and `lcm` with a zero argument is defined as 0, so dividing by the gcd without checking would divide by zero.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is the answer the last non-zero remainder?">
    Because the common divisors never change from step to step, and when `b` is 0 the pair is `(g, 0)`, whose largest common divisor is `g` itself.
  </FaqItem>
  <FaqItem question="Are the Bezout coefficients unique?">
    No. If `(x, y)` works, so does `(x + k*b/g, y - k*a/g)` for any integer `k`. The algorithm returns one particular pair.
  </FaqItem>
  <FaqItem question="How do I get a modular inverse from this?">
    Run extended Euclid on `a` and `m`. If the gcd is 1, then `a*x = 1 (mod m)`, so `x` reduced into `0..m-1` is the inverse. If the gcd is not 1, no inverse exists.
  </FaqItem>
  <FaqItem question="Does the order of the arguments matter?">
    Not for the gcd: if `a < b`, the first step swaps them, because `a mod b = a`. The extended coefficients do depend on the order.
  </FaqItem>
</Faq>
