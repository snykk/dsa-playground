## Definition

Write an odd `n` as `n - 1 = d * 2^r` with `d` odd. A base `a` with `2 <= a <= n - 2` is a **strong witness** for the compositeness of `n` unless one of these holds:

<Equation label="Strong probable prime to base a" expr="a^d = 1 (mod n)   or   a^(d * 2^i) = -1 (mod n) for some 0 <= i < r" />

If `n` is prime, every base passes. If `n` is composite and a base passes, `a` is a **strong liar**. For every odd composite `n`, at most a quarter of the bases in `2 .. n-2` are strong liars, so `k` independent random bases leave an error probability of at most `4^-k`.

## Intuition

Modulo a prime `p`, the only numbers whose square is 1 are 1 and `-1 = p - 1`. Fermat's little theorem says `a^(p-1) = 1`. So starting from `a^(p-1)` and taking square roots step by step must give 1, 1, ..., 1 and then at some point `-1` (or stay 1 all the way down). A composite number has extra square roots of 1, and the chain from a random base usually hits one of them.

<Callout title="A non-trivial square root of 1 proves compositeness">
In the chain for `n = 561` with `a = 2`, the term 67 satisfies `67^2 = 1 (mod 561)` but `67` is neither 1 nor 560. A prime has no such number, so 561 is composite. The Fermat test cannot see this: 561 is a Carmichael number, and it passes the Fermat test for every base coprime to it.
</Callout>

## How it works

<Steps>
  <Step title="Filter the easy cases">
    Return false for `n < 2` and for even `n > 2`; return true for 2 and 3.
  </Step>
  <Step title="Factor out the twos">
    Write `n - 1 = d * 2^r` with `d` odd, by halving `n - 1` until it is odd.
  </Step>
  <Step title="Test each witness">
    Compute `x = a^d mod n`. If `x` is 1 or `n - 1`, the witness passes. Otherwise square `x` up to `r - 1` times; if `n - 1` appears, it passes.
  </Step>
  <Step title="Decide">
    A witness that never reaches `n - 1` proves `n` composite: return false at once. If all witnesses pass, return true.
  </Step>
</Steps>

## See it in action

Run **Carmichael 561, prime 97**: the factors of 2 come out of `n - 1` one at a time, then every random witness gets a row with its chain of squares. For 561 the first witness, 139, gives the chain 10, 100, 463, 67, which never reaches 560, so the code returns False at once; the next square, `67^2`, would be 1, a square root of 1 that a prime cannot have. In the **Miller-Rabin (12 fixed bases)** tab, **Fools eleven bases** shows bases 2 to 31 passing a composite until 37 catches it, and **Beyond the 12-base bound** shows the first number for which all twelve are fooled.

## Pseudocode

```text
isWitness(a, n, d, r):                  # true if a proves n composite
    x = a^d mod n
    if x == 1 or x == n - 1: return false
    repeat r - 1 times:
        x = x * x mod n
        if x == n - 1: return false
    return true

millerRabin(n, k):
    if n < 2: return false
    if n is 2 or 3: return true
    if n is even: return false
    (d, r) = decompose(n - 1)           # n - 1 = d * 2^r, d odd
    repeat k times:
        a = random integer in [2, n - 2]
        if isWitness(a, n, d, r): return false
    return true

deterministic(n):                       # same loop over a in 2,3,5,...,37 (skip a >= n)
```

## Implementation

Python has `miller_rabin` (random witnesses), `is_prime_miller_rabin` and `miller_rabin_deterministic`. C++ and Go have the same three, plus a `U64` variant that accepts the full range up to 2^64 - 1; their `int64` forms accept up to 2^63 - 1 and treat negative input as not prime. Every modular product in C++ and Go goes through a 128-bit multiplication (`unsigned __int128`, `math/bits`). An earlier version multiplied in signed 64 bits and reported primes above about 3.04e9 as composite. C++ draws witnesses from a seeded `std::mt19937_64`, Go from the auto-seeded `math/rand`.

## Applications

- **Prime generation.** Pick random odd numbers and keep the first that passes, as in cryptographic key generation.
- **Competitive programming.** Testing one 64-bit number for primality, and a quick check to run before trying to factor a number (for example with Pollard's rho).
- **Number theory tools.** Choosing prime moduli for hashing or for the Chinese Remainder Theorem.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Overflowing the product.** `(a * b) % n` in signed 64-bit is wrong for `n` above about 3.04e9. Use `__int128` or `math/bits`.
- **Trusting the bound too far.** Twelve witnesses are exact below 318665857834031151167461, not for every integer.
- **Weak randomness.** A fixed sequence or only small witnesses voids the `4^-k` bound.
- **Squaring too often.** After `a^d` only `r - 1` squarings are needed; the chain stops at the first `n - 1`.
- **Skipping the small cases.** Even numbers, 2 and 3 must be handled before the main loop, or the witness range `[2, n - 2]` is empty.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Can Miller-Rabin say a prime is composite?">
    No. A prime passes every base. Only composites can be misreported, as "probably prime".
  </FaqItem>
  <FaqItem question="Why is the error at most 1/4 per witness and not smaller?">
    That is a worst case over all odd composites. For most numbers the share of strong liars is far smaller: only 8 of the 558 bases are strong liars for 561. The 1/4 bound is the guarantee that holds for every composite.
  </FaqItem>
  <FaqItem question="Why are twelve primes enough for 64-bit numbers?">
    Computer searches show that no composite below 318665857834031151167461 is a strong pseudoprime to all of the first twelve primes. That bound is larger than 2^64, which is about 1.8 * 10^19.
  </FaqItem>
  <FaqItem question="How does it relate to the Fermat test?">
    The Fermat test checks only `a^(n-1) = 1`. Miller-Rabin also inspects the square roots along the way, which exposes Carmichael numbers.
  </FaqItem>
</Faq>
