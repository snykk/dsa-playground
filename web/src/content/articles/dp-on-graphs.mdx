## When to use DP on graphs

Use it when a question about paths in a **directed graph without cycles** can be answered from the answers for the node's neighbours.

- "Longest path", "number of paths", or "maximum total value along a path" in a DAG.
- A scheduling problem with dependencies, such as the critical path of a project.
- The graph is given as prerequisites ("task A needs task B"), so cycles would mean the input is invalid.

On a graph with cycles the same recurrence can loop forever (or be undefined for longest path), so you first need to know whether the graph is a DAG.

## How it works

Define `dp[v]` as the answer for paths **starting at** `v`. A path from `v` is one edge to a successor `w` followed by a path from `w`, so:

<Equation label="Longest path recurrence" expr="dp[v] = 0 if v has no successors, otherwise 1 + max over edges v->w of dp[w]" result="answer = dp[start]" />

<Steps>
  <Step title="Recurse into successors first">
    To compute `dp[v]`, call the function on every successor. In a DAG this recursion always ends, because following edges can never return to `v`.
  </Step>
  <Step title="Memoize finished nodes">
    Store each result in a dictionary. A node reached by several paths is computed once, which is what makes the total time O(V + E) instead of the number of paths.
  </Step>
  <Step title="Mark nodes in progress">
    Keep a set of nodes whose call has started but not finished. Meeting one of them again means an edge points back into the current path: a cycle.
  </Step>
</Steps>

<Callout title="The invariant">
When a call for `v` returns, every node reachable from `v` has a finished memo entry. The three states (not started, in progress, finished) are the same colours as a DFS cycle check; in a DAG the in-progress state is never met twice.
</Callout>

### When there is a cycle

For `{0: [1], 1: [2], 2: [0]}` the call chain 0, 1, 2 reaches 0 again while 0 is still in progress. The code raises `ValueError`. Before this check existed, the function returned 2 for this graph, a wrong answer.

## Pseudocode

```text
longestPath(graph, start):
    dp = empty map              # finished nodes -> nodes on longest path from there
    onStack = empty set         # nodes whose call is still running

    visit(v):
        if v in dp: return dp[v]
        if v in onStack: error "graph has a cycle"
        onStack.add(v)
        best = 0
        for w in graph[v] (empty if v is not a key):
            best = max(best, visit(w))
        onStack.remove(v)
        dp[v] = best + 1
        return dp[v]

    return visit(start) - 1     # edges, not nodes
```

## Implementation

The Python version has one function, `dag_longest_path(graph, start)`. The graph is a dictionary from a node to a list of successor ids; a node missing from the dictionary has no successors. C++ has `dagLongestPath` over an `std::unordered_map<int, std::vector<int>>` and throws `std::invalid_argument` on a reachable cycle; Go has `DAGLongestPath` over a `map[int][]int` and returns the error `ErrCycle`.

<TopicCode topic="Algorithms/Dynamic_Programming/Advanced_DP/DP_on_Graphs" />

The recursion depth is at most the number of nodes on the longest path (exactly that on a path graph), so a path graph of more than about 1,000 nodes reaches Python's default recursion limit.

## Applications

- Build systems and task schedulers: the critical path is a longest path in the dependency DAG.
- Counting the ways to reach a state in games or state machines whose transitions never repeat.
- Dynamic programs written as graphs, since every DP's dependency structure is a DAG.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Not detecting cycles.** With only a visited set a back edge looks like a finished node and the answer is silently wrong. You need the in-progress state.
- **Counting nodes instead of edges.** `dp` here counts nodes and the function subtracts 1; mix the two and every answer is off by one.
- **Recomputing shared nodes.** Without the memo a diamond-heavy DAG takes exponential time.
- **Assuming all nodes are keys.** Nodes with no entry in the dictionary are treated as sinks, which is convenient but can hide typos in node ids.
- **Cycles that are not reachable.** The function checks only the part reachable from `start`; a cycle elsewhere is not reported.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is longest path easy on a DAG but hard in general?">
    On a DAG a path can never revisit a node, so the best path from `v` depends only on its successors. With cycles a path must remember which nodes it has used, and no way is known to avoid exploring exponentially many paths.
  </FaqItem>
  <FaqItem question="Do I need a topological sort?">
    Not for the memoized DFS: the recursion finds the order itself. A topological sweep is an alternative that avoids recursion.
  </FaqItem>
  <FaqItem question="How would I count paths instead?">
    Replace the combine step: `ways[v]` is the sum of `ways[w]` over successors, with `ways[target] = 1`. Everything else, including the memo and the cycle check, stays the same.
  </FaqItem>
  <FaqItem question="What is the difference between the longest path and the shortest path in a DAG?">
    Only `max` versus `min` in the transition. The DP is the same, and both run in O(V + E), which is faster than Dijkstra or Bellman-Ford.
  </FaqItem>
</Faq>
