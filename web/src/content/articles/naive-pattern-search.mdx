## How the naive search works

A text of length `n` has `n - m + 1` places where a pattern of length `m` could start. The naive search simply tries them all.

<Steps>
  <Step title="Pick a starting position">
    For each `i` from `0` to `n - m`, line the pattern up under `text[i]`.
  </Step>
  <Step title="Compare left to right">
    Set `j = 0` and advance `j` while `j < m` and `text[i + j] == pattern[j]`. The first mismatch ends the attempt.
  </Step>
  <Step title="Record a match">
    If `j` reached `m`, every character matched: record `i`.
  </Step>
  <Step title="Move one position right">
    Whatever happened, the next attempt starts at `i + 1`. Nothing learned from the previous attempt is reused.
  </Step>
</Steps>

<Callout title="The invariant">
When the attempt at `i` ends, the answer for position `i` is final: either all `m` characters matched or one did not. Because every start in `0..n-m` is tried, no occurrence can be missed, and overlapping occurrences are found naturally.
</Callout>

## Pseudocode

```text
naive_pattern_search(text, pattern):
    if pattern is empty: return []
    if text is empty or len(pattern) > len(text): return []
    n = len(text); m = len(pattern); result = []
    for i = 0 to n - m:
        j = 0
        while j < m and text[i + j] == pattern[j]:
            j += 1
        if j == m:
            result.append(i)
    return result
```

## Implementation

All three languages have the same function (`naive_pattern_search`, `naivePatternSearch`, `NaivePatternSearch`) plus `count` and `first` helpers. Both helpers run the full search and then take its length or its first element. An **empty pattern, an empty text, or a pattern longer than the text returns `[]`**. The other searches in this section do the same, but library searches report an empty pattern as found at index 0 (`'abc'.find('')`, `std::string::find`, `strings.Index`), so check the convention before swapping one in. Python indexes code points; C++ and Go index bytes.

## Applications

- **Short patterns and small texts**, where setup cost would outweigh the saving.
- **A baseline and test oracle** for faster algorithms: a faster search can be checked against it on random inputs.
- **Teaching** the idea of an alignment and why preprocessing helps.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Off-by-one in the loop bound.** The last start is `n - m`, not `n - m - 1` and not `n`. Starting beyond `n - m` reads past the text.
- **Not checking `m > n` first.** The range `0..n-m` is empty, but with unsigned sizes (`size_t` in C++) `n - m` wraps around to a huge number.
- **Skipping ahead after a match.** Moving by `m` instead of 1 misses overlapping matches (`aa` in `aaaa`).
- **Assuming it is O(n).** It is O(n) only when mismatches come early. A long run of equal characters makes it quadratic.
- **Empty-pattern convention.** This implementation returns `[]`; other implementations return every position.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Is the best case O(n)?">
    Yes, when the first character of the pattern differs from the text character at every alignment: one comparison each, n - m + 1 in total. A search that finds an early match still has to finish scanning the rest of the text.
  </FaqItem>
  <FaqItem question="When is naive search good enough?">
    For short patterns, small texts, or one-off searches. On natural text most attempts fail on the first or second character, so it runs in nearly linear time. It only degrades on highly repetitive input.
  </FaqItem>
  <FaqItem question="What input makes it slowest?">
    A text of repeated characters with a pattern that matches almost to the end, such as `AAAA...AB` for the pattern `AAAAB`. Every alignment compares the full pattern before failing.
  </FaqItem>
  <FaqItem question="Which algorithm should I learn next?">
    KMP. It keeps the idea of scanning left to right but uses the pattern's own structure (the LPS table) so that the text pointer never moves back and the worst case is O(n + m).
  </FaqItem>
</Faq>
