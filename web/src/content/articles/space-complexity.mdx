## Definition

The space complexity of an algorithm is a function `S(n)`: the memory it uses on an input of size `n`, as a function of `n`. As with time, it is described with asymptotic notation (see Big-O Notation), so constants and lower-order terms are dropped.

Three quantities are easy to mix up:

<Equation label="Total space" expr="total(n) = input(n) + auxiliary(n)" />

When someone says "Heap Sort uses O(1) space" they mean auxiliary space: the array is being sorted in place and only a few extra variables are used. Each bound is still a Big-O statement about a function, so it can be given for the best, average or worst case of the memory used.

## Intuition: where memory goes

Memory is used in three places:

- **Variables**: a fixed number of scalars is <BigO of="1" />.
- **Data you build**: a list of `n` items is <BigO of="n" />, an `n` by `n` matrix is <BigO of="n^2" />.
- **The call stack**: every active function call keeps a frame. Recursion that goes `d` levels deep holds `d` frames at the same time, so its space is at least <BigO of="d" />.

The stack is the one that is easy to forget. A recursive function with no arrays can still use O(n) space.

Two of these surprise people:

- **Naive Fibonacci** makes exponentially many calls, but the second call only starts after the first returns. At any moment the stack holds one path, at most `n` frames. The measured depth for `n = 5, 10, 20` is 5, 10, 20.
- **Merge Sort** has log n levels and n elements of work per level, which looks like O(n log n) space. But memory from a finished merge is freed before the next one starts. At any time the live buffers hold about n + n/2 + n/4 + &hellip; elements, so the space is O(n).

## Using it in practice

1. **Name what you count.** Say "auxiliary space" or "total space". Include recursion depth.
2. **Find the largest thing alive at once**, not the sum of everything ever allocated.
3. **Decide whether recursion is acceptable.** Depth `n` costs O(n) space and, in Python, hits the default limit of 1,000 frames.
4. **Trade space for time deliberately.** A hash table or memo table spends O(n) memory to avoid recomputation. Streaming and in-place algorithms do the opposite.

## Common misconceptions

<Callout tone="warning" title="Watch out for these">
- **"Recursion uses no extra space."** Every active call has a frame. Depth `d` costs O(d) memory.
- **"Total calls decide the stack."** Only calls alive at the same time count. Naive Fibonacci has O(2<sup>n</sup>) calls but O(n) space.
- **"Depth times work per level."** For Merge Sort that gives O(n log n), but freed memory is reused, so the real answer is O(n).
- **Slicing copies in Python.** `arr[:mid]` allocates a new list. Slicing inside a recursion adds O(n) memory per level of work you thought was free. Pass indices instead.
- **Input vs auxiliary.** Returning a new list of size `n` is O(n) output. Many problem statements do not count the output; state which convention you use.
- **Language limits.** Python allows about 1,000 nested calls by default and raises `RecursionError` beyond that. In C++ a deep recursion overflows the fixed-size stack. Go grows goroutine stacks on demand, starting small (2 KB per goroutine in current Go versions), up to a configurable maximum.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Does space complexity include the input?">
    Usually not. The convention is auxiliary space, the memory beyond the input. Total space includes the input. Say which one you mean, especially when you compare in-place with copying algorithms.
  </FaqItem>
  <FaqItem question="Is Quick Sort O(log n) space?">
    Only if you recurse into the smaller partition first and loop on the larger one, which keeps the depth at most log2(n). Plain two-call recursion can reach O(n) depth on bad input.
  </FaqItem>
  <FaqItem question="Why is Merge Sort O(n) and not O(n log n) in space?">
    Each merge needs a buffer, but the buffer is released when the merge ends. The live buffers at any moment form a geometric series that sums to O(n).
  </FaqItem>
  <FaqItem question="Can I trade time for space?">
    Yes, in both directions. Memoization and hash tables spend memory to save time. In-place algorithms and recomputation save memory at the cost of extra time.
  </FaqItem>
</Faq>
