## What a sparse table is

The problem: a fixed array and many queries "what is the minimum of `a[l..r]`?" A sparse table answers each in O(1) by storing the answer for *every window whose length is a power of two*.

`table[i][j]` is the minimum of the `2^j` elements starting at `i`. Level 0 is the array itself, and each higher level combines two windows of the level below: `table[i][j] = min(table[i][j-1], table[i + 2^(j-1)][j-1])`. Only windows that fit inside the array are valid, so the number of levels is `floor(log2(n)) + 1`. For `[1, 3, 5, 7, 9, 11, 2, 4, 6, 8]` (min), with `-` marking windows that run off the end:

<Callout title="Why overlap is allowed">
For minimum, counting an element twice changes nothing: `min(x, x) = x`. Operations with this property are called **idempotent** (min, max, gcd, bitwise AND and OR). That is why two overlapping windows suffice. For a sum the overlapped part would be counted twice, so a sparse table cannot answer sums in O(1).
</Callout>

    ['`get(i)`', 'the original element', 'O(1)'],
  ]}
/>

`kind` must be `'min'` or `'max'`; anything else raises `ValueError` (Python), throws `std::invalid_argument` (C++) or panics (Go). It used to silently mean max. An empty array is allowed, and every query on it fails with `IndexError`, `std::out_of_range` or a panic. An index outside `0..n-1` fails the same way. If `l > r` the bounds are swapped. The table is built from a copy of the input in all three languages. The exponent `k` is computed with integer bit operations, not floating-point `log2`.

### Query: two windows

Let `len = r - l + 1` and `k = floor(log2(len))`, the largest power of two that fits. The windows `[l, l + 2^k - 1]` and `[r - 2^k + 1, r]` together cover `[l, r]` (they may overlap), so the answer is `min(table[l][k], table[r - 2^k + 1][k])`.

Index 5 is counted by both windows, which is harmless for a minimum. With a **sum** the same two windows would give 55 instead of the true 44, because `a[5] = 11` would be added twice.

### Build

Level `j` is built from level `j - 1` for every start `i` with `i + 2^j <= n`. There are about `n` windows on each of about `log2(n)` levels, so building takes O(n log n) time and stores O(n log n) values (the code allocates `n` rows of `log_n` cells).

## Implementation

The three versions share the same structure: a `table[i][j]` of `n` rows by `floor(log2(n)) + 1` columns, a level-by-level build, and a two-window query. Tests check every possible range of random arrays against brute force, for both min and max.

## Applications

- **Range minimum query (RMQ)** on static arrays, such as CSES "Static Range Minimum Queries".
- **Lowest common ancestor** via an Euler tour and RMQ.
- **Offline analytics:** many "min over a window" questions on fixed data.
- **Range gcd** queries.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using it for sums.** The overlap would be counted twice.
- **Using floating-point `log2`.** It can be off for large inputs; use integer bit length instead.
- **Building levels past the array end.** Level `j` only has windows with `i + 2^j <= n`.
- **Calling it after the data changed.** The table is a snapshot.
- **Empty input.** There is nothing to query; this code allows an empty table and fails on any query.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is the query O(1) when a segment tree needs O(log n)?">
    The table already contains the answer for every window whose length is a power of two. One window of that length starting at `l` and one ending at `r` cover the range, so two reads and one `min` are enough.
  </FaqItem>
  <FaqItem question="Can a sparse table answer range sums in O(1)?">
    Not directly: overlapping windows double-count. Use prefix sums for static sums, or a disjoint sparse table.
  </FaqItem>
  <FaqItem question="How much memory does it use?">
    About `n * (floor(log2 n) + 1)` values. For n = 100000 that is roughly 1.7 million entries.
  </FaqItem>
  <FaqItem question="Why is a sparse table in the Trees folder?">
    It is related to the segment tree and the Fenwick tree as a range-query structure, but it contains no tree. The folder is only a grouping.
  </FaqItem>
</Faq>
