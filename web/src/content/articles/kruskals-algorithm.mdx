## How Kruskal's algorithm works

A spanning tree connects all V vertices with V - 1 edges and no cycle. A **minimum** spanning tree is the one with the smallest total weight. Kruskal's idea is the simplest greedy rule: look at the edges from lightest to heaviest and keep an edge whenever it joins two vertices that are not yet connected.

<Steps>
  <Step title="Sort the edges">
    Order all edges by weight, lightest first.
  </Step>
  <Step title="Start with V separate vertices">
    Create a union-find structure where every vertex is in its own set. Each set is one tree of the growing forest.
  </Step>
  <Step title="Scan the sorted edges">
    For each edge (u, v, w): if `find(u) != find(v)` the endpoints are in different trees, so keep the edge and `union` them. Otherwise the edge would close a cycle, so skip it.
  </Step>
  <Step title="Stop early">
    Once V - 1 edges are kept the tree is complete and the remaining edges are not examined. If the edges run out first, the graph was disconnected.
  </Step>
</Steps>

<Callout title="Why the greedy choice is safe: the cut property">
Take any edge e that is a lightest edge crossing some cut (a split of the vertices into two groups). Then some minimum spanning tree contains e. When Kruskal examines an edge that joins two different trees, that edge is a lightest edge leaving one of those trees, since every lighter edge was already examined and either kept or skipped. So it is always safe to keep.
</Callout>

## Union-find

Kruskal is only fast because "are u and v already connected?" is nearly free. The repository's `UnionFind` stores a `parent` array and a `rank` array.

- **find(x)** follows parent links to the root and, on the way back, points every visited vertex directly at the root (*path compression*).
- **union(x, y)** finds both roots. If they are equal it returns false (a cycle). Otherwise it hangs the root of lower rank under the other (*union by rank*) and returns true.

With both tricks a find costs O(alpha(V)) amortized, where alpha is the inverse Ackermann function, below 5 for any input that fits in memory. The `union` result doubles as the cycle test, which is why the main loop has no separate `find` calls.

## Pseudocode

```text
kruskal(edges, n):
    if n == 0: return [], 0
    sort edges by weight                  # Python: stable; C++ and Go: not stable
    uf = UnionFind(n)
    mst = []; total = 0
    for (u, v, w) in edges:
        if uf.union(u, v):                # different trees: no cycle
            mst.append((u, v, w)); total += w
            if len(mst) == n - 1: break
    return mst, total
```

## Complexity analysis

  rows={[

  ]}
/>

Since E is at most V<sup>2</sup>, log E is at most 2 log V, so O(E log E) is the same as O(E log V). If the weights are small integers, a counting sort makes the sort linear and the whole algorithm nearly O(E).

## Disconnected graphs and negative weights

- **Disconnected input** is not an error. Kruskal returns a **minimum spanning forest**: one tree per component. For edges `(0,1,5), (2,3,3)` on 4 vertices it returns 2 edges with total 8. `kruskal_mst_with_details` reports `is_connected` as `False`, because the result has fewer than V - 1 edges. Prim's algorithm on the same input covers only the start component.
- **Negative weights** are fine: only the order of the weights matters, never their sign. On `(0,1,-2), (0,2,7), (1,2,3), (1,3,-5), (2,3,1)` the total is -6.

## Applications

- **Network design.** Connect sites, such as cables, pipes or roads, at the least total cost.
- **Clustering.** Stop Kruskal before the last k - 1 edges to get k clusters (single-linkage clustering).
- **Approximation algorithms.** A minimum spanning tree is a building block for the metric travelling-salesman 2-approximation.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Skipping the cycle check.** Without union-find (or a similar test) the lightest edges can form a cycle.
- **Assuming a connected graph.** Check `len(mst) == V - 1` (or `is_connected`) before treating the result as a spanning tree.
- **Forgetting that the sort mutates.** The C++ and Go versions sort the edge list you pass in, in place.
- **Relying on a unique answer.** With equal weights, languages can return different edge sets of the same total weight.
- **Vertices outside 0 to V - 1.** The union-find arrays are sized V. Relabel arbitrary ids first.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does Kruskal's algorithm never create a cycle?">
    It keeps an edge only when its endpoints are in different union-find sets, that is, in different trees of the forest. Joining two different trees by one edge cannot create a cycle.
  </FaqItem>
  <FaqItem question="Is the minimum spanning tree unique?">
    Only if all edge weights are distinct. With ties there can be several trees of the same minimum total weight.
  </FaqItem>
  <FaqItem question="Does Kruskal work with negative weights?">
    Yes. It only compares weights, so negative values change nothing. This differs from Dijkstra's algorithm, which breaks on negative edges.
  </FaqItem>
  <FaqItem question="Kruskal or Prim?">
    Kruskal for sparse graphs and edge lists; Prim for dense graphs or when the graph is already an adjacency structure. Both are correct and give the same total weight.
  </FaqItem>
</Faq>
