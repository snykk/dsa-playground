## How 0/1 Knapsack works

Each item is a yes/no decision, so there are 2<sup>n</sup> subsets. The table avoids enumerating them by asking a smaller question: what is the best value using only the **first i items** and a bag of capacity **w**? Call it `dp[i][w]`.

<Steps>
  <Step title="Define the table">
    `dp[i][w]` is the best value using items `1..i` with capacity `w`. The table has `n + 1` rows and `W + 1` columns. Row 0 (no items) is all zeros.
  </Step>
  <Step title="Decide on item i">
    If its weight `wi` is larger than `w`, it cannot be taken: `dp[i][w] = dp[i-1][w]`. Otherwise take the better of two options: skip it, `dp[i-1][w]`, or take it, `dp[i-1][w - wi] + vi`.
  </Step>
  <Step title="Fill row by row">
    Every cell reads only the row above, so one pass over rows `1..n` and columns `0..W` is enough.
  </Step>
  <Step title="Read the answer">
    The best value overall is `dp[n][W]`.
  </Step>
</Steps>

<Callout title="Why the row above is the right thing to read">
Both options look at row `i-1`, which only knows about items `1..i-1`. Item `i` therefore cannot be counted twice: that is exactly the 0/1 rule. The unbounded knapsack reads row `i` for the "take" option instead.
</Callout>

## Worked example

Items as `(weight, value)`: (1, 1), (3, 4), (4, 5), (5, 7). Capacity `W = 7`. These numbers come from running `knapsack_01` on this input.

Two cells in detail:

- `dp[3][7]` (item 3 has weight 4, value 5): skip gives `dp[2][7] = 5`; take gives `dp[2][3] + 5 = 4 + 5 = 9`. The maximum is 9.
- `dp[4][7]` (item 4 has weight 5, value 7): skip gives `dp[3][7] = 9`; take gives `dp[3][2] + 7 = 1 + 7 = 8`. The maximum is 9, so item 4 is skipped.

**Recovering the items.** Start at `dp[n][W]`. If `dp[i][w] == dp[i-1][w]`, item `i` was skipped; otherwise it was taken, so record it and subtract its weight from `w`. Here: `dp[4][7] = dp[3][7]` (skip item 4), `dp[3][7] != dp[2][7]` (take item 3, `w = 3`), `dp[2][3] != dp[1][3]` (take item 2, `w = 0`). The chosen items are 2 and 3: weight 3 + 4 = 7, value 4 + 5 = 9. The repository code returns only the value, so the traceback is a technique, not a function.

## Pseudocode

```text
knapsack01(weights, values, capacity):
    n = length(weights)
    dp = (n + 1) x (capacity + 1) table of zeros
    for i = 1 to n:
        for w = 0 to capacity:
            if weights[i-1] <= w:
                dp[i][w] = max(dp[i-1][w], dp[i-1][w - weights[i-1]] + values[i-1])
            else:
                dp[i][w] = dp[i-1][w]
    return dp[n][capacity]

knapsack01Optimized(weights, values, capacity):     # Python only
    dp = array of capacity + 1 zeros
    for i = 0 to n - 1:
        for w = capacity down to weights[i]:        # right to left
            dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
    return dp[capacity]
```

## Implementation

Python has both the 2D table (`knapsack_01`) and the one-row version (`knapsack_01_optimized`). The C++ and Go versions implement only the 2D table. All three return the best value, not the chosen items, and none validates its input: weights and values must have the same length and the capacity must not be negative.

## Complexity analysis

There are `(n + 1)(W + 1)` cells and each is filled with a constant amount of work.

  ]}
/>

<Callout tone="warning" title="Pseudo-polynomial, not polynomial">
`W` is a number, and writing it takes only log<sub>2</sub>(W) bits. The running time is polynomial in the *value* of `W`, but exponential in its length. With 20 items and `W = 10^9` the table has about 2&times;10<sup>10</sup> cells. Use meet-in-the-middle (<BigO of="2^(n/2)" />) or branch and bound there. 0/1 Knapsack is NP-hard, so no polynomial algorithm is known.
</Callout>

## The one-row version

Row `i` needs only row `i-1`, so one array is enough if it is updated in the right order. The loop must run from `w = W` **down to** `wi`: then `dp[w - wi]` has not been touched for item `i` yet and still holds the old row.

With one item of weight 2 and value 3 and capacity 4, the right-to-left loop returns 3, and the left-to-right loop returns 6 (the item is taken twice). The Python tests cover this case.

## Knapsack vs greedy and alternatives

Greedy by value-per-weight works for the fractional knapsack, but not here. Items (weight, value): (10, 60), (20, 100), (30, 120), capacity 50. Greedy takes the first two (ratios 6 and 5) for a value of 160 and then cannot fit the third. The optimum skips the first item: 100 + 120 = 220.

## Applications

- **Resource allocation.** Pick projects under a budget, or cargo under a weight limit.
- **Subset-sum problems.** Partition into equal halves or reach a target sum, with value equal to weight.
- **Counting and constraint variants.** LeetCode problems such as Target Sum and Ones and Zeroes reduce to a knapsack table, the latter with two capacity dimensions.
- **Teaching.** It is the standard example of a 2D DP with a take-or-skip decision.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Wrong sweep direction in the 1D version.** Going left to right turns the 0/1 problem into the unbounded one.
- **Off-by-one in the table size.** The table needs `n + 1` rows and `W + 1` columns; the weight of item `i` is `weights[i-1]`.
- **Greedy by ratio.** It is optimal only for the fractional variant.
- **Mismatched input lengths.** `weights` and `values` must have the same length. The implementations do not check it.
- **Huge capacities.** Check `n * W` before you allocate the table.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is it called 0/1?">
    Each item has two choices: take it (1) or leave it (0). Fractions are not allowed, and neither are repeated copies.
  </FaqItem>
  <FaqItem question="Is O(n W) really polynomial?">
    Not in the strict sense. Polynomial time is measured in the number of input bits, and `W` takes only log<sub>2</sub>(W) bits to write. That is why the algorithm is called pseudo-polynomial and why the problem is still NP-hard.
  </FaqItem>
  <FaqItem question="How do I get the chosen items, not just the value?">
    Keep the full 2D table and trace back from `dp[n][W]`: if `dp[i][w]` differs from `dp[i-1][w]`, item `i` was taken, so subtract its weight. The one-row version cannot do this, because it overwrites the earlier rows.
  </FaqItem>
  <FaqItem question="What if an item has weight 0?">
    It is always taken. The code handles it without special cases: its weight is at most every `w`, so it adds its value whenever that helps.
  </FaqItem>
</Faq>
