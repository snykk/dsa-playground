## How the Sudoku solver works

The board is a 9 x 9 grid of integers; `0` marks an empty cell. A digit `d` is **legal** at `(row, col)` if `d` does not already appear in that row, that column or that 3 x 3 box. The box of a cell starts at `((row // 3) * 3, (col // 3) * 3)`.

<Steps>
  <Step title="Validate the puzzle">
    `solve_sudoku` first calls `is_valid_puzzle`. It rejects a board that is not 9 x 9, has a value outside 0..9, or whose given digits already repeat in a row, column or box. In that case it returns `False` and does not touch the board.
  </Step>
  <Step title="Find the first empty cell">
    `find_empty` scans row by row. If there is none, every cell is filled and the puzzle is solved.
  </Step>
  <Step title="Try the digits 1 to 9">
    For each digit that `is_valid` accepts, write it into the cell and recurse to the next empty cell.
  </Step>
  <Step title="Undo on failure">
    If the recursive call fails, set the cell back to 0 and try the next digit. When all nine digits fail, return `False` so that the caller changes its own digit.
  </Step>
</Steps>

<Callout title="Why the validation step matters">
The search only checks a digit against the cells around it when it places that digit. Givens are never re-checked, so two equal givens in one row would be accepted silently, and a completely filled but invalid board would be reported as solved. That is why `is_valid_puzzle` runs once before the search.
</Callout>

## Pseudocode

```text
isValid(board, row, col, num):
    if num appears in board[row][*]: return false
    if num appears in board[*][col]: return false
    if num appears in the 3x3 box of (row, col): return false
    return true

search(board):
    (row, col) = first cell with board[row][col] == 0
    if there is none: return true
    for num = 1 to 9:
        if isValid(board, row, col, num):
            board[row][col] = num
            if search(board): return true
            board[row][col] = 0              # backtrack
    return false

solveSudoku(board):
    if not isValidPuzzle(board): return false   # shape, range 0..9, no conflicting givens
    return search(board)
```

## Implementation

The three versions are identical in structure: `is_valid_puzzle`, `is_valid`, `find_empty`, a recursive search, and `solve_sudoku`, which validates and then searches. All of them solve the board in place and return a boolean. They differ only in naming (`isValidPuzzle`, `solveSudoku` in C++ and Go) and in what they use for the empty-cell lookup: a tuple or `None` in Python, `std::optional` in C++, and an index pair plus a flag in Go.

## Complexity analysis

With `k` empty cells, each recursion level tries at most nine digits, so the search tree has at most 9<sup>k</sup> leaves. Each node costs a constant amount of work on a fixed 9 x 9 board: `find_empty` scans 81 cells and `is_valid` scans up to 27.

<Equation label="Search tree" expr="nodes <= 1 + 9 + 9^2 + ... + 9^k" result="O(9^k)" />

The recursion is `k` deep. The validation step runs once and costs <BigO of="81" />, a constant. The example puzzle is solved by this simple method in a small fraction of a second in Python, but puzzles can be built to defeat it by making the early cells in scan order accept many wrong digits.

## Applications

- **Puzzle solving and checking.** Generators use a solver to verify that a puzzle has a solution.
- **Constraint satisfaction.** The same pattern solves timetabling and register-allocation style problems.
- **Teaching.** It introduces pruning, constraint propagation and search heuristics.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Trusting the givens.** Without a check, two equal givens or a full but invalid board look solved. This solver validates first and returns `False` without touching the board.
- **Wrong box index.** The box origin is `(row // 3) * 3` and `(col // 3) * 3`; using `row % 3` shifts the box.
- **Forgetting to reset the cell.** A failed branch must set the cell back to 0, or later searches see a stale digit.
- **Assuming an answer exists.** A puzzle whose givens do not conflict can still have no solution; the solver then returns `False` and the board is restored.
- **Assuming uniqueness.** A puzzle with several solutions returns the first one in digit order.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does the solver validate the board before searching?">
    The search only checks a new digit against the existing ones. Conflicts among the givens are invisible to it, so an invalid starting board could be accepted. Validation costs a single pass over 81 cells.
  </FaqItem>
  <FaqItem question="Is the answer always unique?">
    Well-formed puzzles have exactly one solution, but the solver does not check this. If several solutions exist it returns the first one it reaches.
  </FaqItem>
  <FaqItem question="What happens to the board when there is no solution?">
    The search undoes every placement while unwinding, so the board is exactly the input board and the function returns `False`.
  </FaqItem>
  <FaqItem question="How can I make it much faster?">
    Always branch on the empty cell with the fewest legal digits, and fill cells that have a single candidate before guessing. The same example puzzle then needs 52 calls instead of 4,209.
  </FaqItem>
</Faq>
