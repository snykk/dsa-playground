## Definition

Two integers are congruent modulo `m` if they differ by a multiple of `m`.

<Equation label="Congruence" expr="a = b (mod m)  <=>  m divides (a - b)" />

Reduction commutes with addition, subtraction and multiplication, so you may reduce at any point:

<Equation label="Compatibility" expr="(a * b) mod m = ((a mod m) * (b mod m)) mod m" result="the same holds for + and -" />

The modular inverse of `a` is a number `x` with `a * x = 1 (mod m)`. It exists exactly when `gcd(a, m) = 1`, and then it is unique modulo `m`. Division by `b` means multiplication by the inverse of `b`.

## Intuition

Think of a clock with `m` ticks. Adding walks forward and wraps around; subtracting walks backward and wraps the other way. A negative number is just a position counted backwards: `-3` on an 11-tick clock is tick 8. Division is the odd one out. On a clock of 12, `4x = 8` has several answers and `4x = 1` has none, because 4 shares a factor with 12. On a clock of 11, every non-zero number can be undone.

## How the code works

<Steps>
  <Step title="Normalize operands">
    Reduce each input into `0 .. m-1`. Python's `%` already does this; C++ and Go need an explicit `floorMod`, because their `%` keeps the sign of the dividend (`-3 % 11` is `-3`).
  </Step>
  <Step title="Combine without overflow">
    C++ and Go add with a comparison against `m - y` instead of `x + y`, and multiply in 128 bits (`__int128`, `math/bits`), so any modulus up to the largest 64-bit integer works.
  </Step>
  <Step title="Invert with extended Euclid">
    `mod_inverse` runs the extended gcd on `(a, m)`. If the gcd is 1, the coefficient of `a`, reduced modulo `m`, is the inverse; otherwise there is none.
  </Step>
  <Step title="Power by squaring">
    `mod_power` is binary exponentiation. A negative exponent inverts the base first.
  </Step>
</Steps>

<Callout title="Invariant">
Every function returns a value in `0 .. m-1` (or the no-inverse marker). That is why the `-1` sentinel of C++ and Go is unambiguous: a valid result is never negative.
</Callout>

## See it in action

Run **Modulo 11 (the demo)**: each operand walks round a clock of 11 residues, a sum or product wraps past 0, and `mod_inverse(3, 11)` fills the extended Euclid table before 4 lands on the clock. **No inverse modulo 12** marks the multiples of `gcd(4, 12) = 4`, which never reach 1, and **Negative operands** walks counterclockwise.

## Pseudocode

```text
modAdd(a, b, m):                       # modAdd, modSubtract, modMultiply: all in [0, m)
    x = floorMod(a, m); y = floorMod(b, m)
    if x >= m - y: return x - (m - y)  # avoids x + y overflowing
    return x + y

modMultiply(a, b, m):
    return (floorMod(a, m) * floorMod(b, m)) mod m      # 128-bit product

modInverse(a, m):
    (g, x, y) = extendedGcd(a, m)      # a*x + m*y = g, any signs
    if g != 1: return none
    return floorMod(x, m)

modDivide(a, b, m):
    inv = modInverse(b, m)
    if inv is none: return none
    return modMultiply(a, inv, m)

modPower(base, e, m):
    if e < 0:
        inv = modInverse(base, m)
        if inv is none: return none
        return modPower(inv, -e, m)
    result = 1 mod m; base = floorMod(base, m)
    while e > 0:
        if e is odd: result = result * base mod m
        base = base * base mod m; e = e / 2
    return result
```

## Implementation

Python provides the functions plus its own `extended_gcd`. C++ and Go keep results in `[0, m)`, return `-1` when there is no inverse, and multiply in 128 bits. The modulus must be positive in all three languages. The extended gcd takes absolute values of its inputs and then fixes the signs of `x` and `y`; an earlier version skipped that step and returned 4 instead of 7 for `mod_inverse(-3, 11)`.

The inverse costs one extended Euclid, which takes a logarithmic number of division steps. Its recursion stack is the same depth. Power by squaring does one or two multiplications per bit of the exponent.

## Applications

- **Counting problems.** Answers requested modulo `10^9 + 7`, such as binomial coefficients through inverses of factorials.
- **Cryptography.** RSA, Diffie-Hellman and other schemes work with powers and inverses modulo large numbers.
- **Hashing and cyclic structures.** Polynomial rolling hashes, circular buffers and calendar arithmetic.
- **Solving congruences.** The Chinese Remainder Theorem combines residues from different moduli.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Negative remainders.** `-3 % 11` is `-3` in C++ and Go. Normalize with `((a % m) + m) % m` before using the value as a residue.
- **Overflow.** `(a * b) % m` in signed 64-bit is wrong once `m` is above about 3.04e9. Multiply in 128 bits.
- **Dividing without an inverse.** Check `gcd(b, m) = 1`. Fermat's little theorem needs `m` prime and Euler's theorem needs `gcd(a, m) = 1`; outside those conditions the formulas silently return nonsense.
- **Dropping the sign fix in extended gcd.** Applying `abs` to the inputs and forgetting to negate `x` or `y` gives the inverse of `|a|`, not of `a`.
- **Reducing too late.** Reduce after every multiplication, not once at the end, or the intermediate value overflows.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does modular division need an inverse?">
    Because `a / b` must be a number `q` with `q * b = a`. Modulo 12 the equation `4q = 1` has no solution, since `4q` is always even or a multiple of 4, so 4 cannot be divided out. Modulo 11, `4 * 3 = 12 = 1`, so dividing by 4 means multiplying by 3.
  </FaqItem>
  <FaqItem question="Why do C++ and Go return -1 for a missing inverse?">
    Every real result is in `0 .. m-1`, so `-1` cannot be confused with an answer. Python returns `None` instead.
  </FaqItem>
  <FaqItem question="What does a negative exponent mean?">
    `a^-e` is the inverse of `a` raised to `e`. `mod_power(2, -1, 11)` is 6, because `2 * 6 = 12 = 1`. If `a` has no inverse the function returns the no-inverse marker.
  </FaqItem>
  <FaqItem question="Is the answer the same as taking the full product and reducing at the end?">
    Yes for addition, subtraction, multiplication and powers. That is exactly the compatibility rule, and reducing early only keeps the numbers small.
  </FaqItem>
</Faq>
