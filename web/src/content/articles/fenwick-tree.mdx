## What a Fenwick tree is

The problem: keep an array of numbers, change one element at a time, and answer "what is the sum of elements `0..i`?" A plain array makes updates O(1) and queries O(n). A prefix-sum array does the opposite. A Fenwick tree makes both O(log n).

The trick is to let cell `i` (1-based) store the sum of a block of `lowbit(i)` elements that **ends at `i`**, where `lowbit(i) = i & -i` is the value of the lowest set bit of `i`. Cell 4 (`100`) covers 4 elements, cell 6 (`110`) covers 2, cell 7 (`111`) covers 1.

/>

There are no pointers: the "tree" is implicit in the index arithmetic. Cell `i` has parent `i + lowbit(i)`, which is the next cell whose block contains `i`'s block.

<Callout title="Why i & -i works">
In two's complement, `-i` flips every bit of `i` above the lowest set bit and keeps that bit, so `i & -i` isolates it. Subtracting it from `i` clears the lowest set bit; adding it carries upward and produces the next index whose range covers `i`. Both walks take at most one step per bit of `i`, so O(log n).
</Callout>

## Operations

<DataTable
  columns={['Operation', 'What it does', { label: 'Time', kind: 'mono' }]}
  rows={[
    ['`update(i, delta)`', 'add `delta` to element `i`: climb with `i += lowbit(i)`', 'O(log n)'],
    ['`prefix_sum(i)`', 'sum of elements `0..i`: descend with `i -= lowbit(i)`', 'O(log n)'],
    ['`query(l, r)`', '`prefix_sum(r) - prefix_sum(l - 1)`', 'O(log n)'],
    ['`get(i)`', 'a single element, as `query(i, i)`', 'O(log n)'],
  ]}
/>

All three languages use 0-based public indices and convert to 1-based internally. `update` **adds** a delta; to assign a value, add the difference from the current one (`update(i, new - get(i))`). Any index outside `0..n-1`, and any `l > r`, is rejected: Python raises `IndexError`, C++ throws `std::out_of_range`, Go panics. C++ stores sums as `long long`.

### Prefix query: descend

To get the sum of `a[1..i]`, add `tree[i]`, strip the lowest set bit, and repeat until `i` is 0. Each step jumps over one whole block. For `prefix_sum` of 1-based index 5 on the array above:

The result is 9 + 16 = 25 = 1 + 3 + 5 + 7 + 9. Two cells, even though five elements were summed.

### Point update: climb

To add `delta` to `a[i]`, add it to `tree[i]`, then move to `i + lowbit(i)` and repeat until you pass `n`: those are exactly the cells whose block contains position `i`. Adding 5 to 0-based index 2 (1-based 3) of the same array:

## Implementation

The three versions are the same: a `tree` array of size `n + 1`, a loop for `update` and a loop for `prefix_sum`. The constructor performs `n` updates. Tests cover the examples above, negative values, index errors and a random differential run against a brute-force array.

    ['range query', 'O(log n)', 'two prefix sums'],
    ['build (as implemented)', 'O(n log n)', 'n updates'],
    ['build (alternative)', 'O(n)', 'for each i, add tree[i] into tree[i + lowbit(i)] once'],
  ]}

Space is exactly `n + 1` numbers, against up to `4n` for a Segment Tree.

A Fenwick tree needs to *subtract* (`prefix(r) - prefix(l - 1)`), so it fits sums, XOR and counts but not min or max.

## Applications

- **Dynamic prefix sums:** running totals with updates, for example "Dynamic Range Sum Queries" on CSES or LeetCode 307 (Range Sum Query - Mutable).
- **Counting inversions:** sweep the array and query how many earlier values are larger (LeetCode 315, Count of Smaller Numbers After Self).
- **Frequency tables and order statistics** over a bounded value range.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using index 0 internally.** `lowbit(0)` is 0, so `i += lowbit(i)` never moves: an infinite loop. Always convert to 1-based, and reject `-1` before converting (it becomes 0).
- **Treating `update` as assignment.** It adds a delta.
- **Overflow in C++.** Sums of `int` values overflow `int`; this code stores `long long`.
- **Forgetting `l - 1` at `l = 0`.** `query` must special-case `l = 0`, since `prefix_sum(-1)` is out of range.
- **Expecting range min or max.** Subtraction is required.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is it called a binary indexed tree?">
    The responsibility of each cell is decided by the binary representation of its index: the lowest set bit gives the block length. The tree structure comes entirely from those bits.
  </FaqItem>
  <FaqItem question="When should I use a Segment Tree instead?">
    When the operation has no inverse (min, max, gcd) or when you need range updates with range queries directly. A Fenwick tree is lighter when you only need sums.
  </FaqItem>
  <FaqItem question="How do I set a value instead of adding to it?">
    Read the current value with `get(i)` and call `update(i, new_value - current)`.
  </FaqItem>
  <FaqItem question="Can I build it faster than n updates?">
    Yes. Copy the array into `tree[1..n]`, then for each `i` add `tree[i]` into its parent `i + lowbit(i)` if that index is within `n`. This is O(n). The repository uses the simpler n updates, O(n log n).
  </FaqItem>
</Faq>
