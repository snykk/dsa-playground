## How the algorithms work

The suffix array `SA` of a string `s` lists the start indices of its suffixes in lexicographic order. For `banana`, `SA = [5, 3, 1, 0, 4, 2]`, which stands for the suffixes `a`, `ana`, `anana`, `banana`, `na`, `nana`. The array holds `n` integers instead of the tree nodes of a suffix tree, and the text is kept alongside. Three algorithms turn it into a tool: a **construction**, a **search** and an **LCP computation**.

<Steps>
  <Step title="Construct: sort the suffixes">
    The code in this repository slices every suffix, sorts the `(suffix, index)` pairs, and keeps the indices. It is correct and short, but a comparison may inspect up to `n` characters.
  </Step>
  <Step title="Search: two binary searches">
    Suffixes that start with the pattern are contiguous. One binary search finds the first such rank, a second finds the last. The indices between them are the occurrences, returned in increasing order.
  </Step>
  <Step title="Extend: the LCP array">
    The longest common prefix of each pair of neighbouring suffixes turns repeat questions (longest repeated substring, distinct substrings) into scans. It is not implemented in this folder.
  </Step>
</Steps>

<Callout title="The key property">
In sorted order, all suffixes with a given prefix `P` form one contiguous block. Anything that sorts between two strings starting with `P` also starts with `P`. Pattern search is therefore a range lookup, not a scan of the text.
</Callout>

## Building faster: prefix doubling

Sorting whole suffixes is wasteful, because two suffixes that agree on their first `k` characters are compared again from scratch. **Prefix doubling** sorts by the first 1 character, then the first 2, then 4, 8, and so on. After the round for length `k`, each suffix has a rank among all suffixes by its first `k` characters. For length `2k` the key is the pair `(rank[i], rank[i + k])`, with `-1` when `i + k` runs past the end. After `log2(n)` rounds every rank is unique. The final ranks `[3, 2, 5, 1, 4, 0]` mean that suffix 5 is smallest, then 3, 1, 0, 4, 2: `SA = [5, 3, 1, 0, 4, 2]`, the same order the repository's sort produces. With a comparison sort in each round the cost is O(n log<sup>2</sup> n); radix sorting the pairs gives O(n log n). SA-IS and DC3 reach O(n) but are much longer to write.

Ranks 1 and 2 hold `SA = 3` and `SA = 1`, so the answer is `[1, 3]` after sorting (the block is in suffix order, not text order). A missing pattern returns `[]` after the first search. An empty pattern is a prefix of every suffix, so on a non-empty text it returns every index `0..n-1` (not `n`); on an empty text it returns `[]`.

## Pseudocode

```text
build_suffix_array(s):
    pairs = [(s[i..], i) for i = 0 .. n-1]
    sort pairs by the suffix string
    return [i for (_, i) in pairs]

search_pattern(SA, text, pattern):
    left = 0; right = n - 1; first = -1
    while left <= right:
        mid = (left + right) / 2
        suffix = text[SA[mid] ..]
        if suffix starts with pattern: first = mid; right = mid - 1
        elif suffix < pattern:         left = mid + 1
        else:                          right = mid - 1
    if first == -1: return []
    left = first; right = n - 1; last = first
    while left <= right:
        mid = (left + right) / 2
        suffix = text[SA[mid] ..]
        if suffix starts with pattern: last = mid; left = mid + 1
        else:                          right = mid - 1
    return sorted(SA[first .. last])
```

## Implementation

Each language has free functions for build, search, sorted suffixes and the LCP of two suffixes (`build_suffix_array`, `search_pattern`, `get_suffixes`, `longest_common_prefix` in Python; camelCase in C++; `BuildSuffixArray`, `SearchPattern`, `GetSuffixes`, `LongestCommonPrefix` in Go). A `SuffixArray` class (`NewSuffixArray` in Go) wraps the text and its array and exposes the same operations as methods. Search compares at most `m` characters per probe without copying the suffix, so its two binary searches are O(m log n); sorting the `k` matches adds O(k log k). The build still copies every suffix. Indices are code points in Python and bytes in C++ and Go.

## What the LCP array adds

Define `LCP[k]` as the common prefix length of the suffixes at ranks `k-1` and `k`. For `banana` it is `[-, 1, 3, 0, 0, 2]`. The code computes the LCP of one pair of suffixes (`longest_common_prefix`, O(n)), so filling the whole array that way costs O(n<sup>2</sup>); none of the three languages has the array itself. With it, these applications are linear scans, and Kasai's algorithm builds it in O(n):

## Applications

- **Pattern search in a fixed text**, for many different patterns.
- **Longest repeated substring** and **distinct substring counts**, with the LCP array.
- **Longest common substring** of several strings, over a concatenation.
- **Burrows-Wheeler transform**, taken from the sorted suffixes (the basis of some compressors and genome indexes).

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Testing equality instead of a prefix.** The binary search compares "suffix starts with the pattern", not "suffix equals the pattern".
- **Claiming O(n log n) for a build that sorts copied strings.** Count the comparison cost and the copies.
- **Forgetting to sort the result.** The block is in suffix order, not text order.
- **Appending a separator that occurs in the text** when combining several strings. Use a character that does not appear.
- **Expecting `n` for the empty pattern.** The result stops at `n-1`: there is no empty suffix in the array.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why do the matches form one block?">
    Sorting puts strings with a common prefix next to each other. Nothing can sort between two strings that start with `P` unless it also starts with `P`, so the matches are a range of ranks.
  </FaqItem>
  <FaqItem question="Why does prefix doubling work?">
    A suffix's first 2k characters are its first k characters followed by the first k characters of the suffix k positions later. The rank pair `(rank[i], rank[i+k])` therefore orders suffixes by 2k characters using only ranks that were already computed.
  </FaqItem>
  <FaqItem question="Why is the repository build not O(n log n)?">
    It sorts n strings with a comparison sort, and each comparison can read up to n characters. The result is O(n<sup>2</sup> log n) time, and the copies take O(n<sup>2</sup>) memory in Python and C++.
  </FaqItem>
  <FaqItem question="Why does search sort its result?">
    The matching suffixes are ordered alphabetically, which is unrelated to where they occur. Sorting turns the block of `SA` values into increasing text positions.
  </FaqItem>
</Faq>
