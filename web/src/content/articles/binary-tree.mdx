## What a binary tree is

A binary tree is either empty or a **root** node with a **left subtree** and a **right subtree**, each of which is again a binary tree. A node with no children is a **leaf**. The **depth** of a node is its number of edges from the root, and the **height** of the tree is the greatest depth. In this repository an empty tree has height -1 and a single node has height 0.

Unlike a binary search tree, a plain binary tree places no ordering rule on its keys, so nothing lets a search skip a subtree.

<Callout title="The shape this code builds">
`insert` places each new value in the first free slot found in level order, left to right. The result is always a **complete** tree: every level is full except possibly the last, which fills from the left. That is why the height stays at floor(log<sub>2</sub> n) and why a heap can store the same shape in an array.
</Callout>

## Traversals

A traversal visits every node once. The three depth-first orders differ only in **when the node itself is visited** relative to its two subtrees:

<DataTable
  columns={['Order', 'Rule', 'Result on the 7-node tree']}
  rows={[
    ['pre-order', 'node, left, right', '1 2 4 5 3 6 7'],
    ['in-order', 'left, node, right', '4 2 5 1 6 3 7'],
    ['post-order', 'left, right, node', '4 5 2 6 7 3 1'],
    ['level-order', 'top to bottom, left to right', '1 2 3 4 5 6 7'],
  ]}
/>

In-order is sorted only for a binary **search** tree; here it is just another order. Pre-order is used to copy or serialize a tree (a node before its children), and post-order to delete or evaluate one (children before the node).

### In-order, step by step

The recursion for in-order on the 7-node tree. Each row is a call that finishes its left subtree, emits its node, then moves right:

The recursion stack never holds more than height + 1 calls. Level-order uses a **queue** instead, which may hold a whole level, up to about n / 2 nodes, so its extra space is O(n), not O(height).

### Insert, step by step

Insert 6 into the tree `[1, 2, 3, 4, 5]`. The queue starts with node 1. Node 1 has both children, so its children 2 and 3 are queued. Node 2 has both children as well, so 4 and 5 are queued. Node 3 has a free left slot, so 6 becomes the left child of 3.

## Implementation

All three versions are line-for-line equivalent: level-order `insert`, recursive `search` and depth-first traversals, queue-based level order, and height in edges.

- Empty tree: traversals return an empty list; `height()` is -1.
- The C++ class owns raw pointers, so its copy constructor and assignment are deleted.
- Because the tree is always complete, recursion depth is only log n, so there is no stack risk with this insert. A tree built another way (a long chain) could be deep.

For n nodes, a complete tree has height floor(log<sub>2</sub> n); a chain has height n - 1. The height h is what governs recursion depth and, in search trees, the cost of operations.

## Applications

- **Expression trees:** leaves are operands, internal nodes are operators; post-order evaluates them.
- **Heaps:** a complete binary tree stored in an array.
- **Binary search trees and variants** (AVL, Red-Black, Treap): add an ordering rule.
- **Huffman coding:** a full binary tree of symbols.
- **Decision trees** and game trees with two outcomes per node.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Calling in-order output sorted.** It is sorted only when the tree is a binary search tree.
- **Mixing height conventions.** Height in edges gives an empty tree -1 and a leaf 0; counting nodes gives 0 and 1. Pick one.
- **Quoting O(height) space for level-order.** The queue can hold a whole level, up to about n / 2 nodes.
- **Recursing on skewed trees.** A 10<sup>5</sup>-node chain overflows many stacks. Use an explicit stack or queue.
- **Assuming this insert builds a search tree.** It fills slots in level order and ignores key values.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What is the difference between a binary tree and a binary search tree?">
    A binary tree only limits each node to two children. A binary search tree adds an ordering rule (left keys smaller, right keys larger) that lets search skip a whole subtree at each step.
  </FaqItem>
  <FaqItem question="Which traversal should I use?">
    Pre-order to copy or serialize a tree, in-order to read a search tree in sorted order, post-order to delete or evaluate a tree (children first), and level-order for anything breadth-first, such as the shortest depth to a node.
  </FaqItem>
  <FaqItem question="How many nodes can a binary tree of height h have?">
    At least h + 1 (a chain) and at most 2<sup>h+1</sup> - 1 (a perfect tree), counting height in edges.
  </FaqItem>
  <FaqItem question="Why is insert O(n) here?">
    The tree has no ordering that says where a value belongs, so the code scans in level order for the first free slot. That keeps the tree complete at the price of a linear scan.
  </FaqItem>
</Faq>
