## How Eulerian paths work

An **Eulerian path** is a walk that uses every edge of a graph exactly once. An **Eulerian circuit** is one that ends where it started. Vertices may be visited any number of times; it is the edges that must each be used once.

Every time a walk passes through a vertex, it arrives along one edge and leaves along another. So in the middle of a walk the edges at a vertex are used in pairs, and only the two ends of the walk can have one left over. That gives the whole test:

<DataTable
  columns={['Graph', 'Circuit', 'Path (open)', 'And']}
  rows={[
    ['Undirected', 'every degree even', 'exactly 2 vertices of odd degree; the walk runs from one to the other', 'every edge in one connected component'],
    ['Directed', 'out-degree = in-degree everywhere', 'one vertex with out = in + 1 (the start), one with in = out + 1 (the end), the rest balanced', 'every edge in one weakly connected component'],
  ]}
/>

A self-loop adds 2 to its vertex's degree (1 out and 1 in when directed), and a vertex with no edge does not matter. **Weakly connected** means connected once the directions are ignored: `0 -> 1` has a path even though 1 cannot get back to 0.

<Callout title="The bridges of Konigsberg">
In 1736 Euler asked whether a walk could cross each of Konigsberg's seven bridges exactly once. The four land masses had 5, 3, 3 and 3 bridges: four odd degrees, so no. His argument is the test above, and it is also enough: when the degrees and the connectivity pass, a walk exists.
</Callout>

<Steps>
  <Step title="Build the adjacency lists">
    `adj[v]` lists the edges at `v` as (neighbour, edge index) pairs in the order the edges are given. An undirected edge sits in the lists of both its ends, so a self-loop sits twice in its vertex's list.
  </Step>
  <Step title="Test the degrees, pick the start">
    Count odd degrees (undirected) or out-degree minus in-degree (directed). That decides circuit, path or nothing, and where the walk must start.
  </Step>
  <Step title="Walk until stuck">
    Keep the walk on a stack. From the top vertex `v`, move `ptr[v]` past edges already used and take the first unused one, pushing its other end. When the degrees pass, the walk can only get stuck at the end of the path, or back at the start of a circuit.
  </Step>
  <Step title="Back up and splice">
    A stuck vertex is finished: pop it onto `result`. The vertex below may still have unused edges; a detour from it can only get stuck where it started, so its vertices are popped as a closed circuit, spliced into the result right there.
  </Step>
  <Step title="Check and reverse">
    If `result` holds fewer than E + 1 vertices, the walk missed edges in another component: there is no walk. Otherwise `result`, reversed, is the walk.
  </Step>
</Steps>

## See it in action

**Splice at the start** gets stuck at 3 after one triangle, then backs up to 0, whose triangle is spliced in front. **Directed detour** splices a cycle in at vertex 1. **House in one stroke** never needs a detour, **Weakly connected only** is a directed graph in which nothing leaves vertex 3, **Four odd vertices** fails the degree test, and **Two components** passes it but leaves half the edges unused, while vertex 6, with no edge at all, plays no part. Each vertex's badge shows its degree (or out - in) during the test, then how many unused edges it has left.

## Pseudocode

```text
eulerian_path(n, edges, directed):
    adj[v] = (neighbour, edge) pairs in edge order   # undirected: in both ends' lists
    kind, start = degree_check()                      # None if the degrees fail
    if kind is none: return None
    if there are no edges: return the empty walk
    stack = [start]; ptr = [0] * n; used = [False] * E; result = []
    while stack:
        v = top of stack
        advance ptr[v] past used entries of adj[v]
        if an unused edge e to w is found:
            used[e] = True; push w                    # walk on
        else:
            result.append(pop())                      # v is finished
    if len(result) < E + 1: return None               # edges in another component
    return reversed(result)
```

## Implementation

Each language takes `n`, the vertices `0 .. n - 1`, a list of edges `(u, v)` and whether they are directed. One function says which walk exists: `eulerian_kind` in Python returns `"circuit"`, `"path"` or `"none"`, `eulerianKind` in C++ an `EulerKind`, `EulerianKind` in Go a `Kind`. The other returns the walk as two lists, the E + 1 vertices and the E edge indices in order: `eulerian_path` (an `EulerWalk` named tuple), `eulerianPath` (a `std::optional<EulerWalk>`) and `EulerianPath` (a `Walk`, an `ok` flag and an error).

**No walk, and nothing to walk.** When no walk exists, the answer is `None` in Python, `std::nullopt` in C++ and `ok == false` in Go. A graph with no edges is different: its kind is "circuit" and its walk is two empty lists. A negative `n` or an edge end out of range raises `ValueError`, throws `std::invalid_argument` or returns an error wrapping `ErrInvalidGraph`.

**Which walk comes back.** The start is the smaller of the two odd vertices (undirected path), the vertex with out = in + 1 (directed path), or the smallest vertex with an edge (circuit). From each vertex the walk takes the first unused edge in input order, and the result is the pop order reversed. So the input decides the walk, and Python, C++ and Go return the same one: the C++ and Go tests check 40 graphs against outputs of the Python code. The bowtie `(0, 1), (1, 2), (2, 0), (0, 3), (3, 4), (4, 0)` gives `0 1 2 0 3 4 0`; the same edges in reverse order give `0 4 3 0 2 1 0`.

**Loops, parallel edges, isolated vertices.** A loop is walked as `v -> v`; undirected, its second entry in `adj[v]` is skipped as used. Parallel edges are separate edges with their own indices, so the edge list says which one was taken. Isolated vertices are ignored, which is why the start is the smallest vertex that has an edge.

**No recursion.** All three keep the walk on an explicit stack. A recursive Hierholzer nests one call per edge on a long cycle: in Python a cycle of 997 edges already exceeded the default recursion limit of 1000, and a C++ version built with `-O2` crashed on 10^5 edges with an 8 MB stack. The tests here walk 10^5 edges in Python and 10^6 in C++ and Go.

## Complexity analysis

Building `adj` and testing the degrees is one pass over the edges and one over the vertices. In the walk every edge is pushed once and popped once, and `ptr[v]` only moves forward, so every adjacency entry is read once: E entries for a directed graph, 2E for an undirected one. The connectivity check is the length of the result and costs nothing more.

## Hierholzer vs Fleury and others

  ]}

The recursive form calls itself on each edge it takes and appends `v` when it returns; on 3000 random small graphs it returned exactly the walk of the stack version. Fleury's algorithm never needs a splice, because it avoids burning a bridge too early, but each step pays for a bridge test.

## Applications

- **Routes over every edge.** Mail delivery, street sweeping or inspecting every pipe, when the network's degrees pass the test.
- **Chaining pieces.** Dominoes, words whose last letter starts the next, pairs `[a, b]` arranged so each `b` is the next `a`, an itinerary that uses every ticket.
- **De Bruijn sequences.** The shortest string that contains every string of length n over an alphabet is an Eulerian circuit of the graph on strings of length n - 1.
- **Sequence assembly.** Rebuilding a DNA sequence from its overlapping k-mers is an Eulerian path in a de Bruijn graph.
- **The lexicographically smallest walk.** Sort the edges by their ends first (undirected: smaller end, then larger end), which orders every adjacency list; the walk returned is then the smallest one. On 3000 random small graphs it matched a brute-force search.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Testing degrees without connectivity.** Two separate triangles have only even degrees and no single walk. Check that the walk used all E edges.
- **Checking connectivity over every vertex.** An isolated vertex does not block a walk; only the vertices with edges must be connected.
- **Asking for strong connectivity in a directed graph.** Weak connectivity is enough, together with the degree test.
- **Losing the pointer.** Rescanning `adj[v]` from the front on every return to `v` turns the walk quadratic, as the flower shows.
- **Marking list entries instead of edges.** An undirected edge sits in two lists; mark it used by its index, or it is walked twice.
- **Forgetting to reverse.** The pops come out from the end of the walk; for a directed graph the unreversed list walks every edge backwards.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why can the walk only get stuck at the end?">
    Entering a vertex uses one of its edges. At a vertex that is not an end, the edges used so far come in pairs (in and out) plus the one just used to enter, an odd number, while its degree is even; so an unused edge is left to leave by. Only the end vertex, with its odd degree (or extra in-edge), can run out, and in a circuit only the start.
  </FaqItem>
  <FaqItem question="Why is a detour always a closed circuit?">
    After the first walk, every vertex has an even number of unused edges (or as many unused edges out as in), because the walk used its edges in pairs apart from its two ends, which were the odd ones. By the argument above, a walk on the unused edges can only get stuck where it started.
  </FaqItem>
  <FaqItem question="How does the code check connectivity?">
    It does not run a separate search. A walk only ever reaches edges in the start's component, so if the result holds all E edges they were connected, and if it holds fewer they were not.
  </FaqItem>
  <FaqItem question="What does a graph with no edges return?">
    The empty walk, two empty lists, and the kind "circuit". It is not the same as "no walk", which is None, std::nullopt or ok == false.
  </FaqItem>
</Faq>
