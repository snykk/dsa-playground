## Definition

Given integers `b`, `e >= 0` and `m >= 1`, compute the residue of `b^e` modulo `m`. Two identities make it fast.

<Equation label="Splitting the exponent" expr="b^e = (b^(e/2))^2  (e even),   b^e = b * b^(e-1)  (e odd)" />
<Equation label="Reduce at any time" expr="(x * y) mod m = ((x mod m) * (y mod m)) mod m" result="intermediate values stay below m" />

By convention `b^0 = 1`, and every result modulo 1 is 0.

## Intuition

Write the exponent in binary. For `13 = 1101`, `b^13 = b^8 * b^4 * b^1`. The powers `b^1, b^2, b^4, b^8, ...` come from squaring the previous one, so reaching `b^(2^k)` costs `k` squarings. Then the bits of the exponent say which of those powers to multiply into the answer. The number of steps is the number of bits of `e`.

<Callout title="Invariant">
At the top of each loop iteration, `result * base^exponent = b^e (mod m)`. An odd exponent moves one factor of `base` into `result`; halving the exponent while squaring the base keeps the product unchanged. When the exponent reaches 0, `result` is the answer.
</Callout>

## How it works

<Steps>
  <Step title="Set up">
    If `m = 1` return 0. Otherwise `result = 1` and `base = b mod m`; a negative base is reduced into `0 .. m-1` first.
  </Step>
  <Step title="Look at the lowest bit">
    If the exponent is odd, multiply `result` by `base` and reduce modulo `m`.
  </Step>
  <Step title="Square and shift">
    Replace `base` by `base * base mod m` and shift the exponent right by one bit.
  </Step>
  <Step title="Repeat">
    Loop until the exponent is 0, then return `result`.
  </Step>
</Steps>

A negative exponent means the inverse power: `b^(-e) = (b^-1)^e`. The code first looks for the inverse of `b` modulo `m` and returns `None` (Python) or `-1` (C++ and Go) if there is none.

## See it in action

## Pseudocode

```text
modPow(base, exponent, modulus):
    if exponent < 0:                        # inverse power
        inv = modInverse(base, modulus)
        if inv is none: return none
        return modPow(inv, -exponent, modulus)
    if modulus == 1: return 0
    result = 1
    base = floorMod(base, modulus)
    while exponent > 0:
        if exponent is odd:
            result = result * base mod modulus      # 128-bit product in C++ and Go
        base = base * base mod modulus
        exponent = exponent >> 1
    return result
```

The recursive Python version `mod_pow_recursive` returns `(f(e/2))^2` for even `e` and `base * f(e-1)` for odd `e`, with `f(0) = 1`.

## Implementation

Python has the iterative `mod_pow`, the recursive `mod_pow_recursive` and `mod_inverse`. C++ and Go have `modPow` and `modInverse`. Results are always in `[0, modulus)` (an earlier version returned `-3` for `(-2)^3 mod 5` in C++ and Go). In C++ and Go every product goes through a 128-bit multiplication (`__int128`, `math/bits`); the old 64-bit product gave wrong answers for moduli above about 3.04e9, for example `3^1000000 mod (10^18 + 3)`.

## Applications

- **Cryptography.** RSA and Diffie-Hellman are modular powers with huge exponents.
- **Inverses.** For a prime `p`, `a^(p-2) mod p` is the inverse of `a`, by Fermat's little theorem.
- **Primality tests.** Miller-Rabin and the Fermat test compute `a^d mod n` for each witness.
- **Counting modulo 10^9 + 7.** Powers of two and inverse factorials in combinatorics problems.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Overflow.** `(result * base) % m` in signed 64-bit is wrong for `m` above about 3.04e9. Multiply in 128 bits.
- **Negative base.** `%` keeps the sign in C++ and Go: `-2 % 5` is `-2`. Reduce the base into `0 .. m-1` first.
- **Modulus 1.** The answer is 0, not 1.
- **Reducing the exponent modulo `m`.** Only valid with Euler's theorem: reduce modulo `phi(m)` and only when the base is coprime to `m`. For a prime modulus `p`, reduce modulo `p - 1`.
- **Negative exponents without an inverse.** `2^-1 mod 12` does not exist because `gcd(2, 12) = 2`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does squaring the base give the right powers?">
    Because `(b^(2^i))^2 = b^(2^(i+1))`. After `i` squarings the base is `b^(2^i)`, and the bits of the exponent select which of those powers multiply into the product.
  </FaqItem>
  <FaqItem question="How many multiplications does it really take?">
    One squaring per bit of the exponent and one multiplication per 1 bit. For `e = 13` (`1101`) the loop squares 4 times and multiplies 3 times. In general at most `2 floor(log2 e) + 2`.
  </FaqItem>
  <FaqItem question="What is 0^0?">
    The code returns 1 for any base with exponent 0 when the modulus is greater than 1, so `0^0 = 1`, the usual convention here. With modulus 1 everything is 0.
  </FaqItem>
  <FaqItem question="Does the modulus have to be prime?">
    No. Square and multiply works for any positive modulus. Only the tricks built on top of it need conditions: Fermat's inverse `a^(p-2)` needs a prime `p`, and a negative exponent needs `gcd(base, m) = 1`.
  </FaqItem>
</Faq>
