## How Counting Sort works

Comparison sorts need at least about `n log n` comparisons. Counting Sort avoids that bound by using the values themselves as array indexes. The count array has one slot per possible value, from the minimum to the maximum, so `k = max - min + 1` slots, and the value `x` is counted in slot `x - min`. That offset is what lets it handle negative numbers.

<Steps>
  <Step title="Find the range">
    Compute `min` and `max` of the input. If you pass a `max_val` (or `maxVal`) yourself, it must be at least the real maximum, otherwise Python raises `ValueError`, C++ throws `std::invalid_argument` and Go panics.
  </Step>
  <Step title="Count">
    Add one to `count[x - min]` for every element `x`.
  </Step>
  <Step title="Prefix sums">
    Replace each count by the running total. Now `count[v - min]` is the number of elements that are `<= v`, which is one past the last output slot for the value `v`.
  </Step>
  <Step title="Place, back to front">
    Walk the input from the last element to the first. For each `x`, decrement `count[x - min]` and write `x` to `output[count[x - min]]`.
  </Step>
</Steps>

<Callout title="Why walking backwards keeps it stable">
Equal values receive their slots from the highest down. The last 3 in the input is written first, into the highest slot reserved for 3s, and the earlier 3s fill the slots below it. So equal elements keep their input order, which is what Radix Sort needs from its inner sort.
</Callout>

## Pseudocode

```text
countingSort(arr, maxVal):
    if arr is empty: return arr
    minVal = min(arr)
    require max(arr) <= maxVal
    count = array of size maxVal - minVal + 1, all 0
    for x in arr:
        count[x - minVal] += 1
    for i = 1 to length(count) - 1:
        count[i] += count[i - 1]
    output = array of size length(arr)
    for i = length(arr) - 1 down to 0:
        count[arr[i] - minVal] -= 1
        output[count[arr[i] - minVal]] = arr[i]
    return output
```

The Python code writes the same steps in a slightly different order (`output[count[...] - 1] = x`, then decrement), with identical results.

## Implementation

Python's `counting_sort(arr, max_val=None)` finds the maximum itself when `max_val` is omitted; C++ (`countingSort(arr, maxVal)`) and Go (`CountingSort(arr, maxVal)`) require it. All three return a **new** sorted array and leave the input alone (an empty input is returned as is). Python also has `counting_sort_simple`, which skips the prefix sums and rebuilds the output by writing each value `count` times; it is simpler but only suits plain integers, because it cannot move records around.

<Callout title="Linear does not mean fast for every input">
Sorting `[1, 1000000000]` needs a count array of a billion slots. The running time is linear in `n + k`, and `k` here is the range, not the number of elements. Use Counting Sort when `k` is at most a small multiple of `n`.
</Callout>

## Applications

- **Radix Sort.** Sorting digit by digit needs a stable inner sort with a tiny range (the 10 decimal digits); Counting Sort is that sort.
- **Small integer keys.** Ages, grades, scores, letters of the alphabet, character codes.
- **Frequency tables.** The count array is itself a histogram of the data, useful beyond sorting.
- **Ranking.** The prefix sums say how many elements are smaller than or equal to each value.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Negative values without an offset.** `count[x]` with a negative `x` indexes from the end in Python and out of bounds in C++ and Go. Subtract the minimum.
- **Too small a `maxVal`.** Passing a maximum below the real one is an error here (it is checked), because the value would have no slot.
- **Placing front to back.** Walking the input forwards with the decremented counts breaks stability, which matters for records and for Radix Sort.
- **Ignoring the range.** The memory is `k` slots, so a large spread between the smallest and largest value can exhaust memory.
- **Index arithmetic overflow.** In C++, `x - minVal` can exceed `INT_MAX`, so the repository computes the slot in 64-bit.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is Counting Sort faster than O(n log n)?">
    The O(n log n) bound is for comparison sorts. Counting Sort never compares two elements: it uses each value as an index, so it is not subject to that bound. The price is a dependence on the value range `k`.
  </FaqItem>
  <FaqItem question="Does it work with negative numbers?">
    Yes. Each value `x` is counted in slot `x - min`, so the smallest value maps to slot 0. The count array then has `max - min + 1` slots.
  </FaqItem>
  <FaqItem question="Why do we need prefix sums?">
    A count says how many of each value there are. A prefix sum says where the block of that value ends in the output. With it you can place every element directly, and in a stable way, instead of only rebuilding the values.
  </FaqItem>
  <FaqItem question="When should I choose Radix Sort instead?">
    When the range is too large for one count array, for example 32-bit integers. Radix Sort applies Counting Sort to one digit at a time, so each pass only needs a small count array.
  </FaqItem>
</Faq>
