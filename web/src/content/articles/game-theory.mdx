## When to use it

Think of Sprague-Grundy when a problem says:

- Two players alternate moves, both with the **same** set of moves (impartial).
- The player who cannot move loses (normal play), or loses by making the last move (misere).
- Perfect play, and the answer is "who wins" or "find a winning move".
- The game splits into **independent parts** (several piles, several tokens on separate boards).

If the players have different moves (chess, Go) or the game can loop forever, the theory does not apply directly.

## Winning and losing positions

Every position is either a **P-position** (the Previous player wins, so the player to move loses) or an **N-position** (the Next player, the one to move, wins).

- A position with no moves is a P-position.
- A position with a move to a P-position is an N-position.
- A position whose every move leads to an N-position is a P-position.

That is a DP over the game graph. It is correct but slow when the state space is large. The theory below replaces the DP with arithmetic.

## Nim

Nim has several piles. A move takes any positive number of objects from one pile. The player who takes the last object wins.

<Equation label="Bouton's theorem" expr="first player wins  <=>  p1 xor p2 xor ... xor pk != 0" result="XOR of the pile sizes" />

<Callout title="Why it works">
From a position with XOR 0, every move changes exactly one pile, so the XOR becomes non-zero. From a position with XOR `x != 0`, take the highest set bit of `x`; some pile has that bit set, and reducing it to `pile xor x` (a smaller number) makes the XOR 0. So P-positions are exactly the XOR-0 positions: the terminal position has XOR 0, and the two properties above are the P/N rules.
</Callout>

For piles `[3, 4, 5]` the XOR is `3 xor 4 xor 5 = 2`, so the first player wins. The winning move is `nim_winning_move` = take 2 from pile 0 (pile 3 becomes `3 xor 2 = 1`), leaving `[1, 4, 5]` with XOR 0.

## Grundy numbers

For a game position `s`, define its **Grundy number** as the smallest non-negative integer that is not the Grundy number of any position reachable in one move.

<Equation label="Sprague-Grundy" expr="g(s) = mex { g(t) : t reachable from s }" result="g(terminal) = 0" />

Two facts make it useful:

- `g(s) = 0` exactly when `s` is a P-position.
- A sum of independent games has Grundy number equal to the XOR of the parts' numbers. A Nim pile of size `n` has `g = n`, so every game is equivalent to a Nim pile of size `g`.

<Steps>
  <Step title="List the moves from each position">
    For a subtraction game: from `n` you may remove any amount in the move set, as long as `n` is big enough.
  </Step>
  <Step title="Compute Grundy numbers bottom-up">
    `g[0] = 0`. For each `n`, collect `g[n - m]` for every legal move `m` and take the mex.
  </Step>
  <Step title="Combine with XOR">
    For several independent games, XOR the Grundy numbers of their current positions. Non-zero means the first player wins.
  </Step>
</Steps>

For `n = 6`: the moves reach `g(5) = 3`, `g(3) = 1` and `g(2) = 0`, so the set is `{3, 1, 0}` and the mex is 2.

If the game has two independent piles of sizes 5 and 6, then `g(5) xor g(6) = 3 xor 2 = 1`, which is non-zero, so the first player wins. The tests check this claim against a brute-force search of the joint game for every pair of sizes up to 12.

## Misere Nim

In misere play the player who takes the last object **loses**. The answer is the same as in normal Nim **except when every pile has at most one object**.

- If some pile has 2 or more objects: first player wins iff the XOR is non-zero.
- If all piles have 0 or 1 objects: first player wins iff the number of **non-empty** piles is even.

## Games on a graph, with draws

On a directed acyclic graph, win and lose follow directly from the P/N rules. When the graph has **cycles**, some positions are draws: neither player can force a win. The Python `game_graph_outcomes(n, edges)` uses retrograde analysis:

<Steps>
  <Step title="Seed with terminal nodes">
    Nodes with no moves are losses for the player to move.
  </Step>
  <Step title="Propagate backwards">
    A predecessor of a loss is a win. A node whose moves all lead to wins is a loss (count down its remaining moves).
  </Step>
  <Step title="Whatever is left is a draw">
    Nodes never settled can cycle forever under best play.
  </Step>
</Steps>

`analyze_game_graph` returns a boolean per node (True only for "win"). The older Grundy-number version recursed forever on cycles and raised `RecursionError`; the retrograde version never does.

## Variants

- **Partisan games:** each player has different moves; Sprague-Grundy does not apply.
- **Misere play:** the rule changes, and only Nim-like games have a clean answer.
- **Cyclic games:** need retrograde analysis and allow draws.
- **Turning-coin games:** many reduce to Nim on the positions of the heads.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Applying normal Nim to misere.** The all-ones case flips the answer.
- **Counting empty piles.** In misere Nim, empty piles must not be counted.
- **Wrong staircase indices.** The ground stair is index 0 and is ignored; stones sit on indices 1, 3, 5, ...
- **Treating a draw as a loss.** On graphs with cycles, "not winning" includes draws.
- **Sharing a memo between games.** A memo keyed only by state is valid for one game, not for two games with different moves.
- **Forgetting that Grundy numbers do not give the move.** To produce a winning move you need a position with Grundy number 0 among the options.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What if the XOR is zero, do I lose for sure?">
    Yes, against perfect play: in a XOR-0 position every move gives the opponent a non-zero XOR, and the opponent can answer back to zero. If the opponent errs, you can still win.
  </FaqItem>
  <FaqItem question="Why does the Grundy number of a sum equal the XOR?">
    Each component behaves like a Nim pile whose size is its Grundy number: the options of the component cover every smaller value, and a move to a larger value can be reversed. So the sum behaves like Nim with those piles.
  </FaqItem>
  <FaqItem question="How do I find a winning move from Grundy numbers?">
    Compute the XOR of all component numbers. For some component, there is an option whose Grundy number equals `g xor total`; move there. In plain Nim this is the pile reduced to `pile xor total`.
  </FaqItem>
  <FaqItem question="Does Sprague-Grundy work in misere play?">
    Not in general. Misere play of arbitrary sums does not reduce to Grundy numbers; only special games such as Nim have the simple rule shown above.
  </FaqItem>
</Faq>
