## When to use it

Signals in a problem statement:

- "the next (or previous) greater / smaller element" for every position;
- "how many days until a warmer temperature", "stock span";
- "the largest rectangle", "the area between bars", "trapping water" style problems, where each bar is limited by its nearest shorter bar on both sides;
- a brute-force solution scans left or right from every index, giving O(n<sup>2</sup>).

## How it works

Scan left to right and keep a stack of **indices** whose values are monotone. For the next greater element the stack is decreasing (bottom to top): it holds the elements still waiting for something bigger.

<Steps>
  <Step title="Compare with the top">
    For the new element `arr[i]`, look at the index on top of the stack.
  </Step>
  <Step title="Pop while the order is broken">
    While `arr[top] < arr[i]`, the new element is the first greater one to the right of `top`. Record the answer for `top` and pop it.
  </Step>
  <Step title="Push the new index">
    The stack is monotone again. Whatever is still on it at the end has no answer.
  </Step>
</Steps>

<Callout title="Why it is O(n)">
Each index is pushed exactly once and popped at most once, so the inner `while` loop does at most n pops in total. An element on the stack is exactly an element whose answer has not been found yet.
</Callout>

## Template

```text
next_greater_element(arr):
    result = [-1] * n;  stack = []              # stack of indices
    for i in 0 .. n - 1:
        while stack and arr[stack.top] < arr[i]:
            result[stack.pop()] = arr[i]        # arr[i] is the answer for the popped index
        stack.push(i)
    return result

previous_greater_element(arr):
    for i in 0 .. n - 1:
        while stack and arr[stack.top] <= arr[i]:
            stack.pop()                         # these can never be the answer for anyone later
        result[i] = arr[stack.top] if stack else -1
        stack.push(i)
```

The other two variants flip the comparison: `>` for the next smaller, `>=` for the previous smaller.

## Worked example: largest rectangle in a histogram

For `heights = [2, 1, 5, 6, 2, 3]` the answer is 10. The stack holds indices of bars with increasing heights. When a bar of height `h` arrives and `heights[top] >= h`, the popped bar can extend left up to the new stack top and right up to `i - 1`, so its rectangle has width `i` (empty stack) or `i - stack.top - 1`.

## Implementation

All three languages provide `next_greater_element`, `next_smaller_element`, `previous_greater_element`, `previous_smaller_element` (arrays of values, `-1` for none), `largest_rectangle_histogram`, `daily_temperatures` (days to wait, `0` for none) and `stock_span` (consecutive days with price `<=` today, including today). C++ uses camelCase and Go uses exported names.

Which comparison pops matters when values repeat. The next-greater code pops only on `<` and the previous-greater code pops on `<=`; both therefore answer with a **strictly** greater value. `next_greater_element([3, 3, 3, 5])` is `[5, 5, 5, -1]` and `previous_greater_element([3, 3, 3, 5])` is `[-1, -1, -1, -1]`. The histogram pops on `>=`, which is safe because equal bars produce the same rectangle when the last one pops.

<TopicCode topic="Problem_Patterns/Monotonic Stack" />

Edge cases: the value `-1` means "no answer", so an array that itself contains -1 is ambiguous; return indices if that matters. In C++ and Go the histogram area is an `int`, so `height * width` can overflow for very large inputs.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Storing values instead of indices.** You need indices to compute distances and widths.
- **Mixing strict and non-strict comparisons.** Decide whether equal values count as "greater" and keep the choice consistent; counting problems such as Sum of Subarray Minimums need `<` on one side and `<=` on the other to avoid double counting.
- **Forgetting the leftovers.** Elements still on the stack at the end have no answer; the histogram must process them with width n.
- **Wrong width formula.** After popping, use the new stack top (or the array start) as the left boundary.
- **Using -1 as both an answer and a value.** If the input can contain -1, return indices instead.
- **Using a stack when the window slides.** Expiring elements from the front needs a monotonic queue.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Increasing or decreasing stack: which one do I need?">
    For "next greater" the stack waits for something bigger, so it is decreasing from bottom to top. For "next smaller" it is increasing. The popped element is the one whose question was just answered.
  </FaqItem>
  <FaqItem question="How do I find the previous greater element?">
    Keep the same decreasing stack but read the answer from the top after popping everything that is not greater. The code here pops on `<=`, so the remaining top is strictly greater.
  </FaqItem>
  <FaqItem question="Why does the histogram pop on `>=`?">
    A bar that is not shorter than the new bar cannot extend any further to the right, so its rectangle is complete. For equal heights the earlier bar pops early with a smaller width, but the last equal bar later covers the full width.
  </FaqItem>
  <FaqItem question="Can it handle circular arrays?">
    Yes: loop `i` from 0 to 2n - 1 and use `i mod n`. This repository does not implement the circular version.
  </FaqItem>
</Faq>
