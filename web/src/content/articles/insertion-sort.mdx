## How Insertion Sort works

Hold a hand of cards in order. When you pick up a new card you slide it left past every larger card until it fits. Insertion Sort does exactly this to the array: the prefix `arr[0..i-1]` is always sorted, and step `i` inserts `arr[i]` into it.

<Steps>
  <Step title="Start with a prefix of one">
    A single element is already sorted, so the loop starts at index 1.
  </Step>
  <Step title="Take the next element as the key">
    Save `key = arr[i]`. The slot `arr[i]` is now free.
  </Step>
  <Step title="Shift larger elements right">
    While the element before the gap is greater than `key`, move it one place to the right. Equal elements are not moved, which keeps the sort stable.
  </Step>
  <Step title="Drop the key into the gap">
    Write `key` into the gap. The prefix `arr[0..i]` is sorted.
  </Step>
</Steps>

<Callout title="The invariant">
Before step `i` the prefix `arr[0..i-1]` contains the original first `i` elements in sorted order. The step inserts one more element, so the prefix grows by one and stays sorted. When `i` reaches `n` the whole array is sorted. Unlike Selection Sort, the prefix is not yet in final position: later elements may still be inserted before it.
</Callout>

In total there are 10 shifts and 13 comparisons. The input has exactly 10 **inversions** (pairs in the wrong order), and each shift removes exactly one. So the number of shifts always equals the number of inversions, and the running time is <BigO of="n + d" /> where `d` is that number.

## Pseudocode

```text
insertionSort(arr):
    for i = 1 to length(arr) - 1:
        key = arr[i]
        j = i - 1
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]          # shift right
            j = j - 1
        arr[j + 1] = key
    return arr
```

The comparison `arr[j] > key` is strict, so an equal element stops the shifting and the key lands after it: equal keys keep their order.

## Implementation

Python has `insertion_sort` (in place, returns the same list) and `insertion_sort_recursive`, which sorts the first `n - 1` elements recursively and then inserts the last one. C++ is a template over the element type of a `std::vector`, instantiated for `int` and `double`; its inner loop tests `arr[j - 1] > key` with an unsigned index. Go has `InsertionSort([]int)`.

## Complexity analysis

The inner loop runs once per element that is larger than the key and sits to its left, so the total work is the number of inversions plus the `n - 1` outer steps.

<Equation label="Time" expr="T(n) = (n - 1) + I(arr)" result="O(n + I) where I is the number of inversions, 0 to n(n - 1)/2" />

<ComplexityTable
  rows={[

    { case: 'Average case', time: 'O(n^2)', space: 'O(1)', when: 'A random permutation has about n(n - 1)/4 inversions, so about that many shifts.' },
    { case: 'Worst case', time: 'O(n^2)', space: 'O(1)', when: 'Reverse-sorted: n(n - 1)/2 inversions, every key slides all the way to the front.' },
  ]}
/>

<Callout title="The recursive version needs O(n) stack">
`insertion_sort_recursive` makes one nested call per element, so its depth is `n`. Python's default recursion limit (about 1,000 frames) makes it raise `RecursionError` for lists of a few thousand elements. Use the iterative version for real work.
</Callout>

## Applications

- **Small subarrays inside faster sorts.** Hybrid sorts hand tiny ranges to Insertion Sort because its low overhead beats recursion there.
- **Nearly sorted data.** Appending a few new records to a sorted list and re-sorting costs about `n` plus the number of misplaced pairs.
- **Streaming input.** Keeping a sorted list as items arrive is Insertion Sort, one step at a time.
- **Bucket Sort.** The Python Bucket Sort in this repository sorts each bucket with a small insertion sort of its own.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Losing the key.** Overwriting `arr[i]` while shifting without saving it in `key` first destroys the element.
- **Off-by-one on the gap.** After the loop ends with `j` one position left of the gap, the key goes to `arr[j + 1]`.
- **Unsigned index underflow in C++.** `j = i - 1` with `size_t` and a `j >= 0` test never fails. The repository version keeps `j` as the gap position and tests `j > 0`.
- **Using `>=`.** It shifts equal elements past the key and makes the sort unstable.
- **Starting at index 0.** The loop starts at 1: a one-element prefix is already sorted.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why is Insertion Sort fast on nearly sorted data?">
    The inner loop only runs for elements that are out of order with the key. With few inversions, almost every key is already in place after one comparison, so the total is close to `n`.
  </FaqItem>
  <FaqItem question="Is Insertion Sort better than Bubble Sort?">
    Yes, in practice. Both do one move per inversion and are stable, but Insertion Sort makes fewer comparisons and does not re-scan the array on every pass.
  </FaqItem>
  <FaqItem question="Does binary search make it O(n log n)?">
    No. Binary search cuts the comparisons to O(n log n), but you still have to shift elements to open the gap, and that is O(n^2) in the worst case.
  </FaqItem>
  <FaqItem question="What does online mean here?">
    The algorithm can process elements as they arrive: after each insertion the prefix is a sorted copy of everything seen so far. It does not need the whole input in advance.
  </FaqItem>
</Faq>
