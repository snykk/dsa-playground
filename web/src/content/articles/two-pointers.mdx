## When to use it

Signals in a problem statement:

- a **sorted** array and "find a pair / triplet with a given sum";
- "is this string a palindrome", "reverse in place";
- "remove duplicates in place", "partition in place": a read pointer and a write pointer;
- "maximize an area between two positions" where moving the shorter side is the only move that can help;
- you would otherwise write two nested loops over the same array.

## How it works

There are two shapes:

<Steps>
  <Step title="Place the pointers">
    Opposite ends for a sorted array or a palindrome, or a read and a write index for in-place filtering.
  </Step>
  <Step title="Compare and decide which pointer to move">
    Use the current pair to rule out one end for good. For two sum on a sorted array: if `arr[left] + arr[right]` is too small, `arr[left]` cannot pair with anything at or left of `right`, so `left` moves up.
  </Step>
  <Step title="Stop when the pointers meet">
    `left < right` fails, or `read` reaches the end. Every element was visited once.
  </Step>
</Steps>

<Callout title="Why moving one pointer never skips the answer">
For two sum, if the sum is smaller than the target, every pair `(left, j)` with `j < right` has an even smaller sum, so `arr[left]` has no partner and can be dropped. The same argument works for `right` when the sum is too large. For the container problem, moving the taller side can only shrink the width without raising the height limit set by the shorter side, so only moving the shorter side can improve the area.
</Callout>

## Template

```text
two_sum_sorted(arr, target):
    left = 0; right = n - 1
    while left < right:
        s = arr[left] + arr[right]
        if s == target: return [left, right]
        if s < target:  left += 1          # arr[left] has no partner
        else:           right -= 1         # arr[right] has no partner
    return none

three_sum(arr, target):
    sort a copy (Go) or arr itself (Python, C++)
    for i in 0 .. n - 3:
        skip if arr[i] == arr[i - 1]
        two-pointer scan over i + 1 .. n - 1 for target - arr[i]
        after a hit, step both pointers past equal values

remove_duplicates(arr):                    # sorted input
    write = 1
    for read in 1 .. n - 1:
        if arr[read] != arr[write - 1]: arr[write] = arr[read]; write += 1
    return write
```

## Implementation

Five functions exist in all three languages:

- `two_sum_sorted(arr, target)`: indices of the first pair found by the scan, `None` / empty / `nil` if there is none.
- `three_sum(arr, target)`: unique triplets in sorted order. Python and C++ **sort the caller's array in place**; Go works on a copy.
- `is_palindrome(s)`: ignores non-alphanumeric characters and case (ASCII only in C++ and Go, where strings are indexed by byte).
- `remove_duplicates(arr)`: keeps the first of each run in the front part of the array and returns the new length; the values after that length are left as they were, so only `arr[:length]` is meaningful.
- `container_with_most_water(heights)`: maximum area.

`three_sum` handles arrays with fewer than 3 elements (an empty result). Fast and slow pointers on linked lists are not implemented here.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Unsorted input.** The opposite-end sum argument only holds on a sorted array. Sort first, but then the original indices are lost.
- **Not skipping duplicates in 3-sum.** The same triplet is reported several times. Skip equal `i` values and step both pointers past equal values after a hit.
- **`left <= right` instead of `left < right`.** A pair needs two different elements.
- **Unsigned underflow in C++.** `arr.size() - 2` wraps around for short arrays; write `i + 2 < size`.
- **Forgetting that `three_sum` sorts its input** (Python and C++). Pass a copy if the order matters.
- **Reading past the new length** after `remove_duplicates`: the tail still holds old values.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="How do I know which pointer to move?">
    Move the one whose current element cannot be part of a better answer. On a sorted array with a sum that is too small, that is the left one; too large, the right one. For the container, it is the shorter wall.
  </FaqItem>
  <FaqItem question="Does two pointers need a sorted array?">
    Opposite-end pair problems do. Read/write pointer problems and palindrome checks do not, but remove-duplicates-in-place assumes equal values are adjacent.
  </FaqItem>
  <FaqItem question="How is it different from sliding window?">
    A sliding window moves both ends in the same direction and keeps a state about the range between them. Opposite-end two pointers move towards each other and use the order of the data.
  </FaqItem>
  <FaqItem question="What if I need the original indices of an unsorted array?">
    Sort pairs of `(value, index)`, or use a hash map for two sum, which needs no sorting and costs O(n) extra space.
  </FaqItem>
</Faq>
