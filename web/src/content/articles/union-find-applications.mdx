## When to use it

This article is about **using** a disjoint set union. How the structure itself works is covered in the Disjoint Set Union data structure topic and in the Union-Find DSU algorithm topic (both are linked as prerequisite and related topics at the top of this page).

Signals in a problem statement:

- "are A and B connected", "how many groups / components" while connections are **added** over time;
- "does adding this edge create a cycle" in an undirected graph;
- "build the cheapest network that connects everything": Kruskal;
- grouping by a shared property: merge accounts that share an email, treat equal-valued cells in a grid as one region, merge equivalent variables;
- you only ever merge groups and never split them.

If edges are **removed** as well, process the operations offline in reverse (so deletions become merges), or use a different structure.

## How it works

Each group is a tree stored in a `parent` array; the root is the group's representative.

<Steps>
  <Step title="Find with path compression">
    `find(x)` follows parents to the root and points every node on the way directly at the root, which flattens the tree for later calls.
  </Step>
  <Step title="Union by rank">
    `union(x, y)` finds both roots. If they are equal, nothing happens and the call returns `False`: the two items were already connected. Otherwise the shorter tree is hung under the taller one and the group count drops by one.
  </Step>
  <Step title="Use the boolean and the count">
    A `False` from `union` means "this pair is redundant", which is exactly a cycle in a graph. The final `get_count()` is the number of connected components.
  </Step>
</Steps>

<Callout title="The invariant">
Two items are connected if and only if `find` returns the same root for both. Every `union` that returns `True` merges two groups and lowers the count by one, so after processing all edges, `n - (number of successful unions)` equals the number of components.
</Callout>

## Template

```text
count_components(n, edges):
    uf = UnionFind(n)
    for (u, v) in edges: uf.union(u, v)
    return uf.get_count()

has_cycle(n, edges):                     # undirected graph
    uf = UnionFind(n)
    for (u, v) in edges:
        if not uf.union(u, v): return true      # u and v were already connected
    return false

kruskal(n, weighted_edges):              # minimum spanning forest
    sort weighted_edges by weight
    uf = UnionFind(n); total = 0
    for (u, v, w) in sorted edges:
        if uf.union(u, v): total += w            # accepted: joins two components
    return total
```

The repository provides `UnionFind` (`find`, `union`, `connected`, `get_count`) and `count_components`. Cycle detection and Kruskal are the loops above written on top of `union`'s return value; they are not separate functions here.

## Implementation

All three languages provide the DSU with path compression and union by rank: Python `UnionFind` (`find`, `union`, `connected`, `get_count`), C++ `UnionFind` (`find`, `unite`, `connected`, `getCount`) and Go `UnionFind` (`Find`, `Union`, `Connected`, `GetCount`). `union` returns whether a merge happened. `count_components(n, edges)` exists only in Python.

Invalid indices behave differently: Python raises `ValueError`, C++ throws `std::out_of_range`, and Go does no bounds check, so an out-of-range index panics (and a negative size panics in the constructor). The `find` function is recursive; union by rank keeps the trees shallow (height at most log n), so the recursion stays short.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Comparing parents instead of roots.** `parent[x] == parent[y]` is wrong before the paths are compressed; always compare `find(x)` and `find(y)`.
- **Ignoring the return value of `union`.** It is the cycle signal and the Kruskal accept test.
- **Using it on directed graphs.** DSU models undirected connectivity. Directed cycles need DFS or topological sort.
- **Expecting deletions.** Removing an edge cannot be undone in a DSU.
- **Index mismatch.** Elements must be `0..n - 1`; map strings or large ids to indices first.
- **Calling the Python `count_components` with swapped arguments.** The signature is `count_components(n, edges)`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Union-Find, BFS or DFS for components?">
    For a static graph all three work. Union-Find is better when edges arrive over time and you must answer connectivity after each one, and when you need the cycle test or Kruskal for free.
  </FaqItem>
  <FaqItem question="Why is it called nearly constant time?">
    With path compression and union by rank, a sequence of m operations on n items costs O(m alpha(n)), where alpha grows so slowly that it is at most 4 for any realistic n.
  </FaqItem>
  <FaqItem question="How does Kruskal use it?">
    Sort the edges by weight and take an edge only if `union` succeeds, meaning its ends lie in different components. Skipping the failures guarantees no cycle, and taking the cheapest first gives a minimum spanning tree.
  </FaqItem>
  <FaqItem question="Can it find a cycle in a directed graph?">
    No. Use DFS with colours, or Kahn's algorithm, which returns fewer than n nodes when a cycle exists.
  </FaqItem>
</Faq>
