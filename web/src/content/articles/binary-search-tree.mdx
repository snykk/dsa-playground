## What a binary search tree is

A binary search tree (BST) is a binary tree in which each node holds a key and obeys the **BST property**: every key in the node's left subtree is smaller than the node's key, and every key in its right subtree is larger.

The property is about **all** keys in a subtree, not just the two children. A node whose children look right can still be wrong if a deeper descendant is on the wrong side of an ancestor.

<Callout title="In-order is sorted">
Visiting left subtree, node, right subtree yields the keys in increasing order. That is the easiest way to test the property: a tree is a BST exactly when its in-order traversal is strictly increasing.
</Callout>

This repository's trees ignore duplicate inserts. Height is counted in **edges**: an empty tree has height -1 and a single node has height 0. (The AVL Tree folder counts nodes instead.)

### Search and insert

Searching for 60 in the tree above visits 50, 70, 60: three comparisons instead of seven. Searching for a missing key such as 65 walks down to the empty spot where it would be. Insert uses exactly that walk and attaches the key there, so a new key is always a leaf.

## Implementation

All three versions have the same API: `insert`, `search`, `delete`, `find_min`, `find_max`, four traversals, `height`, `size`, `is_empty`. Differences:

- The Python version is **iterative** (insert, search, delete and every traversal), so a chain of 5,000 or more nodes works without a `RecursionError`.
- C++ and Go are recursive for insert, search and delete. The C++ destructor is iterative.
- Empty tree: Python `find_min` returns `None`, C++ throws `std::runtime_error`, Go returns an error.
- The C++ class owns raw pointers, so its copy constructor and assignment are deleted.

## Complexity

<DataTable
  columns={['Case', { label: 'Search / insert / delete', kind: 'mono' }, 'Shape']}
  rows={[
    ['best, average (random keys)', 'O(log n)', 'a randomly built tree has height O(log n); the average node depth is about 1.39 log2(n)'],
    ['worst', 'O(n)', 'sorted or reverse-sorted input: a chain, h = n - 1'],
  ]}
/>

Every operation follows a single root-to-leaf path and does constant work per node, so the cost is the height h. A randomly built tree is shallow, but real input is often partly sorted. After many random deletes with the successor rule the shape can also drift toward lopsided, which is one reason balanced trees exist.

Space is O(n) for the nodes. The recursive versions use O(h) stack.

## Applications

- Ordered sets and maps in small programs, and the base for balanced trees.
- Range queries and nearest-key lookups (successor and predecessor).
- Sorting by inserting all keys, then reading the in-order traversal (tree sort).
- Interview staples: validate a BST, find the k-th smallest, lowest common ancestor.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Checking only parent and child.** Validating `left < node < right` locally accepts invalid trees. Pass down a (low, high) bound for every subtree, or check that the in-order output is increasing.
- **Assuming O(log n).** The bound holds only for balanced trees. Sorted input is the worst case.
- **Forgetting the duplicate policy.** This code ignores duplicates. Other designs store a count or allow equal keys on one fixed side. Pick one and keep it consistent.
- **Two-child delete with the wrong node.** Use the in-order successor (or predecessor), then delete that node, which has at most one child.
- **Deep recursion.** A chain of 10<sup>5</sup> nodes overflows the stack in a recursive implementation; Python's default limit is about 1,000 frames.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why does in-order traversal give sorted output?">
    Everything in the left subtree is smaller than the node and everything in the right subtree is larger. Visiting left, node, right therefore emits smaller keys first, recursively at every level.
  </FaqItem>
  <FaqItem question="When does a BST become a linked list?">
    When keys are inserted in sorted or reverse-sorted order. Each new key goes to the same side of the previous one, so the height becomes n - 1.
  </FaqItem>
  <FaqItem question="Successor or predecessor for a two-child delete?">
    Either works. This repository uses the in-order successor, the smallest key of the right subtree.
  </FaqItem>
  <FaqItem question="How do I stop the tree from degenerating?">
    Use a self-balancing variant: an AVL or Red-Black tree for worst-case guarantees, or a treap for randomized balancing.
  </FaqItem>
</Faq>
