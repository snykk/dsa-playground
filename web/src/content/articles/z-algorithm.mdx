## How the Z-algorithm works

For a string `s`, `Z[i]` is the length of the longest substring that starts at `i` and is also a prefix of `s`. By convention `Z[0] = 0` here (the whole string would trivially match itself). For `s = aabxaab`, `Z[4] = 3` because `aab` starts at index 4 and equals the prefix `aab`.

Computing each `Z[i]` from scratch would be quadratic. The algorithm keeps the **Z-box** `[l, r]`: the match that reaches furthest right so far, meaning `s[l..r]` equals the prefix `s[0..r-l]`.

<Steps>
  <Step title="Start with Z[i] = 0 and an empty box">
    `l = r = 0`. Positions are processed from `i = 1` to `n - 1`.
  </Step>
  <Step title="Reuse the box when i is inside it">
    If `i <= r`, then `s[i..r]` is a copy of `s[i-l..r-l]` near the start of the string. So `Z[i]` starts at `min(r - i + 1, Z[i - l])`: the value of the mirror, but clipped so it does not claim anything beyond `r`.
  </Step>
  <Step title="Extend by comparing">
    While `i + Z[i] < n` and `s[Z[i]] == s[i + Z[i]]`, increase `Z[i]`. Only characters beyond the box can extend the match; a comparison inside it fails at once.
  </Step>
  <Step title="Move the box">
    If `i + Z[i] - 1 > r`, the new match reaches further right: set `l = i` and `r = i + Z[i] - 1`.
  </Step>
</Steps>

<Callout title="Why it is linear">
`r` never moves left, and every successful comparison in step 3 moves it right by one. When the mirror value is smaller than `r - i + 1`, it is already final and the one comparison made fails, and when it is larger it is clipped to the box. So the total number of successful comparisons is at most `n`, and each position adds at most one failed comparison.
</Callout>

## Pattern search

To search for `P` (length `m`) in `T`, build the Z-array of `P + "$" + T`. A text position `j` corresponds to `i = m + 1 + j`. If `Z[i] >= m`, then `P` occurs at `j`. For `aab` in `aabxaabaab` the combined string is `aab$aabxaabaab`:

The loop starts at `i = m + 1`, skipping the pattern and the separator. The code tests `z[i] >= m`, not `== m`: if `$` also occurs in the text or the pattern, a match can run past the separator and `Z[i]` can be larger than `m`. For example, `a$a` searched for `a` gives `[0, 2]`, not `[2]`.

## Pseudocode

```text
build_z_array(s):
    n = len(s); z = [0] * n; l = 0; r = 0
    for i = 1 to n - 1:
        if i <= r:
            z[i] = min(r - i + 1, z[i - l])
        while i + z[i] < n and s[z[i]] == s[i + z[i]]:
            z[i] += 1
        if i + z[i] - 1 > r:
            l = i; r = i + z[i] - 1
    return z

z_algorithm_search(text, pattern):
    if pattern is empty or text is empty or len(pattern) > len(text): return []
    combined = pattern + "$" + text
    z = build_z_array(combined); m = len(pattern)
    return [i - m - 1 for i = m + 1 to len(combined) - 1 if z[i] >= m]
```

## Implementation

Python exposes `build_z_array` and `z_algorithm_search`; C++ has `buildZArray` and `zAlgorithmSearch`; Go has `ZAlgorithmSearch` (its `buildZArray` is not exported). All three use the separator `$` and the `>=` test. Python indices are code points; C++ and Go indices are bytes.

An **empty pattern** returns `[]` here, as in the naive, KMP, Rabin-Karp and Boyer-Moore searches. An empty text or a pattern longer than the text also returns `[]`.

## Applications

- **Pattern search.** All occurrences in linear time.
- **Smallest period of a string.** The smallest `p` with `p + Z[p] == n` (and `p` dividing `n` for an exact repetition).
- **Prefix versus suffix questions.** For example, which suffixes are also prefixes (borders).
- **Counting and comparing** substrings against a fixed prefix.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Testing `z[i] == m`.** With `$` in the input, `z[i]` can exceed `m` and real matches are dropped. Use `>=`.
- **Starting the scan at the wrong index.** Text position `j` is combined index `m + 1 + j`; the result is `i - m - 1`.
- **Forgetting the clip.** `Z[i] = Z[i - l]` without `min(r - i + 1, ...)` claims matches beyond the box.
- **Treating `Z[0]` as meaningful.** It is set to 0 here, and the loop starts at 1.
- **Assuming an empty pattern matches everywhere.** This implementation returns `[]`.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What is the Z-box?">
    The segment `[l, r]` that reaches furthest right among all prefix matches found so far, so `s[l..r]` equals `s[0..r-l]`. Inside it, the Z-values near the start of the string tell you the Z-values near `l`.
  </FaqItem>
  <FaqItem question="Why must the separator not occur in the input?">
    The separator stops a prefix match from running past the pattern. If it also appears in the text, a match can extend further and `Z[i]` exceeds `m`. This code avoids the problem by testing `z[i] >= m`, which is exact: for `i > m` the window `s[i..i+m-1]` lies entirely in the text, so `z[i] >= m` means the pattern occurs there.
  </FaqItem>
  <FaqItem question="How does it compare with KMP?">
    Both are linear. KMP computes the LPS table of the pattern and streams the text, using O(m) space. The Z-algorithm builds one array over pattern + text, using O(n + m) space, but the array is easier to define and use.
  </FaqItem>
  <FaqItem question="Can I find the longest border of a string with it?">
    Yes: a border of length `k` exists when `i + Z[i] == n` for `i = n - k`. The longest border comes from the smallest such `i`.
  </FaqItem>
</Faq>
