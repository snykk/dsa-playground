## Definition

The number theoretic transform of a<sub>0</sub>, &hellip;, a<sub>n-1</sub> modulo a prime p evaluates the polynomial A(x) = a<sub>0</sub> + a<sub>1</sub>x + &hellip; + a<sub>n-1</sub>x<sup>n-1</sup> at the n powers of a primitive n-th root of unity w modulo p, an integer with w<sup>n</sup> = 1 and no smaller power equal to 1.

<Equation label="NTT" expr="X[k] = sum_{j=0..n-1} a[j] * w^(j k)  mod p,  w = 3^((p - 1) / n)" />
<Equation label="Inverse" expr="a[j] = n^(-1) * sum_{k=0..n-1} X[k] * w^(-j k)  mod p" />

**The modulus used here.** p = 998244353 = 119 &times; 2<sup>23</sup> + 1, a prime, with the primitive root 3. The formula is the Fast Fourier Transform's with e<sup>-2&pi;i/n</sup> replaced by w, so `ntt([1, 2, 3, 4])` is `[10, 173167434, 998244351, 825076915]` where `fft([1, 2, 3, 4])` is `[10, -2+2j, -2, -2-2j]`: 998244351 is -2 modulo p, and 173167434 is -2 - 2w for w = 911660635, as -2 + 2i is -2 - 2w for the FFT's w = -i.

## Intuition

The FFT uses only four facts about its root w = e<sup>-2&pi;i/n</sup>: w<sup>n</sup> = 1, w<sup>n/2</sup> = -1, the powers w<sup>0</sup> to w<sup>n-1</sup> are all different, and w<sup>2</sup> is the same kind of root for n/2. Nothing in the even-odd split needs complex numbers, only those four facts.

Modulo a prime p, the nonzero residues form a cyclic group of order p - 1: the powers of a primitive root run through all of them. For 998244353 the primitive root is 3, and p - 1 = 2<sup>23</sup> &times; 7 &times; 17. So for every power of two n up to 2<sup>23</sup>, w = 3<sup>(p-1)/n</sup> has order exactly n, and w<sup>n/2</sup> is a square root of 1 other than 1, which modulo a prime can only be -1, written p - 1. Every fact the FFT needs holds.

<Callout title="The butterfly identity, modulo p">
For k from 0 to n/2 - 1: `X[k] = E[k] + w^k O[k]` and `X[k + n/2] = E[k] - w^k O[k]`, all modulo p, because w<sup>k+n/2</sup> = -w<sup>k</sup>. These are the FFT's butterflies, and every operation in them is an exact integer sum, difference or product modulo p.
</Callout>

## How it works

<Steps>
  <Step title="Reduce and pad">
    `ntt` copies the list and reduces every entry modulo p, so -1 becomes 998244352. A forward transform pads with zeros to the next power of two, as the FFT does. An empty list returns `[]`.
  </Step>
  <Step title="Reorder by bit reversal">
    Swap `a[i]` and `a[rev(i)]`, where `rev(i)` reverses the log2(n) bits of i. For n = 8 the order becomes 0, 4, 2, 6, 1, 5, 3, 7: the order in which the FFT's recursion, splitting into even and odd positions, reaches its single values.
  </Step>
  <Step title="Combine, stage by stage">
    For length = 2, 4, ..., n: take the root `w_length = 3^((p - 1) / length)`. In every block of `length` entries, run the butterflies on positions `start + k` and `start + k + length/2` with the twiddle `w_length^k`, for k from 0 to length/2 - 1.
  </Step>
  <Step title="Invert">
    The inverse runs the same stages with the inverse roots, then multiplies every entry by n<sup>-1</sup> = n<sup>p-2</sup> mod p (Fermat's little theorem).
  </Step>
</Steps>

<Callout title="How the stages map to the FFT's recursion">
The Fast Fourier Transform topic's code is recursive. Its recursion bottoms out in single values, which are the input in bit-reversed order, so the bit reversal puts every value where the recursion would deliver it. The stage of length L then does the combining loop of every recursive call of size L: the block at `start` is one call, with `E[k]` at `a[start + k]` and `O[k]` at `a[start + k + L/2]`. Each butterfly reads two entries and writes the same two, so the whole transform runs in the list itself, with no recursion and no new lists.
</Callout>

<Callout tone="warning" title="Two limits the FFT does not have">
The result is exact **modulo p**: a coefficient of 0 to p - 1 comes out as itself, a larger one reduced, and a negative one as p minus its size. And no transform is longer than 2<sup>23</sup>, the largest power of two dividing p - 1: `ntt` refuses more than 2<sup>23</sup> values and `multiply_polynomials` a product of more than 2<sup>23</sup> coefficients. Python raises `ValueError`, C++ throws `std::invalid_argument` and Go returns an error wrapping `ErrTooLong`. An inverse of a length that is not a power of two is refused as in the FFT (`ErrNotPowerOfTwo` in Go).
</Callout>

## Pseudocode

```text
ntt(a, inverse):
    n = len(a)
    if n == 0: return []
    if n > 2^23: error
    if inverse and n is not a power of two: error
    values = [x mod p for x in a], padded with zeros to a power of two
    ntt_in_place(values, inverse)
    return values

ntt_in_place(a, inverse):              # len(a) a power of two, at most 2^23
    bit_reverse_permute(a)
    for length = 2, 4, ..., n:
        w_length = 3^((p - 1) / length) mod p     # its inverse if inverse
        for start = 0, length, 2 * length, ...:
            w = 1
            for k = 0 to length/2 - 1:
                u = a[start + k]
                t = w * a[start + k + length/2] mod p
                a[start + k]            = (u + t) mod p
                a[start + k + length/2] = (u - t) mod p
                w = w * w_length mod p
    if inverse: multiply every entry by n^(p - 2) mod p
    return (n/2) * log2(n)                       # the butterflies

multiply(p, q):
    need = len(p) + len(q) - 1               # error above 2^23
    n = smallest power of two >= need
    P = ntt_in_place(pad(p, n));  Q = ntt_in_place(pad(q, n))
    R = ntt_in_place(P * Q pointwise mod p, inverse)
    return the first need entries of R
```

## Implementation

All three versions are iterative and run the stages in place. The public functions are `ntt`, `intt`, `ntt_in_place`, `multiply_polynomials`, `convolve`, `root_of_unity` and `bit_reverse_permute` (`ntt`, `intt`, `nttInPlace`, `multiplyPolynomials`, `convolve`, `rootOfUnity`, `bitReversePermute` in C++; `NTT`, `INTT`, `NTTInPlace`, `MultiplyPolynomials`, `Convolve`, `RootOfUnity`, `BitReversePermute` in Go). They take the same inputs as the FFT topic's functions and give the same residues in every language:

- **Types.** Python takes lists of `int`, C++ `std::vector<long long>` and Go `[]int`; all reduce the entries modulo p first, so negative values work, and return residues from 0 to p - 1. A Python float raises `TypeError`.
- **Products in 64 bits.** A residue is below 2<sup>30</sup>, so the product of two is below 2<sup>60</sup>: C++ multiplies in `uint64_t` and Go in `uint64`, and the largest product, (p - 1)<sup>2</sup> = 996,491,786,299,899,904, fits. No 128-bit arithmetic is needed for this modulus.
- **The work count.** `ntt_in_place` returns its number of butterflies, (n/2) log2(n), in all three languages, and the Python tests also count the calls of its module-level `_butterfly`.
- **Errors.** More than 2<sup>23</sup> values or product coefficients raise `ValueError` in Python, throw `std::invalid_argument` in C++ and return an error wrapping `ErrTooLong` in Go; an inverse of another length than a power of two gives `ValueError`, `std::invalid_argument` or `ErrNotPowerOfTwo`. Where the FFT topic's Go code panics, this one returns errors.
- **Empty input.** `ntt([])` is `[]`. An empty polynomial is zero: the product has len(p) + len(q) - 1 zeros, the same lengths the FFT topic returns.

The C++ and Go tests pin the 24 roots of unity, 12 transforms and 40 products computed by the Python code, and 12 products of the FFT topic's Python code. All three check every transform up to length 64 against the direct O(n<sup>2</sup>) sum and the products against schoolbook multiplication modulo p on 720 random pairs.

So a product whose coefficients stay below p, about 10<sup>9</sup>, is exact in both, and the tests compare the two on such products. Between p and the FFT's limit, the FFT gives the integers and the NTT their residues, which is what a problem that asks for the answer modulo 998244353 wants. Beyond it the FFT is wrong, even modulo p, and the NTT is still exact modulo p:

- `(p - 2)^2 = 996491784303411201` is odd and above 2<sup>53</sup>, so no double holds it. The FFT returns 996491784303411200, which is 3 modulo p; the NTT returns 4, the true value modulo p.
- 4096 coefficients up to 2,000,000 on each side give true coefficients of at most 4.1&times;10<sup>15</sup>, under half of 2<sup>53</sup>. The FFT got 4,038 of the 8,191 wrong; the NTT got every one right modulo p.

## Applications

- **Counting modulo a prime.** Multiplying generating functions, counting pairs or tuples by their sum, combinatorics answers modulo 998244353.
- **Convolutions with small exact counts.** Counts of matching pairs in bit strings stay below p, so the residues are the counts themselves.
- **Polynomial arithmetic.** Powers, inverses and division of power series modulo p are built from repeated NTT products (not in this repository).
- **Big numbers and other moduli.** Several NTT primes and the Chinese Remainder Theorem give exact large coefficients, or a result modulo 10<sup>9</sup> + 7.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **A prime without enough powers of two.** 10<sup>9</sup> + 7 has p - 1 = 2 &times; 500000003, so it has no root of unity of order 4; that is why NTT problems use 998244353.
- **Reading the residue as the integer.** Above p the coefficient is reduced, silently, and a negative one comes out as p minus its size: `(1 - x)(1 + x)` gives `[1, 0, 998244352]`.
- **Forgetting n<sup>-1</sup>.** Without it the inverse is n times too large: `[16, 52, 88, 60]` instead of `[4, 13, 22, 15]`.
- **The forward root in the inverse.** The output comes back reversed after its first entry: position j holds a[(n - j) mod n].
- **Skipping the bit reversal.** The stages expect the bit-reversed order; without it the output is wrong, not merely reordered.
- **Products in 32 bits.** Two residues multiply to almost 2<sup>60</sup>; use a 64-bit type.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Why 998244353?">
    It is a prime of the form 119 &times; 2<sup>23</sup> + 1, so it has roots of unity of every power-of-two order up to 2<sup>23</sup>, it is below 2<sup>30</sup>, so two residues multiply in 64 bits, and 3 is a primitive root. AtCoder's library practice problem Convolution, in the list below, asks for its answer modulo this prime.
  </FaqItem>
  <FaqItem question="Why does the NTT need no rounding?">
    Every value in it is an integer from 0 to p - 1, and every step is an integer sum, difference or product reduced modulo p. Nothing is approximated, so nothing has to be rounded back. Most of the FFT's roots, such as e<sup>-2&pi;i/8</sup> = (1 - i)/&radic;2, have no exact double, so it works with approximations.
  </FaqItem>
  <FaqItem question="Can I get the exact integer coefficients?">
    Only those from 0 to p - 1 come out as themselves. For larger ones, run the NTT modulo three primes such as 998244353, 167772161 and 469762049 and combine each coefficient with the Chinese Remainder Theorem, which recovers anything below their product, about 2<sup>86</sup>. This repository does not implement that; the FFT is exact up to about 10<sup>14</sup> at the lengths measured.
  </FaqItem>
  <FaqItem question="What if the problem asks for the answer modulo 10^9 + 7?">
    That prime has no roots of unity of order 4 or more, so no NTT runs modulo it directly. Compute the product exactly with three NTT primes and the CRT, then reduce it modulo 10<sup>9</sup> + 7.
  </FaqItem>
  <FaqItem question="Why is this version iterative when the FFT topic's is recursive?">
    To show the other standard form of the same algorithm. The bit reversal and the stages do exactly the work of the recursion, in place; the visualization draws both on the same grid, so the two can be compared row by row.
  </FaqItem>
</Faq>
