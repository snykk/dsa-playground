## How rotating calipers works

Picture a pair of calipers clamped on a convex polygon. Each jaw is a **supporting line**: it touches the polygon and has the whole polygon on one side. Rotate the calipers by one full turn, keeping the jaws parallel. Every vertex that touches a jaw while it is rotating is **antipodal** to a vertex on the other jaw, and the farthest pair of points of the polygon is always one of these antipodal pairs. Checking the O(n) antipodal pairs replaces checking all n<sup>2</sup> pairs.

The implementation does not rotate anything. It walks the edges of the polygon in order and keeps a second pointer `j` on the vertex that is farthest from the current edge:

<Steps>
  <Step title="Clean the polygon">
    Remove consecutive repeated vertices and vertices that lie on an edge (a zero cross product). If all points are collinear only the two end points remain. This is what keeps the area test below well behaved.
  </Step>
  <Step title="Take an edge">
    For edge `(i, i+1)`, the distance of a vertex `k` from the line through it is proportional to the triangle area `|cross(i, i+1, k)|`.
  </Step>
  <Step title="Advance the far pointer">
    While vertex `j + 1` is farther from the edge than vertex `j` (strictly larger area), move `j` forward. On a convex polygon the area first grows and then shrinks as `k` goes around, so the pointer stops at the top of the hill. When the polygon has a parallel edge, `j + 1` has the same area and is a candidate too.
  </Step>
  <Step title="Record the candidates">
    For the diameter, test the squared distances from `i` and `i + 1` to `j` (and to `j + 1` on a tie). For the width, take `area / edge length`, the height of `j` over the edge, and keep the smallest over all edges.
  </Step>
</Steps>

<Callout title="Why the area, and not the distance, drives the pointer">
The distance from a fixed vertex to the other vertices of a convex polygon is not unimodal, so climbing on it can stop at a local maximum. The height over an edge is unimodal on a strictly convex polygon. A version that climbed on vertex-to-vertex distance returned 104.96 instead of 104.98 on a six-vertex fan-shaped hull; the tests include that polygon.
</Callout>

## Pseudocode

```text
cleanPolygon(hull):
    drop consecutive repeated vertices (and a last vertex equal to the first)
    if fewer than 3 vertices: return them
    if all vertices are collinear: return the two end points
    drop vertices with cross(prev, v, next) == 0, also across the wrap-around
    return the rest

diameter(hull):
    pts = cleanPolygon(hull)
    if size(pts) <= 2: return the distance between the points (0 for none or one)
    best = -1; j = 1
    for i = 0 to n - 1:
        edge = (i, i + 1)
        while |cross(edge, j + 1)| > |cross(edge, j)|:
            j = j + 1
        candidates = [j], plus j + 1 if |cross(edge, j + 1)| == |cross(edge, j)|
        for k in candidates, for m in [i, i + 1]:
            best = max(best, dist(pts[m], pts[k])^2)
    return sqrt(best)

width(hull):
    pts = cleanPolygon(hull)
    if size(pts) < 3: return 0
    for each edge, move j as above and take |cross(edge, j)| / length(edge)
    return the minimum
```

## Implementation

Each module takes a list of points: the vertices of a convex polygon in order, in either orientation. Output of Graham's scan or Jarvis march from the Convex Hull topic fits directly. Comparisons are exact, so integer input is handled without tolerances. Degenerate input returns sensible values in all three languages: a diameter of 0 for no or one distinct point and a width of 0 for fewer than three distinct corners.

The folder also has `perimeter` (the sum of edge lengths) and `area` (the shoelace formula). They work for any polygon and are not caliper algorithms.

The pointer never moves backwards: as the edge turns counterclockwise, the vertex farthest from it also moves counterclockwise. So j goes around the polygon at most about twice while i goes around once.

## Applications

- **Farthest pair of points.** The diameter of a point set is the diameter of its hull.
- **Narrowest strip.** The width of a point set, for example the thinnest slab that contains an object.
- **Bounding boxes.** The same sweep, with four calipers, gives the smallest bounding rectangle.
- **Collision and clearance checks** between convex shapes.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Climbing on distance.** Moving `j` while `dist(i, j + 1) > dist(i, j)` can stop at a local maximum. Drive the pointer with the triangle area.
- **Feeding a point set that is not a hull.** The input must be the vertices of a convex polygon, in order. Compute the hull first.
- **Collinear or repeated vertices.** A zero-area plateau stalls the pointer, which once made `width` return 0 for a rectangle with an extra vertex on one side. The code removes them first.
- **Only testing `(i, j)`.** Both ends of the edge, `i` and `i + 1`, pair up with `j`, and a parallel edge gives a second antipodal vertex `j + 1`.
- **Returning a sentinel.** A hull with fewer than three distinct corners has width 0, not infinity.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Do I need to pass the hull in counterclockwise order?">
    No. The code uses absolute values of the cross product and works for clockwise and counterclockwise order. The vertices must still go around the polygon in order.
  </FaqItem>
  <FaqItem question="Why are antipodal pairs enough for the diameter?">
    The farthest pair of a convex polygon admits two parallel supporting lines, one through each point. Two such lines exist exactly for antipodal pairs, so the diameter is among them.
  </FaqItem>
  <FaqItem question="What is the width of a polygon?">
    It is the smallest distance between two parallel lines that enclose the polygon. One of the two lines always contains a whole edge of the polygon, which is why the code only tries the lines through edges.
  </FaqItem>
  <FaqItem question="Does this work on a point set that is not already a hull?">
    Not directly. Compute the hull first (for example with Graham's scan from the Convex Hull topic) and pass its vertices.
  </FaqItem>
</Faq>
