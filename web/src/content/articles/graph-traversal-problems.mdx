## When to use it

Signals in a problem statement:

- "fewest moves / steps / edges" with every move costing the same: **BFS**;
- "can I reach B from A", "how many connected regions", "count the islands": **flood fill** (DFS or BFS);
- "do tasks with prerequisites have a valid order", "detect a cycle in dependencies": **topological sort**;
- a grid, a board or a state space where each state has a few neighbours.

If edges have different weights, BFS is wrong; use Dijkstra instead.

## How it works

All traversals share one loop: take a node from a frontier, mark it visited, add its unvisited neighbours. The data structure chosen for the frontier gives the order.

<Steps>
  <Step title="Represent the graph">
    An adjacency list (`dict` of node to neighbours) for general graphs. For a grid, the neighbours of `(r, c)` are the four cells next to it that are inside the grid.
  </Step>
  <Step title="Mark nodes visited when they enter the frontier">
    For BFS, mark on push, not on pop, so a node is never queued twice.
  </Step>
  <Step title="Process until the frontier is empty">
    BFS pops from the front and pushes neighbours with `dist + 1`. DFS pops from the back. Kahn pops nodes whose in-degree has dropped to 0.
  </Step>
</Steps>

<Callout title="Why BFS gives shortest paths">
BFS removes nodes from the queue in order of non-decreasing distance. The first time a node is reached is therefore by a shortest route, because every shorter route would already have been explored layer by layer.
</Callout>

## Template

```text
bfs_shortest_path(graph, start, target):
    if start not in graph: return -1
    if start == target: return 0
    queue = [(start, 0)]; visited = {start}
    while queue:
        node, dist = queue.pop_front()
        if node == target: return dist
        for nb in graph.get(node, []):
            if nb not in visited:
                visited.add(nb); queue.push_back((nb, dist + 1))
    return -1

num_islands(grid):                        # flood fill, modifies the grid
    count = 0
    for each cell (r, c) with grid[r][c] == '1':
        count += 1
        sink(r, c)                        # DFS: turn every connected '1' into '0'
    return count

topological_sort(n, edges):               # Kahn
    queue = all nodes with in_degree 0
    while queue:
        u = queue.pop_front(); order.append(u)
        for v in adj[u]:
            in_degree[v] -= 1
            if in_degree[v] == 0: queue.push_back(v)
    return order if len(order) == n else []     # empty means a cycle
```

## Worked example: topological order

Courses with prerequisites `1 -> 0`, `2 -> 0`, `3 -> 1`, `3 -> 2` (an edge `u -> v` means `u` comes before `v`). `topological_sort(4, edges)` returns `[3, 1, 2, 0]`: node 3 has in-degree 0, removing it frees 1 and 2, and removing both frees 0.

If the output has fewer than `n` nodes, some nodes never reached in-degree 0, which means a cycle: `topological_sort(2, [[0, 1], [1, 0]])` returns an empty list.

## Implementation

Python provides `bfs_shortest_path`, `get_dfs_traversal`, `num_islands` and `topological_sort`. C++ (`GraphTraversal::` static methods) and Go (`BFSShortestPath`, `NumIslands`, `TopologicalSort`) provide BFS, flood fill and Kahn, but no standalone DFS traversal.

Things to know:

- The target of `bfs_shortest_path` need not be a key of the graph, so sink nodes of a directed graph are reachable.
- Python's DFS and flood fill use an explicit stack, so deep inputs do not hit the recursion limit. The C++ and Go flood fills still recurse: a very large single island can exhaust the stack in C++.
- `num_islands` overwrites visited cells with `'0'` in all three languages: pass a copy if you need the grid afterwards.
- `topological_sort` returns an empty list on a cycle. In C++ edge endpoints must be below `n`; there is no bounds check.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Marking visited on pop in BFS.** The same node can be queued many times, and on dense graphs that costs far more than O(V + E).
- **Using BFS with weights.** It counts edges. Weighted graphs need Dijkstra.
- **Requiring the target to be a key.** In a directed adjacency list, a node with no outgoing edges often has no entry.
- **Deep recursion.** Recursive DFS on a long path or a big grid overflows the call stack. Use an explicit stack.
- **Mutating the input.** Sinking islands destroys the grid; copy first or keep a separate visited array.
- **Forgetting the cycle case.** A short Kahn output means a cycle, and you must report it instead of returning a partial order.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="BFS or DFS: which one should I use?">
    BFS when you need the fewest steps. For plain reachability, counting components and flood fill, either works; DFS needs less memory on wide graphs, BFS needs less on deep ones.
  </FaqItem>
  <FaqItem question="Can BFS find the shortest path in a weighted graph?">
    Only if all weights are equal. With weights 0 and 1 use 0-1 BFS, otherwise use Dijkstra.
  </FaqItem>
  <FaqItem question="How does Kahn's algorithm detect a cycle?">
    Nodes on a cycle always have a predecessor that is also on the cycle, so their in-degree never reaches 0 and they are never output. If the output is shorter than n, a cycle exists.
  </FaqItem>
  <FaqItem question="Why do diagonal neighbours not count in Number of Islands?">
    The standard problem defines connectivity by the four edge-sharing neighbours. The code here uses exactly those four offsets; add four more for 8-connectivity.
  </FaqItem>
</Faq>
