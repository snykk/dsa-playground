## The problem

A stack allows two changes, push and pop, and both happen at the same end, called the top. The item you pushed last is the first one you get back (last in, first out).

All three versions offer the same operations in Python, C++ and Go:

- `push(x)` adds an item on top.
- `pop()` removes and returns the top item.
- `peek()` returns the top item without removing it.
- `is_empty()` and `size()` report the state.
- `pop` and `peek` on an empty stack fail with an error: `IndexError` in Python.

The versions differ in one question: what happens when the stack runs out of room, and what does each item cost in memory?

Pop, peek, `is_empty` and `size` are O(1) in every version. The static stack's capacity must be at least 1; a smaller value raises `ValueError` in Python.

The static stack pays for its whole capacity up front, even when it is empty. The dynamic stack's O(1) push is amortized: one push in a while finds the array full and copies every item.

## Applications

- **Undo and redo.** Each action is pushed, and undo pops the latest.
- **Expression evaluation and bracket matching.** Operators and open brackets wait on the stack.
- **Depth-first search.** An explicit stack replaces the call stack.
- **Monotonic stack problems.** Next greater element and similar questions.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Popping or peeking an empty stack.** Python raises `IndexError`. Check `is_empty()` first.
- **Ignoring the overflow error.** A full static stack rejects the push and keeps the old state, so a swallowed error loses the item.
- **Expecting the static stack to grow.** Its capacity is fixed when you create it.
- **Reading the array beyond the top.** In the array versions the slots above the top may hold old values. Use `peek()` and `size()`.
- **Assuming every push is cheap in the dynamic stack.** The average is O(1), but one push in a while copies the whole array.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which stack should I start with?">
    Start with the static array stack: it shows the idea with the least machinery. Then read the dynamic array stack to see how the capacity limit is removed, and the linked list stack to see how pointers remove it without any copying.
  </FaqItem>
  <FaqItem question="Do the three versions behave differently?">
    Not on valid use. The order of pops is the same, and so are the names of the operations. They differ only when the stack is full, which only the static stack can be, and in how much memory each item takes.
  </FaqItem>
  <FaqItem question="Why is push O(1) amortized in the dynamic stack?">
    The array grows by a constant factor, so copies are rare. Spread over many pushes, the copying adds only a constant amount of work to each one.
  </FaqItem>
  <FaqItem question="Is a stack the same as the call stack?">
    The call stack is one use of the idea: each function call pushes a frame and each return pops it. A stack in your own code gives you the same order without the depth limit of recursion.
  </FaqItem>
</Faq>
