## The problem

In a contest the algorithm is often right and the program is still too slow, too big or wrong at the edges of the integer range. The four techniques here address those failures without a new idea:

- **Input and output cost.** Millions of numbers read one call at a time. Fast I/O fixes it.
- **Repeated work across queries.** The same table is rebuilt for every query. Precomputation moves that work before the first query.
- **Subsets of a few items.** Sets stored as lists or booleans are slow to combine. Bitmasking makes a set one integer.
- **Huge answers.** Counting problems ask for the answer modulo a prime. Modular tricks keep every step exact, fast and inside 64 bits.

## Applications

- **Contests,** where a tight limit often decides between passing and a time-limit error.
- **Combinatorics and probability,** with `nCr` and fractions modulo a prime.
- **Static range queries,** with prefix sums and sparse tables.
- **Subset DP,** such as the travelling salesman problem over a few cities.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Optimizing I/O before the algorithm.** Fast I/O changes the constant factor only. An O(n^2) loop stays O(n^2).
- **Using a sparse table for a sum.** It works for idempotent operations such as min, max and gcd. For sums, use prefix sums.
- **Bitmasking beyond about 25 items.** There are 2^n masks, so the cost doubles with every item.
- **Reducing too late.** In modular arithmetic, reduce after every operation. A plain product of two residues breaks 64 bits once the modulus exceeds about 3e9.
- **Buffering an interactive problem.** The judge sees nothing until you flush, so read and write one query at a time.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Start with Fast I/O: it is the Beginner topic and the lowest-cost fix. Then Precomputation, Bitmasking and Modular Arithmetic Tricks, which are Intermediate. Bitmasking builds on the Bit Manipulation pattern, and the modular tricks build on the number-theory topics, so read those first if they are new.
  </FaqItem>
  <FaqItem question="Which technique helps most often?">
    It depends on the problem. Fast I/O matters when the input is large, precomputation when queries repeat, and the modular tricks in almost every counting problem. They are tools you combine, for example factorial tables for `nCr` modulo a prime.
  </FaqItem>
  <FaqItem question="Do I need these outside contests?">
    The ideas carry over. Batched I/O, lookup tables and compact set representations appear in ordinary software, and modular arithmetic appears in hashing and cryptography.
  </FaqItem>
  <FaqItem question="Where are the boilerplates that use them?">
    In the Templates folder of Utilities, which holds C++, Go and Python starting files. Each of the three has buffered input and a modular power and inverse.
  </FaqItem>
</Faq>
