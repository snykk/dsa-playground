## The problem

Some problems have no formula, only a space of candidates: placements of queens, colorings of a graph, fillings of a grid, routes through a maze. Backtracking walks that space with a recursive search. It extends a partial solution by one choice and checks the new partial solution against the constraints. If it breaks one, the search undoes the choice and tries the next. A branch that fails early removes everything below it, which is called **pruning**.

All four topics follow one template:

- **State**: the partial solution, such as a board, a color array or a solution matrix.
- **Choice**: what the next step picks, such as a column, a color, a digit or a direction.
- **Constraint check**: a test that a choice does not break the rules, such as `is_safe` or `is_valid`.
- **Undo**: the state is restored before the next choice is tried.

The topics differ in how the search stops. N-Queens (with `find_all = False`), Graph Coloring, Sudoku and the maze stop at the first solution. N-Queens with `find_all = True` visits every branch and collects all boards.

The maze is the odd one out. It never revisits a cell, so a dead end is explored once, and the search stays polynomial. In the other three a failure belongs to a whole partial board or coloring, not to one cell, and there are exponentially many of those, so their running time is exponential in the worst case.

## Applications

- **Puzzles and games.** Sudoku, crosswords, n-queens and similar placement problems.
- **Scheduling and timetabling.** Graph coloring models exams or classes that may not share a time slot.
- **Register allocation.** Variables that are live together get different registers, which is a coloring problem.
- **Path finding in small grids.** Any search that needs one valid route, not the best one.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Forgetting to undo.** Each topic resets the state after a failed branch (`board[row][col] = 0`, `color[v] = 0`, `solution[x][y] = 0`). Without it, a stale choice blocks later branches.
- **Saving the live state.** N-Queens must copy the board into the result. A reference to `board` ends up empty after the search backtracks.
- **Un-marking visited cells in the maze.** If the visited mark is reset on the way back, the search becomes exponential on open mazes.
- **Expecting the best solution.** The maze returns the first path in the order right, down, left, up. `graph_coloring` returns some coloring with colors in `1..m`. Use `chromatic_number` for the minimum.
- **Trusting the input.** The Sudoku solver validates the givens first. A graph coloring matrix must be symmetric, because the code reads `graph[v][i]` only.
- **Using 0 as a real value.** In Graph Coloring and Sudoku, 0 means uncolored or empty, so valid colors and digits start at 1.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Start with Rat in a Maze: it has one choice per step and the simplest check. Then N-Queens, which adds a real constraint and the idea of one item per row. Graph Coloring generalises the constraint to any graph, and Sudoku is the largest search with an input check. Each needs only a depth-first search as background.
  </FaqItem>
  <FaqItem question="Is backtracking the same as depth-first search?">
    It is a depth-first search over the tree of partial solutions, with a check that cuts branches. The maze is also a plain graph search. Its visited mark is the same one DFS uses.
  </FaqItem>
  <FaqItem question="How do I make a backtracking search faster?">
    Prune earlier and make the check cheaper. N-Queens can keep the used columns and diagonals in sets so the check is O(1). Graph Coloring benefits from coloring high-degree vertices first. Sudoku solvers pick the empty cell with the fewest legal digits. This repository uses the plain order everywhere.
  </FaqItem>
  <FaqItem question="Why is the maze polynomial and the others are not?">
    A cell that failed once fails again, so the visited mark is never cleared and every cell is entered at most once. In the other three problems a failure belongs to a whole partial board or coloring, not to one cell. There are exponentially many of those, and the search keeps no memory of failures.
  </FaqItem>
</Faq>
