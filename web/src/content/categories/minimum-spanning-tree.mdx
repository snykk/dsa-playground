## The problem

A spanning tree of a connected graph is a set of edges that connects all V vertices without a cycle, so it has exactly V - 1 edges. A minimum spanning tree (MST) is one whose edge weights add up to the least possible total.

Both algorithms rely on the same fact, the **cut property**: for any split of the vertices into two groups, the lightest edge between the groups can be part of some MST. So choosing the lightest safe edge, again and again, is never a mistake. The two algorithms differ in how they find that edge.

- **Kruskal** looks at all edges from lightest to heaviest and keeps one unless it would close a cycle.
- **Prim** starts from one vertex and repeatedly adds the lightest edge that leaves the growing tree.

The two trees contain the same four edges. Kruskal adds them by weight, so it starts in the middle of the graph with the weight-1 edge. Prim starts at vertex 0, so its first edge is the lightest one at 0, which is `0-2`. Kruskal also stops as soon as it has V - 1 = 4 edges, so it never examines the three heaviest edges.

When several edges share a weight, different valid choices can give different trees. The total weight is the same in every case.

## Applications

- **Network design.** Cable, pipes or roads that connect every site for the least total length.
- **Clustering.** Cutting the heaviest edges of an MST splits the points into groups.
- **Approximation.** The MST is a building block for approximating the travelling salesman problem.
- **Image segmentation and circuit layout.** Both need a cheap connected structure.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Confusing an MST with a shortest-path tree.** The MST minimises total weight. The path between two vertices inside it can be longer than their shortest path in the graph.
- **Adding an edge without a cycle check in Kruskal.** The union-find test is what keeps the result a tree.
- **Assuming the input is connected.** A disconnected graph has no spanning tree. Kruskal returns fewer than V - 1 edges without an error, and Prim silently leaves out vertices it cannot reach.
- **Using the directed-graph version of the idea.** These algorithms are for undirected graphs. A minimum spanning arborescence of a directed graph needs a different algorithm.
- **Expecting a unique tree.** Equal edge weights allow several minimum spanning trees.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which one should I learn first?">
    Kruskal. The idea is simple, sort and skip cycles, and it introduces union-find. Prim is easier to picture as growth from one vertex, and its heap version is close to Dijkstra's algorithm.
  </FaqItem>
  <FaqItem question="Do they always give the same tree?">
    They always give the same total weight. When the edge weights are all different the MST is unique, so they give the same tree. With ties, they can pick different edges of equal weight.
  </FaqItem>
  <FaqItem question="How is Prim different from Dijkstra?">
    Both pull the cheapest candidate from a priority queue. Dijkstra ranks a vertex by its total distance from the source. Prim ranks it by the weight of the single edge that connects it to the tree.
  </FaqItem>
  <FaqItem question="Can an MST have negative edges?">
    Yes. Both algorithms only compare weights, so negative weights are fine. This is unlike Dijkstra, which fails on them.
  </FaqItem>
</Faq>
