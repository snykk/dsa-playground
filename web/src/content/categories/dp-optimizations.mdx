## The problem

Some DP recurrences have the form `dp[i] = min over j < i of (m_j * x_i + b_j)`. Evaluating every `j` costs O(n) per state and O(n^2) in total. Each earlier state is a line `y = m*x + b`, and the minimum over lines at one `x` is the lower envelope of those lines. The Convex Hull Trick keeps only the lines that appear on that envelope.

Both structures in the Python code solve one problem: given a set of lines, return the minimum `y` at a query `x`.

- `MonotonicCHT` needs slopes inserted in non-increasing order and queries with non-decreasing `x`. It keeps a deque of lines and drops a line that can never be best.
- `LiChaoTree` has no such requirement, but it covers a fixed range of `x` that is given at construction.

Used in a DP, the monotonic version turns O(n^2) into O(n) when the slopes and queries are already sorted, and the Li Chao tree gives O(n log V) otherwise.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Breaking the order.** `MonotonicCHT` assumes non-increasing slopes and non-decreasing queries. Other orders give wrong answers.
- **Querying outside the range.** `LiChaoTree.query` raises `ValueError` when `x` is outside the range given to the constructor.
- **Overflow.** The products `m*x + b` must fit in the integer type. C++ and Go use wide arithmetic in the comparison of lines, but not in the values themselves.
- **Querying an empty structure.** Python raises `ValueError`, C++ has undefined behavior and Go panics.
- **Using the minimum structure for a maximum.** Both structures answer minimum queries.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="When should I reach for a DP optimization?">
    When the recurrence is correct but a profile shows the transition dominating, and the cost has the structure the technique needs. Here that structure is a minimum over lines.
  </FaqItem>
  <FaqItem question="Why do slopes have to be sorted for the monotonic version?">
    Lines then enter the deque in the order they can become best, so a line that is never best can be removed from the back, and one that has stopped being best can be removed from the front.
  </FaqItem>
  <FaqItem question="Is the Li Chao tree always better?">
    It is more general, but it costs O(log V) instead of amortized O(1) and needs a bounded range of `x`. When both inputs are sorted, the monotonic version is faster.
  </FaqItem>
</Faq>
