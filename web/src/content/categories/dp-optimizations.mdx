## The problem

Some DP recurrences have the form `dp[i] = min over j < i of (m_j * x_i + b_j)`. Evaluating every `j` costs O(n) per state and O(n^2) in total. Each earlier state is a line `y = m*x + b`, and the minimum over lines at one `x` is the lower envelope of those lines. The Convex Hull Trick keeps only the lines that appear on that envelope.

Both structures in the Convex Hull Trick's Python code solve one problem: given a set of lines, return the minimum `y` at a query `x`.

- `MonotonicCHT` needs slopes inserted in non-increasing order and queries with non-decreasing `x`. It keeps a deque of lines and drops a line that can never be best.
- `LiChaoTree` has no such requirement, but it covers a fixed range of `x` that is given at construction.

Divide and Conquer Optimization needs no formula for the cost. It works on layered DPs, `dp[g][i] = min over j < i of dp[g-1][j] + C(j, i)`, such as splitting an array into exactly `k` groups. If the best `j` never moves left as `i` grows, the middle cell of a layer is solved first, and each half searches only on its side of that cell's best `j`. The quadrangle inequality `C(a, c) + C(b, d) <= C(a, d) + C(b, c)` guarantees it.

Knuth's optimization rests on the same inequality, for interval DPs: `dp[i][j] = min over i <= k < j of dp[i][k] + dp[k+1][j] + C(i, j)`, such as merging neighbouring piles at the cost of the pile made. When `C` also never grows as a range shrinks (`C(b, c) <= C(a, d)` when `b..c` lies inside `a..d`), the smallest best split satisfies `opt(i, j-1) <= opt(i, j) <= opt(i+1, j)`. Each cell then tries only the splits between the best splits of its two neighbours on the previous diagonal, and along a diagonal those windows telescope: O(n^2) in all instead of O(n^3).

## One problem, both techniques

Split `3, 1, 4, 1, 5, 9, 2, 6` into exactly three contiguous groups so that the sum of `(sum of the group)^2` is smallest. With prefix sums `P`, a layer is `dp[g][i] = min over j of dp[g-1][j] + (P[i] - P[j])^2`.

- `min_cost_partition(values, 3)` in Divide and Conquer Optimization returns 341, with the groups `3, 1, 4, 1`, then `5, 9`, then `2, 6`. Its recursion evaluates 41 costs, where trying every `j` evaluates 57.
- The same cost expands to `P[i]^2 + (-2 P[j]) * P[i] + (dp[g-1][j] + P[j]^2)`: a line in `P[i]` for each `j`, with slopes that never increase and queries that never decrease. One `MonotonicCHT` per layer returns 341 too.

They meet here because the square expands into lines. A cost that does not, such as the number of equal pairs inside a group, leaves only divide and conquer; a cost made of lines whose best `j` is not monotone leaves only the Convex Hull Trick, with a Li Chao tree.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Breaking the order.** `MonotonicCHT` assumes non-increasing slopes and non-decreasing queries. Other orders give wrong answers.
- **Querying outside the range.** `LiChaoTree.query` raises `ValueError` when `x` is outside the range given to the constructor.
- **Overflow.** The products `m*x + b` must fit in the integer type. C++ and Go use wide arithmetic in the comparison of lines, but not in the values themselves.
- **Querying an empty `MonotonicCHT`.** Python raises `ValueError`, C++ has undefined behavior and Go panics.
- **Using the minimum structure for a maximum.** Both structures answer minimum queries.
- **Divide and conquer without its inequality.** With a negative value, `(sum of the group)^2` breaks the quadrangle inequality, and the recursion returns 10 instead of 2 for `1, 2, 4, -5` in two groups, with no error.
- **Knuth's window without its inequality.** A merge that costs the square root of its size breaks it, and the narrowed DP returns 8 instead of 7 on the piles `1, 1, 2, 1, 6`, with no error.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="When should I reach for a DP optimization?">
    When the recurrence is correct but a profile shows the transition dominating, and the cost has the structure the technique needs: a minimum over lines for the Convex Hull Trick, a best `j` that never moves left for divide and conquer, a best split between those of its two neighbours for Knuth's optimization.
  </FaqItem>
  <FaqItem question="Why do slopes have to be sorted for the monotonic version?">
    Lines then enter the deque in the order they can become best, so a line that is never best can be removed from the back, and one that has stopped being best can be removed from the front.
  </FaqItem>
  <FaqItem question="Is the Li Chao tree always better?">
    It is more general, but it costs O(log V) instead of amortized O(1) and needs a bounded range of `x`. When both inputs are sorted, the monotonic version is faster.
  </FaqItem>
  <FaqItem question="How do I know whether divide and conquer applies?">
    Check the quadrangle inequality on the cost, as the topic does for the square of a group's sum, or run the plain DP on small random inputs and compare. A wrong answer is the only symptom when it does not apply.
  </FaqItem>
</Faq>
