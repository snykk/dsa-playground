## The problem

One index is not enough to name the subproblem, so the table has two axes. What each axis means decides the shape of the table.

<DataTable
  columns={['Topic', 'Table', 'Cell `dp[i][j]`']}
  rows={[
    ['LCS', '`(m+1) x (n+1)`', 'length of the LCS of the first `i` characters of `s1` and the first `j` of `s2`'],
    ['Edit Distance', '`(m+1) x (n+1)`', 'fewest edits that turn the first `i` characters of `s1` into the first `j` of `s2`'],
    ['0/1 Knapsack', '`(n+1) x (W+1)`', 'best value using the first `i` items with capacity `j`'],
    ['Matrix Chain', '`(n+1) x (n+1)` for n matrices', 'fewest scalar multiplications for the chain from matrix `i` to matrix `j`'],
  ]}
/>

The first three fill row by row, and each cell reads only cells above and to the left. Matrix Chain fills by chain length, because a cell reads shorter intervals of its own chain.

## Two string tables, one pair of strings

LCS and Edit Distance ask different questions about the same pair, so their numbers can differ. The values below come from `lcs_length`, `lcs_sequence` and `edit_distance`.

Edit Distance allows replacement, so for `kitten` and `sitting` it is 3, less than the 5 that deletions and insertions alone would need (6 + 7 - 2*4). Both functions use the same table shape and the same `s1[i-1] == s2[j-1]` test.

## Applications

- **Diff tools and version control.** LCS finds the lines two files share.
- **Spell checking and fuzzy search.** Edit Distance ranks candidate words.
- **Resource allocation.** Knapsack selects projects or cargo under a limit.
- **Query planning and compilers.** Interval DP chooses the cheapest order of associative operations.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Confusing subsequence and substring.** LCS may skip characters, while a common substring may not.
- **Counting a swap as one edit.** Edit Distance here has only insert, delete and replace, so swapping two letters costs 2.
- **Looping capacity upward in a one-row knapsack.** It lets an item be taken twice. `knapsack_01_optimized` loops downward.
- **Expecting items back from the space-saving versions.** A single row or two rows drop the table that the traceback needs.
- **Treating O(n*W) as polynomial.** A capacity of 10^9 makes the table unusable, even with few items.
- **Assuming the answer is unique.** Several subsequences can share the LCS length, and the code returns one of them.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which one should I read first?">
    LCS. Edit Distance reuses its table shape, and Knapsack and Matrix Chain build on the same idea of filling a table from smaller cells.
  </FaqItem>
  <FaqItem question="Why does Matrix Chain fill by chain length?">
    A cell for matrices `i` to `j` reads the cells for `i` to `k` and `k+1` to `j`, both shorter chains. Filling by length guarantees they are ready.
  </FaqItem>
  <FaqItem question="Can I recover the solution, not just its value?">
    Yes, by walking back from the final cell and following which neighbor produced each value. LCS, Edit Distance and Knapsack allow it in the full table, and the one-row versions do not.
  </FaqItem>
  <FaqItem question="How does this relate to Linear DP?">
    A 1D table has one index. Here the second index adds a second sequence, a capacity or the other end of an interval, so the table grows from O(n) to O(n^2) cells or more.
  </FaqItem>
</Faq>
