## The problem

In earlier areas the state is one or two numbers. Here it is a shape: a contiguous range of a row, a node with all of its subtree, a node with all of its successors, a set of chosen items, or a prefix of a number. The recurrence is the same kind of statement, "the answer for this state is built from smaller states", and the order follows the structure.

## Applications

- **Merging and splitting a row.** The cheapest order to merge neighbouring files or piles, the best way to cut a string, the order of a chain of products.
- **Hierarchies.** Choosing non-adjacent nodes, for example employees for a task with no manager and report together.
- **Dependency graphs.** Longest chain of build steps in a DAG.
- **Routing and scheduling.** Exact Traveling Salesman tours for about 20 stops at most.
- **Number problems.** Counting integers with a digit sum or another digit rule.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Filling an interval table row by row from the top.** A split reads `dp[k+1][j]`, a cell lower in the same column, before it is computed: on piles `3, 2, 4, 1` that order returns 10 instead of 20. Fill by length.
- **Recursing twice per child in tree DP.** Calling the recursion again for each child makes the algorithm exponential. Compute each child once and reuse the result.
- **Running graph DP on a cycle.** There is no order in which the successors are solved first. The code detects this and raises `ValueError`.
- **Using bitmask DP past about 20 items.** The table has `n * 2^n` cells, and in Python the cell objects make the practical limit lower.
- **Forgetting the tight flag in digit DP.** Without it a number above the bound is counted, because the digits are no longer limited by the bound's digits.
- **Comparing sentinels across languages.** No tour is infinity in all three languages, but the path sum of an empty tree is `-inf` in Python and the smallest 64-bit integer in C++ and Go.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which one should I read first?">
    Interval DP, right after Matrix Chain Multiplication: its table is still two indices, a range. Then DP on Trees, whose state is the easiest structure to picture; DP on Graphs generalizes it from trees to DAGs. Bitmask DP and Digit DP use a different kind of state and can be read in either order.
  </FaqItem>
  <FaqItem question="How is DP on Graphs different from DP on Trees?">
    A tree has one parent per node and no cycles, so a post-order pass is enough. A DAG can reach one node by several paths, so a memo is needed to avoid repeated work, and cycles must be ruled out.
  </FaqItem>
  <FaqItem question="Why does bitmask DP stop at about 20 items?">
    The table has `n * 2^n` cells. At n = 20 that is about 21 million, and each doubling of the table costs one more item.
  </FaqItem>
  <FaqItem question="When is digit DP needed?">
    When the bound is too large to loop over and the property depends only on digits, such as the digit sum. The memo size depends on the number of digits, not on the value of the bound.
  </FaqItem>
</Faq>
