## The problem

Each topic here keeps one array and fills it in one direction. What changes is the meaning of an entry and which earlier entries it reads.

<DataTable
  columns={['Topic', 'Entry', 'Reads']}
  rows={[
    ['Coin Change', '`dp[a]`: fewest coins for amount `a` (or the number of ways)', '`dp[a - c]` for every coin `c`'],
    ['LIS', '`dp[i]`: length of the longest increasing run that ends at index `i`', '`dp[j]` for every `j < i` with `arr[j] < arr[i]`'],
    ['Kadane', 'the best sum of a run that ends at index `i`', 'the previous entry only'],
  ]}
/>

An entry is a state, and the final answer is either the last entry (Coin Change) or the best entry (LIS, Kadane).

## Applications

- **Payments and change-making.** Fewest coins or bills for an amount, when the denominations are not canonical.
- **Sequence analysis.** LIS is used for patience-sorting style problems and for comparing orderings.
- **Signals and time series.** Kadane finds the best stretch of gains, such as the best window of daily changes.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Trusting greedy for coins.** It fails for `1, 3, 4`, and DP is correct for any coin set.
- **Using the wrong loop direction.** Upward over amounts allows reuse, downward allows one use per coin.
- **Treating equal values as increasing.** The LIS here is strictly increasing, so `7, 7, 7` has length 1.
- **Returning the tails array as the LIS.** It holds the smallest tail per length, and it need not be a subsequence of the input.
- **Forgetting the all-negative case.** Kadane must return the largest element, because the run cannot be empty. Empty input returns 0.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Coin Change first, because it extends the Climbing Stairs table with a choice per entry. Then LIS, which looks back at every earlier entry, and Kadane, which looks back at one.
  </FaqItem>
  <FaqItem question="Is Kadane's algorithm really dynamic programming?">
    Yes. The state is the best sum of a run that ends at `i`, and the transition is `max(arr[i], previous + arr[i])`. Because it reads one earlier value, two variables replace the table.
  </FaqItem>
  <FaqItem question="Why is the LIS tails method correct if tails need not be an LIS?">
    Only the length of `tails` is used. Its entry `k` is the smallest last value of any increasing run of length `k+1`, and that array stays sorted, so binary search finds where each value goes.
  </FaqItem>
  <FaqItem question="How does this differ from 2D DP?">
    Linear DP needs one index per state. 2D DP needs two, such as an item and a capacity, or a position in each of two strings.
  </FaqItem>
</Faq>
