## The problem

Both topics define a value for each `n` in terms of smaller values, and the same smaller values are needed many times. A plain recursion repeats them. A table, or two running variables, computes each one once.

- **Fibonacci:** `F(n) = F(n-1) + F(n-2)`, with `F(0) = 0` and `F(1) = 1`.
- **Climbing Stairs:** `ways(n) = ways(n-1) + ways(n-2)`, with `ways(0) = 1` and `ways(1) = 1`, when a move is 1 or 2 stairs.

The base cases differ, so the values are shifted by one: `ways(n) = F(n + 1)`. With a set of allowed steps, `climbing_stairs_variable_steps` sums over every step size that fits, so the recurrence has k terms.

## Applications

- **Teaching the method.** Every DP topic reuses the idea of a state, a transition and a base case.
- **Counting paths.** Climbing Stairs counts ordered sequences of moves, for example walks along a line with allowed jumps.
- **Fast linear recurrences.** Matrix power generalizes to any recurrence with a fixed number of earlier terms.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Leaving out the table.** Without it both problems take O(2^n) time.
- **Mixing up the base cases.** `F(0) = 0` but `ways(0) = 1`, one way to climb no stairs. That is why the tables are shifted.
- **Overflow in C++ and Go.** Both return 64-bit integers, so `F(n)` is exact only up to `F(92)` and `ways(92)` overflows. Python integers do not overflow.
- **Treating the count as a set of routes.** Climbing Stairs counts ordered sequences, so `1 + 2` and `2 + 1` are two different ways.
- **Passing a negative `n`.** The Climbing Stairs functions raise `ValueError` for it.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which topic should I read first?">
    Fibonacci. It introduces the table and the cost of recomputation. Climbing Stairs then shows the same recurrence applied to counting.
  </FaqItem>
  <FaqItem question="Why does Climbing Stairs equal Fibonacci?">
    The last move was a 1-step or a 2-step, so `ways(n)` adds the ways to reach `n-1` and `n-2`. That is the Fibonacci recurrence with different starting values.
  </FaqItem>
  <FaqItem question="Is a table needed, or are two variables enough?">
    Two variables are enough when each value depends only on the last two. A table is needed when a value reads further back, as in Climbing Stairs with a list of step sizes, or when you want to keep every entry.
  </FaqItem>
  <FaqItem question="Where does this lead?">
    To Linear DP, where an entry chooses among several earlier entries. Coin Change has the same shape as Climbing Stairs, with a minimum or a count taken over the coins.
  </FaqItem>
</Faq>
