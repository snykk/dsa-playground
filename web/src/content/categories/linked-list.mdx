## The problem

An array keeps items next to each other, so reading index `i` is fast and inserting in the middle is slow. A linked list makes the opposite trade. Each item sits in its own node together with a reference to another node, so inserting or removing a node changes a few links and moves nothing. The price is that there is no index arithmetic: to reach the i-th item you start at the head and follow i links.

The versions in this repository keep only a head pointer, with no tail pointer and no stored length. That is why inserting at the tail walks the whole list.

What separates the four kinds is the shape of the links:

- **Singly:** one link per node, forward only.
- **Doubly:** a forward and a backward link per node.
- **Circular:** a singly linked list whose last node points to the head.
- **Skip list:** a sorted list with extra forward links on some nodes, so a search can skip ahead.

The circular list is O(n) at the head because it must update the tail's link, and the code finds the tail by walking from the head. The skip list inserts a key at its sorted position, so it has no head or tail insert.

## Applications

- **Stacks and queues.** A head pointer is a stack, and a list with two ends is a queue.
- **Least-recently-used caches.** A doubly linked list moves an entry to the front in O(1).
- **Round-robin scheduling.** A circular list cycles through tasks.
- **Ordered sets in databases.** Skip lists give sorted access without a balanced tree.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Losing the rest of the list.** Set the new node's `next` before you change the old links, or the tail of the list is unreachable.
- **Forgetting the head when deleting it.** Deleting the first node must move `head`. In the circular list the tail's link changes too.
- **Looping forever on a circular list.** There is no null end, so stop when you are back at the head.
- **Assuming insert at the tail is O(1).** These lists keep no tail pointer, so it walks all n nodes.
- **Expecting a guaranteed bound from the skip list.** O(log n) is expected, not worst case. The skip list also does not store duplicate keys.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Start with the singly linked list: the others change its links. Then the doubly and circular lists, in either order. Read the skip list last, because it adds randomness and levels on top of a sorted singly linked list.
  </FaqItem>
  <FaqItem question="Why is insertion at the tail O(n) here?">
    The code keeps only a head pointer, so it walks to the last node first. A version that stores a tail pointer would make a singly or doubly linked tail insert O(1).
  </FaqItem>
  <FaqItem question="Are linked lists faster than arrays?">
    For inserting at a known place, yes, since nothing shifts. For reading and scanning, usually not: nodes are scattered in memory and every step follows a pointer, while an array is contiguous and cache-friendly.
  </FaqItem>
  <FaqItem question="What does the skip list add?">
    Plain linked lists search in O(n). The skip list adds sparser lists above the bottom one, so a search skips many nodes at once and takes expected O(log n) time, like a balanced tree but with coin flips instead of rotations.
  </FaqItem>
</Faq>
