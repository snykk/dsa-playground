## The problem

Some computations look like they need `k` steps or `n^2` multiplications, and some counts are far too large to list. The topics here avoid both, and Gaussian elimination solves the linear systems that come up beside them.

- **Combinatorics** counts choices with the binomial coefficient `C(n, k)`: Pascal's triangle with additions only, the multiplicative formula exactly, and factorial tables modulo a prime for `C(n, k) mod p` in O(1) after O(n) work. Catalan numbers, stars and bars and derangements build on it.
- **Matrix exponentiation** computes `A^k` for a square matrix `A`. A linear recurrence such as Fibonacci becomes one matrix power, so the `k`-th term takes O(log k) multiplications of small matrices instead of `k` additions.
- **Gaussian elimination** solves `A x = b`, n equations in m unknowns, by subtracting multiples of rows until `[A | b]` is a staircase, then reading the unknowns from the bottom up. It reports no solution, one, or infinitely many, and gives the rank and the determinant on the way. In floating point it picks the largest entry of each column as the pivot; modulo a prime it divides with modular inverses and is exact.
- **The Fast Fourier Transform** computes the discrete Fourier transform of `n` values in O(n log n). Its best-known use in programming is multiplying two polynomials, or convolving two sequences, in O(n log n) instead of O(n^2).
- **The Number Theoretic Transform** runs the same butterflies with the integers modulo the prime 998244353, whose powers of 3 give the roots of unity, so the product comes out exact modulo that prime.

Combinatorics, matrix exponentiation and the NTT are exact integer arithmetic, the FFT is floating point, and Gaussian elimination comes in both versions; that difference decides where each one fits.

## Applications

- **Counting modulo a prime.** Subsets, grid paths, distributions of identical items, Catalan structures and derangements, modulo 10<sup>9</sup> + 7.
- **Fast recurrences.** Fibonacci modulo `m`, counting walks in a graph, and linear recurrences in contests.
- **Big-number multiplication.** Large integers are polynomials in their digits.
- **Signal processing.** The transform moves a signal between time and frequency.
- **String and counting problems.** Matching with wildcards and counting sums as convolutions.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Skipping the modulus.** Without one, matrix entries and Fibonacci numbers overflow 64 bits quickly. The C++ `fibonacciMatrix` and Go `FibonacciMatrix` refuse n above 92 without a modulus, but the matrix power itself does not check.
- **Passing a non-square matrix.** The power is only defined for a square matrix.
- **Trusting the FFT for exact big integers.** The result is rounded from doubles. Past coefficients of about 2^53 it is wrong.
- **Expecting the NTT's integers above the prime.** It is exact only modulo 998244353: a larger coefficient comes out reduced.
- **Inverting a length that is not a power of two.** The forward transform pads with zeros to the next power of two, so its result is longer than the input. The inverse refuses other lengths: Python raises `ValueError`.
- **Building factorial tables with n >= p.** From n = p on, n! is 0 modulo p and has no inverse; Lucas's theorem takes over there.
- **Eliminating without pivoting in floating point.** A pivot of 1e-8 passes the tolerance and still turns the answer 3 into 4.47; take the largest entry of each column.
- **Reaching for either on a small input.** The plain loop or the direct product is faster and simpler there.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which one should I read first?">
    Combinatorics, then matrix exponentiation. Combinatorics needs only modular arithmetic and one modular inverse; matrix exponentiation builds directly on modular exponentiation, which uses the same square and multiply idea. Gaussian elimination comes next: its exact version needs only the modular inverse. The FFT needs divide and conquer and an understanding of complex numbers, and the NTT comes after the FFT, whose butterflies it reuses.
  </FaqItem>
  <FaqItem question="Why is Fibonacci a matrix power?">
    The pair of consecutive terms is multiplied by the same 2 x 2 matrix at every step, so the k-th pair is that matrix to the power k applied to the first pair. Squaring computes that power in O(log k) multiplications.
  </FaqItem>
  <FaqItem question="Why is the FFT not exact?">
    It works with complex numbers stored as doubles, so every operation rounds. The product of small integer polynomials is recovered by rounding back, which is correct only while the true coefficients stay below about 2^53.
  </FaqItem>
  <FaqItem question="How do they relate?">
    All are divide and conquer on structure. Matrix exponentiation halves the exponent, and the FFT halves the number of points. In counting problems the NTT replaces the complex numbers with arithmetic modulo a prime, so the result is exact modulo that prime.
  </FaqItem>
</Faq>
