## The problem

Given n points in the plane, these algorithms answer global questions. What is the outer boundary? How wide is the set? Which two points are closest? A check of all pairs costs O(n^2). Each topic here finds the answer faster by using the geometry.

The convex hull and rotating calipers belong together. The hull is the input that rotating calipers needs. Closest Pair is independent and uses divide and conquer, as in Merge Sort.

What the code does with awkward input:

- **Exact arithmetic.** The hull and the calipers compare cross products with exact zero. They use no tolerance, so integer input is handled exactly. The C++ and Go versions are exact while the cross products stay below 2^53.
- **Collinear points.** Both hull functions pop on `cross <= 0`, so points lying on a hull edge are not in the output. If all points are collinear, the result is the two end points.
- **Duplicates.** The hull removes equal points first. Closest Pair accepts duplicates and returns distance 0 for them.
- **Few points.** Fewer than three distinct points are returned as they are by the hull. Closest Pair raises `ValueError` for fewer than two points.
- **Orientation of the polygon.** The hull is counterclockwise. Graham's scan starts at the bottom-most point and Jarvis march at the leftmost point. Rotating calipers accepts either orientation.

## Applications

- **Collision detection.** A convex hull is a simple bound for a shape.
- **Geographic information systems.** The outline of a region, the farthest two sites and the nearest pair of facilities.
- **Computer graphics.** Bounding polygons and the width of a shape in a direction.
- **Clustering and air traffic.** Closest pair finds the pair most at risk of collision.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **A tolerance on angles or cross products.** An angle sort with an epsilon is not a consistent ordering and can leave interior points on the hull. These codes compare exactly.
- **Popping only on right turns.** Pop on `cross <= 0`. Popping on `< 0` keeps collinear points on the boundary.
- **Feeding calipers a point set.** The input must be the vertices of a convex polygon in order. Compute the hull first.
- **Moving the calipers pointer by distance.** It can stop at a local maximum. Drive it by triangle area.
- **Splitting the y-sorted list by x value in Closest Pair.** Repeated x values go to the wrong half. Split by membership.
- **Ignoring duplicates.** Equal points make a zero-length hull edge, and two copies of a point are a closest pair at distance 0.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Convex Hull first, then Rotating Calipers, which needs the hull. Closest Pair of Points is independent. Take it last, or after Merge Sort if divide and conquer is new to you.
  </FaqItem>
  <FaqItem question="Why are collinear boundary points left out of the hull?">
    A point on an edge is not a corner. Both functions remove it so the result has only true vertices. If your problem needs points on the boundary, you need a variant that pops on `< 0` only.
  </FaqItem>
  <FaqItem question="Which hull algorithm should I use?">
    Graham's scan, unless you expect a hull with only a handful of vertices. Jarvis march wins only when h is small. When every point is on the hull it takes O(n^2).
  </FaqItem>
  <FaqItem question="Does the order of the hull matter for calipers?">
    No. The diameter and width code accepts a clockwise or counterclockwise polygon, and it removes repeated and collinear vertices before it starts.
  </FaqItem>
</Faq>
