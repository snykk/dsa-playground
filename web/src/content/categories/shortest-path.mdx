## The problem

Given a weighted graph, find the path between two vertices whose edge weights add up to the smallest total. Variants ask for one source to every vertex, or for every pair.

BFS solves this when every edge costs the same. Once weights differ, the path with the fewest edges is no longer the cheapest, and these four algorithms take over. Each one keeps a distance estimate for every vertex and lowers it by **relaxing** an edge: if `dist[u] + w < dist[v]`, then `dist[v]` becomes `dist[u] + w`. They differ in which edges they relax and in what order.

A negative cycle, one whose weights sum below zero, makes the cheapest path undefined, because every lap makes it cheaper. Bellman-Ford and Floyd-Warshall report it. In Python both return `None`.

Vertex 1 shows why the cheapest route is not the direct one. The edge `0->1` costs 4, but going through vertex 2 costs 1 + 2 = 3. In the full Floyd-Warshall matrix, vertices that cannot reach each other hold a very large number (`sys.maxsize` in Python). Vertex 0 can reach every vertex, but no vertex can reach it, so column 0 holds that value everywhere except on the diagonal.

When one edge is negative, the picture changes. Take `0->1 4`, `0->2 5` and `2->1 -3`:

    ['Bellman-Ford from 0', '2', '5'],

Dijkstra settles vertex 1 at distance 4 before it ever looks at vertex 2, and it never revisits a settled vertex. The cheaper route `0 -> 2 -> 1` costs 5 - 3 = 2. Dijkstra does not raise an error; it returns the wrong number.

## Complexity

<DataTable
  columns={['Algorithm', { label: 'Time', kind: 'mono' }, { label: 'Extra space', kind: 'mono' }, 'Notes']}
  rows={[
    ['Dijkstra', 'O((V + E) log V)', 'O(V + E)', 'binary heap with lazy deletion; the heap can hold one entry per edge'],
    ['Bellman-Ford', 'O(V * E)', 'O(V)', 'V - 1 rounds over all E edges, plus one check round'],
    ['Floyd-Warshall', 'O(V^3)', 'O(V^2)', 'three nested loops over a distance matrix'],
    ['A*', 'O(b^d)', 'depends on the open set', 'worst case with a useless heuristic; with h = 0 it behaves as Dijkstra'],
  ]}
/>

To get all pairs, you can also run Dijkstra from every vertex. That costs V times the single-source time, which beats O(V^3) on a sparse graph with non-negative weights.

## Choosing one

<DataTable
  columns={['Situation', 'Use', 'Why']}
  rows={[
    ['One source, non-negative weights', 'Dijkstra', 'the fastest of the general methods here'],
    ['Negative edges, or you must detect a negative cycle', 'Bellman-Ford', 'it does not assume that settled vertices are final'],
    ['Distances between all pairs on a small graph', 'Floyd-Warshall', 'three short loops, handles negative edges, one table'],
    ['One goal and a good distance estimate, such as a map or a grid', 'A*', 'the heuristic prunes vertices that point away from the goal'],
    ['Every edge costs the same', 'BFS', 'no priority queue needed, and it runs in O(V + E)'],

## Applications

- **Navigation.** Road routing with Dijkstra or A*, and pathfinding on game maps with A*.
- **Network routing.** Link-state protocols compute shortest paths with Dijkstra. Distance-vector protocols are close to Bellman-Ford.
- **Currency and arbitrage.** A negative cycle on log-prices is an arbitrage loop, which Bellman-Ford can detect.
- **Precomputed distance tables.** Floyd-Warshall on a small graph, for fast lookups of any pair.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using Dijkstra with a negative edge.** There is no error, only a wrong answer, as in the example above.
- **Using BFS on weighted edges.** It minimises the number of edges, not the cost.
- **Ignoring negative cycles.** If a negative cycle is reachable, no shortest path exists. Bellman-Ford and Floyd-Warshall return `None` in Python, and the others do not check.
- **Treating `inf` as a number to add to.** An unreachable distance plus a weight must stay unreachable. Check for it before relaxing.
- **An overestimating heuristic in A*.** If h is larger than the true remaining cost, A* can return a path that is not the cheapest.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="What should I read first?">
    Dijkstra's algorithm. The other three each change one of its assumptions: Bellman-Ford drops the ban on negative edges, Floyd-Warshall computes every pair, and A* adds a heuristic to the priority.
  </FaqItem>
  <FaqItem question="Is A* always faster than Dijkstra?">
    No. It expands fewer vertices only when the heuristic is informative. With h = 0 it is Dijkstra, and with a poor estimate it does as much work. It also answers one goal only, while Dijkstra gives distances to every vertex.
  </FaqItem>
  <FaqItem question="Why does Dijkstra fail on negative edges?">
    It treats a vertex as final the moment it is settled, which is only safe when no later path can be cheaper. A negative edge can make a later path cheaper, so a settled distance can be too high.
  </FaqItem>
  <FaqItem question="Can I get the path as well as the distance?">
    Yes. The repository has path-returning versions: `dijkstra_with_path` and `bellman_ford_with_path` return the distance and the vertex list, and Floyd-Warshall has `floyd_warshall_path` with a `reconstruct_path` helper.
  </FaqItem>
</Faq>
