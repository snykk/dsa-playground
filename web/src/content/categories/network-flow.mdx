## The problem

A flow network is a directed graph in which every edge has a capacity, plus a source `s` and a sink `t`. A flow assigns an amount to each edge so that no edge exceeds its capacity and every other vertex passes on exactly what it receives. The task is to find the largest total amount that leaves the source.

All three algorithms keep a **residual graph**. An edge `u -> v` with capacity `c` and flow `f` leaves `c - f` of spare room forward, and a backward edge `v -> u` of size `f` that lets later steps cancel earlier flow. They repeat three steps:

1. Find a path from `s` to `t` in the residual graph with spare capacity on every edge.
2. Push the smallest spare capacity on that path, the bottleneck, along it.
3. Stop when no such path exists. The flow is then maximum.

Dinic groups these rounds into phases: one BFS sorts the vertices into levels, and then every path it pushes in that phase is a shortest one, found by DFS without another BFS.

The max-flow min-cut theorem proves that the result is optimal: the maximum flow equals the capacity of the cheapest cut that separates `s` from `t`.

Edmonds-Karp needs 3 rounds and Ford-Fulkerson needs 6, but both stop at 23. Dinic takes Edmonds-Karp's three paths, but the first two share one BFS, so it runs 3 BFS where Edmonds-Karp runs 4. The DFS wanders along long paths with small bottlenecks, while BFS takes the shortest route first. Round 3 of Ford-Fulkerson takes five edges, `0 -> 1 -> 3 -> 2 -> 4 -> 5`, although `0 -> 1 -> 3 -> 5` has only three and still had spare capacity.

The minimum cut agrees. `min_cut` in the Ford-Fulkerson code returns 23 with the source side `0, 1, 2, 4` and the sink side `3, 5`. The three edges that cross it, `1->3` (12), `4->3` (7) and `4->5` (4), add up to 23.

On a diamond network with capacities of 1000 and a cross edge of 1, an unlucky Ford-Fulkerson can take 2000 rounds where Edmonds-Karp needs 2. The repository's DFS takes 4 rounds on that network when the cross edge is written before `1->3`, and 2 otherwise, but nothing in the method rules out the bad order.

Push-relabel algorithms, which move flow vertex by vertex instead of along paths, are not in this repository.

## Applications

- **Capacity planning.** The most data, traffic or goods that a network can carry.
- **Bipartite matching.** Assign jobs to workers by giving every edge capacity 1.
- **Minimum cuts.** The cheapest set of edges to remove to separate two parts of a network.
- **Project selection and scheduling.** Many assignment problems reduce to a flow.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Skipping the backward edges.** Without them the algorithm can get stuck below the maximum, because it cannot undo a bad early choice.
- **Using Ford-Fulkerson with huge capacities.** The running time depends on the flow value, so it can be very slow.
- **Using non-integer capacities with Ford-Fulkerson.** With irrational capacities a careless path choice may never terminate.
- **Expecting per-edge flows from Edmonds-Karp.** It returns only the total flow value here; Dinic's `dinic_flow` returns the flow on each edge.
- **Adding flow in both directions of an undirected edge.** Model an undirected edge as two directed edges, each with the capacity.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which one should I read first?">
    Ford-Fulkerson. It defines the residual graph and the augmenting step. Edmonds-Karp then changes only the path search, and Dinic groups the shortest paths into phases.
  </FaqItem>
  <FaqItem question="Why does using BFS make it polynomial?">
    With shortest augmenting paths, the distance from the source to any vertex in the residual graph never decreases, and every augmentation saturates at least one edge on a shortest path. That limits the number of rounds to O(V E), and each costs one BFS.
  </FaqItem>
  <FaqItem question="What is a minimum cut?">
    A split of the vertices into a source side and a sink side with the smallest total capacity of edges leaving the source side. The max-flow min-cut theorem says its capacity equals the maximum flow.
  </FaqItem>
  <FaqItem question="Do they always find the same flow on each edge?">
    No. They always find the same total, but the flow on each edge can differ, because the choice of augmenting paths differs. Edmonds-Karp in this repository returns the total only; Dinic returns the flows, fixed by trying every vertex's edges in increasing order of the neighbour.
  </FaqItem>
</Faq>
