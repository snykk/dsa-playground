## The problem

In a linear structure every item has a place in a line: a first item, a next item and a last item. What differs is how the line is stored and which positions you may touch.

- **How it is stored.** Contiguous in one block (array), or scattered in nodes joined by links (linked list).
- **Which positions you may touch.** Any index (array), the top only (stack), the two ends with a rule (queue, deque), or every character in order (string).

Storage decides the cost of each operation. A contiguous block gives O(1) access and an O(n) middle insert, and linked nodes give the reverse. Stack, queue and string are the same two layouts with a restricted or specialised interface.

Memory differs as well. The array has no per-item overhead and is cache-friendly. A linked list adds at least one pointer and one allocation to every item. A ring queue and a static stack fix their size when they are created.

## A path through the section

1. **Array.** Start here. Index access, resizing and the cost of shifting explain most of what follows.
2. **Linked list.** The opposite trade: cheap inserts, slow access. Read the singly list first.
3. **Stack.** One end, last in first out. It shows how the same behaviour can sit on an array or on nodes.
4. **Queue.** Two ends and a rule. The simple queue exposes the shifting cost and the circular queue, deque and priority queue each answer it.
5. **String.** An array of characters with traps of its own, and the rope for long text.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Inserting in the middle of an array in a loop.** Each insert is O(n), so n inserts are O(n^2).
- **Counting a linked list as fast for access.** Reaching index `i` follows `i` links.
- **Expecting O(1) dequeue from every queue.** The plain array queue shifts its items in Python and C++.
- **Treating strings as mutable.** In Python and Go every edit builds a new string.
- **Popping or peeking when empty.** The stack and queue raise an error, so check `is_empty()` first.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Are stacks and queues separate structures from arrays and lists?">
    They are interfaces. A stack or queue says which operations are allowed and in what order items leave, and an array, a ring or a linked list supplies the storage. This repository shows the same stack on an array and on nodes for that reason.
  </FaqItem>
  <FaqItem question="Array or linked list?">
    Choose the array unless you mostly insert or remove at a known place, such as the head. Contiguous memory makes scans fast, and in practice that often outweighs the cost of an occasional shift.
  </FaqItem>
  <FaqItem question="Where does hashing fit?">
    A hash table is an array of buckets that are themselves lists. It adds a hash function to turn a key into an index, which gives O(1) average lookup by key. It has its own section.
  </FaqItem>
  <FaqItem question="Why is the string in this section?">
    A string is an array of characters, so it inherits the array's costs, plus rules about immutability and about what counts as a character. The rope is its answer to editing long text.
  </FaqItem>
</Faq>
