## The problem

Given a list of `n` items that can be ordered, rearrange it so that every item is no larger than the next. Sorting is a building block: binary search, merging, deduplication and many greedy algorithms start with a sorted list.

The ten algorithms in this section solve this one problem. Nine of them split into three families, and Shell Sort sits between the first two:

- **Quadratic sorts** (Bubble, Insertion, Selection) compare neighbours or scan for a minimum. They are short and need O(1) extra space.
- **Shell Sort** runs Insertion Sort over shrinking gaps, so far-apart elements move in long jumps first. It is as short and as frugal as the quadratic sorts and much faster in practice, but how fast depends on the gap sequence, and the best one known has no proven bound.
- **Comparison sorts that scale** (Merge, Quick, Heap) use a different structure to reach O(n log n): halving, partitioning or a heap.
- **Sorts that place keys by value** (Counting, Radix, Bucket) use the value of a key as an index or a bucket number; Bucket Sort compares keys only inside a bucket. They beat the `n log n` bound for comparison sorts, but only on integers or numbers in a known range.

Three properties tell the algorithms apart besides speed:

- **Stable** means equal keys keep their original order. It matters when you sort records by one field after another.
- **In place** means the sort needs no second array of size `n`.
- **Adaptive** means the sort is faster on input that is already nearly sorted.

Counting, Radix and Bucket Sort are not comparison sorts, so the `n log n` bound does not apply to them. Their cost depends on the range of the keys (`k`), the number of digits (`d`) or how the values spread. Bucket Sort's worst case is a Python figure: it needs every value in one bucket and insertion-sorted buckets. C++ and Go sort the buckets with a library sort.

## The same input through seven sorts

The seven comparison sorts were run from the repository's Python code on four lists of eight numbers (`7 3 9 1 5 8 2 6`, the same sorted, the same reversed, and eight 4s), with the elements wrapped so that every `<`, `>` and `<=` is counted. Insertion Sort and Bubble Sort adapt to the input, Selection Sort does not look at it, and Quick Sort pays for sorted input.

Read the columns:

- **Sorted:** Bubble and Insertion Sort make `n - 1 = 7` comparisons. Quick Sort makes `n(n - 1)/2 = 28`, the same as Selection Sort, because the last element is always the largest and each partition removes only the pivot.
- **Sorted and all equal:** Shell Sort uses the gaps 4 and 1 on eight values and makes one comparison per element per pass, `(8 - 4) + (8 - 1) = 11`, with no move.
- **Reversed:** Bubble, Insertion and Selection Sort all reach 28 comparisons, the n(n - 1)/2 of the quadratic family. Shell Sort's gap-4 pass first swaps four far-apart pairs, so it needs 20. Merge Sort stays at 12.
- **All equal:** the strict comparisons mean that nothing moves, apart from Heap Sort swapping the root to the end in every round. Bubble and Insertion Sort finish in 7 comparisons, and Heap Sort needs only 18, but Quick Sort still makes 28 with this partition.

Stability shows when keys repeat. Sort these six records by their number only: `3a 1b 3c 2d 1e 3f`.

The three stable sorts keep `3a 3c 3f` in input order. Selection Sort's long-distance swap and Quick Sort's partition swaps put `3c` before `3a`, and Heap Sort scrambles the three. Shell Sort's gap-4 pass swaps `3a` and `1e`, which puts `1e` before `1b` and `3a` after `3c`. Counting and Radix Sort are stable by construction, but they sort bare integers, so this check does not apply to them.

Notes on the table:

- Bubble and Insertion Sort reach O(n) only on sorted input. Heap Sort's best case is O(n) when all elements are equal, and otherwise O(n log n).
- Shell Sort's bounds depend on the gaps: Theta(n^2) in the worst case with Shell's own n/2, n/4, ..., 1, O(n^(3/2)) with Knuth's, and no proven bound with Ciura's, the default, which made the fewest comparisons of the three on every random input measured. Its best case, sorted input, is one comparison per element per pass: O(n log n).
- Quick Sort's O(log n) space holds in Python, which recurses into the smaller side and loops on the larger one. The C++ and Go versions make two recursive calls, so their stack reaches O(n) on sorted input.
- Heap Sort keeps its heap in the array. The O(log n) is the stack of the recursive `heapify`, which a loop would reduce to O(1).
- Bucket Sort's O(n^2) assumes Python's insertion-sorted buckets. Only the insertion-sort version here is stable. The C++ and Go versions use unstable library sorts.
- `k` is the size of the value range for Counting Sort (`max - min + 1`) and the number of buckets for Bucket Sort. `d` is the number of digits and `b` the base (10 here) for Radix Sort.

## Applications

- **Preparing for other algorithms.** Binary search, two pointers, merging and interval problems all need sorted input.
- **Databases and reports.** Ordering rows by one or more columns, where stability keeps earlier orderings intact.
- **Duplicate detection.** After sorting, equal values sit next to each other.
- **Greedy algorithms.** Activity Selection sorts by finish time, and Fractional Knapsack sorts by value per unit of weight.
- **Fixed-width keys.** Counting and Radix Sort handle ids, ages, scores and other integers in linear time.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Using Quick Sort with the last element as pivot on sorted data.** Sorted, reversed and all-equal input all give O(n^2) here. Pick the pivot at random or take the median of three.
- **Assuming Quick Sort or Heap Sort is stable.** Neither is, and Selection Sort and Shell Sort are not either. Use Merge Sort or a stable library sort when equal keys must keep their order.
- **Calling Merge Sort in place.** Its temporary halves cost O(n) extra memory.
- **Using Counting Sort on a huge range.** Time and memory grow with `k = max - min + 1`, so a few huge values make it unusable. Use Radix Sort or a comparison sort.
- **Feeding Bucket Sort values outside the range.** The Python version here expects `0.0 <= x <= 1.0` and raises `ValueError` for anything else.
- **Using an unstable digit sort inside Radix Sort.** It scrambles the work of the earlier digits and gives a wrong result.
- **Comparing algorithms by their big-O alone.** Constants and memory behaviour matter: Insertion Sort beats Merge Sort on small arrays, and Quick Sort usually beats Heap Sort at the same O(n log n).
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Start with Bubble, Insertion and Selection Sort: they teach comparisons, swaps, invariants and stability. Shell Sort comes right after Insertion Sort, because every one of its passes is an insertion sort with a stride. Then Merge Sort and Quick Sort, which add recursion and divide and conquer, and Heap Sort, which needs the heap. Last come Counting, Radix and Bucket Sort. Radix Sort uses Counting Sort as its digit sort, so read Counting Sort first.
  </FaqItem>
  <FaqItem question="Why can a comparison sort not beat n log n?">
    A comparison sort learns about the order only through yes-or-no answers. There are `n!` possible orders, so it needs at least about `log2(n!)` answers, which is about `n log n`. Counting, Radix and Bucket Sort avoid the bound because they place each key by reading its value, not by comparing it with other keys; Bucket Sort compares keys only inside its small buckets.
  </FaqItem>
  <FaqItem question="What is a stable sort and why does it matter?">
    A stable sort keeps equal keys in their input order. Sort people by city and then by last name, and a stable second sort keeps each last name's people in city order. It is also what lets Radix Sort chain one digit pass after another.
  </FaqItem>
  <FaqItem question="Which one do standard libraries use?">
    Tuned hybrids rather than one textbook algorithm. Quick Sort variants are common, and they switch to Insertion Sort for tiny ranges and to Heap Sort when the recursion gets too deep. Python's `sorted` uses Timsort, which mixes Merge Sort and Insertion Sort and is stable.
  </FaqItem>
  <FaqItem question="Which sort is fastest?">
    It depends on the input. Quick Sort is usually the fastest comparison sort in memory. Insertion Sort wins on tiny or nearly sorted arrays, and Counting or Radix Sort wins on integers when the range or the digit count is small. Merge Sort and Heap Sort are the ones with a guaranteed O(n log n).
  </FaqItem>
</Faq>
