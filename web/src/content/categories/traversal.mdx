## The problem

Given a graph and a start vertex, visit every vertex reachable from the start exactly once. Both algorithms keep a set of visited vertices and a collection of discovered but unexpanded vertices. They take one vertex from the collection, visit its unvisited neighbours and repeat.

The only difference is the collection. A queue hands back the oldest vertex, which makes the search spread outwards in rings. A stack, or the call stack in recursion, hands back the newest vertex, which makes the search run down one branch before it tries another.

Each vertex and each edge is handled a constant number of times, so the cost is O(V + E) with an adjacency list.

## Applications

- **Shortest hops.** Routing in an unweighted network, word ladders, grid mazes.
- **Reachability and components.** Flood fill, counting islands, finding connected groups.
- **Dependency order.** Build systems and course schedules, through DFS or Kahn's algorithm.
- **Structure.** Cycle detection, bipartite checks, bridges and strongly connected components.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Marking a vertex as visited too late in BFS.** Mark it when you enqueue it, not when you dequeue it, or the same vertex enters the queue many times.
- **Expecting DFS to find the shortest path.** It finds a path. In the example above it needs five edges where BFS needs three.
- **Starting from one vertex only.** A search covers one component. For a disconnected graph, loop over all vertices and start a new search from each unvisited one.
- **Recursing on a deep graph.** A path graph with a hundred thousand vertices can overflow the call stack, so use an explicit stack.
- **Using either one for weighted shortest paths.** Neither looks at weights.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Which one should I learn first?">
    BFS. It is the simpler picture, a queue and rings, and it leads straight into Dijkstra's algorithm. Learn DFS next, because strongly connected components, bridges and topological sort all build on it.
  </FaqItem>
  <FaqItem question="Do they visit vertices in the same order?">
    Not in general. They visit the same set of vertices but in different orders. Both also depend on the order of each adjacency list, so the same graph stored with its neighbours in another order gives another visit order.
  </FaqItem>
  <FaqItem question="Which one uses more memory?">
    On a wide graph BFS holds a whole ring in its queue. On a long, thin graph recursive DFS holds a deep call stack. Both are O(V) in the worst case.
  </FaqItem>
  <FaqItem question="Can DFS be written without recursion?">
    Yes. Use an explicit stack. The repository has both an iterative version, `dfs_adjacency_list`, and a recursive one, `dfs_recursive`, and on the example graph above they give the same order.
  </FaqItem>
</Faq>
