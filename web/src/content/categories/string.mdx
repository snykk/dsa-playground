## The problem

A string is stored like an array of characters, so reading character `i` and asking for the length are O(1). Three things make strings different from a plain array of numbers:

- **Immutability.** Python and Go strings cannot be changed in place, so every edit builds a new string. C++ `std::string` is mutable.
- **What a character is.** Python counts code points. C++ and Go count bytes, so `len` and indexing differ on non-ASCII text.
- **The cost of long text.** Editing the middle of a very long string copies everything after the edit.

The first two topics deal with the first two points on flat strings. The rope answers the third.

## One edit, two ways

Take `Hello, World`, insert ` there` at position 5, then delete the first 7 characters. These results come from running the Python code.

For 12 characters the difference does not matter. It does for a text of millions of characters, where each flat edit copies everything and each rope edit touches only a path of about log n nodes. The price is that `index(i)` follows that path too, so it is O(log n) where a flat string is O(1).

## Applications

- **Text editors.** A rope is the classic buffer for large files with many edits.
- **Parsing and validation.** Splitting, counting and checking palindromes are everyday tasks.
- **Pattern matching and bioinformatics.** Searching text is the next step, in the Pattern Matching algorithms.
- **Interview problems.** The two-pointer idea behind reverse and palindrome carries over to many of them.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Mixing bytes and characters.** Python indexes code points. C++ and Go index bytes, so a cut can land inside a character.
- **Concatenating in a loop in Python or Go.** Each step builds a new string, so n steps cost O(n^2) in total. Collect the parts and join once.
- **Assuming the palindrome check ignores case and punctuation.** `is_palindrome("A man, a plan, a canal: Panama")` is `False`, because it compares the string with its reverse exactly.
- **Treating a rope as a faster string.** Indexing is O(log n) and reading it back is O(n). It wins only when edits dominate.
- **Expecting a substring to be free.** It copies in Python and C++, and only Go slices in O(1).
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    String basics first, since it explains immutability and the byte versus character question. Then string manipulation, which uses those operations in passes. The rope comes last, because it needs a balanced binary tree as background.
  </FaqItem>
  <FaqItem question="Why are strings immutable in Python and Go?">
    A string that cannot change can be shared safely and used as a dictionary key. The cost is that every edit makes a new string.
  </FaqItem>
  <FaqItem question="When is a rope worth it?">
    When the text is long and you edit it often in the middle. For short strings, or when you mostly read, a flat string is simpler and faster.
  </FaqItem>
  <FaqItem question="Where do I go to search inside a string?">
    To the Pattern Matching algorithms, which find every place a pattern occurs. This section only covers how a string is stored and edited.
  </FaqItem>
