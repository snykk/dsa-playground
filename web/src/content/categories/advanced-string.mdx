## The problem

Pattern Matching finds one pattern in one text. The topics here keep the same alphabet of characters but change the question:

- **Prefix matches.** For each position of a string, how far does it agree with the start of the string? The Z-algorithm answers this for all positions in O(n), and a search falls out of it.
- **Many patterns.** Aho-Corasick searches a whole dictionary in one pass.
- **Many queries.** The suffix array sorts every suffix once so that each later query is a binary search.
- **Structure inside strings.** Manacher finds the longest palindrome, and a table finds the longest block that two strings share.

Every topic returns exact answers, and every search reports overlapping matches.

## Applications

- **Malware and intrusion scanning.** Aho-Corasick checks traffic or files against thousands of signatures in one pass.
- **Search indexes.** Suffix arrays answer substring queries over a fixed document set.
- **Bioinformatics.** Shared substrings between sequences, and motifs inside a genome.
- **Text tools.** Palindrome detection, plagiarism checks and diff-like comparison.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Testing `Z == m` in a Z-search.** The search runs on `pattern + "$" + text`. If `$` also occurs in the input, a Z-value can run past the separator and exceed `m`, so the test must be `Z >= m`, as the code here does.
- **Reading Aho-Corasick positions as start indices.** The search returns the index where each match ends.
- **Expecting every longest answer.** Manacher and the longest common substring return one longest result, not all of them.
- **Using a suffix array on changing text.** It is a static structure, so each edit means a rebuild.
- **Confusing substring with subsequence.** Both the palindrome and the common-substring problems here require contiguous characters.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="Z-algorithm or KMP?">
    Both are linear. KMP builds a table over the pattern only and streams the text in O(m) space. The Z-algorithm builds one array over pattern, separator and text, so it uses O(n + m) space, but the array is easier to define and use.
  </FaqItem>
  <FaqItem question="Why is the suffix array build so slow here?">
    The repository sorts a copy of every suffix, which costs O(n^2 log n) time and O(n^2) space in Python and C++. Prefix doubling is faster, but it is described in the article and not implemented.
  </FaqItem>
  <FaqItem question="What is the relation between Aho-Corasick and KMP?">
    Aho-Corasick applies KMP's fall-back idea to a trie. The failure link of a node plays the role of the LPS value, and the build is amortized in the same way.
  </FaqItem>
  <FaqItem question="Which of these should I read first?">
    The Z-algorithm and Manacher need only Pattern Matching. Aho-Corasick builds on KMP and a trie, and the suffix array reads best after you know a linear search. The longest common substring needs the dynamic-programming basics.
  </FaqItem>
</Faq>
