## The problem

Most problems ask you to compute a value from the input. These three do not, and a data structure or a search is the wrong first thought.

- **Constructive problems** ask for an object: a permutation, an array, a string or a graph that satisfies a list of constraints. You also have to say when no such object exists. You find a rule that satisfies the constraints by design and prove it.
- **Interactive problems** hide the input. Your program sends queries to a judge, reads the answers and must find the hidden value within a query budget. The format is part of the problem.
- **Game problems** ask who wins when both players play perfectly. For impartial games the answer comes from a formula, not from searching the game tree.

## Applications

- **Contest problems** with a special judge, which accepts any valid answer.
- **Testing and verification,** where a builder pairs with a cheap checker for randomised tests.
- **Search under a budget,** which any system with an expensive oracle shares.
- **Game solvers,** for Nim-like puzzles and combinatorial games.

## Common mistakes

<Callout tone="warning" title="Watch out for these">
- **Building without checking feasibility.** A constructive problem usually has impossible inputs, and the answer for them is part of the output.
- **Forgetting to flush.** In an interactive problem the judge sees nothing until you flush, so the program waits and the judge times out.
- **Exceeding the query budget.** A correct but wasteful strategy fails. Count the queries before you code.
- **Assuming misere play is the same as normal play.** The Nim rule changes when every pile has at most 1 object.
- **Applying Sprague-Grundy to a partisan game.** It needs both players to have the same moves.
</Callout>

## Frequently asked questions

<Faq>
  <FaqItem question="In what order should I read these?">
    Constructive algorithms first: they need only the greedy topics and the habit of testing small cases. Interactive problems next, since they are binary search with a strict protocol. Game theory last: it is the Advanced topic and it uses XOR from the Bit Manipulation pattern together with dynamic programming.
  </FaqItem>
  <FaqItem question="How is a constructive problem different from a search?">
    A search tries candidates until one works. A constructive solution produces a valid object directly, and a proof says why it always satisfies the constraints. Small cases help you see the rule.
  </FaqItem>
  <FaqItem question="How do I test an interactive solution without a judge?">
    Write a small fake judge that answers from a hidden value, run your solution against it in a test, and count the queries. The topic article does this in its tests.
  </FaqItem>
  <FaqItem question="What is a Grundy number?">
    It is the mex of the Grundy numbers of the positions you can move to, where mex is the smallest non-negative integer not in that set. A position with Grundy number 0 loses for the player to move, and independent games combine by XOR of their Grundy numbers.
  </FaqItem>
</Faq>
